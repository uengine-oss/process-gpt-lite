# 대화를 프로젝트로

2026-11-27 휴대폰 녹화: 받은 메일의 요청을 채팅에서 조사한 뒤 「이 내용을 기반으로 프로젝트를 하나 만들자」라고 했는데, 채팅 에이전트는 채팅 안에서
계획만 세웠고 「프로젝트」 탭에는 아무것도 생기지 않았다. 사용자: 「여기로 프로젝트로 승격하겠다는 거거든 … 채팅을 좀 하다가 아 이거 좀 제대로 가야
되겠다 그래서 프로젝트로 갈 거잖아」 · 「이 프로젝트에 폴더 적절한 이 템플릿 폴더가 좀 우리가 추천이 좀 필요할 수도 있고 … 교육과정 만드는 템플릿
폴더가 있을 수 있겠지」. 서버는 이 스킬을 회사의 스킬 폴더(`chat-to-project`)에서 먼저 찾고, 없으면 Lite 와 함께 온 이 기본 판을 쓴다
(서버 `lib/chatProject.js`).

낱말을 맞추는 규칙으로 뜻을 정하지 않는다. 「프로젝트로 만들자」라는 뜻은 채팅의 라우터 모델이 도구(`start_project`)로 고르고, 무엇을 적고 어느 템플릿이
맞는지는 모델과 판정 모델이 읽는다.

## 절차

1. **알아챔**: 채팅의 라우터가 `start_project` 를 고르거나(말로), 사람이 답 카드의 「프로젝트로 시작」을 누른다(단추로). 아직 아무것도 만들지 않는다.
2. **적기**(`prompts/draft.md`): 그 채팅의 최근 대화(`lines` 개, `lineChars` 자씩), 사람이 고른 답(없으면 가장 최근 답, `answerChars` 자),
   출처(대화에 받은 메일이 있으면 그 메일의 제목 · 보낸 사람), 사람이 지금 한 말, 템플릿 폴더 목록을 읽어
   이름 · 목적 · 배경 · 만들 것과, 맞는 템플릿마다 한 줄 까닭을 적는다.
3. **템플릿 고르기**(`prompts/pick-template.md`): 그 사람이 「실행」 이상으로 쓸 수 있는 템플릿 폴더(`templates.judge` 개까지)마다
   이름 · 설명 · TEMPLATE.md 의 설명 · 에이전트 자산(스킬 · 명령, `kitItems` 개)을 보기로, 판정 모델이 첫 글자 확률로 고른다
   (`templates.minP` 이상, `templates.max` 개까지 — lib/decide.js chooseSome). 템플릿이 하나도 없으면 묻지 않고 추천 칸을 숨긴다.
4. **확인 카드**: 채팅에 「프로젝트로 시작할까요?」 카드 — 이름(고칠 수 있음), 목적 · 배경, 추천 템플릿(까닭 한 줄)과 「빈 프로젝트로」,
   「만들기」 · 「아니요」. 사람이 「만들기」를 눌러야 만든다.
5. **만들기**: 템플릿을 고르면 기존 「템플릿으로 시작」(lib/folders/templates.js startProject)으로 그 프로젝트의 작업 공간을 만들고, 고르지 않으면 빈
   프로젝트를 만든다. 프로젝트 계획(lib/projectNote.js)의 목적 · 만들 것 · 정한 것(배경 · 출처)을 채우고, 고른 답을 프로젝트의 첫 문서(Markdown)로
   넣는다. 원래 대화에는 「프로젝트로 옮겼어요 · 열기」 한 줄을 남기고, 대화는 그대로 둔다(옮기기가 아니라 이어 가기).

## 남기는 것

- 확인 카드: 채팅 메시지(`pro_messages.kind = 'project_offer'`) — 이름 · 목적 · 배경 · 만들 것 · 출처 · 추천 템플릿 · 상태(offered · making ·
  made · declined) · 만든 프로젝트. 새 테이블 · SQL 없음.
- 프로젝트: `pro_threads`(kind project), 계획의 행(`kind note`), 첫 문서(`kind file`), 「채팅에서 이어 온 프로젝트예요」 칩.
- 원래 대화: 「프로젝트로 옮겼어요」 칩(`content.project`).
