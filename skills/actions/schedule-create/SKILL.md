# 예약 만들기

## 언제 쓰나
- 사용자가 실행 시각이나 주기를 새로 정한다: 날짜·요일·시각, 「N분 뒤」, 「매일·매주·평일·장중·N시간마다」.
- 무엇을 할지는 지시문(`prompt`)으로 저장되고 실행 때마다 에이전트가 그대로 수행한다.

## 쓰지 않나
- 사실의 「내 예약 작업」에 이미 있는 작업을 지금 돌리는 일 → schedule-run-now.
- 이미 있는 작업의 결과를 텔레그램으로도 받기 → telegram-delivery.
- 시각 없이 기억해 둘 할 일 → home-action-add.
- 지금 한 번 하는 조사·작성 → delegate.

## 인자 채우는 법
- `cron`: 서울 시각(Asia/Seoul) 기준 5필드 cron. `in_minutes` 를 쓰면 비운다.
- `in_minutes`: 지금부터 몇 분 뒤 한 번. 이때는 한 번만 돈다.
- `once`: 정한 시각에 한 번만 돌 때 true(「내일 오전 9시에 한 번」).
- `notify`: `always` = 실행할 때마다 알림(리마인더, 보고). `on_change` = 직전 실행 뒤로 달라진 것이 있을 때만(새 글·새 영상·값의 변화 감시).
- `prompt`: 실행 때마다 혼자 읽고 수행할 수 있는 지시문. 사용자가 쓴 이름(회사·사람·상품·종목)은 쓴 그대로 둔다. 사용자가 주지 않은 코드·티커·id 를 덧붙이지 않는다 — 실행할 때 찾는다. 조건(얼마 이상 오르면 등)과 알릴 내용을 빠짐없이 넣는다.
- `skill`: 사실의 「에이전트 스킬」이나 「내 스킬」 중 하나가 바로 이 일을 하면 그 이름. 스킬은 한 사람의 일을 한 에이전트가 하고, 결과는 만든 사람에게만 간다.
- `process`: 사실의 「프로세스」 중 하나를 정한 때마다 시작하는 일이면 그 id. 일이 사람·역할 사이를 오가거나(검토·승인), 결정에 따라 갈리거나, 여러 단계가 이어지면 스킬이 아니라 프로세스다. 각 실행이 새 인스턴스를 시작한다.
- `params`: 스킬이면 그 스킬이 받을 입력, 프로세스면 첫 단계 입력(사실에 적힌 키)을 요청에서 옮긴다.
- `name`: 짧은 작업 이름.
