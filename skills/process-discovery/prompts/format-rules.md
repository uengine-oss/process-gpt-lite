회사가 메일로 주고받아 온 양식 하나의 「형식 규칙」을 정합니다. 형식 규칙은 이 양식으로 만드는 문서가 건마다 내용이 달라도 늘 지키는 것이에요 — 로고 · 머리글 그림, 머리글 · 바닥글 글, 고정 문구(면책 · 문의처 · 회사 정보 · 안내문), 제목 붙이는 법, 파일 이름 붙이는 법.

입력(JSON):
- form: 양식 이름, type: 파일 종류(docx · xlsx · pptx · hwpx)
- files: 규칙을 찾은 파일 수. low_confidence 가 true 면 파일이 하나뿐이라 무엇이 건마다 같은지 견줄 수 없어요.
- candidates: 서버가 파일에서 규칙으로 찾은 후보. 하나마다 id, kind(image · header · footer · phrase · title · filename), where(머리글 · 바닥글 · 첫 쪽 · 본문 · 끝 쪽 · 슬라이드 마스터 · 모든 슬라이드 · 시트), text(그 글 — 사람 이름 · 고객 이름 · 연락처는 가려져 있어요. 「…」는 파일마다 다른 부분), in_files(몇 개 파일에 있었는지).

할 일 — 후보마다:
- keep: 건마다 늘 지켜야 할 형식이면 true. 지난 건의 내용(고객 · 날짜 · 금액 · 그 건의 문장)이면 false.
- name: 사람이 알아볼 짧은 이름(예: 「회사 로고」, 「머리글: 과정 이름」, 「문의처」, 「면책 문구」, 「제목: ○○ 과제 정의서」, 「파일 이름: 고객_양식이름」).
- mandatory: 빠지면 회사 문서로 내보낼 수 없는 것(로고 · 회사 정보 · 법적 문구 · 정해진 머리글)이면 true, 있으면 좋은 정도면 false.
- why: 그렇게 본 까닭 한 줄(해요체).

지킬 것:
- 후보에 없는 것을 더하지 않아요. 답은 받은 id 만 씁니다.
- low_confidence 면 mandatory 는 로고 · 머리글 · 바닥글 · 회사 정보처럼 문서의 틀에 있는 것만 true 로 하고, 본문 문장은 false 로 둡니다.
- 가려진 이름을 추측해 채우지 않아요.

JSON 으로만 답합니다:
{"items":[{"id":"c1","keep":true,"name":"회사 로고","mandatory":true,"why":"두 파일 모두 머리글 같은 자리에 같은 그림이 있어요"}]}
