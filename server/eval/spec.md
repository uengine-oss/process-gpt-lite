# 채팅 라우터 평가 — 기능 명세 (문항 작성용)

이 문서는 평가 문항을 쓰는 사람(또는 모델)이 보는 **기능 명세**다. 라우터가 읽는 스킬 설명(skills/actions/*/SKILL.md)은 보지 않고 이 문서만 보고 문항을 쓴다(docs/mobile-review-1121/skill-routing-design.md 7.1).

## 무엇을 평가하나

Process GPT Lite 의 메인 채팅에 사용자가 한 메시지를 보내면, 라우터가 그 메시지를 아래 셋 중 하나로 보낸다.

1. **행동** — Lite 서버가 직접 하는 일 11가지(아래 표). 서버가 가진 상태(예약, 텔레그램 설정, 패널, 폴더 변경안, 프로세스 인스턴스, 내장 브라우저, 홈 알림)가 바뀌거나 그 상태를 보여 준다.
2. **delegate** — 범용 에이전트에게 넘긴다. 답을 쓰고, 문서·파일·그림·도면·영상을 만들고, 바깥 정보를 찾아 읽고, 스킬을 만든다. 서버 상태를 바꾸지 않는 거의 모든 일.
3. **ask** — 되묻기. 뜻이 둘 이상으로 갈리고, 잘못 고르면 사람에게 무언가가 나가거나 바깥 사이트에 손을 대거나 업무 절차가 시작되는 경우에만.

## 행동 11가지 — 각각 무엇을 하나

| 라벨 | 하는 일 |
|---|---|
| `schedule-create` | 새 예약 작업을 만든다. 정해진 시각에 한 번, 또는 주기적으로(매일·매주·N분마다·장중 등) 같은 일을 돌린다. 몇 분 뒤 한 번도 여기다. 무엇을 확인·요약·보고할지는 지시문으로 저장되고 실행 때마다 에이전트가 수행한다. 알림 방식은 매번 알림 또는 바뀐 것이 있을 때만. 회사의 스킬이나 프로세스를 정해진 때에 돌리는 것도 여기(그때는 그 스킬/프로세스 이름을 고른다). |
| `schedule-run-now` | 이미 만들어 둔 예약 작업 하나를 새 예약 없이 지금 한 번 돌려 결과를 바로 보여 준다(시험 실행). 어떤 작업인지는 이름으로 가리키거나, 방금 이 대화에서 만든/돌린 작업을 가리킨다. 인자: `schedule`(작업 id). |
| `telegram-delivery` | 사용자의 텔레그램 봇과 관련된 서버 설정. 네 가지: `connect`(내 봇 연결 안내 카드), `alerts_on`(어떤 예약 작업의 결과를 텔레그램으로도 받기), `alerts_off`(그 전달 끄기), `send_last_answer`(이 대화의 마지막 답을 지금 텔레그램으로 보내기). 인자: `action`, 필요하면 `schedule`(작업 id). 텔레그램이 무엇인지·봇 만드는 법 같은 질문, 텔레그램 채널 내용을 읽어 오는 일은 여기가 아니다(delegate). |
| `panel-create` | 홈 화면에 새 패널을 만든다. 실시간 위젯(날씨, 환율, 시세 같은 값이 계속 바뀌는 카드) 또는 기록을 쌓는 작은 데이터 앱(명단, 대장, 목록, 관리표, 기록부 — 시트에 저장되고 팀과 공유). 문서·보고서·파일을 쓰는 일은 여기가 아니다. |
| `panel-record` | 이미 있는 패널 앱 하나에 행을 더하거나, 고치거나, 목록·건수를 본다. 기록형 앱은 기록(부여·사용·취소 같은)을 더한다. 인자: `app`(앱 id), `action`(add/update/list). |
| `folder-change` | 공유 폴더(또는 스킬 폴더) 안의 파일을 고치거나 새 파일을 그 폴더에 넣어 달라는 요청. 원본을 바로 바꾸지 않고 변경안을 만들어 폴더 주인이 검토·반영한다. 대화에 폴더가 붙어 있으면 폴더 이름을 말하지 않아도 그 폴더다(`attached`). 폴더 내용을 묻거나 폴더 자료로 새 문서를 써 달라는 것은 여기가 아니다(delegate). 인자: `folder`(slug 또는 `attached`). |
| `process-work` | 회사 업무 프로세스(결재·신청·접수 같은 정해진 절차): `start`(인스턴스 시작 — 시작 폼 카드를 띄움), `view`(프로세스가 어떻게 생겼는지 보기), `catalog`(어떤 프로세스가 있는지), `instances`(진행 중인 인스턴스), `my_todos`(내가 처리할 할 일·결재 대기), `create`(새 프로세스 정의를 설계). 인자: `intent`, start/view 면 `process`(id). |
| `process-improve-explain` | 실행 기록이 있는 프로세스의 병목·지연·리드타임·개선 방법을 서버가 계산한 숫자로 설명한다. 인자: `process`(id). 실행 기록이 없는 프로세스나 일반적인 업무 개선 이론 질문은 여기가 아니다. |
| `browser-task` | 실제 웹 브라우저를 서버가 띄워 사이트에서 직접 해야 하는 일: 로그인, 잔액·내역 확인, 예약·주문·결제, 웹 양식 제출, 웹 관리 콘솔 조작. 연결된 서비스(유튜브, 구글 메일·캘린더·드라이브, 슬랙, 깃허브, 노션)에서 정보를 찾는 일은 여기가 아니다(delegate — 에이전트가 연결 도구로 먼저 함). |
| `teammate-notify` | 팀원(이름·이메일·역할)에게 홈 알림을 보내 무엇을 봐 달라거나 처리해 달라고 부탁한다. 인자: `member`(팀원 이름 또는 역할). |
| `home-action-add` | 할 일·리마인더를 홈 화면의 액션 버튼으로 저장해 둔다(정해진 시각에 돌리는 예약이 아니라, 홈에 남겨 두는 할 일 카드). |

## delegate 가 맞는 것(예시 범주, 문장 아님)

질문에 답하기, 설명·요약·번역·교정, 글·메일 초안, 문서·보고서·제안서·견적서 만들기(워드·한글·엑셀·PPT·PDF), 열린 문서 고치기, 도면·로고·이미지·오디오·영상 만들기나 편집, 바깥 정보 찾기(주가 지금 얼마인지 한 번, 뉴스, 유튜브, 메일함·캘린더·드라이브·슬랙·깃허브·노션 조회), 데이터 분석, 스킬 만들기·스킬 다듬기, 내 스킬로 일 처리, 잡담, 회사·업무 상담, 첨부 파일 읽기.

## ask 가 맞는 것

행동이 거의 분명하지만 대상이 둘 이상 그럴듯하고, 그 행동이 사람에게 나가거나(팀원 알림, 텔레그램 전송) 바깥에 손대거나(브라우저 작업) 업무 절차를 시작하는(프로세스 시작) 경우. 예: 같은 이름 팀원이 둘인데 성을 말하지 않음, 비슷한 프로세스가 둘인데 어느 쪽인지 불분명, 지금 실행할 작업이 여러 개이고 어느 것인지 단서가 없음.

## 상태(fixtures.json)

문항마다 `state` 를 하나 고른다. 상태가 라우터에 사실로 주어진다.
- `base`: 예약 4개(환율 변동 감시, 아침 뉴스 요약, 주간 매출 보고 알림, 경쟁사 블로그 새 글 확인[멈춤]), 패널 앱 3개(비품 대장, 연차 기록[기록형], 거래처 명단), 공유 폴더 2개(11월 고객 세미나 `seminar-2026-11`, 영업 자료 `sales-kit`)와 스킬 폴더 1개(`skill:weekly-report-writer`), 프로세스 4개(휴가 신청 `vacation_request`, 구매 요청 `purchase_request`, 고객 제안 `customer_proposal`, 경비 정산 `expense_claim`), 실행 기록이 있는 프로세스 2개(고객 제안, 구매 요청), 팀원 3명(김민지 제품 책임자, 박서준 영업팀장, 최유나 디자이너), 내 스킬(공유 전) `meeting-minutes-cleanup`, 텔레그램 미연결.
- `empty`: 예약·앱·폴더·프로세스·팀원·내 스킬이 하나도 없음.
- `recent`: base + 이 대화에서 방금 「환율 변동 감시」(`a3f1c9e2`)를 만들었음(대화 기록이 함께 감).
- `attached`: base + 이 대화에 「11월 고객 세미나」 폴더가 붙어 있음(변경 제안 가능).
- `tg_on`: base + 텔레그램 봇 연결됨.
- `opendoc`: base + 채팅 옆 편집기에 「3분기 실적 보고.docx」가 열려 있음.
- `twins`: base 인데 팀원에 김민지·이민지가 둘 다 있고, 프로세스에 구매 요청 `purchase_request` 와 구매 요청(해외) `purchase_request_overseas` 가 둘 다 있음.
- `files`: base + 이 메시지에 「견적서_초안.xlsx」가 첨부됨.

id: 예약 `a3f1c9e2`(환율 변동 감시) `b7d20e14`(아침 뉴스 요약) `c91e5a07`(주간 매출 보고 알림) `d4a8f3b6`(경쟁사 블로그 새 글 확인), 앱 `e5c1a9d3`(비품 대장) `f2b8d6e1`(연차 기록) `09a7c3f5`(거래처 명단).

## 문항 형식(JSON Lines, 한 줄에 하나)

```json
{"id":"dev-0001","text":"…","state":"base","history":[{"role":"user","text":"…"},{"role":"agent","text":"…"}],"expect":{"route":"schedule-run-now","args":{"schedule":"a3f1c9e2"}},"category":"positive","skill":"schedule-run-now","axis":{"style":"banmal","lang":"ko","quality":"clean","context":"none"},"mode":"ko"}
```

- `route`: 행동 라벨 11개 중 하나, 또는 `delegate`, `ask`.
- `args`: id·열거값만, 확실할 때만 적는다(그 외 인자는 적지 않음). schedule-run-now→`schedule`, telegram-delivery→`action`(+`schedule`), panel-record→`app`,`action`, folder-change→`folder`, process-work→`intent`(+`process`), process-improve-explain→`process`, teammate-notify→`member`(이름).
- `category`: `positive`(그 스킬이 맞음) / `boundary`(그 스킬과 같은 낱말·비슷한 상황이지만 다른 라벨이 맞음 — `skill` 에 가까운 스킬 이름, `route` 에 맞는 라벨) / `delegate` / `ask`.
- `history`: 맥락이 필요한 문항만(대명사, 방금 한 일). `recent` 상태는 대화 기록이 이미 들어 있다.
- `axis.style`: plain(해요체 평서·요청) · banmal · formal(합쇼체) · command · question · monologue · indirect(바라는 바만 / 불만으로 / 되묻는 꼴).
- `axis.lang`: ko · en · ja · zh · mix. `axis.quality`: clean · typo · nospace · dictation. `axis.context`: none · pronoun · prior-chip · state.
- `mode`: 화면 언어 `ko` 또는 `en`(영어로 쓴 문항의 절반쯤은 `en`).

## 규칙

- 금지 문장(forbidden.txt)과 같거나 거의 같은 문장은 쓰지 않는다. 그 문장들의 낱말 조합을 흉내 내지도 않는다.
- 같은 꼴을 반복하지 않는다. 한 스킬 안에서 말투·언어·간접 표현·오타를 고르게 섞는다.
- 사람 이름·회사·숫자는 상태에 있는 것만 id 로 가리킨다(새 작업·새 패널을 만드는 문항은 자유).
