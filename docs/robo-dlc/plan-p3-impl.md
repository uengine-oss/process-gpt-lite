## 2. 시나리오 — 시험 · 녹화 · 스펙 · 튜토리얼이 같은 단계를 밟는다

운영 중인 「회의실 예약」(1차 릴리스, 유닛 6개)에 일을 더 넣는 하루다. 팀 리드 한지수, PO 오세린, 아키텍트 최민준, 개발 강다은, QA 윤서준.

- **S1 대화에서 접수해 바로 시작** — 한지수가 대화에 「작업 접수: 예약 알림 메일이 두 번 와요…」 → 대화에 계획안 카드(범위 bugfix, 건드릴 유닛 u5, 점수) → 「크게 보기」 → 「지금 시작」 → Claude Code가 처음 여는 폴더라 「이 폴더를 믿고 시작할까요?」 → 「믿고 시작」 → 팀 세션에 `/aidlc bugfix "…"` → 엔진이 인텐트를 만들면 볼트 줄 머리에 「도는 중」.
- **S2 앞 작업 뒤에 세우기와 볼트 의존** — 오세린이 접수 앱에서 「반복 예약」 → 계획안(feature, 유닛 여럿) → 「앞 작업 뒤에 세우기」 → 볼트 줄 끝에 유닛마다 예상 볼트 → 다른 볼트에 기대는 볼트 하나를 「다음 릴리스」로 옮기려 하면 막히고, 함께 가야 할 볼트를 알려 준다 → 「함께 옮기기」.
- **S3 도는 볼트와 맞지 않는 요청** — 오세린이 「알림을 메일 대신 슬랙으로, 메일 발송은 없앱니다」 → 계획안에 충돌 카드: 도는 볼트 · 「둘 중 하나만」 또는 「함께 갈 수 있음」 · 요청의 말과 기록의 말 · 까닭.
- **S4 보안 멈춤과 폐기** — 윤서준(멈춤 권한 없음)이 볼트 줄에서 「멈춤 요청」 → 「보안」 + 까닭 → 세션이 바로 멈추고 볼트는 멈춰 둠 → 한지수 홈에 카드 → 볼트 줄에서 까닭을 보고 「폐기」(미리 보기, 까닭 필수, 마지막 볼트면 인텐트 보관) → 줄 머리가 비고 원장에 모든 걸음.
- **S5 대화 진입의 갈래** — 접수 권한이 없는 사람의 「작업 접수: …」는 접수함으로 가고 누가 정하는지 알려 준다 · 두 프로젝트에 있으면 어느 프로젝트인지 묻는다 · 평소 말로 부탁하면 라우터가 넘기고, 확신이 없으면 먼저 묻는다.

시험: `server/test/aidlc-intake.e2e.test.js`(S1~S4), `aidlc-chat.e2e.test.js`(S5), 화면 회귀 `e2e/tests/feature/robo-dlc.spec.js` F-RD-10…13.
녹화: `pgpt-pro/demo/product/robo-dlc-intake-ko`(S1) · `robo-dlc-line-ko`(S2~S4) — 실제 Claude Code 세션과 실제 AI-DLC 2.11.2 엔진.

## 4. 결정 — 「알아서」 맡은 판단과 이유

1. **앱은 둘이다.** 접수(무엇을 할지 정하는 곳)와 줄(언제·어떤 순서로 내보낼지 보는 곳)은 보는 사람과 때가 다르다. 한 번의 조작으로 서로 오갈 수 있다(「볼트 줄에서 보기」 · 「접수함」).
2. **자동으로 넘어가지 않는다.** 계획안은 추천일 뿐이고, 시작·대기·합치기는 접수 권한자가 누른다. 줄 머리가 비어도 다음 요청을 스스로 시작하지 않고 「다음 작업 시작」을 사람에게 보인다(HITL).
3. **범위 추천 규칙**: 종류(버그·기능·변경·리팩터·보안)와 AI-DLC의 ARS(다섯 점수: 요청의 모호함·코드의 얽힘·확인 근거 부족·틀렸을 때 위험·숨은 가정)에서 AI-DLC 범위(bugfix · feature · classic …)를 고른다. 추정은 헤드리스로 한 번 호출하고 팀 세션을 쓰지 않는다. 도는 작업을 방해하지 않기 위해서다.
4. **되돌리기는 스냅숏으로.** 볼트를 시작할 때 바뀐 파일 목록의 기준을 잡아 두고, 폐기하면 그 뒤에 바뀐 파일만 되돌리고 새 파일을 치운다. AI-DLC 기록(`aidlc/`)은 남긴다. 왜 버렸는지 기록해야 하기 때문이다.
5. **한 회사 = 한 프로젝트면 묻지 않는다.** 대화에서 접수할 때 프로젝트가 하나면 바로, 둘 이상이면 고르게 한다(D-1112-26).
6. **줄의 칸**: 내보냄 · 지금 · 다음 릴리스 · 줄 끝. 새 요청은 줄 끝에 서고, 의존(계약을 주는 유닛 먼저)을 깨는 이동은 막되 함께 옮길 볼트를 알려 준다(D-1112-27).
7. **폐기된 인텐트는 줄 머리를 비운다.** 도는 볼트를 폐기하면 세션에 그만하라고 알리고 머리를 비워, 뒤에 선 요청을 시작할 수 있게 한다. 그 볼트에 기대던 볼트의 기본 상태는 「멈춰 둠」이다.
8. **보안 멈춤은 권한을 묻지 않고 바로**(D-1112-24): Esc 하나만 보내고 그 밖의 키는 넣지 않는다. 풀거나 버리는 것은 멈춤 권한자(팀 리드·PO).
9. **폴더를 믿는지는 사람이 답한다.** Claude Code가 처음 여는 폴더에서 묻는 화면 위에는 아무것도 치지 않는다. 그 폴더가 미리 허용한 도구 수를 보여 주고, 「믿고 시작」을 누른 사람과 수를 원장에 남긴다.
10. **인텐트 보관은 엔진 명령으로, 됐는지는 기록에서.** `aidlc engine intent archive <dir> --reason …`을 부르고, 성공 여부는 명령의 출력이 아니라 `intents.json`의 `status: archived`로 읽는다.

## 6. 남은 공백

- **메신저 방에서 접수**: 지금은 내 대화와 앱에서만. 팀 방의 말에서 요청을 만드는 길은 없다(§12-4 작업 함도 미구현).
- **작업 트리 격리**(D-1112-25): 엔진의 병렬 경로(유닛마다 가지)를 쓰는 폐기는 안 했다. 지금은 한 작업 사본에서 스냅숏으로 되돌린다. 동시에 도는 세션은 하나다.
- **Esc와 뒤에서 도는 하위 에이전트**: 세션이 하위 에이전트를 뒤에서 실행 중일 때 Esc 한 번으로 모두 멈추는지는 화면으로 확인하지 못했다. 폐기 때 세션에 그만하라는 말을 따로 보내는 것으로 보완한다.
- **코드가 다른 감시기 두 개가 한 폴더를 볼 때**: 보관된 인텐트를 읽지 못하는 옛 서버가 같은 DB를 보면, 보관 뒤 그 인텐트의 빈 질문 파일을 다시 「기다림」으로 열어 알림이 되풀이된다(8초마다). 서버 하나로 운영하는 환경에는 이 문제가 없다. 개발 서버에는 `PRO_AIDLC_WATCH_ONLY`를 준다.
- **영향 검토 상세**(§4 유닛 대응표) · **이전 결정 충돌**(§5): 추정 결과를 담은 충돌 카드까지만 구현했다. 아키텍트의 영향 검토 화면은 다음으로 미뤘다.
- **홈 카드의 글**: 계획안 창은 `` `이름` ``을 코드 글자로 바꾸지만(P3-7), 홈의 「계획안이 나왔어요」 카드 본문에는 백틱이 그대로 보인다.
- **「맞지 않음」은 실제 판에서 못 봤다**: 녹화 판의 판단은 「함께 갈 수 있음」 이었다. 「둘 중 하나만」 화면은 고정 답 시험(E2E S3)으로만 확인했다.
- **이전 결정과의 대조는 모델의 판단**이라 놓치거나 잘못 짚을 수 있다. 칩이 「둘 중 하나만」이어도 결정은 사람이 한다.
