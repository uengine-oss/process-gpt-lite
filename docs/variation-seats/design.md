# 작업실을 내 PC 에서 — 작업본은 한 곳에 (설계, Process GPT Lite, 2026-11-26)

대상 저장소: `process-gpt-lite` (main `137a777` 기준, SQL 은 055 + 059 + 062 까지). 구현 · 커밋 없음, 설계만.
바탕: 챔피언 폴더 설계(`docs/champion-folders/design.md` — P0 는 PR #81 로 들어감, P1~P4 는 설계만), 로컬 에이전트 설계(`docs/local-agents/design.md`), 그리고 이 문서 끝 「확인한 것」의 코드.

## 사용자 요청 (2026-11-26, 그대로)

> 「폴더내 작업실을 누르면 일렉트론에 연결된 모바일이나 일렉트론내 해당 워크트리를 클론하여 작업할 수 있고 로컬 폴더 작업 결과를 서버로 동기화 할 수 있다. 작업본이 여러군데 흩어져서는 안되니 잘 설계해」

### 이렇게 읽었다

| 요청의 말 | 읽은 뜻 | 코드에 비춰 보탠 것 |
|---|---|---|
| 「폴더내 작업실을 누르면」 | 공유 폴더 화면의 「작업실」 단추(폴더 머리 `FolderDetail.vue:254`, 변형 화면 `VariationView.vue:126`) | 폴더 머리의 단추는 지금 **main** 을 연다. main 에는 「워크트리」가 없으므로, 내 PC 에서 일할 때는 **그 사람의 변형(내 작업본)** 을 만들거나 이어서 연다(§3.1) |
| 「일렉트론내 해당 워크트리를 클론하여 작업」 | 데스크톱 앱에서 누르면 그 PC 가 변형을 받아(clone + 작업 트리) 거기서 일한다 | 자리는 앱 데이터 폴더 아래(지금 스펙 그대로) |
| 「일렉트론에 연결된 모바일」 | 같은 사람으로 로그인한 휴대폰 · 웹. 그 사람의 PC 앱이 서버에 이어져 있으면 **PC 가** 받아서 일하고, 휴대폰은 시키고 · 보고 · 입력한다 | 휴대폰과 PC 를 따로 짝짓지 않는다 — 이미 있는 링크(`localAgents/hub.js`)와 터미널 중계(`relay.js`)를 쓴다. 휴대폰이 clone 하지는 않는다 |
| 「로컬 폴더 작업 결과를 서버로 동기화」 | PC 의 결과가 그 변형의 가지로 올라간다(main 은 지금처럼 일괄 반영으로만) | 이미 있는 공개 git 경로(`/api/local-git`)에 범위 하나 |
| 「작업본이 여러군데 흩어져서는 안되니」 | 한 일의 작업본은 **한 번에 한 곳**. 말없이 갈라지는 일이 없어야 한다 | 지금은 같은 변형이 서버 체크아웃 · PC 의 채팅 일 폴더에 동시에 있을 수 있다(§1.4) — 이번에 닫는다 |

요청하신 분의 읽기와 같다. 다만 두 가지를 더 분명히 했다: ① 폴더 머리의 「작업실」은 main 이므로 PC 쪽은 「내 작업본(변형)」으로 받는다, ② 「흩어지지 않게」는 사람 대 PC 뿐 아니라 **지금 있는 로컬 일(채팅 · 넘겨받은 일)의 폴더까지** 같은 작업본으로 모아야 지켜진다(§5.3).

## 0. 한눈에

```
                        서버 (폴더 저장소)                                   그 사람의 PC (앱 데이터)
        ┌────────────────────────────────────────────┐            ┌─────────────────────────────────┐
        │ main ◀── 일괄 반영 ── var/u/<사람>/<일>      │  fetch     │ folders/<서버>/<사람>/<폴더>/    │
        │                        ▲  (변형 가지 = 원본) │ ─────────▶ │   repo  (받은 것 보관)           │
        │        앞으로만 옮김   │                     │            │   wt/<변형>  ◀── 작업본(자리)    │
        │ pgpt-agent/seat-<변형8>-<회차>/head ◀────────│── push ─── │   Finder · 터미널 · VS Code ·    │
        │                                              │            │   claude · codex                 │
        │ .people/<사람8>/<변형>  ◀── 작업본(자리)     │            └─────────────────────────────────┘
        └────────────────────────────────────────────┘                    ▲ 중계(보기 · 입력)
              ▲ 웹 작업실(파일 · 셸)                                        │
              └───────────────── 휴대폰 · 웹 ─────────────────────────────┘
        변형마다 「자리」는 하나: 없음(보관 중) · 서버 작업실 · 어느 PC.  자리가 아닌 곳에는 작업 트리가 없다.
```

핵심 세 줄:

1. **원본은 늘 서버의 변형 가지 하나**(`var/u/<사람8>/<제목>`)다. 작업 트리는 그 가지를 고칠 수 있는 「자리」일 뿐이고, 자리는 변형마다 **하나**다.
2. 자리를 옮길 때는 **먼저 올리고(커밋 · push) 치운 뒤** 다음 곳이 받는다. 그래서 두 곳에 고칠 수 있는 사본이 동시에 있는 순간이 없다.
3. 자리를 잃은 곳에 남은 변경은 **버리지도 말없이 섞지도 않고** 이름 붙은 새 변형(「○○ PC 에 남아 있던 변경」)으로 올라와 지금의 일괄 반영으로만 합쳐진다.

## 1. 작업본은 한 곳에 — 규칙

### 1.1 낱말

| 낱말 | 뜻 |
|---|---|
| **변형** | 사람 × 일 하나. 서버 폴더 저장소의 가지 하나(`pro_folder_variations`). 내용의 원본 |
| **작업본** | 그 변형을 고칠 수 있게 디스크에 펼친 작업 트리. 저장하지 않은 변경이 쌓일 수 있는 곳 |
| **자리** | 지금 작업본이 있는 곳. `없음`(가지만 있음) · `서버`(`.people/<사람8>/<변형id>` 또는 서버 에이전트 실행의 체크아웃) · `PC`(기기 하나의 `wt/<변형>`) |
| **회차(epoch)** | 자리가 바뀔 때마다 1 씩 오르는 수. PC 의 올리기 토큰과 올리는 가지 이름에 들어가, 옛 자리의 push 를 서버가 가려낸다 |
| **저장 지점** | 작업본의 지금 상태를 커밋해 변형 가지로 올린 것(자리를 옮기지 않음) |

작업본이 **아닌** 것(규칙의 대상이 아님): 프로세스 단계의 일회용 실행 폴더(`work/<서버>/<인스턴스>-<폴더8>` — 실행마다 `reset --hard` · `clean` 뒤 자기 실행 가지로 올리고 끝), 일괄 반영의 통합 작업 트리, 인스턴스 라인의 잠깐 쓰는 체크아웃(`.lines/`), 챔피언의 원본 폴더(그것은 main 줄의 원본이고 규칙은 챔피언 설계 §2 — §4.3 에서 관계를 정함).

### 1.2 상태와 보이는 말

| 상태 | 저장(`pro_variation_seats`) | 변형 화면 · 폴더 목록 · 작업실 머리의 말 | 누가 고칠 수 있나 |
|---|---|---|---|
| 보관 중 | 행 없음 | 「보관 중 — 열기」 | 아무도(열면 자리가 생김) |
| 서버 작업실에서 | `place=server, run=workroom` | 「서버 작업실에서 · 정하윤」 | 그 사람(웹 작업실의 파일 · 셸) |
| 서버 에이전트가 | `place=server, run=agent` | 「서버 에이전트가 작업 중」 | 그 실행 |
| ○○의 PC 에서 | `place=device, state=held` | 「정하윤의 PC(맥북)에서 · 저장 안 한 변경 3 · 방금 올림」 / PC 가 꺼지면 「… · PC 꺼짐 · 마지막 올림 3시간 전」 | 그 PC 의 그 사람 |
| 넘기는 중 | `state=moving`(받는 쪽 준비) · `returning`(돌려놓는 중) | 「맥북으로 넘기는 중…」 「서버로 돌려놓는 중…」 | 아무도(끝날 때까지, 기한 90초) |

- 다른 사람에게도 같은 말이 보인다(어디에 있는지 · 누가 · 마지막으로 올린 때). PC 의 경로 · 기기 id 는 보이지 않고 기기 **이름**만(지금 설정 화면의 이름).
- 변형의 `status`(open · ready · conflicted · merged · discarded)는 그대로다. 자리가 있는 동안은 `open`, 자리를 내려놓거나(「돌려놓기」) 사람이 「검토 준비됨」을 누르면 `ready`.

### 1.3 넘기기

```
            열기(웹)                        「내 PC 에서 열기」
  보관 중 ──────────▶ 서버 작업실 ─────────────────────────────▶ 넘기는 중 ──ready──▶ PC
     ▲                    │  ① 서버가 커밋 ② 셸 닫음 ③ 체크아웃 치움      │ 기한 지나면 보관 중
     │  돌려놓기           │                                               ▼
     └────────────────────┴──────────── 돌려놓는 중 ◀──── 「서버로 돌려놓기」 · 「서버 작업실에서 열기」 ── PC
                             ① PC 가 커밋 · push ② 서버가 변형 가지를 앞으로 옮김 ③ 회차 +1 ④ PC 가 작업 트리 치움
```

**서버 → PC** (`POST …/seat {to:'device'}`)
1. 폴더 직렬 잠금 안에서: 서버 체크아웃이 있으면 **있는 그대로 커밋**(메시지 「작업실에서 옮김」, 작성자 = 그 사람) → 그 방의 셸을 닫고(보는 화면에 「PC 로 옮겼어요」) → 체크아웃을 치운다 → 회차 +1, `state=moving`.
2. 링크로 그 기기에 `seat:prepare {variation, folder, branch, head, epoch}`.
3. PC: 폴더 저장소를 받고(처음이면 clone, 아니면 fetch) `wt/<변형8>-<제목>` 에 그 가지를 그 머리로 펼친다 → `seat:ready {head}`.
4. 서버: 머리가 같으면 `state=held`. 90초 안에 답이 없으면 행을 지워 「보관 중」으로(내용은 1 에서 이미 가지에 있음) — 서버 체크아웃을 되살리지 않는다.

**PC → 서버 / 보관** (`POST …/seat {to:'server'}` 또는 `…/seat/release`, PC 의 「돌려놓기」)
1. 서버가 `seat:recall`(또는 PC 가 먼저 시작) → `state=returning`.
2. PC: 도는 CLI 세션이 있으면 턴이 끝나기를 기다렸다가(지금의 `settle`) 닫고, **있는 그대로 커밋**(되돌리기 · 치우기 없음) → 자기 회차의 가지로 push → `seat:release {head, left}`.
3. 서버(push 직후 `after` 훅, 폴더 잠금 안): 들어온 것을 검사(챔피언 P0 의 `inspect` — 링크 · 서브모듈 · 제어 파일 · 크기 · 비밀 생김새) → 변형 가지를 **앞으로만** 옮김 → 회차 +1 → 행을 지우거나(`보관 중`) 서버 체크아웃을 만든다(`서버 작업실`) → `seat:released`.
4. PC: `seat:released` 를 받은 뒤에만 작업 트리를 치운다. git 이 싣지 않은 파일(`.gitignore` 가 뺀 `.env` · 빌드 산출물 등)이 있으면 지우지 않고 앱 휴지통 폴더로 옮기고(30일) 「이 PC 에만 있던 파일 N개」를 알린다. `repo`(받은 객체)는 다음에 빨리 받으려고 남긴다 — 작업 트리가 아니므로 고칠 수 있는 사본이 아니다.

**PC 에 있는 동안**(자리는 그대로): 저장 지점(§4.1)이 변형 가지를 따라 옮긴다. 다른 사람은 변형 화면에서 올라온 데까지의 차이를 본다.

### 1.4 강제하는 곳 (말이 아니라 문지기)

| 길 | 지금 | 바꿈 |
|---|---|---|
| 웹 작업실의 파일 쓰기 · 셸 표 (`workroom.js writeFile` · `issueTicket`, 방 = `rooms.js folderRoom('variation')`) | 폴더 역할(runner)만 봄 | 방을 풀 때 자리를 본다: `place=server` 이고 그 사람의 것일 때만 쓰기 · 셸. 아니면 읽기 전용 방(서버 가지의 머리를 보여 줌)과 「○○의 PC 에서 작업 중」 |
| 변형 체크아웃 (`POST …/variations/:vid/checkout` → `S.checkout`) | 가지가 다른 곳에 나와 있으면 그 체크아웃을 **커밋 없이** 치우고 새로 펼침(`service.js checkout` 의 `release(… keep)`) | 자리 모듈을 거친다: 다른 사람 · 다른 곳의 자리면 409 와 자리 정보. 서버 안에서 옮길 때도 **커밋 먼저** |
| PC 의 push (`/api/local-git`, `gitHttp.js`) | 범위 `device`(일) · `sync`(챔피언 원본) | 범위 `seat` 하나 더: 토큰 `{folder, device, seat: 변형id, epoch, push: 'pgpt-agent/seat-<변형8>-<회차>/'}`, **요청마다** `devices.seatAccess` — 기기 연결됨 · 자리가 그 기기 · 회차 같음 · 그 사람의 역할 ≥ runner. 회차가 지난 push 는 git 이 보기 전에 거절 |
| 변형 가지를 옮기는 서버 쪽 길 (`line.js advanceLine`, `localAgents/chat.js bringIn`, `handover.js runReceiver`) | 체크아웃이 있으면 그 안에서 병합, 없으면 가지를 옮김 | 자리가 PC 이면 옮기지 않는다 — 그 일을 그 자리로 보내거나(§5.3) 까닭과 함께 멈춘다 |
| 일괄 반영 · 버리기 · 인계 (`merge.js` · `discard` · `handover`) | 변형 상태만 봄 | 자리가 PC 이면 먼저 「돌려 달라」(보유자에게 알림, 앱이 켜져 있고 CLI 가 쉬고 있으면 저절로 돌려놓음). 인계는 넘기기 전에 반드시 돌려놓는다(챔피언 설계의 「먼저 올리고 넘긴다」와 같은 줄) |
| PC 안 | — | 변형마다 작업 트리 자리가 하나로 정해진다(경로가 변형 id 에서 나옴). 서버가 그 기기의 자리가 아니라고 하면 그 작업 트리는 읽기만 하고 「남은 변경」 길(§1.5)로 |

### 1.5 어긋나는 경우

| 경우 | 동작 |
|---|---|
| 서버 작업실에 저장 안 한 변경 | 옮길 때 서버가 있는 그대로 커밋한다(지금 작업실의 저장이 곧 커밋인 것과 같은 줄) |
| PC 에 저장 안 한 변경 | 돌려놓을 때 있는 그대로 커밋해 올린다. 앱은 변형 작업본에서 `reset` · `clean` 을 **하지 않는다**(`runner/git.js` 의 `branch()` 는 일회용 폴더에만 — 단위 시험으로 고정) |
| 넘기는 중에 서버가 꺼짐 | 다시 뜰 때 `moving` · `returning` 이 기한을 넘겼으면: 서버 가지 머리가 그대로면 「보관 중」, PC 가 `ready` 를 다시 보내면 PC 로 |
| 넘기는 중에 PC 가 꺼짐 · 앱이 죽음 | 기한 뒤 「보관 중」. PC 가 다시 이어지면 서버가 `seat:list`(이 기기의 자리 목록)를 보내고, PC 는 목록에 없는 작업 트리를 「남은 변경」 길로 맞춘다 |
| PC 가 오프라인인 채 일함 | 자리는 그대로(저절로 만료하지 않음). 저장 지점은 PC 에 쌓였다가 이어지면 올라간다. 남에게는 「PC 꺼짐 · 마지막 올림 …」 |
| 같은 사람의 둘째 PC · 휴대폰에서 열려고 함 | 「맥북에서 작업 중 — 이 PC 로 가져오기 / 맥북에서 계속 보기」. 가져오기 = 맥북이 켜져 있으면 보통의 돌려놓기 → 넘기기(저절로), 꺼져 있으면 「맥북에 안 올린 변경이 있을 수 있어요 — 마지막 올림(3시간 전)에서 이어 갈까요?」 확인 뒤 회차 +1 |
| 자리를 잃은 PC 가 돌아옴(가져감 · 그 사이 반영됨 · 버려짐 · 권한이 내려감) | 그 PC 의 작업 트리에 서버 가지에 없는 것이 있으면: 있는 그대로 커밋 → `pgpt-agent/left-<변형8>-<기기8>/head` 로 올림(읽기만 남은 토큰이 아니라 이 일만 하는 한 번짜리 토큰) → 서버가 **새 변형**(종류 `imported`, 제목 「<원래 제목> — 맥북에 남아 있던 변경」, 보유자 = 그 사람)으로 등록 → 작업 트리를 치운다. 없으면 그냥 치운다. 권한이 아예 없어졌으면 올리지 못하고 「이 PC 에 남은 변경 — 내보내기(zip) / 버리기」 |
| 사람이 작업 트리에서 가지를 바꾸거나 이력을 고쳐 씀(rebase) | 앱은 그 변형의 가지가 체크아웃돼 있을 때만 올린다(아니면 「다른 가지로 바뀌어 있어요」로 멈춤). 앞으로 옮길 수 없는 머리는 서버가 거절 → 「새 변형으로 올리기」(위의 남은 변경 길) |
| 기기 연결을 끊음(설정에서 revoke) · 로그아웃 · 다른 사람이 같은 앱에 로그인 | 그 기기의 자리는 「보관 중」으로(마지막 올림 기준). 작업 트리는 사람별 자리에 그대로 두고, 그 사람이 다시 로그인하면 남은 변경 길 |
| 폴더가 지워짐 · 테넌트가 다름 | 토큰 · 링크 메시지가 그 테넌트 · 그 사람 안에서만 폴더를 찾으므로 닿지 않음. 작업 트리는 「연결이 끊긴 작업본」으로 목록에 남아 사람이 치운다 |

### 1.6 왜 이 방식인가

| 대안 | 흩어짐 | 버린 까닭 |
|---|---|---|
| 늘 서버에서만 | 없음 | 운영(여러 회사가 함께 쓰는 서버)에서는 작업실 셸이 닫혀 있다(`workroom.js terminalStatus`) → 파일 편집만 남는다. 각자 계정의 CLI 를 각자 PC 에서 쓴다는 데스크톱 앱의 목적과 어긋남 |
| 늘 PC 에서만 | 사람의 PC 마다 | 앱이 없는 사람 · 휴대폰만 든 사람이 고칠 수 없고, 꺼진 PC 의 일이 안 보인다 |
| 어디서나 고치고 나중에 병합 | **많음** — 서버 체크아웃 · PC 마다 · 채팅 일 폴더가 저마다 앞서 감 | 문서(docx · xlsx · hwpx)는 병합이 안 된다. 「어느 것이 최신인가」가 사람의 기억에 달림. 요청이 금한 바로 그 모습 |
| PC 파일을 양방향 실시간 맞춤(드라이브 방식) | 사본이 늘 둘 | CLI 가 쓰는 중인 파일을 서버 쪽 변경이 덮는 경쟁, 충돌 사본 파일이 생김 |
| **자리 하나 + 넘기기(이 설계)** | 없음(고칠 수 있는 곳이 하나) | 넘길 때 몇 초가 든다. 대신 git 가지가 하나의 원본이라 지금의 변형 · 일괄 반영 · 차이 보기 · 인계가 그대로 붙는다 |

### 2.1 폴더 머리의 「작업실」(main) 과 변형의 「작업실」

- **변형 화면**의 단추: 그 변형을 연다(위 표).
- **폴더 머리**의 단추: 시트가 뜬다 — 「내 작업본으로 일하기」(이 폴더의 내 열린 변형 목록, 없으면 「새 작업본」 = `createVariation`(kind `person`, 지금 라우트) 뒤 위 표) · 「main 을 서버 작업실에서 열기」(편집자 이상, 지금 동작 그대로).
- **main 을 PC 로 받아 고치는 길은 만들지 않는다.** main 은 여럿이 합친 줄이고(웹 편집 · 챔피언 원본 · 일괄 반영), PC 에서의 일은 변형으로 하고 반영한다. 예외는 챔피언의 원본 폴더뿐(그 PC 에서는 「이 PC 의 원본 폴더 열기」가 맨 위에 — §4.3).
- 실행 설정(훅 · MCP · 허용 목록)이 든 남의 폴더는 그 PC 에서 처음 열 때 시스템 창으로 확인(챔피언 설계 §7.4 의 `pro_folder_trust` — 같은 테이블 · 같은 창).

## 4. PC 의 결과를 서버로

### 4.1 언제 · 어떻게

| 때 | 하는 일 |
|---|---|
| **저장 지점(자동)** — 작업 트리가 바뀌고 조용해진 뒤 60초, 앱이 시작한 CLI 의 턴이 끝날 때(`Stop` 훅), 앱이 켜질 때 · 다시 이어질 때 | 있는 그대로 커밋(작성자 = 그 사람, 메시지 「저장 지점」) → `pgpt-agent/seat-<변형8>-<회차>/head` 로 push → 링크로 `seat:pushed {variation, head}` → 서버가 검사 뒤 변형 가지를 앞으로 옮기고 `seat:taken`. 변형 `status` 는 `open` 그대로 |
| **「지금 올리기」** | 같은 바퀴를 바로 |
| **「돌려놓기」 · 「검토 준비됨」 · 인계 직전 · 반영 요청을 받았을 때** | 같은 바퀴 + 자리를 내려놓음(또는 `ready` 표시) |
| 끔 | 변형마다 「자동으로 올리기」 스위치(기본 켬). 꺼도 돌려놓을 때는 반드시 올린다 |

- **main 으로는 가지 않는다.** PC 의 토큰이 올릴 수 있는 것은 자기 회차의 가지 하나뿐이고(지금 `refusals` 의 접두사 규칙 그대로), 서버가 그것을 변형 가지로 옮긴다. main 은 지금의 일괄 반영(`merge.js`)으로만.
- **충돌이 구조상 생기지 않는다.** 자리가 하나이므로 서버의 변형 가지는 PC 가 올린 것 말고는 움직이지 않는다 → 늘 앞으로 옮기기. 앞으로 옮길 수 없으면 규칙이 깨진 것이므로 서버는 거절하고(`seat:refused {why:'diverged'}`) 남은 변경 길(§1.5)로 간다. 변형과 main 사이의 충돌은 지금처럼 일괄 반영 화면에서 푼다. main 의 새 것을 변형으로 가져오기(「main 따라가기」)는 PC 에서 사람이 누를 때만(작업 트리에서 병합 — 겹치면 그 사람의 도구로 푼다).
- **올리기 전 검사**: 데스크톱이 비밀 생김새(`secret-shapes.json`)와 크기를 먼저 보고(걸리면 그 파일은 커밋에서 빼고 「확인이 필요해요」), 서버가 같은 목록으로 다시 본다(챔피언 P0 의 `sources.js inspect` 를 그대로 부름). 서버가 거절하면 변형 가지는 그대로, 회차 가지는 직전 머리로.
- 서버가 받은 뒤: 변형의 `head_commit` 갱신 · 「바뀐 점」 카드(`indexer.changeCard`) · `folders` 이벤트(다른 사람 화면이 새로 고침 없이 바뀜).

### 4.2 엔진은 하나, 바깥은 둘

챔피언의 원본 폴더 동기화(P1)와 이 작업본 올리기는 **같은 바퀴**다: 지켜보기 → 조용해지면 → 검사 → 커밋 → 링크로 한 시간짜리 토큰 → push → 서버가 폴더 잠금 안에서 검사하고 들임 → 상태. 그래서 코드를 둘로 짓지 않는다.

| 층 | 함께 쓰는 것 | 다른 것 |
|---|---|---|
| 데스크톱 | `runner/upload.js`(새 — `sync.js` 에서 꺼냄: 지켜보기 · 쉬었다가 · 토큰 받기 · 올리기 · 상태 · 오프라인 쌓기), `git.js`(토큰 머리글 · `NEUTRAL` · `core.symlinks=false`), `secret-shapes.json` | **원본 폴더**(`sync.js`): 그림자 저장소 — 사람 폴더는 읽기만, 쓰는 git 명령이 없음. **작업본**(`runner/seats.js` 새): 앱 데이터 안의 진짜 작업 트리 — 커밋 · 병합을 그 안에서 |
| 서버 | `gitHttp.js`(한 경로 · 범위별 `check` · `after`), `sources.js inspect`, 폴더 직렬 잠금, 숨긴 가지(`transfer.hideRefs` — 회차 가지도 다른 토큰에 안 보이게) | 원본은 `intoMain`(main 으로, 병합 가능), 작업본은 변형 가지를 앞으로만 |
| 링크 메시지 | `sync:*` 와 같은 꼴(`*:token` · `*:pushed` · `*:taken` · `*:refused`) | 접두사 `seat:` |

### 4.3 한 PC 에 같은 폴더가 둘이 되지 않게

| 경우 | 동작 |
|---|---|
| 이 PC 가 그 폴더의 **원본 PC**(챔피언이 고른 폴더가 여기 있음)이고 폴더 머리의 「작업실」을 누름 | 맨 위가 「이 PC 의 원본 폴더 열기」(Finder · 터미널) — 새로 받지 않는다. 원본 폴더가 곧 main 줄의 작업본이다 |
| 원본 PC 에서 **변형**을 따로 열려 함 | 됨(그것은 main 이 아닌 다른 일). 시트에 「원본 폴더와 다른, 따로 떼어 하는 일이에요」 한 줄 |
| 같은 변형을 한 PC 에서 두 번 | 자리가 변형 id 로 정해져 하나뿐. 「이미 이 PC 에 있어요 — 열기」 |
| 설정 화면 | 「원본 폴더」와 「작업본」을 다른 묶음 · 다른 아이콘으로(§3) |
| 채팅의 프로젝트 변형 · 넘겨받은 일이 같은 PC 에서 돎 | 그 변형의 작업본에서 돈다(§5.3) — `work/…/chat-…` 에 따로 받지 않음 |

## 5. 그 사람의 도구로

### 5.1 열기

| 단추(데스크톱 IPC) | 하는 일 |
|---|---|
| 「폴더 열기」 `seats.reveal(id)` | 파일 관리자에서 작업 트리 |
| 「터미널 열기」 `seats.openTerminal(id)` | 그 운영체제의 터미널을 그 폴더에서(macOS Terminal · Windows Terminal/cmd — 정해진 실행 파일 목록, 서버가 준 글을 실행하지 않음) |
| 「편집기로 열기」 `seats.openEditor(id)` | PATH 에서 찾은 `code` · `cursor` 가운데 사람이 설정에서 고른 것(없으면 단추 없음) |
| 「Claude Code 시작 / Codex 시작」 `seats.start(id, agent)` | 앱이 그 폴더에서 CLI 세션을 띄우고 중계한다(§5.2). 폴더의 `CLAUDE.md` · `.claude/…` · `AGENTS.md` 는 CLI 가 스스로 읽는다 |

페이지는 경로를 주지도 받지도 않는다(id 만). 자기 터미널에서 직접 `claude` · `codex` · `git commit` 을 해도 된다 — 앱이 손대는 것은 「있는 그대로 커밋해서 올리기」뿐이다. 토큰은 저장소 설정에 없으므로(호출마다 환경으로만) 사람이 직접 한 `git push` 는 서버에 닿지 않고, 올리기는 앱의 단추와 저장 지점으로만 간다.

### 5.2 앱이 띄운 세션(중계)

- 중계 종류 `seat`(대상 = 변형 id)를 하나 더한다(`relay.registerKind('seat', …)` — 스펙의 「단계에 묶이지 않은 세션」 그대로): 여는 것은 자리를 가진 그 기기만, 입력은 그 사람만, 보기는 §10 Q4.
- 세션은 작업본마다 남아 다음에 `--resume`(같은 PC). 자리가 다른 곳으로 가면 세션은 그 PC 에 남고 옮기지 않는다(챔피언 설계 §3.2 와 같음).
- 휴대폰에서: 대화 보기 · 묻는 것에 답하기 · 프롬프트 넣기(본인), 「끝내기」. 지금 로컬 실행 카드의 부품을 그대로.

### 5.3 지금 있는 로컬 일도 같은 작업본에서 (흩어짐을 닫는 마지막 조각)

| 일 | 지금 | 바꿈 |
|---|---|---|
| 채팅 · 프로젝트 변형(`kind:'chat'`, `mode:'project'`) | `work/<서버>/chat-<해시>-<폴더8>` 에 따로 받고 실행 가지로 올림 → 서버 `bringIn` 이 변형으로(서버 체크아웃이 있으면 그 안에서 병합) | 그 변형의 자리를 그 PC 로 옮기고(서버 체크아웃은 커밋 뒤 치움) 작업본에서 돈다. 올리기는 저장 지점 바퀴. 서버 에이전트(「기본」)로 보낸 턴은 자리를 서버로 가져온다 — PC 가 켜져 있고 쉬고 있으면 저절로, 아니면 「작업본이 맥북에 있어요 — 내 PC 에이전트로 보내거나 돌려놓으세요」 |
| 넘겨받은 일(챔피언 P3 `kind:'handover'`) | (설계) 변형 작업 트리에서 | 같은 자리 모듈로. 수락 = 받는 사람의 변형 + 자리를 그 PC 로 |
| 프로세스 단계(`kind:'step'`, 인스턴스 라인) | 일회용 폴더 · 실행 가지 | 그대로(작업본이 아님 — §1.1) |
| 채팅 · 내 PC 폴더(`mode:'personal'`, main 으로) | 일 폴더 → main | 그대로(그 폴더는 그 사람 혼자의 「내 PC 에이전트 작업」 폴더) |

### 5.4 지켜보기

앱이 작업 트리를 지켜보며(파일 변화 + 5분마다 `git status`) 링크로 `seat:status {variation, dirty, ahead, branchOk}` 를 보낸다(10초에 한 번까지, 수만 — 파일 이름 · 경로 없음). 화면의 「저장 안 한 변경 N」 「안 올린 저장 지점 N」이 여기서 온다.

## 7. 보안

| 항목 | 결정 |
|---|---|
| 토큰 범위 | 변형 하나 × 기기 하나 × 회차 하나. 올릴 수 있는 것은 `pgpt-agent/seat-<변형8>-<회차>/` 아래뿐(main · 변형 가지 · 태그 · 지우기는 지금처럼 거절). 수명 1시간, 바퀴마다 링크로 새로. git 에는 호출마다 환경의 머리글로만(설정 파일 · 명령줄 · 로그에 없음) |
| 요청마다 다시 봄 | 기기가 끊겼나 · 자리가 그 기기인가 · 회차가 같은가 · 그 사람의 지금 역할. 살아 있는 토큰도 그 순간 멈춘다 |
| 읽기 범위 | 토큰은 그 폴더 저장소를 읽는다(지금 일 토큰과 같음). 다른 기기의 동기화 가지 · 다른 사람의 회차 가지는 숨긴다(`transfer.hideRefs`, 프로토콜 v0 만) |
| 자리 남용 | 자리를 잡는 것은 변형의 보유자뿐(runner 이상). 남의 자리는 「돌려 달라」만. 한 사람이 가진 PC 자리 수에 한도(기본 20), 링크 메시지에 분당 한도. `moving` 은 90초, 「켜지면 준비」는 24시간 뒤 풀림. 자리가 있다고 반영을 영영 막지 못한다 — §10 Q3 |
| 테넌트 격리 | 자리 · 기록 테이블 모두 `tenant_id`, 링크 메시지는 그 링크의 테넌트 · 사람 안에서만 폴더 · 변형을 찾음. 데스크톱의 자리는 서버 주소 · 사람별 |
| 사람의 폴더 | 작업본은 앱 데이터 아래에만. 사람이 고르지 않은 곳에 쓰지 않는다. 서버 · 페이지는 경로를 정하지도 알지도 못한다. 원본 폴더(챔피언)는 이 설계가 건드리지 않는다 |
| 폴더가 싣고 오는 것 | 링크는 평범한 파일로(`core.symlinks=false`), 필터 · 줄 끝 바꾸기 끔(`NEUTRAL`), 훅 경로 없음, 서브모듈 · LFS 주소로 토큰이 가지 않음(주소별 머리글) — 지금 일 폴더와 같은 줄. 남이 만든 폴더의 실행 설정은 그 PC 의 사람이 시스템 창으로 확인한 뒤에만 앱이 CLI 를 띄운다 |
| 페이지의 요청만으로 열리지 않는 것 | 다른 사람 폴더의 첫 실행(실행 설정 확인) · 남은 변경 버리기 · 내보내기 — 시스템 창. 「실행 전에 묻기」를 켠 PC 는 휴대폰에서 시킨 준비 · 시작도 시스템 창으로 묻는다 |
| 바깥 프로그램 | 터미널 · 편집기는 정해진 실행 파일 목록에서만, 인자는 그 작업본의 경로 하나. 서버가 보낸 글은 명령이 되지 않는다(지금 스펙 그대로) |
| 올리기 전 · 받은 뒤 검사 | 데스크톱과 서버가 같은 생김새 목록으로(챔피언 P0). 걸린 값은 화면 · 로그 · 서버로 가지 않는다(파일 이름 · 줄 번호만) |

## 8. 스펙 변경

**새 스펙 `openspec/specs/working-copy/spec.md` — ADDED** (요구사항 제목)

1. 변형의 작업본은 한 번에 한 곳에만 있다(없음 · 서버 작업실 · 기기 하나).
2. 작업본이 어디에 있는지 폴더를 보는 사람 모두에게 보인다(경로 · 기기 id 없이).
3. 자리를 옮길 때는 먼저 올리고 치운 뒤 다음 곳이 받는다 — 저장하지 않은 변경은 있는 그대로 커밋된다.
4. 자리가 아닌 곳의 쓰기 · 올리기는 거절된다(회차가 지난 push 포함).
5. 「작업실」을 누르면 어디서 열지 고른다 — 웹 · 데스크톱 앱 · 휴대폰.
6. 휴대폰에서 내 PC 에 준비를 시키고, 그 PC 의 CLI 를 보고 입력한다.
7. PC 의 결과는 그 변형의 가지로만 올라가고, main 은 일괄 반영으로만 바뀐다.
8. 자리를 잃은 곳에 남은 변경은 새 변형으로 올라온다(버리지도 섞지도 않음).
