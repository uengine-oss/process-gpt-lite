# English mode — handoff from the web UI to the server side

From the English-mode UI work (src/i18n, scripts/i18n-*) to whoever owns the server, agents and
data. Terms: i18n/GLOSSARY.md. This file is generated by `scripts/i18n-handoff.py` from
`i18n/HANDOFF.head.md` (this part) and the extractor's output (the list below).

## Contract (as built in the web app)

- Every `/api` request carries `X-PGL-Lang: en|ko` (a fetch wrapper in `src/i18n/lang.js`, so
  every call site is covered, including the raw `fetch('/api/…')` ones). EventSource cannot send
  headers: `/api/events?token=…&lang=en|ko` carries it as a query parameter instead.
- `PUT /api/me/lang {lang}` is called when the person picks a language (login screen, Settings ›
  Accounts › Language, or `?lang=`), and once when `GET /api/me` says `lang: null` (then the
  browser's language is sent). A non-2xx answer is ignored and retried on the next load.
- `GET /api/me → {…, lang}`: **please keep `lang: null` until the person has chosen** (no column
  default). The page follows a non-null server value set on another device; a default `ko` would
  flip English-browser users to Korean after they sign in.
- Order on the page: `?lang=` > saved setting (localStorage `pgl-lang`, synced with the server) >
  browser language (`ko*` → ko, else en). `<html lang>` follows.

## What the page does with server text

- Korean that arrives is translated on screen by the dictionary (`src/i18n/ko-en.json`): exact
  strings, patterns with `{0}` slots, and built-in rules for Korean dates, relative times, 만/억/원
  amounts, durations and counters. So a Korean card still shows English — but only when the
  dictionary has the sentence. Anything the model writes (answers, titles, summaries) cannot be in
  the dictionary: it has to be written in English at the source.
- A line break inside a server text becomes `<br>` in markdown: the dictionary also holds each
  line of a multi-line entry on its own, but keep the line structure the same in both languages.
- Text stored in the database (messages, notifications, room messages, minutes) is shown as it was
  written. The dictionary covers the fixed Korean ones; English at the source is better because the
  stored row is then English for the tutorial and the videos too.

## Model-written text the screens show (needs English at the source)

Found while checking the screens; most already go through `isEn()` / `langInstruction()` — listed
so nothing is missed:

- project titles (`index.js` "요청을 5~12자 한국어 프로젝트 제목으로"), document titles (`agent.js` "다음 문서의 제목을 8~20자 한국어로")
- browser task title and steps (`browser.js` "Break a web task into 3-6 short Korean steps", `"title": "짧은 작업명"`)
- mail action texts and briefs (`mail.js` "text: Korean, one line …", "brief: 1-3 Korean 해요체 sentences")
- mining flow names / summaries / keywords (`mining/service.js`), folder index abstracts and variation titles (`folders/indexer.js`)
- review "missing" notes on edited files (`review.js`), skill verification cases and verdicts (`folders/skills.js`)
- mission result summaries (`missions.js` RESULT_LINE "결과 한 문장(해요체)")
- floor plan room names (`floorPlan.js` "Room names and uses in Korean")
- the quick answer in `index.js` ("짧게 한국어로 답해")

## Data the screens show in Korean on a shared tenant

The checker (`scripts/i18n-check.mjs`) sets tenant data apart from UI text: teammates' names, role
names, process and step names, skill names and descriptions, file names. On the dev tenant they are
Korean because other accounts made them; the English sample data (seeds with `--lang en`) and the
English cast in GLOSSARY.md cover the tutorial and the videos.

## Embedded editors

- IeumOffice (office host, `ieumoffice-web/host`): the editors have an English UI (the fork's
  `packages/i18n`). The running host sets one language per process — `setUiLang(IEUM_LANG || 'ko')`
  in `host/editors.mjs` — and answers every editor's `app:get-language` from it. The page adds
  `lang=en` to the editor URL in English mode (`src/officeEditor.js`; nothing is added in Korean
  mode). The office-host branch `feat/per-page-ui-lang` (HANDOFF.server.md) answers from that
  parameter per connection; until it is built and the host restarted, the editor's ribbon tabs
  (홈 · 삽입 · 페이지 레이아웃 · 수식 · 데이터 · 검토 · 보기), 자동 저장, dialogs and the status bar
  ("…를 스트리밍하는 중") stay Korean inside the frame. The frame's own header (file name, Linked to
  the conversation, Share, Point, Expand ribbon, Maximize, Full screen) is the app's and is English.
- ArtCraft: VectorCraft gets `?lang=en|ko` from the page. PhotoCraft, FilmCraft and CADCraft follow
  the browser's languages (`navigator.languages`): an English browser gets English. SoundCraft has
  no language switch.
