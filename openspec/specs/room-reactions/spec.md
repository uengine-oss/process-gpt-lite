# 대화방 말풍선 반응

## Purpose
2026-11-26 사용자가 휴대폰의 단체 대화방 화면(제목 「박용주 · gmail.com…」, 「AI 제안 켬」 · 「회의 시작」 · 「+」 단추, 팀원의 회색 말풍선)을 보내며 다음과 같이 요청했다. 「대화방 설정으로 대화방 명칭 바꿀 수 있게하고 다른 사람 말풍선에 좋아요 확인했음 사랑해 웃음 등을 붙힐 수 있게」. 지금까지는 팀원의 메시지에 응답하려면 「확인했어요」 같은 메시지를 따로 보내야 했고, 이 메시지가 기존 대화를 밀어 올렸다.

이 스펙은 팀 메신저의 말풍선에 짧은 반응을 붙이거나 떼는 방법, 반응을 말풍선 아래에 표시하는 방법, 방의 모든 사람에게 실시간으로 전달하는 방법을 정한다. 대화방 이름 변경은 `messenger-dock` 스펙의 「단체방의 이름을 바꾼다」에서 다룬다.

Process GPT의 채팅(`chats` · `chat_rooms`, process-gpt-vue3)에는 반응 기능이 없다. 따라서 Lite는 자체 테이블(`pro_chat_reactions`, `server/sql/062_room_reactions.sql`)에 사람 · 메시지 · 반응 종류의 조합마다 행 하나를 저장한다. 메시지 자체(`chats` 행)는 변경하지 않는다.

## Requirements

### Requirement: 다른 사람의 말풍선에 정해진 반응을 붙이고 뗀다
시스템은 팀원과 에이전트의 메시지 말풍선에서 반응 막대를 열 수 있어야 한다(SHALL). 휴대폰에서는 말풍선을 길게 누르면(약 0.45초) 열린다. 데스크톱에서는 말풍선에 포인터를 올렸을 때 옆에 나타나는 반응 단추를 누르거나, 말풍선을 오른쪽 클릭하면 열린다. 막대는 말풍선 위에 표시되며, 위쪽에 공간이 없으면 아래에 표시된다. 막대는 대화 영역을 벗어나지 않는다.

막대에는 여섯 가지 반응이 다음 순서로 표시된다: 👍 좋아요 · ✅ 확인했음 · ❤️ 사랑해 · 😂 웃음 · 😮 놀람 · 🙏 감사. 앞의 네 가지는 사용자가 요청한 반응이고, 뒤의 두 가지는 회사 대화에서 자주 쓰는 반응을 추가한 것이다. 이 밖의 반응은 허용하지 않는다(MUST NOT). 하나를 누르면 내 반응이 붙고 막대가 닫힌다. 이미 붙인 반응을 다시 누르면 제거된다. 한 사람은 한 메시지에 여러 종류의 반응을 붙일 수 있지만, 같은 종류는 한 번만 붙일 수 있다. 텍스트가 있는 메시지에는 막대 아래에 「복사」가 표시된다. 휴대폰에서 길게 누르면 글자를 선택하는 대신 막대가 열리기 때문이다. 막대 밖을 누르거나, Esc를 누르거나, 대화를 스크롤하면 막대가 닫힌다.

내 메시지에는 반응 막대가 열리지 않는다(사용자의 말 「다른 사람 말풍선에」). 내 말풍선을 오른쪽 클릭하면 브라우저의 기본 메뉴가 열린다. 시스템 줄(초대 · 이름 바꾸기)과 회의 카드에도 반응을 붙일 수 없다. 서버(`POST /api/team/messages/:id/reactions`, `{key, on?}`)에도 같은 규칙을 적용한다. 내 메시지 · 시스템 줄 · 회의 카드에 대한 요청이나 정해지지 않은 반응 종류는 400으로 거절한다. 방의 구성원이 아니거나, 다른 회사의 메시지이거나, 존재하지 않는 메시지이면 404로 거절한다. `on`을 생략하면 현재 반응 상태를 반대로 바꾸고, `true` · `false`이면 지정한 상태로 맞춘다. 한 사람이 같은 반응을 동시에 여러 번 눌러도 행은 하나만 남는다.

#### Scenario: 데스크톱에서 포인터를 올려 👍를 붙인다
- **WHEN** 정하윤이 1280px 화면의 「견적 회의」 방에서 김서연의 「견적서 초안 올렸어요. 확인 부탁해요.」 말풍선에 포인터를 올리고, 옆에 나타난 반응 단추를 누른 뒤 👍 좋아요를 누른다
- **THEN** 막대가 닫히고, 말풍선 아래에 내 반응으로 표시된 「👍 1」 칩이 생긴다

#### Scenario: 오른쪽 클릭으로 반응을 하나 더 붙인다
- **WHEN** 같은 말풍선을 오른쪽 클릭한다
- **THEN** 포인터 위치에 막대가 열리고, 👍는 이미 선택된 상태로 보인다
- **AND** ✅ 확인했음을 누르면 칩이 「👍 1」 · 「✅ 1」 순서로 표시된다

#### Scenario: 휴대폰에서 길게 누른다
- **WHEN** 박도윤이 390px 휴대폰 화면에서 김서연의 말풍선을 길게 누른다
- **THEN** 말풍선에 테두리가 생기고, 화면 안에 여섯 가지 반응이 담긴 막대와 「복사」가 표시된다
- **AND** ❤️ 사랑해를 누르면 「❤️ 1」 칩이 생긴다

#### Scenario: 내 말풍선
- **WHEN** 정하윤이 자기 메시지 「네, 오후에 볼게요.」에 포인터를 올리거나 오른쪽 클릭한다
- **THEN** 반응 단추와 막대가 나타나지 않는다
- **AND** 서버에 직접 반응을 추가하려 해도 400으로 거절된다

### Requirement: 말풍선 아래의 칩은 반응의 종류 · 수 · 반응한 사람을 보여 준다
시스템은 반응이 있는 말풍선 아래에 종류별로 칩 하나를 정해진 순서로 표시해야 한다(SHALL). 칩에는 이모지와 반응한 사람 수가 표시되고, 내가 반응한 칩에는 파란 테두리가 표시된다. 다른 사람의 말풍선에서 칩을 누르면 내 반응이 추가되거나 제거된다. 마지막 사람의 반응이 제거되면 칩이 사라진다. 반응한 사람은 휴대폰에서는 칩을 길게 누르면, 데스크톱에서는 칩에 포인터를 잠시 올리면 확인할 수 있다. 「👍 좋아요」 아래에 반응을 붙인 순서대로 「정하윤, 박도윤」처럼 이름이 표시된다. 이름은 모든 화면에서 사용하는 해당 사용자의 이름과 같다. 내 말풍선의 칩을 누르면 반응은 바뀌지 않고 반응한 사람이 표시된다. 칩을 누르면 화면은 서버의 응답을 기다리지 않고 즉시 바뀐다. 서버가 요청을 거절하면 원래 상태로 돌아가고 이유가 표시된다.

#### Scenario: 칩을 다시 누르면 반응이 제거된다
- **WHEN** 정하윤과 박도윤이 👍를 붙인 말풍선에서 정하윤이 「👍 2」 칩을 누른다
- **THEN** 칩이 「👍 1」로 바뀌고, 정하윤이 반응했다는 표시가 사라진다

#### Scenario: 내 말풍선에서 반응한 사람을 확인한다
- **WHEN** 김서연이 1280px 화면에서 자기 메시지의 「👍 2」 칩에 포인터를 올린다
- **THEN** 「👍 좋아요 · 정하윤, 박도윤」이 칩 위에 표시된다
- **AND** 그 칩을 눌러도 수는 「👍 2」 그대로다

#### Scenario: 휴대폰에서 칩을 길게 누른다
- **WHEN** 390px 화면에서 「❤️ 2」 칩을 길게 누른다
- **THEN** 「❤️ 사랑해 · 박도윤, 정하윤」이 화면 안에 표시되고, 칩의 수는 바뀌지 않는다

### Requirement: 반응은 방의 모든 사람에게 즉시 보인다
시스템은 반응이 추가되거나 제거될 때마다 해당 메시지의 칩을 메시지와 같은 실시간 통로(`team` 이벤트 `reactions`)로 방의 모든 사람에게 즉시 전송해야 한다(SHALL). 반응을 누른 사람이 열어 둔 다른 화면에도 전송한다. 칩의 「내 것」 표시는 받는 사람에 따라 달라진다. 대화를 다시 열면 메시지 목록과 함께 각 메시지의 반응을 받는다. 반응이 없는 메시지에는 빈 목록이 전달된다. 메시지가 수정되어 다시 전달되더라도(에이전트의 답에 파일이 붙는 경우 등) 이미 표시된 반응은 사라지지 않는다.

#### Scenario: 열어 둔 화면에 즉시 표시된다
- **WHEN** 김서연이 「견적 회의」 방을 열어 둔 상태에서 정하윤이 김서연의 메시지에 👍를 붙인다
- **THEN** 김서연의 화면에 새로 고침 없이 「👍 1」 칩이 생기고, 해당 칩은 김서연의 반응으로 표시되지 않는다

### Requirement: 반응은 알림을 만들지 않는다
시스템은 반응으로 인해 알림 행, Home 카드, 종 알림, 휴대폰 푸시, 읽지 않은 수, 메신저 토스트를 생성하면 안 된다(MUST NOT). 반응은 메시지가 아니며, 단체방에서 반응마다 알림이 오면 대화에 방해가 되기 때문이다. Process GPT에도 반응 알림이 없다. 대화방 목록의 미리보기와 순서도 바뀌지 않는다.

#### Scenario: 반응을 받은 사람의 Home
- **WHEN** 정하윤과 박도윤이 김서연의 메시지에 👍 · ✅를 붙였다 뗀다
- **THEN** 김서연의 알림 목록 · Home · 읽지 않은 수는 그대로다

### Requirement: 반응 행은 해당 방의 구성원만 읽을 수 있다
시스템은 반응 행(`pro_chat_reactions`)에 RLS를 활성화해야 한다(SHALL). 화면 키(`authenticated`)로는 같은 회사(`tenant_id = public.tenant_id()`)에 속하면서 해당 방의 구성원(`public.pro_room_is_member`)인 경우에만 읽을 수 있다. 쓰기 정책은 두지 않는다. 반응의 추가와 제거는 서버에서만 처리한다. `anon`에는 아무 권한도 부여하지 않는다. 방이나 메시지가 삭제되면 반응도 함께 삭제된다.

#### Scenario: 방에 속하지 않은 팀원
- **WHEN** 같은 회사의 최도현이 자신이 속하지 않은 방의 반응을 화면 키로 읽으려 한다
- **THEN** 행이 하나도 보이지 않는다
- **AND** 해당 방의 구성원이라도 다른 회사로 요청하면 행이 보이지 않으며, 누구도 화면 키로 반응 행을 쓸 수 없다

### Requirement: 휴대폰 · 낮과 밤 · 영어 화면
시스템은 390px 휴대폰의 낮 · 밤 테마에서 반응 막대 · 칩 · 반응한 사람 정보가 화면 안에 들어오고 가로로 넘치지 않도록 표시해야 한다(SHALL). 이모지는 선명하게 표시한다. 영어 화면에서는 막대의 반응 이름이 Like · Got it · Love · Haha · Wow · Thanks로, 「복사」가 Copy로, 칩의 읽기 이름이 「Like · 2」처럼 바뀐다.

#### Scenario: 밤 테마 휴대폰
- **WHEN** 밤 테마의 390px 화면에서 말풍선과 칩을 차례로 길게 누른다
- **THEN** 반응 막대와 반응한 사람 정보가 어두운 배경에서도 잘 읽히고, 화면 밖으로 나가지 않는다
