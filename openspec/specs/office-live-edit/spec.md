# 열린 문서를 채팅으로 고치기

## Purpose
이 스펙은 채팅 옆에 열린 이음오피스 문서를 문서에서 선택한 부분과 채팅에 입력한 요청을 바탕으로 수정할 때의 동작을 정한다. 근거는 2026-11-25 운영 녹화다. 사용자는 회의록_템플릿.docx의 표 안 글씨를 선택하고 「글씨가 표의 윗부분에 붙어있다. 중앙정렬」이라고 보냈다. 에이전트는 「세로 정렬을 중앙으로 맞췄습니다」라고 답했지만 문서는 그대로였다. 해당 요청은 「새 주제」로 이동했고, 이후 요청을 처리하는 중에는 「연결 안 됨」이 표시됐다. 편집기 안의 「AI 수정 요청」은 화면에 보이지 않는 편집기 자체 AI로 전달되어 채팅에 아무것도 남지 않았다.

시험: `e2e/tests/feature/office-ask.spec.js`(F-OA-01~08, 실제 이음오피스 편집기), `server/test/officeAsk.test.js`. 화면: `e2e/results/`.

## Requirements

### Requirement: 문서에서 선택한 부분이 채팅 입력창에 칩으로 표시된다
시스템은 사용자가 채팅과 연결된 워드 문서에서 글이나 표 칸을 선택하면, 해당 위치와 선택한 글을 채팅 입력창에 즉시 칩으로 보여 주어야 한다(SHALL). 칩에는 선택한 위치(표 번호와 행·열, 또는 문단)와 글이 표시된다. 선택한 부분이 바뀌면 칩도 바뀌고, 선택을 해제하면 칩이 사라진다. 칩의 ✕를 누르면 칩이 사라지고, 같은 선택에는 다시 나타나지 않는다. 다른 곳을 선택하면 다시 나타난다. 휴대폰에서는 문서 위 다이얼을 열면 같은 칩이 보인다. 칩은 밝은 테마와 밤 테마에서 모두 읽을 수 있다.

#### Scenario: 표 칸을 선택한다
- **WHEN** 회의록의 표에서 「대표, 개발팀, 운영팀, 영업팀」을 선택한다
- **THEN** 입력창 위에 「@표 1 · 3행 2열 "대표, 개발팀, 운영팀, 영업팀"」 칩이 나타난다

#### Scenario: 다른 칸을 선택하고, 선택을 해제하고, ✕를 누른다
- **WHEN** 「3층 소회의실」을 선택한다
- **THEN** 칩이 「@표 1 · 2행 2열 "3층 소회의실"」로 바뀐다
- **AND** 칸을 한 번 눌러 선택을 해제하면 칩이 사라진다
- **AND** 다시 선택한 뒤 ✕를 누르면 칩이 사라지고, 같은 선택에는 다시 나타나지 않는다

#### Scenario: 휴대폰
- **WHEN** 390×844 화면에서 표 칸을 선택하고 문서 위 다이얼을 연다
- **THEN** 밝은 테마와 밤 테마 모두에서 다이얼의 입력창 위에 같은 칩이 화면을 벗어나지 않고 표시된다

### Requirement: 편집기 안의 「AI 수정 요청」은 Lite에서 보이지 않는다
시스템은 Lite 채팅과 연결된 편집기에서 글을 선택해도 편집기 자체의 「AI 수정 요청」 단추를 보여 주지 않아야 한다(SHALL). 수정 요청은 채팅으로 보낸다. 편집기를 Lite 밖에서 따로 열면 해당 단추는 그대로 표시된다.

#### Scenario: Lite 안과 밖
- **WHEN** Lite에서 연 문서의 표 칸을 선택한다
- **THEN** 「AI 수정 요청」이 보이지 않는다
- **AND** 같은 문서를 편집기만 따로 열어 선택하면 「AI 수정 요청」이 보인다

### Requirement: 선택한 부분과 함께 보낸 요청은 열린 문서의 해당 위치만 바로 수정한다
시스템은 입력창에 칩이 있는 상태에서 보낸 메시지를 채팅에 표시할 때, 메시지 앞에 칩을 붙여 보여 주어야 한다(SHALL). 에이전트에는 요청, 선택한 글, 해당 위치(문서 안의 블록, 표 칸 범위), 열린 문서가 함께 전달되어야 한다. 에이전트는 이음오피스의 실시간 편집 도구(MCP)로 해당 위치만 수정하고, 수정한 내용은 열린 편집기에 바로 표시된다. 메시지를 보내면 입력창의 칩은 사라진다. 수정 후 검수는 편집기가 확인한 변경 사항을 근거로 한다. 글이 바뀌지 않는 서식 변경을 「반영되지 않음」으로 판정하지 않는다.

#### Scenario: 표 칸의 글씨를 세로 가운데로 정렬한다
- **WHEN** 「대표, 개발팀, 운영팀, 영업팀」을 선택하고 「글씨가 표의 윗부분에 붙어 있어요. 세로 가운데로 맞춰 주세요」를 보낸다
- **THEN** 채팅에 「@표 1 · 3행 2열 "대표, 개발팀, 운영팀, 영업팀" 글씨가 표의 윗부분에 …」가 표시되고 입력창의 칩은 사라진다
- **AND** 열린 편집기에서 해당 칸의 글씨가 세로 가운데로 이동하고, 옆의 「참석자」 칸은 그대로 유지된다
- **AND** 에이전트의 답변 뒤에 표시되는 검수 결과에 「편집기 확인」이 보이고 ⚠는 없다

#### Scenario: 「@ 가리키기」로 가리킨 표
- **WHEN** 「@ 가리키기」를 켜고 표를 누른 뒤 메시지를 보낸다
- **THEN** 입력창에 「@표 1 …」 칩이 나타나고, 보낸 메시지 앞에 붙으며, 에이전트는 사용자가 가리킨 표를 식별한다

### Requirement: 열린 문서에 대한 요청은 해당 문서의 대화에 남는다
시스템은 편집할 수 있는 문서가 열려 있는 동안 메인 채팅에서 보낸 메시지를 해당 문서의 카드가 있는 대화로 보내야 한다(SHALL). 맥락 라우터는 그 메시지를 새 주제로 옮기지 않는다. 카드가 어느 대화에도 없으면, 해당 문서에 대한 첫 메시지가 전달된 대화가 그 문서의 대화가 된다. 사용자가 직접 선택한 대화를 보고 있으면 그 대화를 우선한다.

#### Scenario: 카드가 있는 대화로 보낸다
- **WHEN** 「회의록 템플릿」 대화의 카드로 문서를 열고, 라우터가 모든 요청을 새 주제로 보내는 환경에서 수정 요청을 보낸다
- **THEN** 답변은 「회의록 템플릿」 대화에 이어서 표시되며 「새 주제」로 표시되지 않는다

#### Scenario: 대화가 없는 카드
- **WHEN** 어느 대화에도 없는 카드의 문서에 대해 첫 요청을 보내고, 이어서 다른 칸을 선택해 두 번째 요청을 보낸다
- **THEN** 두 번째 요청은 라우터를 거치지 않고 첫 요청이 전달된 대화로 전달된다

### Requirement: 적용되지 않은 편집을 완료했다고 하지 않는다
시스템은 편집기가 「바뀐 곳 없음」이나 오류를 반환한 편집을 적용된 것으로 처리하지 않아야 한다(SHALL). 해당 편집이 적용되지 않았다는 사실은 도구 오류로 에이전트에 전달된다. 한 번의 요청에서 에이전트가 수행한 편집이 모두 적용되지 않았다면, 채팅 답변에는 에이전트의 「맞췄어요」 대신 「요청한 수정이 '<파일>' 문서에 반영되지 않았어요」와 편집기가 알린 이유를 그대로 보여 준다.

#### Scenario: 잘못된 위치에 적용하려 한 편집
- **WHEN** 에이전트가 표가 아닌 블록에 표 칸 서식을 적용하고 「세로 가운데로 맞췄어요」라고 답한다
- **THEN** 채팅에는 「요청한 수정이 '회의록_템플릿.docx' 문서에 반영되지 않았어요. 편집기가 바뀐 곳이 없다고 알려 왔어요 (…)」가 표시되고 「맞췄어요」는 표시되지 않는다
- **AND** 문서의 해당 칸은 그대로 유지된다

### Requirement: 대화와의 연결이 끊겨도 자동으로 다시 연결된다
시스템은 한 번 연결됐던 문서와 대화의 연결이 서버 재시작·배포 또는 네트워크 문제로 끊기면, 문서가 열려 있는 동안 자동으로 다시 연결해야 한다(SHALL). 다시 연결하는 동안 머리줄에 「다시 연결하는 중…」을 보여 준다. 빨간색 「연결 안 됨 · 다시 연결」은 처음부터 연결하지 못했거나 서버가 연결을 거절했을 때만 표시된다. 연결이 끊긴 동안 진행 중이던 요청의 편집은 그대로 적용된다.

#### Scenario: 요청 도중 서버가 20초 동안 응답하지 않는다
- **WHEN** 수정 요청을 보낸 직후 서버가 20초 동안 응답하지 않다가 다시 응답한다
- **THEN** 그동안 머리줄에 「다시 연결하는 중…」이 표시되고 「연결 안 됨」은 한 번도 표시되지 않는다
- **AND** 서버가 다시 응답하면 사용자가 누르지 않아도 「대화와 연결됨」으로 돌아오고, 해당 칸의 글씨는 세로 가운데로 정렬된다
