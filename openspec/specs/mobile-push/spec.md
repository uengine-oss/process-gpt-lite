# 휴대폰 알림: AI의 질문과 대화방 메시지

## Purpose
2026-11-26 사용자가 안드로이드 알림 창 화면을 보내며 다음과 같이 물었다. 화면에는 카카오톡의 대화방별 묶음 알림(「이상부, 정석진 전무, 김병곤 · 김병곤: …」, 숫자 2), Gemini의 「보고서 준비 완료」, 「Claude의 질문이 있습니다 · Claude: 정리 대상 (+1 more)」가 떠 있었다. 「퀵하게 대화방에서 온 내용 혹은 ai의 후먼인더루프 등을 모바일에서 보게할 수 있나?」

Lite는 이미 Home 카드에 표시되는 알림을 웹 푸시로 휴대폰에 보내고 있었다(`server/lib/webpush.js` · `public/sw.js` · Home의 「브라우저 알림 켜기」). 하지만 AI가 사람의 답을 기다릴 때는 알림을 보내지 않았고, 대화방 메시지는 메시지마다 알림이 따로 떴으며, 알림에서 바로 할 수 있는 동작은 없었다.

이 스펙은 다음 다섯 가지를 정한다. AI가 사람의 응답을 기다릴 때 휴대폰에 알리는 방법, 알림 버튼으로 바로 답하는 방법, 버튼에 사용하는 일회용 서명 토큰, 대화방 메시지를 방마다 하나로 묶는 방법, 알림을 켜고 시험하는 화면과 iPhone 안내다. 알림은 Home 카드와 같은 경로로 전달된다. process-gpt의 `notifications` 테이블에 행이 생성되면 Home이 그 행을 카드로 보여 주고, 알림 피드(`server/lib/notify.js` feedOnce)가 해당 사용자의 기기로 푸시를 보낸다.

## Requirements

### Requirement: AI가 사람의 답을 기다리면 휴대폰에 알린다
시스템은 AI가 사람의 답 없이는 더 진행하지 못하고 멈출 때, 해당 사용자에게 `notifications` 행(type `ai_ask`)을 하나 생성해야 한다(SHALL). 이 행은 Home 카드로 표시되고, 알림 피드는 해당 사용자의 각 기기에 푸시를 보낸다. Lite가 닫혀 있어도 알림이 온다. 대상은 다음과 같다.

- 채팅 · 프로젝트의 에이전트가 사람에게 질문하고 멈춘 경우(deepagents의 `human_input_required`). 질문과 선택지는 응답 메시지에 `ask`로 함께 저장된다.
- 브라우저 작업이 사람의 응답이나 조치를 기다리는 모든 경우: 선택지 중 하나를 고르는 질문, 승인(결제 · 첨부하지 않은 파일 업로드), 보관함 카드(로그인 · 카드 · 인증 코드), 로그인 요구 · 로봇 확인 · 멈춘 화면처럼 사람이 직접 처리해야 하는 화면.

알림 제목은 대기 유형에 따라 「Process GPT 의 질문이 있어요」 · 「승인이 필요해요」 · 「로그인이 필요해요」 · 「직접 확인해 주셔야 해요」 중 하나이며, 본문은 짧게 요약한 질문이다. Home 카드의 라벨은 「질문」 · 「승인」 · 「로그인」 · 「확인」이다. 「답하러 가기」를 누르면 질문이 있는 곳(메인 채팅에서 질문이 나온 대화, 해당 프로젝트, 해당 루틴의 화면)이 열린다. 카드를 여는 것만으로는 답한 것으로 처리하지 않는다. 카드는 답할 때까지 남는다.

진행 상황 한 줄, 중간 메모, 작업 완료는 이 알림으로 보내지 않는다(MUST NOT). 사람이 지켜보지 않는 작업(프로세스 단계에서 실행된 브라우저 작업)도 알리지 않는다. 카드 하나가 응답을 기다리는 동안에는 알림 행이 하나만 생성된다.

대기가 끝나면 해당 알림 행은 확인 상태로 바뀌고, Home 카드도 사라져야 한다(SHALL). 대기가 끝나는 경우는 카드에서 답했을 때, 채팅에 답을 입력했을 때, 알림 버튼으로 답했을 때, 작업을 취소하거나 직접 제어로 전환했을 때, 서버가 다시 시작되어 브라우저 작업이 종료됐을 때다. Home은 목록을 만들 때마다 카드가 아직 응답을 기다리는지 확인하고, 더 이상 기다리지 않는 행은 확인 처리한다.

#### Scenario: 채팅 에이전트가 정리 형식을 묻는다
- **GIVEN** 정하윤이 프로젝트 방에 「이번 주 회의록 정리해 줘」를 보냈다
- **WHEN** 에이전트가 「어떤 형식으로 정리할까요?」라고 묻고 선택지 「세 줄 요약」 · 「표로 정리」를 제시한 뒤 멈춘다
- **THEN** 채팅에는 질문과 두 선택지가 보이고, 응답 메시지에 질문과 선택지가 저장된다
- **AND** 정하윤에게 `ai_ask` 알림 행이 하나 생성된다. 제목은 「Process GPT 의 질문이 있어요」, 본문은 「어떤 형식으로 정리할까요?」이다
- **AND** Home에 「질문」 라벨이 붙은 카드가 생성되고, 「답하러 가기」를 누르면 해당 프로젝트가 열린다

#### Scenario: 브라우저 작업이 결제 승인을 기다린다
- **WHEN** 브라우저 작업이 장바구니의 49,000원 결제를 앞두고 승인 카드를 띄운다
- **THEN** 알림 제목은 「승인이 필요해요」, 본문은 결제 내용이다
- **AND** 카드에서 「승인」이나 「취소」를 누르면 알림 행이 확인 처리되고 Home 카드도 사라진다

#### Scenario: 채팅에 직접 답한다
- **GIVEN** 에이전트의 질문 알림이 Home과 휴대폰에 떠 있다
- **WHEN** 정하윤이 해당 대화에 「표로 정리해 줘」라고 입력한다
- **THEN** 해당 대화의 질문 알림이 즉시 확인 처리되고 Home 카드가 사라진다

### Requirement: 알림 버튼으로 바로 답한다
시스템은 응답을 기다리는 카드의 알림에 다음 규칙에 따라 버튼을 표시해야 한다(SHALL). Android에서는 웹 알림 버튼이 최대 두 개까지 보이므로 버튼은 두 개를 넘지 않는다.

- 선택지가 하나 또는 둘이고 모두 24자 이하인 질문에는 선택지를 버튼으로 표시한다. 누르면 앱을 열지 않고 바로 답한다.
- 승인(결제 · 파일 업로드)에는 「열기」와 거절 선택지(「취소」)만 표시한다. 승인은 화면을 확인한 뒤 카드에서만 한다(MUST). 휴대폰 잠금 화면에서는 누구나 알림 버튼을 누를 수 있기 때문이다. 거절은 어디서 해도 안전하다.
- 그 밖의 경우(선택지가 셋 이상이거나 긴 경우, 로그인 · 보관함 · 직접 처리해야 하는 화면)에는 「열기」만 표시한다.

채팅 질문의 선택지 버튼을 누르면, 해당 선택지가 그 대화에 정하윤의 메시지로 한 번 전송되고 에이전트가 이어서 답해야 한다(SHALL). 채팅의 빠른 답변 버튼을 누른 것과 같다. 브라우저 작업의 선택지 버튼을 누르면 해당 카드에 그 선택지로 답한 것으로 처리되고 작업이 이어진다. 답변이 수락되면 알림 자리에 「「세 줄 요약」으로 답했어요」가 잠깐(4초) 보였다가 사라진다. 이미 답했거나, 더 이상 응답을 기다리지 않거나, 너무 오래된 알림이면 답변을 전송하지 않고 질문이 있던 곳을 연다. 그 대화에서 에이전트가 다른 답을 쓰고 있는 중이면 답을 보내지 않고 질문이 있던 곳을 열며, 알림 행과 Home 카드는 그대로 남는다. 알림 본문을 누르면 질문이 있는 곳이 열리고, 휴대폰에서는 Home 탭을 닫고 해당 채팅을 보여 준다.

알림 안에서 글을 입력해 답하는 기능(인라인 답장)은 구현하지 않는다. 웹 알림에는 브라우저가 안정적으로 지원하는 인라인 입력란이 없기 때문이다. 대화방 알림의 「답장」을 누르면 해당 방이 열리고 입력창에 커서가 놓인다.

#### Scenario: 「세 줄 요약」 버튼으로 답한다
- **GIVEN** 휴대폰 알림에 「Process GPT 의 질문이 있어요 · 어떤 형식으로 정리할까요?」와 「세 줄 요약」 · 「표로 정리」 버튼이 떠 있다
- **WHEN** 정하윤이 앱을 열지 않고 「세 줄 요약」을 누른다
- **THEN** 해당 대화에 정하윤의 메시지 「세 줄 요약」이 한 번 전송되고, 에이전트가 이어서 답한다
- **AND** 알림 자리에 「「세 줄 요약」으로 답했어요」가 잠깐 보이고, Home 카드는 사라진다

#### Scenario: 이미 답한 질문의 알림을 다시 누른다
- **GIVEN** 같은 질문의 알림이 다른 기기에도 떠 있었고, 한 기기에서 이미 답했다
- **WHEN** 다른 기기의 알림에서 「표로 정리」를 누른다
- **THEN** 두 번째 답변은 전송되지 않고, 앱이 해당 채팅을 연다

#### Scenario: 결제 승인 알림
- **WHEN** 결제 승인을 기다리는 알림이 온다
- **THEN** 버튼은 「열기」와 「취소」뿐이다
- **AND** 「취소」를 누르면 결제하지 않고 작업을 이어 간다. 승인은 카드에서만 할 수 있다

### Requirement: 버튼의 답변은 일회용 서명 토큰으로만 받는다
푸시에는 로그인 토큰을 넣지 않는다(MUST NOT). 대신 서버는 알림마다 해당 알림 전용 토큰을 생성해 넣어야 한다(SHALL). 토큰은 사용자 · 알림 행 · 카드 · 선택 가능한 선택지에 연결되며 24시간 동안 유효하다. 서명은 서버의 비밀 키에서 정해진 이름으로 추출한 키로 만든 HMAC-SHA256이며, 서버의 비밀 키 자체는 서버 밖으로 나가지 않는다.

알림 버튼은 로그인 없이 `POST /api/push/act`(`{token, answer}`)를 호출한다. 서버는 다음을 차례로 확인한다. 서명, 만료 여부, 회사, 선택지 번호, 알림 행이 해당 사용자의 것인지, 카드가 알림 행에 연결된 카드인지, 대화가 해당 사용자의 것인지. 모두 일치하면 알림 행을 미확인 상태에서 확인 상태로 한 번만 바꾸고, 카드가 아직 응답을 기다리는지 확인한 뒤 답변을 처리한다. 같은 토큰을 다시 사용하거나 다른 기기에서 같은 알림을 누르면 알림 행이 이미 확인 상태이므로 답변을 처리하지 않는다(MUST NOT). 거절 응답은 다음과 같다. 위조된 토큰이나 다른 서버 · 다른 회사의 토큰은 401, 다른 사람의 토큰이나 다른 카드는 403, 이미 사용한 토큰이나 더 이상 응답을 기다리지 않는 카드는 409, 만료된 토큰은 410, 토큰에 없는 선택지는 400이다.

#### Scenario: 같은 토큰을 두 번 사용한다
- **WHEN** 「세 줄 요약」으로 답한 알림의 토큰으로 다시 「표로 정리」를 보낸다
- **THEN** 409로 거절되고, 대화에는 아무것도 추가되지 않는다

#### Scenario: 다른 사람의 토큰
- **WHEN** 박도윤에게 발급된 토큰으로 정하윤의 질문 알림에 답하려 한다
- **THEN** 403으로 거절되고 정하윤의 알림 행은 대기 상태로 유지된다

#### Scenario: 위조와 만료
- **WHEN** 토큰의 선택지를 「승인」으로 바꾸거나 서명을 바꿔서 보낸다
- **THEN** 401로 거절된다
- **AND** 25시간 전에 발급된 토큰은 410으로 거절된다

### Requirement: 대화방 메시지는 방마다 알림 하나로 묶는다
시스템은 팀원이 1:1 방이나 단체방에 보낸 메시지를 방마다 알림 하나로 보여 주어야 한다(SHALL). 같은 방의 알림에는 같은 태그(`pgl-room-<방>`)를 사용한다. 새 메시지가 오면 이전 알림을 교체하고 다시 울린다. 제목은 「<방 이름> · <읽지 않은 수>」이다. 1:1 방에는 이름이 없으므로 보낸 사람의 이름을 사용하고, 이름을 정하지 않은 단체방에는 나를 뺀 사람들의 이름(「박도윤, 김민수」)을 사용한다. 읽지 않은 메시지가 하나뿐이면 수를 붙이지 않는다. 본문에는 마지막 두 줄을 「보낸 사람: 말」로 보여 준다. 버튼은 「답장」이며, 누르면 해당 방이 열리고 입력창에 바로 글을 쓸 수 있다. 앱이 설정 화면에 있었다면 설정 화면에서 나와 해당 방을 연다. 해당 기기에서 방을 읽으면 그 방의 알림이 사라진다.

내가 보낸 메시지는 알리지 않는다(MUST NOT). 나를 언급한 메시지는 방 알림과 별도의 알림으로 보내며, 항상 알린다. 현재 화면에 열려 있는 방의 메시지는 알리지 않는다. 서비스 워커는 현재 표시 중인 Lite 화면에 해당 방이나 대화를 보고 있는지 묻는다. 메신저에 해당 방이 열려 있으면 그 방의 메시지를 알리지 않고, 화면 가운데 열린 대화가 해당 대화이면 AI 질문을 알리지 않는다. 휴대폰의 Home 탭이 채팅을 가리고 있거나 설정 화면이 열려 있으면 보고 있지 않은 것으로 처리한다.

Lite의 메신저에서 보낸 메시지에 대해 process-gpt의 채팅 트리거가 생성한 알림 행에는 회사(tenant)가 비어 있어, 지금까지 Home과 휴대폰에 알림이 오지 않았다. 알림 피드는 최근 10분 안에 생성된 대화방 알림 행 중 회사가 비어 있는 행에 해당 방의 회사를 채운다.

#### Scenario: 김서연이 1:1 방에 세 번 보낸다
- **WHEN** 김서연이 정하윤과의 1:1 방에 「회의 자료 올렸어요」 · 「견적서도 같이 봐 주세요」 · 「오늘 안에 부탁해요」를 보낸다
- **THEN** 정하윤의 휴대폰에는 해당 방의 알림 하나만 남는다. 제목은 「김서연 · 3」, 본문은 「김서연: 견적서도 같이 봐 주세요」와 「김서연: 오늘 안에 부탁해요」 두 줄이며, 버튼은 「답장」이다

#### Scenario: 「답장」으로 해당 방에 바로 쓴다
- **WHEN** 정하윤이 해당 알림의 「답장」을 누른다
- **THEN** 해당 방이 열리고 입력창에 커서가 놓여, 바로 「지금 볼게요」를 입력할 수 있다
- **AND** 방을 읽으면 해당 기기에 떠 있던 그 방의 알림이 사라진다

#### Scenario: 열어 둔 방과 멘션
- **GIVEN** 정하윤이 김서연과의 방을 메신저에 열어 두고 화면을 보고 있다
- **WHEN** 해당 방에 새 메시지가 온다
- **THEN** 휴대폰 알림이 뜨지 않는다
- **AND** 다른 방의 메시지와 해당 방에서 정하윤을 언급한 메시지는 알림이 뜬다

### Requirement: 알림을 켜고 몇 초 안에 시험한다
시스템은 Home과 설정 › 계정 › 연결에서 이 기기의 알림 상태를 보여 주어야 한다(SHALL).

- 브라우저가 아직 알림 권한을 묻지 않은 상태이면 Home에 「브라우저 알림 켜기 · 앱을 닫아도 팀 메시지 · AI 질문 · 내 할 일을 알려 드려요」 카드와 「알림 켜기」 버튼을 보여 준다. 알림 권한은 사용자가 버튼을 눌렀을 때만 묻는다.
- Home에서 알림을 켜면 카드가 「알림이 켜져 있어요」와 「시험 알림 보내기」로 바뀌고, 닫을 때까지 남는다.
- 설정에는 「메일 · 연결 안 됨」 항목처럼 「이 기기의 알림 · 켜짐 / 꺼짐 / 차단됨」 항목이 항상 표시되고, 알림이 켜져 있으면 「시험 알림 보내기」가 표시된다.
- 「시험 알림 보내기」를 누르면 서버(`POST /api/push/test`)가 내 기기마다 「시험 알림이에요」를 하나씩 보내고, 카드에 전송한 기기 수를 보여 준다. 이 브라우저가 푸시를 받을 수 없으면(데스크톱 앱, 구독 실패) 해당 화면에 알림을 직접 띄우고 그 사실도 안내한다.

iPhone · iPad의 Safari 탭(홈 화면 앱이 아닌 경우)에서는 알림 켜기 버튼 대신 「iPhone에서 알림 받기 · iOS 16.4 이상에서 Safari 공유 › 「홈 화면에 추가」로 설치한 앱을 열고 알림을 켜 주세요. Safari 탭에서는 알림을 받을 수 없어요.」를 보여 주어야 한다(SHALL). 이 안내를 닫으면 해당 기기에서는 다시 표시하지 않는다. 그 밖의 내용은 약속하지 않는다.

#### Scenario: 휴대폰에서 알림을 켜고 시험한다
- **GIVEN** 390px 휴대폰의 Home(밝은 테마 · 어두운 테마)에 「브라우저 알림 켜기」 카드가 있고, 화면은 가로로 넘치지 않는다
- **WHEN** 「알림 켜기」를 누르고 브라우저의 알림 권한 요청을 허용한다
- **THEN** 카드가 「알림이 켜져 있어요」로 바뀐다
- **AND** 「시험 알림 보내기」를 누르면 몇 초 안에 휴대폰에 「시험 알림이에요」가 오고, 카드에 「보냈어요 · 기기 1대」가 보인다

#### Scenario: iPhone의 Safari 탭
- **WHEN** iPhone의 Safari 탭에서 Lite의 Home을 연다
- **THEN** 알림 켜기 버튼 없이 「iPhone에서 알림 받기」 안내가 보인다. 안내에는 iOS 16.4 이상과 「홈 화면에 추가」로 설치한 앱에서만 알림을 받을 수 있다는 내용이 있다
- **AND** ✕를 누르면 안내가 닫히고, 다시 열어도 표시되지 않는다
