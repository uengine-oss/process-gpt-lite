# 프로세스 단계를 담당자 컴퓨터의 CLI 에이전트로 돌리고, 사람들이 기기와 사람을 넘나들며 함께 일한다

## Purpose
이 스펙의 핵심은 **사람과 기기를 넘나드는 협업**이다. 어떤 단계가 한 사람의 컴퓨터에서 그 사람의 CLI 에이전트(Claude Code · Codex)로 돌고 있으면, 그 인스턴스의 참여자는 웹이나 휴대폰에서 **그 CLI 의 터미널을 그대로** 실시간으로 본다. 참여자는 그 실행에 프롬프트를 제안할 수 있고, 제안은 그 터미널의 입력란에 추천으로 쌓인다. 그것을 실제로 CLI 에 입력하는 사람은 **그 CLI 를 가진 사람(작업자)뿐**이다. 작업자는 제안을 골라 고쳐서 넣거나 버리고, 자기 터미널에 직접 칠 수도 있다(사용자 규칙, 2026-11-24: 「여러 사람이 참여하고 있는 인스턴스에 내가 하고 있는 cliclient 작업에 타인이 의견을 넣을 수 있다(프롬프트). 해당 의견이 해당 ssh 터미널의 입력란에 추천으로 쌓인다. 그것을 입력버튼으로 실제 입력시키는 당사자는 해당 cli를 가진 사람만이 할 수 있다.」). 끝난 결과는 인스턴스의 작업 폴더로 이어지고, 다음 담당자의 컴퓨터가 그것을 받아 시작한다. 로컬 실행에서 생긴 노하우(실행 중의 입력, 에이전트가 적은 기억, 스킬의 수정)는 서버로 모이고, 사람이 고르면 회사의 활동 정의와 스킬에 들어간다.

실행과 보기의 주 화면은 **터미널**이다. 단계는 작업자 컴퓨터에서 그 사람 자신의 대화형 CLI(`claude` · `codex`)로 PTY 안에서 돈다. 그래서 그 사람이 자기 터미널에서 열었을 때와 똑같이 동작한다: 그 사람의 로그인 · 설정 · 슬래시 명령 · 같은 화면(사용자 결정, 2026-11-24: 「cliagent 실행은 기존에 만들어뒀던 ssh 터미널 기능을 이용한다. agent share 의 것.」). 터미널의 바이트는 데스크톱의 링크로 서버에 가고, 서버가 그 화면을 모든 보는 사람에게 agent-share 의 프로토콜로 내준다. PTY 를 만들 수 없는 곳에서만 헤드리스(`claude -p` · `codex exec`)로 돈다. 같은 세션은 실행 카드에서 두 가지로 본다: 「터미널」(그 화면을 Lite 의 색 · 글꼴 · 카드 틀로)과 「대화」(그 CLI 가 스스로 남기는 기록 — Claude Code 의 세션 jsonl, Codex 의 rollout — 을 Lite 의 부품으로: 프롬프트와 누가 넣었는지, 에이전트의 말, 도구 호출, CLI 가 묻는 것)(사용자 질문, 2026-11-24: 「ssh 터미널이지만, 보기 모드에 따라 원하는 경우는 우리 디자인에 맞춰서 스타일링이 가능할까?」). 턴이 끝나면 단계는 바로 끝나지 않고 사람들의 제안과 작업자의 입력을 기다린다.

그 바탕은 다음과 같다. Lite 데스크톱 앱은 사람마다 자기 컴퓨터의 CLI 에이전트를 그 사람의 구독으로 쓰게 한다. 서버에서 여러 사람이 계정 하나로 Claude Code 를 돌리지 않고, 서버에 부하도 쌓지 않는다. 회사 프로세스 지도의 활동마다 쓸 에이전트를 정하고, 그 단계가 담당자에게 오면 담당자의 켜져 있는 데스크톱 앱이 돌린다. 로컬 실행도 서버의 스킬과 프로세스 지도를 그대로 쓴다. 설계는 `docs/local-agents/design.md` 에 있다. 단계가 아니어도, 채팅에서 메시지마다 「기본」 대신 내 PC 의 Claude Code · Codex 를 골라 보낼 수 있다(「채팅에서 고르는 에이전트」 — 같은 데스크톱 · 같은 터미널 중계 · 같은 실행 카드).

## Requirements

### Requirement: 참여자는 다른 사람의 CLI 를 그 터미널 그대로 보고 프롬프트를 제안하며, 입력은 그 CLI 를 가진 사람만 한다
인스턴스의 참여자(인스턴스를 볼 수 있는 사람)는 다른 사람의 컴퓨터에서 도는 실행을 웹 · 휴대폰에서 그 CLI 의 터미널 그대로(작업자의 화면과 같은 바이트) 실시간으로 볼 수 있어야 한다(SHALL). 작업자가 아닌 사람의 터미널은 읽기 전용이다(커서 · 키 없음). 서버는 작업자가 아닌 사람이 보낸 입력을 버린다. 참여자는 누구나 그 실행에 프롬프트를 제안할 수 있다. 제안은 CLI 로 가지 않고, 그 터미널 아래 입력란 위에 누가 언제 올렸는지와 함께 칩으로 쌓인다(작업자의 데스크톱 앱 · 웹 · 휴대폰 모두에서). 제안은 의견이거나, 역할을 가진 사람이 CLI 가 보인 선택지에 대해 고른 결정(고른 항목과 함께)일 수 있다 — 둘 다 같은 자리에 쌓인다. 작업자가 칩을 누르면 그 글이 입력란에 들어오고, 고쳐서 보내면 사람이 붙여 넣는 것처럼(붙여 넣기 후 Enter) 그 CLI 에 들어간다. 그 입력에는 「<제안한 사람> 제안 · <작업자> 입력」이 남는다. 작업자는 제안을 버릴 수 있다. 제안의 상태는 입력 기다림 · 입력함(고쳤으면 「고쳐서 입력함」) · 버림이다. 제안이 오면 작업자의 데스크톱에 시스템 알림이 뜨고 Home 에 그 인스턴스의 카드가 생긴다. 제안이 입력되면 제안한 사람에게 알림이 간다. 작업자가 아닌 사람의 입력(`POST …/steer`)과 제안 버리기는 403 이다. 인스턴스를 볼 수 없는 사람의 제안 · 터미널 열기는 403 이다. 메인 채팅에는 아무것도 더하지 않는다.

#### Scenario: 휴대폰으로 같은 터미널을 본다
- **WHEN** 윤태호의 PC 가 「견적서 작성」을 그의 Claude Code 로 돌리는 중에, 같은 인스턴스의 참여자 서하린이 휴대폰(390px)으로 그 인스턴스를 연다
- **THEN** 서하린의 화면에 「Claude Code · 윤태호 · 윤태호의 맥」과 그 CLI 의 터미널이 보이고, 새로 고침 없이 회사 스킬(「보이는 스킬: 견적-규칙」)과 도구 줄(`Write(산출물/01_견적서 작성/견적서.md)`)이 늘어난다
- **AND** 서하린의 터미널과 윤태호의 화면의 터미널은 같은 글을 보인다(윤태호 데스크톱의 터미널 바이트 그대로)
- **AND** 서하린의 터미널은 읽기 전용이다(커서 · 키 없음), 화면은 옆으로 넘치지 않는다

#### Scenario: 제안이 입력란에 쌓인다
- **WHEN** 서하린이 휴대폰에서 「WRITE_OUT 하린.md :: 서하린의 제안 — 할인 줄을 따로」와 「목차를 맨 앞에」를 제안한다
- **THEN** 서하린의 화면에 그 제안이 「입력 기다림」으로 보이고, CLI 에는 아무것도 들어가지 않는다
- **AND** 윤태호의 화면에서 터미널 입력란 위에 「서하린 · 방금」 칩 두 개가 쌓이고, 윤태호의 Home 에 「서하린의 제안 · 견적서 작성」 카드가, 윤태호의 데스크톱에 알림이 뜬다

#### Scenario: CLI 를 가진 사람이 골라 고쳐 입력한다
- **WHEN** 윤태호가 「목차를 맨 앞에」를 버리고, 첫 칩을 눌러 입력란에 넣고, 「…할인 줄을 따로(윤태호가 고침)」으로 고쳐 보낸다
- **THEN** 그 글이 붙여 넣기로 윤태호의 CLI 에 들어가(가짜 CLI 의 입력 기록에 고친 글), 같은 턴에서 `하린.md` 를 쓰는 것이 두 사람의 터미널에 보인다
- **AND** 입력 목록에 「서하린 제안 · 윤태호 입력」과 「반영 — 실행을 멈추지 않고」가 보이고, 서하린의 제안은 「윤태호가 고쳐서 입력함」, 버린 것은 「버림」이 된다
- **AND** 서하린에게 「제안이 입력됐어요 · 견적서 작성」 알림이 「윤태호가 고쳐서 입력했어요: …」와 함께 간다(이름의 받침에 맞는 조사 — 「서하린이」, 「윤태호가」)

#### Scenario: 다른 사람은 입력하지 못한다
- **WHEN** 서하린이 입력하려 한다
- **THEN** 서하린의 화면에는 보내기 입력이 없고 「입력은 윤태호님만 해요 — 제안하면 윤태호님의 입력란에 쌓여요」가 보인다
- **AND** 서하린이 `POST /api/local-agents/jobs/:id/steer` 를 직접 부르면 403, 터미널에 보낸 입력은 서버가 버려 CLI 에 닿지 않는다
- **AND** 인스턴스 밖의 도외부는 제안도 터미널 열기도 403 이다

#### Scenario: 역할을 가진 사람의 결정도 제안으로 쌓인다
- **WHEN** 참여자가 CLI 가 보인 선택지에서 「2. 부가세 포함」을 결정으로 제안한다
- **THEN** 작업자의 입력란에 「<이름> 결정 · 2. 부가세 포함」 칩이 쌓이고, 그것을 넣는 것도 작업자만 한다(다른 사람은 403)

#### Scenario: 결과가 다음 담당자에게 이어진다
- **WHEN** 윤태호의 실행이 끝나고 다음 단계 「견적 검토」가 서하린에게 온다
- **THEN** 서하린의 PC 가 인스턴스 라인을 먼저 받아, 윤태호의 결과와 서하린이 제안해 윤태호가 입력한 파일을 읽고 시작한다

### Requirement: 단계는 작업자 자신의 대화형 CLI 로, 작업자의 컴퓨터 터미널에서 돈다
담당자 컴퓨터의 단계는 그 사람의 대화형 CLI(`claude` · `codex`)를 PTY 안에서 띄워 돌려야 한다(SHALL). 그 사람이 자기 터미널에서 열었을 때와 같게: 그 사람의 로그인과 설정을 쓰고(설정 소스를 줄이지 않는다), 계정을 바꾸는 명령(`/login` · `/logout`)은 끈다. 작업 폴더의 파일 고치기는 묻지 않는다(Claude Code `--permission-mode acceptEdits`). 앱은 자기가 만든 작업 폴더만 그 CLI 에서 신뢰한 폴더로 둔다(Claude Code: 그 CLI 의 설정 `projects[<폴더>].hasTrustDialogAccepted` — 사람이 신뢰 창에서 「예」를 고른 것과 같다. Codex: 그 세션의 명령줄 설정으로만). 첫 프롬프트는 CLI 가 입력을 받을 수 있다고 알린 뒤 사람이 붙여 넣듯 넣는다(Claude Code: 그 세션의 `SessionStart` 훅. Codex: 명령줄의 첫 메시지로, 프롬프트 파일을 가리킨다). 턴이 끝난 것은 화면의 글로 짐작하지 않고 CLI 가 남기는 것으로 안다(Claude Code: 그 세션의 `--settings` 로 넣은 `Stop` 훅과 세션 기록 jsonl, Codex: rollout 의 `task_complete`). 턴이 끝나면 단계는 인스턴스의 사람들을 기다리고(「턴이 끝나면 사람들을 기다리고, 끝내는 것은 그 CLI 를 가진 사람이다」), 끝나면 커밋 · 올리기를 한다. 작업자는 자기 터미널에 직접 칠 수 있다. CLI 가 사람을 기다리면(권한 확인 등, `PermissionRequest` · `Notification` 훅) 작업자의 데스크톱에 알림이 뜬다. 앱이 실행 중에 다시 켜지면 서버가 그 일을 CLI 의 세션과 함께 다시 보내고, 데스크톱은 남은 작업 폴더에서 같은 세션을 이어서(`claude --resume` · `codex resume`) 끝낸다. PTY 를 만들 수 없는 곳(터미널 모듈이 없는 빌드)에서만 헤드리스로 돈다.

#### Scenario: 내 터미널과 똑같이
- **WHEN** 회사 스킬 「인사말-규칙」을 지정한 단계가 이 맥의 실제 Claude Code 2.1.330 으로 돈다
- **THEN** 데스크톱은 `claude --session-id <id> --settings <세션 설정> --permission-mode acceptEdits` 를 터미널에서 띄우고, `SessionStart` 훅이 온 뒤 프롬프트를 붙여 넣는다
- **AND** 실행 중에 보낸 입력이 같은 턴에 들어가고(`UserPromptSubmit`), `Stop` 훅 뒤에 기다림이 지나면 단계가 끝나며, 결과 파일이 스킬의 규칙대로다(실측 `e2e/results/smoke-tty-2026-11-24.json`, 16.2초 — 그때의 기다림은 3초)

#### Scenario: 터미널에 직접 친다
- **WHEN** 작업자가 자기 실행의 터미널에 「WRITE_OUT 터미널.md :: …」를 치고 Enter 를 누른다
- **THEN** 그 글이 작업자의 CLI 에 들어가 그 파일이 결과에 남는다
- **AND** 같은 때 다른 참여자가 그 터미널에 친 글은 서버가 버려 CLI 에 닿지 않는다

#### Scenario: 앱이 다시 켜지면 같은 세션을 이어서
- **WHEN** 실행 중에 작업자의 데스크톱 앱이 꺼졌다가 다시 켜진다
- **THEN** 같은 일이 그 데스크톱으로 다시 오고, 데스크톱은 작업 폴더를 되돌리지 않은 채 `claude --resume <같은 세션>` 으로 이어서 끝낸다
- **AND** 꺼지기 전에 쓴 파일이 결과에 있다

#### Scenario: 터미널을 만들 수 없는 곳
- **WHEN** 데스크톱 앱이 터미널 모듈(node-pty)을 불러오지 못한다
- **THEN** 그 데스크톱은 단계를 헤드리스(`claude -p --input-format stream-json …` · `codex exec --json`)로 돌리고, 실행 카드는 터미널 대신 CLI 의 마지막 줄들을 보인다

### Requirement: 로컬 실행도 서버의 스킬과 프로세스 지도를 쓴다
담당자 컴퓨터의 실행은 그 활동에 서버 에이전트가 받았을 스킬(활동의 일 정의가 지정한 스킬, 활동이 부르는 에이전트의 스킬)과 담당자 자신의 비공개 스킬을 받아야 한다(SHALL). 스킬은 서버의 스킬 폴더(main)에서 실행마다 최신으로 받아, 그 CLI 가 스스로 읽는 자리에 둔다: Claude Code 는 작업 폴더의 `.claude/skills/<이름>/`, Codex 는 `.pgl-skills/<이름>/` 와 그것을 가리키는 `AGENTS.md`. 스킬 폴더는 읽기만 하는 토큰으로 받고(올리기는 거절), 다른 사람의 비공개 스킬은 받지 않는다. 받은 스킬은 일의 결과(커밋)에 들어가지 않는다. 프롬프트에는 그 활동의 일 정의 · 점검 항목 · 내놓는 것 · 작업 폴더의 메일과 앞 단계 결과 · 받은 스킬이 들어간다.

#### Scenario: 회사 스킬대로 만든다
- **WHEN** 활동 「인사말 쓰기」가 회사 스킬 「인사말-규칙」(「안녕하세요, 달빛상사입니다.」로 시작, 끝 줄에 「— 달빛상사 인사 규칙 v1」)을 지정하고, 그 단계가 담당자의 Claude Code 로 돈다
- **THEN** 실행 카드에 「스킬 1개를 받았어요: 인사말-규칙」이 보이고, Claude Code 가 그 스킬을 불러 쓴다
- **AND** 결과 파일이 그 규칙대로 시작하고 끝 줄에 「— 달빛상사 인사 규칙 v1」이 있다(실측: 터미널 `e2e/results/smoke-tty-2026-11-24.json`, 헤드리스 `smoke-skill-2026-11-24.json`)

#### Scenario: 스킬은 늘 최신, 결과에는 들어가지 않는다
- **WHEN** 스킬 폴더의 main 이 바뀐 뒤 다음 단계가 돈다
- **THEN** 그 실행은 바뀐 스킬을 받고, 일의 결과 파일 목록에는 `.claude` · `.pgl-skills` · `AGENTS.md` 가 없다

### Requirement: 로컬 실행에서 생긴 노하우는 서버로 모이고, 사람이 고르면 활동과 스킬에 들어간다
단계가 끝나면 데스크톱은 그 실행이 배운 것을 서버로 보내야 한다(SHALL): 실행 중의 입력(누가 제안했고 누가 넣었는지 · 어떻게 반영됐고 그 뒤에 실행이 한 일), 에이전트가 스스로 적은 기억(`CLAUDE.md` · `AGENTS.md`), 받은 스킬을 고친 것. 서버는 입력과 기억 하나하나를 판정 모델(스킬의 판정 프롬프트, 첫 글자 확률)로 「앞으로 이 활동에서 지킬 일의 방식」인지 「이번 건에만」인지 읽어, 방식일 수 있는 것만 후보로 둔다(판정할 수 없으면 「판정 못 함 — 사람이 정해요」로 둔다). 스킬을 고친 것은 그 스킬의 후보가 된다. 아무것도 저절로 반영하지 않는다. 후보는 인스턴스의 실행 카드와 건의 주인(없으면 작업자) · 프로세스 담당자의 Home 카드에 「배운 것 N개」로 보이고, 출처 「<사람>의 로컬 실행에서 배움 (<날짜>)」와 제안한 사람 · 넣은 사람(「<제안한 사람> 제안 · <작업자> 입력」)을 지닌다. 활동의 노하우는 프로세스 담당자나 관리자가 「이 일에 반영」하면 그 활동의 정의(회사 프로세스 지도의 일 정의, 지도에 없는 단계는 프로세스 정의의 활동)의 「배운 것」에 출처와 함께 들어가, 다음 실행(로컬이든 서버든)이 읽는다. 스킬의 수정은 작업자나 관리자가 「스킬에 반영 요청」하면 그 스킬 폴더의 변형과 반영 요청이 되고, 스킬의 작성자나 관리자가 기존 흐름대로 반영한다.

#### Scenario: 제안에서 온 입력이 활동의 노하우가 된다
- **WHEN** 서하린이 제안하고 윤태호가 고쳐 넣은 입력이 반영되고 실행이 끝난다
- **THEN** 실행 카드에 「실행 중 조종 → 이 일의 방식」 후보가 「서하린 제안 · 윤태호 입력」, 「윤태호의 로컬 실행에서 배움 (2026-11-24)」과 함께 보이고, 윤태호(프로세스 담당자)의 Home 에 「배운 것 N개 · 견적서 작성」 카드가 생긴다
- **AND** 서하린의 화면에는 반영 단추가 없고, 서하린이 반영하려 하면 403 이다
- **AND** 윤태호가 「이 일에 반영」을 누르면 「견적서 작성」의 정의 끝 「## 배운 것」에 그 글과 출처가 들어가고, 후보는 「이 일의 정의에 반영함」이 된다
- **AND** 「견적서 작성」의 다음 실행은 그 줄을 정의에서 읽는다

#### Scenario: 이번 건에만 해당하는 말은 후보가 아니다
- **WHEN** 실행 중 입력이 「이번만 3월 5일로」이고 판정이 「이번 건에만」으로 읽는다
- **THEN** 그 입력은 후보로 올라오지 않는다

#### Scenario: 에이전트가 고친 스킬은 스킬의 반영 요청으로
- **WHEN** 로컬 Claude Code 가 받은 스킬 「견적-규칙」의 `SKILL.md` 에 한 줄을 더하고 끝난다
- **THEN** 「스킬 「견적-규칙」 고침」 후보가 생기고, 작업자가 「스킬에 반영 요청」하면 그 스킬 폴더의 변형과 반영 요청이 만들어진다(스킬 원본은 반영 전까지 그대로)

### Requirement: 활동마다 쓸 에이전트와 꺼져 있을 때 할 일을 정한다
회사 프로세스 지도의 일 정의는 그 일을 할 에이전트를 지녀야 한다(SHALL). 서버 에이전트(업무 에이전트 · deepagents · Claude Code(서버)) 가운데 하나이거나, 담당자 컴퓨터의 CLI 에이전트(Claude Code · Codex · OpenHands) 가운데 하나다. 담당자 컴퓨터의 에이전트를 고르면 함께 정한다.
- 하는 만큼: 초안만(담당자가 확인하고 냄), 또는 끝까지(결과로 단계를 끝냄).
- 담당자의 데스크톱이 꺼져 있으면: 「서버에 맡기기」(맡길 서버 에이전트), 또는 「켜질 때까지 기다리기」(그리고 기다릴 시간 — 비우면 계속 기다림, 지나면 서버 에이전트에게).

관리자만 바꾼다. 담당자 컴퓨터의 에이전트는 회사의 어느 데스크톱이 그 CLI 가 있다고 알렸을 때만 고를 수 있다. 활동의 에이전트로 고르는 서버 에이전트는 업무 에이전트이고, deepagents · Claude Code(서버)는 꺼져 있을 때 맡길 곳으로만 고른다. 담당자 컴퓨터의 에이전트를 고르며 사람의 단계가 「초안만」이 됐다면, 업무 에이전트로 되돌릴 때 원래(사람의 단계)로 돌아간다. 바꾼 설정은 그 뒤에 열리는 단계부터 쓴다. 끝난 일(실패 · 취소 · 서버에 맡김 · 끝남)의 단계를 다시 시도하면 지금의 설정으로 새로 배정하고, 단계는 언제나 관문(사람 기다림 · 초안 먼저)을 먼저 지난다.

#### Scenario: 활동에 Claude Code 를 정한다
- **WHEN** 관리자가 지도의 「견적서 작성」 일에서 에이전트를 「Claude Code — 담당자의 컴퓨터」로, 꺼져 있으면 「켜질 때까지 기다리기 — 120분」으로 정하고 저장한다
- **THEN** 그 일의 정의에 그 설정이 남고, 일 패널에 「Claude Code · 담당자의 컴퓨터 · 초안만 · 꺼져 있으면 켜질 때까지 기다리기 (120분 뒤 업무 에이전트)」가 보인다
- **AND** 다음에 열리는 「견적서 작성」 단계는 담당자의 데스크톱으로 간다

#### Scenario: 아무 데스크톱도 알리지 않은 CLI
- **WHEN** 회사의 어떤 데스크톱도 Codex 가 있다고 알리지 않았다
- **THEN** 에이전트 목록의 Codex 는 「아직 알린 데스크톱이 없어요」로 보이고 고를 수 없다

### Requirement: 데스크톱 앱은 로그인한 사람의 기기로 서버와 잇는다
데스크톱 앱 안에서 사람이 로그인하면, 앱은 그 사람의 이 컴퓨터용 기기 토큰을 받아 서버와 나가는 연결 하나를 열어야 한다(SHALL). 이 컴퓨터에는 포트를 열지 않는다. 토큰은 페이지가 서버에서 받아 앱에 넘기고, 앱은 페이지의 저장소를 읽지 않는다. 앱은 이 컴퓨터에 어떤 CLI 가 있는지, 그 버전과 로그인 여부, 단계를 터미널로 돌릴 수 있는지를 알린다(계정 이름은 알리지 않는다). 토큰은 한 사람의 한 기기만 대신하고, 설정에서 끊으면 그 연결이 바로 닫히고 다시 쓸 수 없다. 로그아웃하면 그 컴퓨터의 토큰을 끊는다. 이 컴퓨터를 스스로 끊은 사람은 다음 로그인 때 저절로 다시 잇지 않는다. 터미널의 바이트 · CLI 의 훅 이벤트 · 지켜보는 파일도 이 연결 하나로만 서버에 간다(CLI 가 서버 주소를 직접 부르지 않는다).

#### Scenario: 로그인하면 저절로 잇는다
- **WHEN** 김견적이 데스크톱 앱에서 로그인한다
- **THEN** 설정 › 계정 › 「내 컴퓨터의 에이전트」에 「이 컴퓨터 · 연결됨」과 Claude Code · Codex 의 버전 · 로그인 여부가 보인다
- **AND** 페이지의 저장소에는 기기 토큰이 없다

#### Scenario: 연결을 끊는다
- **WHEN** 김견적이 「연결한 데스크톱」에서 이 컴퓨터를 「연결 해제」한다
- **THEN** 그 컴퓨터의 연결이 닫히고, 그 토큰으로는 다시 잇지 못한다

### Requirement: 단계는 담당자 자신의 데스크톱으로만 간다
담당자 컴퓨터의 에이전트를 정한 단계가 열리면 시스템은 그 단계의 담당자(단계에 배정된 사람 — 에이전트가 아닌 첫 사람, 없으면 건의 주인)의 데스크톱으로만 보내야 한다(SHALL). 그 CLI 가 있고, 로컬 실행이 켜져 있고, 자리가 있는(기본 동시 2개) 데스크톱이다. 다른 사람의 데스크톱으로는 보내지 않고, 데스크톱이 다른 사람의 일에 대해 보낸 말(터미널 열기 포함)은 받지 않는다.

#### Scenario: 켜져 있으면 바로
- **WHEN** 김견적의 데스크톱이 켜져 있고 김견적에게 「견적서 작성」 단계가 온다
- **THEN** 그 단계가 김견적의 데스크톱의 터미널에서 돈다(이검토의 데스크톱으로는 가지 않는다)
- **AND** 김견적의 데스크톱 앱에 「로컬 에이전트 실행 중 · Claude Code」가 보인다

### Requirement: 데스크톱이 꺼져 있으면 활동 설정대로 맡기거나 기다린다
담당자의 데스크톱이 꺼져 있거나, 그 CLI 가 없거나, 로컬 실행이 꺼져 있으면 시스템은 활동 설정대로 해야 한다(SHALL). 「서버에 맡기기」면 바로 서버 에이전트가 맡는다. 「켜질 때까지 기다리기」면 단계가 기다리고, 인스턴스 화면에 「PC 앱이 켜지면 시작」과 기다리는 까닭(정한 시간이 있으면 그 시각)이 보인다. 데스크톱 앱이 켜지면 기다리던 일을 오래된 것부터, 동시 한도 안에서 돌린다. 기다릴 시간이 지나면 서버 에이전트가 맡는다. 작업자와 그 일을 고칠 수 있는 사람은 기다리는 단계를 「기다리지 않고 서버 에이전트에게 맡기기」로 바로 넘길 수 있다. 담당자가 「실행 전에 묻기」에서 「이번에는 하지 않기」를 고르면 서버 에이전트가 맡는다.

#### Scenario: 기다리다가 켜지면 돈다
- **WHEN** 이검토의 데스크톱이 꺼져 있을 때 「발송 준비」(켜질 때까지 기다리기) 단계가 이검토에게 온다
- **THEN** 인스턴스 화면에 「PC 앱이 켜지면 시작 — 담당자의 데스크톱이 꺼져 있어 기다리는 중이에요」가 보인다
- **AND** 이검토가 데스크톱 앱을 켜면 그 단계가 이검토의 컴퓨터에서 돌아 끝난다

#### Scenario: 서버에 맡긴다
- **WHEN** 이검토의 데스크톱이 꺼져 있을 때 「보관」(서버에 맡기기) 단계가 온다
- **THEN** 그 단계는 바로 업무 에이전트가 맡고, 인스턴스 화면에 「담당자의 데스크톱이 꺼져 있어 업무 에이전트에게 맡겼어요」가 보인다

#### Scenario: 기다릴 시간이 지났다
- **WHEN** 10분 기다리기로 정한 단계가 10분이 지나도록 데스크톱이 켜지지 않는다
- **THEN** 서버 에이전트가 맡고, 「10분을 기다려도 데스크톱이 켜지지 않아 … 맡겼어요」가 보인다

#### Scenario: 휴대폰에서 바로 서버에 맡긴다
- **WHEN** 김견적이 휴대폰으로 기다리는 단계를 보고 「기다리지 않고 업무 에이전트에게 맡기기」를 누른다
- **THEN** 그 단계는 업무 에이전트가 맡고 카드가 「서버에 맡김 · 기다리지 않고 업무 에이전트에게 맡겼어요」로 바뀐다

### Requirement: 내 컴퓨터의 작업 폴더는 앞 사람의 결과를 받고, 내 결과는 서버로 이어진다
담당자의 데스크톱은 단계를 돌리기 전에 인스턴스의 작업 폴더를 서버에서 받아, 앞 단계들의 결과(인스턴스 라인)에서 시작해야 한다(SHALL). 기다리는 동안 라인이 움직였으면 CLI 를 띄우기 직전에 다시 받는다. 폴더 토큰은 그 기기의 그 일에만 쓰이고(공개 주소의 데스크톱 전용 git 경로는 이 토큰만 받는다 — 그 기기가 끊기지 않았고 그 일이 그 기기의 것일 때, 올리기는 그 일이 도는 동안 그 일의 가지로만), 요청 머리글로만 보내며, 컴퓨터의 폴더 설정 · 명령줄 · CLI 의 환경 · 터미널 · 로그에 남지 않는다. 작업 폴더가 스스로 지닌 파일(`AGENTS.md` · `CLAUDE.md` · `.claude/…`)은 지우거나 덮어쓰지 않는다. 같은 폴더의 다음 일은 앞 일을 서버가 받아들이고 폴더가 라인을 따라간 뒤에 시작한다. 단계가 끝나면 데스크톱은 바뀐 것을 담당자 이름으로 커밋해 자기 가지로 올리고, 서버는 그 가지를 폴더의 변경안으로 두고 인스턴스 라인에 넣는다. 단계는 결과로 끝나거나(끝까지), 담당자가 확인할 초안으로 남는다(초안만). 결과는 산출 폴더(`산출물/NN_<단계>/`)에 `결과.md`(한 일 · 실행 중에 바꾼 방향 · 요약)와 함께 남는다. 끝난 실행의 마지막 화면(마지막 턴이 끝났을 때의 화면 — CLI 가 닫히며 지운 화면이 아니다)과 그 실행의 대화는 그 일에 남아, 서버가 다시 켜진 뒤에도 보는 사람이 볼 수 있다. 결과의 변경안(작업 폴더의 변형)은 휴대폰(390px)에서도 제목이 한 덩어리로 보이고 바뀐 파일 목록과 차이를 볼 수 있다.

#### Scenario: 끊은 기기와 클러스터의 토큰은 공개 git 경로에서 막힌다
- **WHEN** 공개 주소의 `/api/local-git/<폴더>.git` 에 토큰 없이, 클러스터 안 일꾼의 폴더 토큰으로, 끊은 기기의 일 토큰으로 묻는다
- **THEN** 각각 401 · 403 · 403 이고, 링크된 기기의 그 일 토큰만 읽을 수 있다

#### Scenario: 작업 폴더 자신의 AGENTS.md 는 그대로
- **WHEN** 작업 폴더가 `AGENTS.md` · `CLAUDE.md` · `.claude/settings.json` · `.claude/skills/견적-규칙/` 을 지니고, 회사 스킬 「견적-규칙」을 받는 Codex · Claude Code 단계가 돈다
- **THEN** 그 파일들은 결과 가지에서도 그대로이고, Codex 의 스킬 안내는 프롬프트로 가며, 같은 자리의 스킬은 폴더의 것을 쓴다

#### Scenario: 끝난 실행의 마지막 화면과 대화
- **WHEN** 윤태호의 실행이 끝나 Claude Code 가 닫히며 화면을 지우고 「Resume this session with …」를 남긴 뒤, 그 실행이 서버의 메모리에서도 빠진다
- **THEN** 실행 카드의 「터미널」은 「끝난 화면이에요 — 마지막 턴이 끝났을 때의 화면」과 함께 마지막 답(「견적서를 만들었어요」)이 있는 화면을 보이고, 「Resume this session」은 없다
- **AND** 「대화」는 그 실행의 대화(「고침 · 견적서.md」, 「서하린 제안 · 윤태호 입력」, 마지막 말)를 보인다

#### Scenario: 휴대폰에서 결과의 변경안을 본다
- **WHEN** 윤태호가 휴대폰(390px)으로 그 실행의 「작업 폴더의 변경안」(`/folders/<폴더>/v/<변형>`)을 연다
- **THEN** 제목은 글자마다 줄을 바꾸지 않고 한 덩어리로 보이고, 그 아래 단추들, 「main 과 비교해 바뀐 파일」 목록, 고른 파일의 차이(그 상자 안에서만 옆으로 움직임)가 차례로 보이며, 화면은 옆으로 넘치지 않는다
- **AND** 그 폴더(`/folders/<폴더>`)와 폴더 목록(`/folders`)도 옆으로 넘치지 않는다

#### Scenario: 두 사람이 이어서 한다
- **WHEN** 김견적의 데스크톱이 「견적서 작성」을 끝내 `산출물/01_견적서 작성/견적서.md` 를 올리고, 이어서 「견적 검토」가 이검토에게 온다
- **THEN** 이검토의 데스크톱은 그 파일을 받은 폴더에서 시작하고, 이검토의 결과(`산출물/02_견적 검토/…`)가 같은 인스턴스 라인에 더해진다
- **AND** 두 데스크톱의 폴더 설정 어디에도 폴더 토큰이 없다

### Requirement: 실행 중에 작업자가 방향을 바꾼다
작업자(그 CLI 를 가진 사람)가 실행 중에 쓴 글 — 실행 카드의 입력란(직접 쓴 것, 또는 고른 제안), 인스턴스 대화 — 은 그 실행에 대한 입력으로 그 데스크톱의 CLI 에 전해져야 한다(SHALL). 데스크톱은 그 글을 터미널에 사람이 붙여 넣듯(붙여 넣기 후 Enter) 넣는다. Claude Code 와 Codex 모두 실행을 멈추지 않고 같은 세션에서 받는다. CLI 가 아직 입력을 받을 수 없으면 첫 프롬프트 뒤에 차례로 넣는다. 데스크톱이 잠시 끊겨 있으면 다시 이어질 때 전한다. 입력마다 상태가 보인다: 보내는 중 → 데스크톱에 보냄 → 데스크톱이 받음 → 반영(CLI 의 기록에 그 글이 들어감), 또는 「못 함 — 까닭」(결과를 올리는 중이었음, 반영 전에 실행이 끝남 등). 작업자가 아닌 사람의 입력은 403 이다.

#### Scenario: Claude Code 를 멈추지 않고 조종한다
- **WHEN** 이검토의 데스크톱에서 Claude Code 가 「견적 검토」를 하는 중에 이검토가 인스턴스 화면에 「WRITE_OUT 조종.md :: 부가세 포함 금액으로」라고 보낸다
- **THEN** 카드에 「Claude Code에 입력했어요」가 보이고, 입력이 「반영 — 실행을 멈추지 않고」가 된다
- **AND** 같은 세션이 그 지시를 따른 결과를 내고, `결과.md` 의 「실행 중에 바꾼 방향」에 그 글이 남는다

#### Scenario: Codex 도 같은 세션의 터미널에서
- **WHEN** Codex 가 단계를 하는 중에 김견적이 지시를 보낸다
- **THEN** 그 지시가 같은 Codex 세션의 터미널에 들어가고(그 rollout 에 그 글), 프로세스를 멈추거나 다시 띄우지 않는다
- **AND** 입력이 「반영 — 실행을 멈추지 않고」가 된다

#### Scenario: 반영하기 전에 끝났다
- **WHEN** 입력을 보냈는데 CLI 가 받기 전에 실행이 끝난다
- **THEN** 그 입력은 「못 함 — 실행이 먼저 끝나 반영하지 못했어요」로 보인다

### Requirement: 다른 기기에서도 실행을 실시간으로 본다
담당자 컴퓨터에서 도는 단계는 인스턴스를 볼 수 있는 사람이면 어느 기기(다른 컴퓨터의 브라우저, 휴대폰, 작업자 자신의 데스크톱 앱)에서든 볼 수 있어야 한다(SHALL). 인스턴스 화면과 그 인스턴스의 Home 카드에 보인다. 카드는 누가 어느 컴퓨터에서 돌리는지, 어느 단계인지, 상태(PC 앱이 켜지면 시작 · 보냄 · 실행 중 · 방향 전달 중 · 끝남 · 멈춤 · 서버에 맡김), 걸린 시간, 그리고 그 CLI 의 터미널(헤드리스 실행이면 최근 도구 · 글 줄)을 보인다. 카드는 새로 읽지 않아도 서버가 밀어 주는 대로 바뀌고, 터미널은 보는 사람이 붙을 때 지금까지의 화면을 다시 받아 같은 화면에서 시작한다. 실행이 터미널로 도는 데스크톱에 보내지면 카드는 곧바로 터미널 자리에 「터미널에 연결하는 중…」을 보이고, 터미널이 열리는 순간 그 화면을 보인다(열리기를 기다리지 않고 미리 붙어 있다). 휴대폰 폭(390px)에서도 화면이 옆으로 넘치지 않는다(터미널이 넓으면 그 상자 안에서만 옆으로 움직인다). 휴대폰에서 터미널은 손가락으로 관성 있게 넘긴다. 작업자의 터미널에는 휴대폰에 없는 키(Esc · Tab · ↑ · ↓ · Ctrl-C · Enter)가 있고, Ctrl+C · Ctrl+D 를 잇달아 누르면 두 번째는 막는다(CLI 가 꺼져 실행이 끝나지 않게). 인스턴스를 볼 수 없는 사람은 카드도 터미널도 실시간 알림도 받지 못한다(403). 메인 채팅에는 아무것도 더하지 않는다.

#### Scenario: 휴대폰에서 보고 조종한다
- **WHEN** 김견적의 데스크톱이 「견적서 작성」을 돌리는 중에 김견적이 휴대폰 브라우저로 그 인스턴스(`/projects/p/<인스턴스>`)를 연다
- **THEN** 카드에 「Claude Code · 김견적 · 김견적의 맥」, 「「견적서 작성」 단계 · N초째」, 「실행 중」과 그 CLI 의 터미널이 보이고, 새로 고침 없이 도구 줄(`…/견적서.md` 뒤에 `…/비고.md`)이 늘어난다
- **AND** 김견적이 휴대폰에서 보낸 입력이 「데스크톱이 받음」을 거쳐 「반영 — 실행을 멈추지 않고」가 되고, 김견적의 컴퓨터의 runner 기록과 CLI 입력에 그 글이 있다
- **AND** 화면은 옆으로 넘치지 않는다

#### Scenario: 참여자는 보기만, 바깥 사람은 막힌다
- **WHEN** 인스턴스의 참여자지만 작업자가 아닌 최참관이 휴대폰으로 그 인스턴스를 연다
- **THEN** 같은 카드와 터미널이 실시간으로 보이지만 입력은 없고(제안은 할 수 있다), 입력을 보내면 403 이다
- **AND** 인스턴스에 없는 박외부는 그 인스턴스의 실행 목록 · 입력 · 터미널 모두 403 이고 실시간 알림도 받지 않는다

#### Scenario: Home 카드
- **WHEN** 김견적의 단계가 「PC 앱이 켜지면 시작」으로 기다린다
- **THEN** 김견적의 Home 에 있는 그 단계의 카드에 「Claude Code · PC 앱이 켜지면 시작」이 보인다

### Requirement: 실행은 「대화」와 「터미널」 두 보기로 본다
터미널로 도는 실행의 카드는 같은 세션을 「대화」와 「터미널」 두 보기로 보여야 한다(SHALL). 「터미널」은 그 CLI 의 화면 그대로이되 Lite 의 색(밝은 · 어두운 테마, 테마가 바뀌면 그 자리에서), 한글이 두 칸 폭인 고정폭 글꼴, Lite 카드의 틀로 보인다. 글과 16색은 바탕과 4.5:1 이상으로 읽힌다. 「대화」는 화면을 읽지 않고 그 CLI 가 스스로 남기는 기록(Claude Code 의 세션 jsonl, Codex 의 rollout)에서 만든다: 사람이 넣은 말과 누가 넣었는지(「<제안한 사람> 제안 · <작업자> 입력」, 작업자가 직접 친 것은 「<작업자> 입력」, 단계의 첫 프롬프트는 「단계 프롬프트」로 접힘), 에이전트의 말(markdown — 스크립트 · 링크 위험 없이), 생각(접힘), 도구 호출 한 줄씩(「파일 읽음 · 견적서.md」, 「만듦 · 견적서.md」, 「고침 · 견적서.md」 — 펼치면 차이, 「명령 실행」 — 펼치면 명령과 출력, 「스킬 사용 · 견적-규칙」 …), 턴이 도는 동안 「작업 중…」. 기록 관리 항목과 하위 에이전트의 기록은 보이지 않는다. 「대화」에서 따로 가리는 것은 없고(터미널과 같은 노출), 터미널을 볼 수 있는 사람만 본다. 입력란과 제안 칩은 두 보기가 함께 쓴다. 기본 보기는 작업자가 아닌 사람과 휴대폰(760px 이하)에서 「대화」, 데스크톱의 작업자에게 「터미널」이고, 보는 사람이 고른 보기는 그 브라우저에 남는다. 휴대폰(390px)에서 화면은 옆으로 넘치지 않고, 차이 · 출력은 그 상자 안에서만 움직인다. 끝난 실행의 「대화」는 그 일에 남은 기록에서 온다.

#### Scenario: 기본 보기와 고른 보기
- **WHEN** 윤태호(작업자)가 1280px 데스크톱 브라우저로, 서하린(참여자)이 390px 휴대폰으로 같은 실행을 연다
- **THEN** 윤태호의 카드는 「터미널」로 열리고(실행이 보내지자마자 「터미널에 연결하는 중…」), 서하린의 카드는 「대화」로 열린다
- **AND** 윤태호가 「대화」를 고르고 새로 고치면 「대화」로 열린다

#### Scenario: CLI 가 기록을 쓰는 대로 대화가 늘어난다
- **WHEN** 윤태호의 Claude Code 가 생각하고, 스킬 「견적-규칙」을 쓰고, `견적서.md` 를 만들고, 고치고, `wc -l 견적서.md` 를 돌린다
- **THEN** 서하린의 「대화」에 새로 고침 없이 「생각」(접힘), 「스킬 사용 · 견적-규칙」, 「만듦 · 견적서.md」, 「고침 · 견적서.md」, 「명령 실행 · wc -l 견적서.md」와 「작업 중…」이 차례로 생긴다
- **AND** 서하린이 「고침 · 견적서.md」를 펼치면 빠진 줄(「1,000,000원」)과 더한 줄(「1,100,000원」)이 그 상자 안에 보이고, 화면은 옆으로 넘치지 않는다

#### Scenario: 누구의 입력인지 대화에 남는다
- **WHEN** 서하린이 「WRITE_OUT 하린.md :: 할인 줄을 따로」를 제안하고, 윤태호가 그것을 「…(윤태호가 고침)」으로 고쳐 넣는다
- **THEN** 두 사람의 「대화」에 그 말이 「서하린 제안 · 윤태호 입력」과 함께 보인다

#### Scenario: Lite 의 색으로 보는 터미널
- **WHEN** 서하린이 밝은 테마와 어두운 테마에서 휴대폰(390px)으로 「터미널」을 본다
- **THEN** 터미널의 바탕은 밝은 테마에서 rgb(251, 251, 253), 어두운 테마에서 rgb(29, 29, 31)이고, 16색은 바탕과 4.5:1 이상이다
- **AND** 테마가 바뀌면 새로 고치지 않아도 터미널의 색이 따라 바뀌고, 화면은 옆으로 넘치지 않는다

### Requirement: CLI 가 묻는 것은 카드로 보이고, 답은 그 CLI 를 가진 사람만 한다
터미널의 CLI 가 사람을 기다리며 묻으면(권한 확인, 고르기) — CLI 의 훅과 기록이 그렇다고 할 때 — 「대화」에 그 물음이 선택지와 함께 카드로 보여야 한다(SHALL). 권한 확인의 선택지는 「허락」 · 「허락 — 앞으로 묻지 않기」(CLI 가 그 규칙을 내놓을 때만) · 「거절」이고(CLI 의 자동 모드로 바꾸는 선택지는 내놓지 않는다), 고르기는 CLI 가 보인 항목들이다. 선택지를 누를 수 있는 사람은 작업자뿐이고, 누르면 그 CLI 의 터미널에 사람이 누르는 키로 들어간다(허락 `1` · 앞으로 묻지 않기 `2` · 거절 `Esc` · 고르기는 그 항목의 번호, 여러 물음이면 물음마다 번호와 끝에 Enter). 다른 사람의 카드에는 선택지 없이 「<작업자>님의 답을 기다려요」가 보이고, 그 사람이 답을 보내면 403 이다. 이미 답했거나 CLI 가 더는 묻지 않는 물음에는 키를 보내지 않는다(409). 작업자는 터미널에서 직접 답할 수도 있고, 그러면 카드는 사라진다. 거절하면 CLI 의 그 턴이 멈추고 단계는 사람을 기다린다.

#### Scenario: 권한 확인
- **WHEN** 윤태호의 Claude Code 가 `python3 -c "print(42)"` 를 돌려도 되는지 묻는다
- **THEN** 서하린의 「대화」에 「명령 실행을 허락할까요?」와 그 명령, 「윤태호님의 답을 기다려요」가 보이고 선택지는 없으며, 서하린이 답을 보내면 403 이고 CLI 에는 아무 키도 가지 않는다
- **AND** 윤태호의 카드에는 「허락」 · 「허락 — 앞으로 묻지 않기」 · 「거절」이 있고, 「허락」을 누르면 그 터미널에 `1` 이 들어가 CLI 가 그 명령을 돌리며, 두 사람의 카드에서 물음이 사라진다

#### Scenario: 거절하면 턴이 멈추고 사람을 기다린다
- **WHEN** 윤태호가 다음 권한 확인에 「거절」을 누른다
- **THEN** 그 터미널에 `Esc` 가 들어가 CLI 가 그 도구를 쓰지 않고 턴을 멈추고, 그 뒤의 일은 하지 않는다
- **AND** 단계는 끝나지 않고 사람을 기다리다가(기다림이 지나면) 그때까지의 결과로 끝난다

#### Scenario: 고르기
- **WHEN** Claude Code 가 「금액을 부가세 포함으로 적을까요?」를 「포함」 · 「별도」로 묻는다
- **THEN** 윤태호의 카드에 두 항목이 보이고, 「별도」를 누르면 그 터미널에 `2` 가 들어가 CLI 가 「별도」로 이어 간다
- **AND** 한 번에 두 물음(「통화는?」 · 「할인 줄은?」)을 물으면 둘 다 고른 뒤 「답 보내기」로 내고, 그 터미널에 `2` · `1` · Enter 가 들어가 CLI 가 「달러」 · 「따로」로 이어 간다

### Requirement: 턴이 끝나면 사람들을 기다리고, 끝내는 것은 그 CLI 를 가진 사람이다
터미널로 도는 단계는 CLI 의 턴이 끝나도 바로 끝나지 않고 인스턴스의 사람들을 기다려야 한다(SHALL)(사용자 요구, 2026-11-24: 「여러 사람이 참여하고 있는 인스턴스에 … 타인이 의견을 넣을 수 있다(프롬프트). 해당 의견이 해당 ssh 터미널의 입력란에 추천으로 쌓인다.」 — 3초 뒤에 끝나면 첫 초안을 본 참여자의 제안이 늦었다). 기다리는 동안 작업자의 카드에는 「끝내기」와 「N분 동안 새 입력이 없으면 저절로 끝나요」, 다른 사람의 카드에는 「<작업자>님이 끝내기를 기다려요 — 지금 제안하면 이어서 입력할 수 있어요」가 보이고, 상태는 「끝내기 기다림」이다. 누구의 새 제안이든, 작업자의 입력 · 타자 · 물음에 답하기 · CLI 의 새 턴이든 기다림을 처음부터 다시 시작한다. 기다림 동안 아무것도 없으면 단계가 저절로 끝난다(기본 5분 — 데스크톱의 설정 「턴이 끝난 뒤 기다리기」로 바꿈). 「끝내기」는 작업자만 누르고(다른 사람은 403), 누르면 바로 끝난다(CLI 가 일하는 중이면 그 턴이 끝난 뒤).

#### Scenario: 첫 초안 뒤에 기다린다
- **WHEN** 윤태호의 Claude Code 가 첫 초안을 내고 턴을 끝낸다(이 데스크톱의 기다림 90초)
- **THEN** 윤태호의 카드에 「끝내기」와 「2분 동안 새 입력이 없으면 저절로 끝나요」, 상태 「끝내기 기다림」이 보이고, 서하린의 카드에 「윤태호님이 끝내기를 기다려요」가 보이며 「끝내기」는 없다

#### Scenario: 제안이 기다림을 다시 시작한다
- **WHEN** 기다리는 동안 서하린이 「목차를 맨 앞에 넣어 주세요」를 제안한다
- **THEN** 저절로 끝날 때가 그만큼 뒤로 밀린다

#### Scenario: 끝내기
- **WHEN** 서하린이 「끝내기」를 보내고(`POST /api/local-agents/jobs/:id/finish`), 윤태호가 「끝내기」를 누른다
- **THEN** 서하린의 것은 403 이고, 윤태호의 것으로 단계가 바로 끝나 결과(`하린.md` 포함)가 인스턴스 라인에 들어간다

### Requirement: 중계되는 터미널은 단계에 묶이지 않은 세션이다
데스크톱이 서버로 중계하는 터미널은 한 저장소(또는 작업 트리)에서 도는 CLI 세션 하나여야 한다(SHALL): 세션 id 와 이어서 하기를 지니고, 종류(`step` 등)와 그 종류의 대상으로 서버에 알려진다. 단계의 실행은 그 종류 하나(`step`, 대상은 그 일)다. 종류마다 누가 그 세션을 열 수 있는지(데스크톱 쪽)와 누가 볼 수 있는지(사람 쪽)를 서버가 정한다. 서버는 중계된 바이트로 화면 모델을 두어 「지금 화면에 무엇이 있는지」를 답한다. CLI 의 훅 이벤트(그 세션의 `--settings` 로 넣은 `SessionStart` · `UserPromptSubmit` · `Stop` · `StopFailure` · `Notification`)와, 세션이 지켜보기로 한 저장소 경로의 바뀐 파일도 같은 연결로 서버에 오고, 서버 안의 듣는 쪽에 전해진다. 이것들에는 이 컴퓨터의 경로나 토큰이 들어가지 않는다.

#### Scenario: 단계가 아닌 개발 세션
- **WHEN** 데스크톱이 저장소 하나에서 종류 `dev` 의 Claude Code 세션을 열고 `aidlc/` 를 지켜보게 하며, CLI 가 `aidlc/질문.md` 와 `src/a.js` 를 쓴다
- **THEN** 서버에 그 세션이 `dev` 로 알려지고, `aidlc/질문.md` 의 내용만 서버로 오며(`src/` 는 오지 않음), `Stop` 훅 이벤트가 마지막 답과 함께 온다
- **AND** 그 이벤트에는 이 컴퓨터의 경로가 없다

#### Scenario: 지금 화면
- **WHEN** 보는 사람이 실행 중인 단계의 「지금 화면」(`GET /api/local-agents/jobs/:id/screen`)을 묻는다
- **THEN** 서버의 화면 모델이 터미널의 보이는 줄들(작업자가 친 글의 메아리 포함)과 입력 · 버린 입력 수를 돌려준다

### Requirement: 데스크톱의 실행은 정해진 CLI · 자기 폴더 · 그 사람의 일로만
데스크톱은 서버가 보낸 글을 명령으로 실행하지 않아야 한다(SHALL). 받은 일은 서버가 「아직 이 기기의 일」이라고 확인한 뒤에만 폴더와 CLI 를 건드린다(그 사이 서버가 거둔 일 — 서버에 맡김, 다른 곳으로 다시 보냄 — 은 돌리지 않는다). 링크가 그대로인 채 기기의 설정을 바꿔도 돌던 일은 그 기기의 것으로 남는다. CLI 마다 정해진 실행 파일과 인자만 쓰고, 단계의 프롬프트는 터미널에 붙여 넣거나(Claude Code) 작업 폴더의 프롬프트 파일로 준다(Codex — 명령줄에는 그 파일을 가리키는 한 줄만). 일은 앱의 데이터 폴더 아래 인스턴스 폴더에서만 하고, 그 밖을 가리키는 산출 폴더는 거절한다. 그 사람의 일이 아니면 거절한다. 터미널의 입력은 그 데스크톱의 사람 것만 받는다(서버도 막고 데스크톱도 본다). 로컬 실행을 끄면 그 데스크톱으로 단계가 오지 않고, 「실행 전에 묻기」를 켜면 단계마다 시스템 창으로 묻는다. 로그 · 터미널 · 중계되는 것에는 토큰이 없다. 끝난 보고는 서버가 받았다고 할 때까지 남겨 두었다가 다시 보낸다.

#### Scenario: 로컬 실행을 끈다
- **WHEN** 이검토가 설정에서 「이 컴퓨터에서 단계 실행」을 끄고, 기다리기로 정한 단계가 온다
- **THEN** 그 단계는 이검토의 데스크톱으로 가지 않고 「PC 앱이 켜지면 시작」으로 기다린다
- **AND** 다시 켜면 그 단계가 돈다

#### Scenario: 거둔 일은 돌지 않는다
- **WHEN** 데스크톱이 일을 받겠다고 했는데 그 사이 서버가 그 일을 서버 에이전트에게 맡겼다
- **THEN** 서버가 그 기기에 취소를 보내고, 데스크톱은 폴더도 CLI 도 건드리지 않는다 — 서버와 데스크톱이 같은 단계를 함께 돌지 않는다

#### Scenario: 폴더 밖을 가리키는 일
- **WHEN** 산출 폴더가 `../밖` 이나 `.git/hooks` 인 일이 온다
- **THEN** 데스크톱은 그 일을 거절한다

### Requirement: 채팅에서 고르는 에이전트
채팅 입력창의 보내기 옆에, 이 메시지를 받을 에이전트를 고르는 칩이 있어야 한다(SHALL)(사용자 요청, 2026-11-24: 「채팅 입력창 보낼때 기본, codex, claude code 등 cli 에이전트를 선택할 수 있는 옵션이 대화창에 있으면 좋겠음」). 고를 수 있는 것은 「기본」(서버의 업무 에이전트 — 지금까지의 답)과, 그 사람의 데스크톱 앱이 알린 CLI 인 「Claude Code · 내 PC」 · 「Codex · 내 PC」다. 켜져 있는 데스크톱이 없으면 내 PC 항목은 꺼진 채 까닭과 함께 보이고(「PC 앱이 꺼져 있어요」, 데스크톱을 이은 적이 없으면 「PC 앱을 설치하고 로그인하면 쓸 수 있어요」), 데스크톱 앱을 내려받는 링크가 있다. 켜진 데스크톱이 있으면 그 데스크톱이 알린 CLI 만 보인다. PC 앱이 켜지거나 꺼지면 새로 고침 없이 바뀐다. 칩은 키보드로 열고(Enter · Space · ↑ · ↓), 목록에서 ↑ · ↓ · Home · End 로 움직여 Enter 로 고르며, Esc 로 닫는다. 고른 것은 대화마다(메인 채팅, 메인 채팅에서 맥락으로 나눈 대화 하나하나, 프로젝트 하나하나) 사람마다 남아 다시 오면 그대로이고, 웹 · 휴대폰 · 데스크톱 앱에서 같다. 새 프로젝트를 쓰는 중, 루틴(인스턴스) 화면, 새 패널 만들기에서는 칩이 없다. 휴대폰 폭에서는 칩이 입력창 위 오른쪽에 있고, 목록은 화면 안에 들어온다.

내 PC 의 CLI 로 보낸 메시지는 보낸 사람 자신의 데스크톱에서만 돈다 — 다른 사람의 데스크톱으로는 가지 않는다. 서버의 에이전트는 그 메시지에 답하지 않는다. 채팅에는 보낸 메시지가 여느 때처럼 보이고 그 아래 「→ Claude Code · 내 PC」가 붙으며, 그 아래 실행 카드(「대화 / 터미널」)가 생긴다. CLI 의 턴이 끝날 때마다 그 CLI 의 마지막 말이 보통의 답 메시지로(위에 「Claude Code · 내 PC」) 올라오고, 그 턴에 CLI 가 만들거나 고친 파일은 파일 카드로 온다(맥락으로 나눈 대화에서는 그 대화의 산출물에 들어간다). 같은 대화에서 같은 에이전트로 이어서 보낸 메시지는 새 실행을 만들지 않고 같은 CLI 세션에 그 사람의 입력으로 들어간다. 실행은 턴이 끝난 뒤 데스크톱의 「턴이 끝난 뒤 기다리기」(기본 5분)만큼 다음 메시지를 기다렸다가 닫히고(카드의 「끝내기」로 바로 닫을 수도 있다), 닫힌 뒤의 메시지는 새 실행이 같은 CLI 세션을 이어서 받는다 — 그 컴퓨터에 세션이 남아 있지 않으면 새 세션이 대화의 최근 말을 간추린 것과 함께 받는다. 실행이 닫히는 사이에 보낸 메시지는 잃지 않고 다음 실행이 받는다.

작업 폴더는 이렇다. 자기 폴더에서 일하는 프로젝트의 대화는 그 폴더에서, 그 프로젝트의 변형에 파일이 들어간다(원본은 사람이 「반영」할 때까지 그대로). 그 프로젝트 폴더를 고칠 수 있는 사람(편집자 이상)만 내 PC 로 보낼 수 있고, 아니면 메시지 아래에 「내 PC 에이전트로 보내지 못했어요 — …」가 까닭과 함께 보인다. 그 밖의 대화(메인 채팅, 그 안의 대화, 자기 폴더가 없는 프로젝트)는 처음 보낼 때 만드는 그 사람만의 폴더 「내 PC 에이전트 작업 · <이름>」에서 하고, 파일은 그 폴더의 원본에 바로 들어간다(그 사람 말고는 구성원이 없다). 데스크톱이 꺼져 있으면 메시지는 PC 앱을 기다리고(카드의 「PC 앱이 꺼져 있어요 …」), 실행 중에 PC 앱 연결이 끊기거나 CLI 가 실패하거나 PC 에서 받지 않으면 카드가 그 까닭을 말한다. 그때 보낸 사람의 카드에 「기본으로 다시 보내기」가 있다: 누르면 실행이 멈추고, 답을 받지 못한 그 메시지가 서버의 에이전트에게 다시 간다. 실행을 보고 입력하고 끝내고 다시 보내는 것은 보낸 사람만 한다 — 다른 사람은 403(그의 대화에 보내기는 404)이고, 프로젝트 폴더의 구성원은 그 실행을 볼 수 있으나 입력하지 못한다(단계의 규칙과 같다). PC 앱은 0.2.2 이상이어야 채팅의 메시지를 받는다(그 전 판이 켜져 있으면 내 PC 항목이 「PC 앱을 새 판(0.2.2 이상)으로 올리면 …」로 꺼져 있다). 데스크톱의 「실행 전에 묻기」는 채팅의 메시지에는 묻지 않는다(그 사람이 방금 자기 채팅에서 보낸 것이다).

#### Scenario: PC 앱이 없으면 내 PC 항목은 꺼져 있다
- **WHEN** 데스크톱 앱을 이은 적이 없는 윤태호가 채팅의 에이전트 칩을 연다
- **THEN** 「기본」이 골라져 있고, 「Claude Code · 내 PC」 · 「Codex · 내 PC」는 꺼진 채 「PC 앱을 설치하고 로그인하면 쓸 수 있어요」와 함께 보이며, 「PC 앱 내려받기」 링크가 있다
- **AND** 꺼진 항목을 눌러도 「기본」 그대로다

#### Scenario: PC 를 이으면 켜진다
- **WHEN** 목록을 연 채로 윤태호의 맥(Claude Code · Codex 설치)이 이어진다
- **THEN** 새로 고침 없이 두 항목이 켜지고 「윤태호의 맥」이 함께 보인다

#### Scenario: 키보드로 고르고 보낸다
- **WHEN** 윤태호가 칩에서 ↓ 로 목록을 열고 ↓ · Enter 로 「Claude Code · 내 PC」를 고른 뒤, 「회의록을 만들어 줘」를 보낸다
- **THEN** 칩은 「Claude Code · 내 PC」가 되고 포커스는 칩으로 돌아온다
- **AND** 그 메시지 아래 「→ Claude Code · 내 PC」, 그 아래 「내 폴더 「내 PC 에이전트 작업 · 윤태호」」의 실행 카드가 생기고, 그의 맥의 Claude Code 가 받는다
- **AND** 그 답이 「Claude Code · 내 PC」의 답 메시지로 오고, CLI 가 쓴 `회의록.md` 가 파일 카드로 온다 — 그 파일은 그의 폴더 원본에 있다
- **AND** 서버의 에이전트는 답하지 않는다

#### Scenario: 이어서 보내면 같은 세션
- **WHEN** 윤태호가 답을 받은 뒤 같은 대화에서 다시 메시지를 보낸다
- **THEN** 실행 카드는 하나 그대로이고, 같은 CLI 세션이 그 메시지를 받아 답과 파일 카드가 하나씩 더 온다

#### Scenario: 끝난 뒤의 메시지는 그 세션을 잇는다
- **WHEN** 윤태호가 「끝내기」로 실행을 닫은 뒤 같은 대화에서 다시 보낸다
- **THEN** 닫힌 카드는 「세션을 닫았어요 — 다음 메시지는 같은 세션을 이어요」이고, 새 실행이 같은 Claude Code 세션을 이어(`--resume`) 답한다

#### Scenario: 고른 것은 대화마다 남는다
- **WHEN** 윤태호가 메인 채팅에서 「Claude Code · 내 PC」를 고른 뒤 새로 고치고, 다른 브라우저로 열고, 한 프로젝트로 갔다가 돌아온다
- **THEN** 메인 채팅은 두 브라우저 모두 「Claude Code · 내 PC」, 그 프로젝트는 「기본」이다

#### Scenario: 다시 기본
- **WHEN** 윤태호가 「기본」을 다시 고르고 「오늘 할 일을 알려 줘」를 보낸다
- **THEN** 그 메시지는 서버의 에이전트에게 가고(태그 없음), 실행 카드는 생기지 않는다

#### Scenario: PC 가 꺼지면 기본으로 다시 보낸다
- **WHEN** 실행이 다음 메시지를 기다리는 중에 윤태호의 PC 앱이 꺼진다
- **THEN** 칩은 꺼진 표시가 되고 목록의 「Claude Code · 내 PC」에 「PC 앱이 꺼져 있어요」가 보인다
- **AND** 그 실행의 카드에 「PC 앱 연결이 끊겼어요 …」와 「기본으로 다시 보내기」가 보인다
- **AND** 그 사이 보낸 「내일 회의 안건 정리해 줘」를 두고 「기본으로 다시 보내기」를 누르면 그 글이 서버의 에이전트에게 가고, 카드는 「기본 에이전트로 다시 보냈어요」가 된다
- **AND** PC 앱이 꺼진 채 새로 보낸 메시지의 카드는 「PC 앱이 켜지면 시작」 · 「PC 앱이 꺼져 있어요 — 켜지면 Claude Code에게 보내요 …」와 「기본으로 다시 보내기」를 보인다

#### Scenario: 프로젝트 폴더
- **WHEN** 윤태호가 자기 폴더 「세미나 준비 폴더」에서 일하는 프로젝트에서 「Codex · 내 PC」로 `설계.md` 를 쓰게 한다
- **THEN** `설계.md` 는 그 프로젝트의 변형에 들어가고 원본에는 없으며, 파일 카드가 온다
- **AND** 그 폴더의 구성원이 된 서하린은 그 실행을 볼 수 있으나 입력은 403 이다
- **AND** 그 폴더를 실행만 할 수 있는(편집자가 아닌) 서하린이 같은 폴더의 자기 프로젝트에서 내 PC 로 보내면 「내 PC 에이전트로 보내지 못했어요 — …(편집자 이상)…」이 메시지 아래에 보인다

#### Scenario: 다른 사람
- **WHEN** 서하린이 윤태호의 채팅 실행을 보거나, 입력하거나, 끝내거나, 기본으로 다시 보내려 하고, 윤태호의 대화에 메시지를 보낸다
- **THEN** 앞의 것들은 403, 대화에 보내기는 404 이다
- **AND** 서하린 자신의 채팅에서 Claude Code 로 보낸 메시지는 그녀의 PC 를 기다리고, 켜져 있는 윤태호의 맥으로는 가지 않는다

#### Scenario: 휴대폰과 어두운 테마
- **WHEN** 윤태호가 휴대폰(390px)에서 밝은 · 어두운 테마로 Home 입력창의 칩을 연다
- **THEN** 칩은 입력창 위에 있고, 목록은 화면 양옆 16px 안에 들어오며, 화면은 옆으로 넘치지 않는다

#### Scenario: 넓은 창에서 입력창만 좁을 때
- **WHEN** 창 너비는 1280px인데 메신저를 옆에 붙이거나 옆 패널을 열어 입력창의 폭이 460px 미만으로 줄어든다
- **THEN** 칩은 휴대폰에서처럼 입력창 위 줄로 옮겨지고, 입력창의 안내 문구는 한 줄에 들어간다
- **AND** 입력창이 다시 460px 이상으로 넓어지면 칩은 입력창 안으로 돌아온다

### Requirement: 데스크톱 앱의 에이전트 선택 안내

웹 화면이 데스크톱 앱 안에서 열려 있고 사용자의 데스크톱이 서버에 하나도 연결되어 있지 않으면, 에이전트 선택 화면은 서버가 파악한 이유(「PC 앱을 설치하고 로그인하면 …」) 대신 이 컴퓨터의 상태에 맞는 이유를 보여야 한다(MUST). 앱이 이 컴퓨터를 연결할 수 없는 이전 버전이면 「PC 앱이 오래돼 …」와 현재 버전, 최신 버전, 「최신 버전 받기」 링크를 보여 준다. 이 컴퓨터를 연결하지 못했거나 서버가 연결을 끊었거나 사용자가 연결을 해제한 상태라면 「이 컴퓨터 연결」 단추를, 연결 중이라면 「연결 중」을 보여 준다. 브라우저에서는 기존 동작을 유지한다. 서버는 최신 데스크톱 앱 릴리스의 버전도 알려 주되, 버전 정보를 읽느라 응답이 늦어져서는 안 되며 읽지 못하면 알리지 않는다. 앱 버전이 최신 릴리스보다 오래되었으면, 앱 안의 에이전트 선택 화면과 설정 › 계정 › 내 컴퓨터의 에이전트에 「PC 앱 새 버전(…)이 나왔어요」와 내려받기 링크를 보여 준다. 막 페어링되어 아직 CLI 정보를 알리지 않은 데스크톱 때문에 CLI가 목록에서 사라져서는 안 된다(MUST NOT). 앱이 페어링을 수락하지 않으면 그때 만든 기기 토큰은 회수한다.

#### Scenario: 브라우저의 기존 동작 유지
- **WHEN** 데스크톱을 연결한 적이 없는 한서윤이 브라우저에서 에이전트 칩을 연다
- **THEN** 「PC 앱을 설치하고 로그인하면 쓸 수 있어요」와 「PC 앱 내려받기」가 보이고, 앱 버전을 표시하는 줄은 없다

#### Scenario: 이전 버전 앱에서 안내
- **WHEN** 한서윤이 로컬 에이전트가 도입되기 전 버전(0.1.0)의 데스크톱 앱에서 에이전트 칩을 연다(최신 릴리스는 0.2.3)
- **THEN** 「Claude Code · 내 PC」와 「Codex · 내 PC」는 비활성화된 상태로 「PC 앱이 오래돼 이 컴퓨터를 연결할 수 없어요 — 업데이트하면 쓸 수 있어요」를 보여 주고, 「PC 앱을 설치하고 로그인하면」은 어디에도 없다
- **AND** 목록 아래에 「지금 쓰는 PC 앱은 0.1.0 버전, 최신은 0.2.3 버전이에요」와 내려받기 페이지로 연결되는 「최신 버전 받기」 링크가 있고, 목록에서 Tab을 누르면 해당 링크로 이동한다
- **AND** 설정 › 계정의 「내 컴퓨터의 에이전트」에도 「PC 앱이 이전 버전이에요 · 0.1.0」과 「최신 버전 받기」가 보인다
- **AND** 화면 너비가 390px이고 어두운 테마를 사용해도 목록이 화면 안에 표시되고 가로로 넘치지 않는다

#### Scenario: 이 컴퓨터 다시 연결
- **WHEN** 이 컴퓨터의 연결을 해제해 둔 한서윤이 앱 안에서 칩을 열고 「이 컴퓨터 연결」을 누르지만, 앱이 처음에는 연결 요청을 수락하지 않는다
- **THEN** 안내 문구가 「이 컴퓨터를 연결하지 못했어요 — 다시 연결해 주세요」로 바뀌고, 그때 만든 기기 토큰은 회수된다
- **AND** 다시 누르면 새 기기 토큰이 앱에 전달되고, 안내 문구는 「이 컴퓨터가 서버에 연결 중이에요」로, 목록 아래 문구는 「연결되면 바로 고를 수 있어요」로 바뀐다
- **AND** 그동안 두 CLI 항목은 목록에서 사라지지 않는다

#### Scenario: 새 버전 출시 안내
- **WHEN** 한서윤의 0.2.2 앱이 연결되어 있고 최신 데스크톱 릴리스가 0.2.3이다
- **THEN** 에이전트 선택 목록 아래에는 「PC 앱 새 버전(0.2.3)이 나왔어요」와 「내려받기」가 보이고, 설정에는 「PC 앱 새 버전(0.2.3)이 나왔어요 — 지금은 0.2.2 버전이에요」가 보인다

### Requirement: 데스크톱은 그 사람의 브라우저 작업도 같은 링크로 받는다
데스크톱 앱 0.2.3 은 자기 브라우저가 있다고 링크의 hello · caps 에 알려야 한다(SHALL, `caps.browser: true`). 그러면 그 사람의 브라우저 작업이 그 PC 의 브라우저에서 돈다(스펙 `browser-handoff` 「브라우저 작업은 내 PC 의 브라우저에서도 돈다」, 설계 `docs/local-agents/browser.md`). 서버는 같은 링크로 이름 붙은 동작(열기 · 쥐기/놓기 · 읽기 · 누르기 · 입력 · 키 · 스크롤 · 보관함 값 · 그림 · 멈추기 · 파일 넣기 · 직접 제어 · 보이기)을 보내고, 데스크톱은 답 · 실시간 프레임 · 받은 파일을 같은 링크로 돌려준다(900KB 넘는 메시지는 바이트로 재어 조각으로 — 허브는 메시지 하나에 1MB). 새 포트 · 새 연결은 없다.

- 데스크톱은 그 데스크톱에 로그인한 사람의 브라우저만 연다. 다른 사람이면 거절한다. 서버가 보낸 코드는 돌리지 않는다(MUST NOT) — 페이지 안에서 도는 읽기 스크립트도 데스크톱이 가진 사본이다(서버의 것과 같은지는 시험이 본다).
- 그 사람의 세션은 데스크톱 앱 안의 따로 된 세션(`persist:pgl-browser-<사람>`)이고, 앱 창(Lite 웹 앱)과 섞이지 않는다. 창은 숨어 있고, 그 사람의 PC 를 재우지 않는 것은 서버가 그 브라우저를 움직이는 동안만이다.
- 데스크톱은 실행 설정과 함께 「브라우저 작업은 이 PC에서」(`prefs.browser`: 「내가 시킨 작업만」 `own` 기본 · 「단계 · 예약 작업까지 모두」 `all` · 「쓰지 않음」 `off`)를 그 PC 에 저장하고 hello · caps 로 알려야 한다(SHALL). 서버는 그대로 따른다(스펙 `browser-handoff` 「PC 마다 동의한 작업만 그 PC 로 간다」) — 서버에 저장하지 않고, 웹 · 휴대폰은 읽기만 한다. 다른 실행 설정(실행 전에 묻기 · 기다리기)을 바꿔도 이 값은 남는다.
- 「이 컴퓨터에서 단계 실행」을 끈 PC(`enabled: false`)로는 단계도 브라우저 작업도 가지 않는다(MUST NOT).
- 0.2.2 이하의 데스크톱이 켜져 있으면 브라우저 작업은 서버에서 돌고, 설정에 「PC 앱을 0.2.3 이상으로 올리면 …」이 보인다.

#### Scenario: 0.2.3 으로 로그인한다
- **WHEN** 윤태호가 데스크톱 앱 0.2.3 에서 로그인한다
- **THEN** 「연결한 데스크톱」의 그 기기가 `caps.browser` 와 `prefs.browser: 'own'` 을 가지고, 앱의 설정에 「브라우저 작업은 이 PC에서 · 내가 시킨 작업만」, 「내가 시킨 브라우저 작업」에 「「테스트 맥」의 브라우저에서 해요」가 보인다
- **AND** 앱에서 「단계 · 예약 작업까지 모두」 · 「쓰지 않음」으로 바꾸면 서버의 `GET /api/browser/where` 가 곧바로 그대로 바뀐다

#### Scenario: 다른 사람의 열기
- **WHEN** 링크로 다른 사람의 브라우저를 열라는 동작이 온다
- **THEN** 데스크톱은 거절하고 아무것도 열지 않는다

## 시험이 못 덮는 것
- 내 PC 의 브라우저(데스크톱 0.2.3): 맥 arm64 에서만 돌려 보았다(Electron 45 · 숨은 창 · 스크린캐스트). Windows 의 숨은 창 · 스크린캐스트 · 키 입력은 CI 가 단위 시험과 묶음만 한다. 묶은(패키지) 앱으로 브라우저 작업을 돌려 보지는 않았다.
- 운영의 공개 주소에서 데스크톱이 git 경로와 링크 · 터미널(WebSocket)에 닿는지(운영 nginx · 게이트웨이 설정이 필요하다 — 설계 §8).
- OpenHands 실행(이 맥에 없어 명령을 확인하지 못했다).
- 묶은(패키지) 데스크톱 앱은 mac arm64 로 묶어 node-pty 가 앱 안에서 뜨는 것까지만 봤다. Windows(ConPTY) · Linux 는 묶지도 돌리지도 않았다.
- 실제 대화형 CLI 는 Claude Code 를 회사 모델 게이트웨이로 한 번 돌렸다(이 맥의 구독 로그인은 대화형 첫 설정이 끝나지 않아 무인으로 쓸 수 없었다 — `e2e/results/smoke.md`). 실제 대화형 Codex 는 돌리지 않았다(헤드리스는 실측). 긴 작업 · 많은 파일 · 문서(워드 · 엑셀) 생성은 실측하지 않았다.
- 사람의 Claude Code 가 처음 설정(테마 고르기)이나 신뢰 창을 띄우는 경우: 터미널에서 작업자가 답하면 이어지지만(그 사이 첫 프롬프트는 기다린다) 자동 시험은 없다.
- 회사 프로세스 지도(Ontological)의 일 정의에 노하우를 반영하는 길: 이 맥에 Ontological 이 떠 있지 않아 자동 시험은 프로세스 정의의 활동 쪽 길로만 했다.
- 실제 Codex 가 `.pgl-skills` 의 스킬을 쓰는 것, 판정 모델이 실제로 「일의 방식 / 이번 건에만」을 가르는 정확도(시험은 판정을 대역으로, 모델이 없으면 「판정 못 함」).
- 데스크톱의 시스템 알림 창 자체(시험은 runner 가 내는 알림 이벤트까지 확인), 휴대폰 손가락 관성 스크롤 · 「/」 목록 탭(손으로 확인할 일).
- CLI 의 물음에 답하는 키: 실제 Claude Code 2.1.331 로 허락 `1` · 앞으로 묻지 않기 `2` · 거절 `Esc` · 한 물음 고르기의 번호 · 여러 물음 고르기의 번호들과 Enter 를 확인했다(임시 설정 폴더 · 회사 모델 게이트웨이). 화면의 「4. No」는 쓰지 않는다(거절은 `Esc`). Codex 의 승인 창은 기록 · 훅에 남지 않아 카드로 만들지 않는다. 대화형 Codex 의 rollout 은 실제 실행이 아니라 고정 자료(실제 모양을 따른 지어낸 내용)로 시험했다.
- 채팅에서 고르는 에이전트: 실제 Claude Code · Codex 로 채팅 메시지를 돌려 보지 않았다(가짜 대화형 CLI 로만). 같은 폴더에서 앞 세션을 이어받는 `--resume` 은 단계의 「앱이 다시 켜졌을 때」 실측과 같은 길이다. 데스크톱 앱 0.2.2 를 묶어(패키지) 채팅 메시지를 돌려 보지는 않았다(CI 가 묶는다). 맥락 라우터가 나눈 대화(`/chat/c/:id`) 안에서 보내는 길은 서버 시험(대화 열쇠 · 답의 맥락)으로만 보았다 — 화면 시험은 모델이 없어 그 대화를 만들 수 없다. 메인 채팅에서 대화를 고르지 않고 내 PC 로 보낸 답은 맥락 라우터를 거치지 않는다(그 답은 지금 대화에 머문다).
- 「대화」의 항목 모양은 이 맥의 Claude Code 2.1.331 의 실제 기록을 보고 맞췄다. 이후 판에서 기록의 모양이 바뀌면(새 항목 종류) 그 항목은 보이지 않을 뿐 터미널은 그대로다.
