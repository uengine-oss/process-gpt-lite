# 프로필 사진 — Process GPT와 같은 사진, 같은 칸

## Purpose
2026-11-25 사용자 요청: 「내 프로필 사진 어떻게 바꾸냐? Process GPT 버전과 일관성고려하여」. 지금까지 Lite의 설정 화면과 위 막대에는 이름 첫 글자가 들어간 동그라미만 있었고, 사진을 설정할 방법은 없었다.

같은 날 추가한 요청: 「프로필 사진은 기본적으로 social login 인 경우는 구글에 설정된 이미지가 나오는게」.

이제 사용자의 사진은 Process GPT의 계정 설정에서 쓰는 칸, 즉 회사별로 있는 해당 사용자의 `users` 행의 `profile` 칸 하나에 저장한다. 구글로 로그인한 사용자는 구글 계정의 사진을 기본 사진으로 쓴다. 어느 앱에서 사진을 바꾸든 두 앱에 같은 사진이 보인다. Lite에서는 Process GPT의 기본 사진 18장 중 하나를 골라 Process GPT와 같은 값으로 저장하거나, 자기 사진을 올리거나, 사진을 지울 수 있다. Process GPT에는 자기 사진을 올리는 기능이 없지만, Lite에서 올린 사진은 Process GPT 화면에도 그대로 보인다.

같은 날 운영에서 받은 보고에 따르면, 두 동료와 함께 있는 대화방에서 사용자 자신의 에이전트가 올린 결과 메시지 옆에 사용자 사진 대신 메일 주소 첫 글자가 들어간 동그라미가 표시됐고, 대화방 상단의 사람 목록에는 사용자 이름 대신 메일 주소 앞부분이 표시됐다. 「왜 대화창에는 "j"라는 아이콘으로 내 포트레잇 아이콘이 뜨는가?」 · 「일관성있는 컴포넌트 사용이 되어야」. 메신저는 Process GPT의 `users.username`(해당 회사에서는 메일 주소 앞부분)을 읽고 있었고, 나머지 화면은 Lite 프로필의 이름을 읽고 있었다. 이제 이름과 사진은 서버의 단일 규칙에 따라 결정하고, 동그라미는 하나의 공통 컴포넌트로 표시한다.

## Requirements

### Requirement: 사진은 Process GPT와 같은 칸 하나에 둔다
시스템은 로그인한 사용자가 현재 속한 회사의 `users` 행에서 `profile` 칸의 사진을 읽고, 같은 칸에 저장해야 한다(SHALL). Lite 전용 사진 칸은 따로 두지 않는다. `GET /api/me`는 `user.picture`에 화면에 표시할 사진 주소를 담는다. 표시할 사진이 없으면 `null`이다. Process GPT가 그 칸에 저장한 사진도 Lite가 다음에 읽을 때 그대로 보인다. Lite가 저장한 사진도 Process GPT 화면에 보인다. 새 계정의 기본값인 `/images/defaultUser.png`는 Process GPT에서 「사진 없음」을 뜻하므로, Lite는 이 값일 때 이름 첫 글자를 보여 준다.

#### Scenario: Process GPT에서 바꾼 사진
- **WHEN** Process GPT의 계정 설정에서 기본 사진 5번을 선택해 저장한 뒤 Lite를 연다
- **THEN** Lite의 위 막대와 설정 상단에 같은 사진이 보인다

#### Scenario: 새 계정
- **WHEN** 사진을 한 번도 설정하지 않은 사용자가 Lite를 연다
- **THEN** 위 막대와 설정 상단에 이름 첫 글자가 들어간 동그라미가 보인다

---

### Requirement: 구글로 로그인한 사용자는 구글 계정의 사진이 기본이다
시스템은 화면에 표시할 사진을 다음 순서로 정해야 한다(SHALL). (1) `users.profile`에 선택한 사진(기본 사진 · 올린 사진 · Process GPT가 저장한 사진)이 있으면 그 사진을, (2) 없으면 해당 사용자의 구글 계정 사진을, (3) 그것도 없으면 이름 첫 글자를 보여 준다. 구글 계정 사진은 인증 서버가 기록한 값에서만 읽는다. 구글 로그인 기록(구글 identity의 `picture`, 없으면 `avatar_url`)이나 Lite 자체 구글 로그인 시 서버가 저장한 값이 여기에 해당한다. 사용자가 직접 수정할 수 있는 사용자 메타데이터는 읽지 않는다. 구글 사진 주소는 허용된 호스트(`PRO_AVATAR_HOSTS`, 기본 https `*.googleusercontent.com`)에 있을 때만 사용한다. `GET /api/me`의 `user.pictureDefault`는 해당 사용자의 기본 사진이다. 구글 사진이 있으면 그 주소이고, 없으면 `null`이다.

구글로 로그인한 사용자가 Lite를 열 때 `users.profile`이 비어 있으면(값이 없거나 `/images/defaultUser.png`) 구글 사진 주소를 한 번 저장한다. 그러면 Process GPT에도 같은 사진이 보인다(Process GPT가 예전에 소셜 가입 시 처리하던 방식과 같다). 사용자가 선택한 사진은 덮어쓰지 않는다. `users.profile`에 구글 사진 주소가 있는 동안 구글 계정의 사진이 바뀌면 새 주소로 갱신한다. Lite는 화면에서 보낸 구글 주소를 사용자가 선택한 사진으로 받지 않으므로, 그 칸의 구글 주소는 언제나 「기본 사진」이다. 구글 사진은 리퍼러 없이 요청한다. 만료나 네트워크 문제로 불러오지 못하면 이름 첫 글자를 보여 준다. 「프로필」 줄에는 「Google 계정의 사진이에요」가 보인다.

#### Scenario: 구글로 로그인한 사용자는 구글 사진이 기본
- **WHEN** 구글로 로그인했고 사진을 선택한 적 없는 이하준이 Lite를 연다
- **THEN** 위 막대 · 설정 · 「프로필」 줄에 구글 계정의 사진이 보이고, `users.profile`에 그 주소가 저장되며, 「프로필 사진」 창에는 되돌리기 단추가 없다

#### Scenario: 선택한 사진이 우선한다
- **WHEN** 이하준이 기본 사진 5번을 선택하고 Lite를 다시 연다
- **THEN** 기본 사진 5번이 보이고, `users.profile`은 그대로 `/assets/images/profile/5.jpg`이다

#### Scenario: 구글 계정의 사진이 바뀜
- **WHEN** 구글 사진이 보이던 이하준이 구글 계정의 사진을 바꾸고 Lite를 다시 연다
- **THEN** 새 구글 사진이 보이고, `users.profile`도 새 주소로 바뀐다

#### Scenario: 구글 사진을 불러오지 못함
- **WHEN** 구글 사진 주소가 더 이상 열리지 않는다
- **THEN** 동그라미에 「이」가 보이고, 화면에 오류가 나지 않는다

### Requirement: 사진이 보이는 곳 — 위 막대, 설정, 그리고 사용자 동그라미
시스템은 사용자 사진을 이름 첫 글자가 표시되던 동그라미와 같은 자리, 같은 크기의 동그라미에 가운데를 기준으로 잘라 꽉 차게 보여 주어야 한다(SHALL). 위 막대의 동그라미, 설정 첫 화면 맨 위의 큰 동그라미, 「프로필」 화면의 첫 줄에 사진이 보인다. 다른 사용자를 나타내는 동그라미에도 해당 사용자의 사진이 표시된다. 팀·역할의 팀원 목록, 메신저의 대화 목록·받은 편지함·메시지 발신자 표시·@ 사람 선택·새 대화 상대 선택, 채팅 입력창의 @ 팀원 목록과 받는 사람 칩, 「팀원에게 공유」 창, 회의에서 카메라를 끈 사용자의 칸, 공유 폴더의 사용자 동그라미가 여기에 해당한다. 에이전트가 작성한 메시지에는 해당 에이전트를 사용한 사람의 사진에 에이전트 표시를 붙여 보여 준다(「같은 사람은 어디서나 같은 이름과 같은 얼굴로 보인다」). 파일이 없거나 지워졌거나 그림이 아니어서 사진을 불러오지 못하면 오류 표시 없이 이름 첫 글자를 보여 준다. 밝은 테마와 밤 테마 모두 사진 가장자리에 옅은 테두리를 두어 배경과 구분한다.

#### Scenario: 팀원의 사진
- **WHEN** 김서연이 사진을 설정한 뒤 같은 회사의 박도윤이 팀·역할 화면과 메신저의 대화 목록을 연다
- **THEN** 김서연의 줄과 김서연과의 대화에 그 사진이 보이고, 사진이 없는 박도윤 자신의 줄에는 「박」이 보인다

#### Scenario: 깨진 사진
- **WHEN** 저장된 사진이 이 사이트에 없는 파일이거나 저장소에서 지워진 사진이다
- **THEN** 동그라미에 이름 첫 글자가 보이고, 화면에 오류가 나지 않는다

### Requirement: 같은 사람은 어디서나 같은 이름과 같은 얼굴로 보인다
시스템은 한 사람을 표시하는 모든 곳에서 같은 이름과 같은 얼굴을 보여 주어야 한다(SHALL). 이름과 사진은 서버의 공통 규칙(`server/lib/people.js`)으로 정하고, 화면의 동그라미는 공통 컴포넌트(`PersonAvatar.vue`)로 그린다. 메신저의 방 제목 · 방 상단의 사람 목록 · 보낸 사람 · 받은 편지함 · @ 사람 선택 · 새 대화 상대 선택, 채팅 입력창의 @ 팀원 목록과 받는 사람 칩, 「팀원에게 공유」 창, 팀·역할, 사용량, 정책 결정 원장, 팀 활동 카드, 회의에서 카메라를 끈 사용자의 영역, 공유 폴더의 사용자 동그라미, 상단 막대와 설정의 내 동그라미, 알림의 보낸 사람, 에이전트와 MCP 도구가 받는 사용자 정보가 모두 여기에 해당한다.

이름은 다음 순서대로 확인하여 이름으로 인정할 수 있는 첫 번째 값을 사용한다. (1) Lite 프로필의 이름(`pro_profile.name`), (2) Process GPT의 `users.username`, (3) 인증 기록의 `user_metadata`에 있는 `name`과 `full_name`, (4) 앞에서 사용할 수 있는 이름을 찾지 못하면 메일 주소의 `@` 앞부분. 메일 주소의 `@` 앞부분과 같은 값(대소문자 구분 없음)이나 메일 주소 형태의 값은 이름으로 인정하지 않는다. Process GPT와 Lite에서는 메일로 로그인할 때 사용자가 이름을 입력하기 전에 이런 값을 먼저 저장하기 때문이다. 사진은 「구글로 로그인한 사용자는 구글 계정의 사진이 기본이다」에 명시된 순서를 따른다. 서버는 한 사람의 이름과 사진을 30초 동안 임시로 저장하고, 사용자가 Lite에서 이름이나 사진을 바꾸면 즉시 다시 읽는다. `GET /api/people`은 해당 회사의 사람(에이전트 제외)에 대해 `{ 사람 id: { name, picture } }`를 반환하며, 화면은 이 값을 기준으로 이름의 첫 글자와 사진을 정한다. 이 규칙을 적용하기 위해 Lite가 Process GPT의 `users` 행을 변경하지는 않는다.

이 규칙에 따라 정한 이름은 화면에만 사용한다. Process GPT의 데이터 행에 저장하는 이름에는 해당 사용자의 `users.username`을 그대로 사용한다. 이는 대화방 참여자(`chat_rooms.participants`), 메시지의 `mentionedUsers`, 폴더 변형 인계의 `todolist.username` · `handover_events.to_user_name` · 인계받는 방의 참여자 · 변형 보유자(`holder_name`), 공유 기록의 `handover_events`에 적용된다. 인계받는 사람은 화면에서 보낸 이름이 아니라 서버가 `users` 행에서 읽은 값으로 정한다. 로그인 주소는 소문자로 변환한 뒤 동일한 계정을 찾는 데 사용하며, 행에도 소문자로 저장한다.

동그라미는 표시되는 위치에 따라 크기만 다르고(20 · 28 · 34 · 44px 등), 모양과 색은 같다. 사람 수를 나타내는 그룹 동그라미, 역할(#), 메신저의 AI(✦)도 같은 컴포넌트의 동일한 바탕 모양을 사용한다.

에이전트가 사용자를 대신해 방에 올린 메시지에는 해당 에이전트를 사용한 사람의 얼굴에 작은 에이전트 표시(✦)를 붙여 보여 주고, 메시지 위에는 「<이름>님의 에이전트」(영어 화면에서는 "<name>'s agent")를 표시한다. 이때 이름은 메시지에 함께 저장된 이름이 아니라 위 규칙에 따라 정한 이름을 사용한다. 방의 AI가 답한 메시지(「@AI …」에 대한 답변)와 에이전트를 사용한 사람을 알 수 없는 메시지에는 얼굴 대신 ✦ AI 동그라미를 사용한다.

#### Scenario: 내 에이전트의 결과
- **WHEN** Process GPT의 `username`이 메일 주소 앞부분(`hayoon`)이고 Lite의 이름은 「정하윤」인 사용자의 에이전트가 김서연 · 박도윤과 함께 있는 방에 결과를 올린다
- **THEN** 결과 메시지 옆에 「h」 대신 정하윤의 사진과 에이전트 표시가 보이고, 메시지 위에는 「정하윤님의 에이전트」가 보인다
- **AND** 김서연의 화면에도 같은 얼굴과 같은 이름이 보이고, 같은 방에서 AI가 답한 메시지에는 ✦ AI 동그라미가 보인다

#### Scenario: 방 머리와 목록
- **WHEN** 김서연이 그 방을 연다
- **THEN** 방 상단의 사람 목록에는 「정하윤, 김서연, 박도윤」이 표시되고, 대화 목록 · 새 대화 상대 선택 · 팀·역할에도 `hayoon`이 아니라 「정하윤」이 보인다

#### Scenario: Lite를 연 적 없는 사람
- **WHEN** Lite 프로필이 없고 `username`도 메일 주소 앞부분인 최도현이 구글 계정으로 Process GPT에 로그인한 적이 있다
- **THEN** 인증 기록에 저장된 구글 계정의 이름 「최도현」이 보인다

#### Scenario: Process GPT의 행에는 Process GPT의 이름
- **WHEN** 정하윤이 김서연을 「@」로 멘션하고, `username`이 「봉여울」이고 Lite의 이름이 「Yeoul Bong」인 팀원에게 폴더 변형을 인계하는 과정에서 화면이 다른 이름을 보낸다
- **THEN** 메시지의 `mentionedUsers`와 대화방 참여자에는 각자의 `users.username`이 저장되고, 인계의 `todolist.username` · `handover_events.to_user_name` · 변형의 `holder_name`에는 「봉여울」이 저장되며, 화면에는 「Yeoul Bong」이 표시된다

#### Scenario: 고르는 창의 얼굴
- **WHEN** 메신저에서 「@」를 입력하거나, 채팅 입력창에서 「@」로 팀원을 선택하거나, 「팀원에게 공유」 창을 연다
- **THEN** 사진이 있는 팀원은 사진이, 사진이 없는 팀원은 이름의 첫 글자가 동일한 모양의 동그라미 안에 보이고, 선택한 팀원의 받는 사람 칩에도 같은 얼굴이 보인다

### Requirement: 같은 이름의 사람은 한 목록 안에서 주소로 가른다
2026-11-25 운영 중 한 회사에 한 사람의 계정 두 개(Gmail 계정과 회사 계정)가 있었고, 두 계정의 화면 이름이 모두 「윤가람」이어서 메신저 목록에 똑같은 항목이 두 개 표시되었다. 가입을 열어 두고 있으므로 이런 일은 다시 생길 수 있다. 시스템은 사람을 나열하거나 선택하는 목록에 같은 화면 이름이 둘 이상 있으면 이름 뒤에 각 사람을 구분하는 표시를 붙여야 한다(SHALL). 같은 이름을 가진 사람들 중 메일 주소의 도메인이 다른 사람과 겹치지 않으면 도메인을(「윤가람 · gmail.com」 · 「윤가람 · uengine.org」), 겹치면 메일 주소 전체를 붙인다. 목록에 같은 이름이 없으면 이름을 그대로 표시한다. 구분 표시는 목록별로 판단하며, 한 곳(`src/sameNames.js`, 화면에서는 `src/people.js`의 `tagsFor`)에서 결정한다. 적용 대상은 메신저의 대화 목록 · 방 제목 · 방 상단의 사람 목록 · 단체방의 보낸 사람, 팀원 선택 창(새 대화 · 초대 · 단체방 만들기), 메신저와 채팅 입력창의 @ 목록 · 받는 사람 칩, 「팀원에게 공유」 창, 팀·역할의 팀원 목록과 역할 담당자 선택이다. 이를 위해 `GET /api/people`과 대화방의 사람 목록에는 메일 주소가 함께 제공된다.

#### Scenario: 한 사람의 계정 둘
- **WHEN** 회사 주소 계정과 다른 주소 계정의 화면 이름이 모두 「윤가람」인 회사에서 정하윤이 두 계정과 각각 1:1 대화를 한 뒤 메신저를 연다
- **THEN** 대화 목록에 「윤가람 · uengine.org」와 「윤가람 · people-mail.test」가 각각 표시되고, 같은 이름이 없는 「김서연」은 그대로 표시된다

### Requirement: Process GPT의 기본 사진은 Process GPT의 파일을 먼저 불러오고, 없으면 Lite의 사본을 불러온다
시스템은 기본 사진을 Process GPT와 같은 사이트 기준 경로(`/assets/images/profile/1.jpg` … `8.jpg`, `user-1.jpg` … `user-10.jpg`)로 저장하고, 그 경로에서 먼저 불러와야 한다(SHALL). 운영 환경처럼 Lite가 Process GPT와 같은 주소 아래(`/lite`)에 있으면 이 경로는 Process GPT의 파일을 가리킨다. 그 파일을 불러오지 못하면 Lite에 함께 포함된 동일한 사진 18장의 사본을 불러온다. 사본은 Lite의 주소 아래 같은 경로에 있다. Lite만 설치한 환경에서는 사이트 기준 경로가 곧 Lite의 사본을 가리킨다. 사본은 Process GPT의 파일과 바이트가 동일하다.

#### Scenario: Lite만 설치한 회사
- **WHEN** Process GPT 화면이 없는 설치 환경에서 기본 사진 3번을 선택한다
- **THEN** Lite에 포함된 사본이 보이고, 저장된 값은 `/assets/images/profile/3.jpg`이다

### Requirement: 사진 바꾸기 — 기본 사진 고르기
시스템은 설정 첫 화면 맨 위의 동그라미(카메라 표시가 붙어 있다)를 누르거나 「프로필」 화면의 「바꾸기」를 누르면 「프로필 사진」 창을 열어야 한다(SHALL). 창에는 Process GPT와 같은 순서로 나열된 기본 사진 18장, 「내 사진 올리기」, 선택한 사진이 있을 때 되돌리는 단추(구글 사진이 기본이면 「Google 사진으로」, 아니면 「사진 지우기」), 그리고 「Process GPT에도 같은 사진이 보여요.」라는 안내가 있다. 현재 사진이 기본 사진이면 해당 칸에 테두리가 표시된다. 기본 사진을 누르면 바로 저장되고 창이 닫히며, 새로 고치지 않아도 설정 상단과 위 막대의 사진이 바뀐다. 저장에 실패하면 창이 열린 상태로 유지되고, 실패 이유가 한 줄로 보인다. 휴대폰(390px)에서도 창과 그 안의 모든 단추가 화면 안에 들어오고, 화면이 옆으로 밀리지 않는다.

#### Scenario: 기본 사진 고르기
- **WHEN** 설정 상단의 동그라미를 누르고 기본 사진 11번(`user-3.jpg`)을 누른다
- **THEN** 창이 닫히고 설정 상단에 그 사진이 보이며, 설정을 닫으면 위 막대에도 보인다
- **AND** `users.profile`은 `/assets/images/profile/user-3.jpg`이고, 새로 고쳐도 같은 사진이 보이며, 창을 다시 열면 해당 칸에 테두리가 있다

### Requirement: 사진 바꾸기 — 내 사진 올리기
시스템은 「내 사진 올리기」로 선택한 사진을 브라우저에서 가운데를 기준으로 정사각형으로 자르고, 한 변이 256px 이하가 되도록 줄인 뒤 올려야 한다(SHALL). 원본이 더 작으면 원본 크기를 유지한다. 형식은 WebP이며, 브라우저가 WebP를 만들지 못하면 JPEG로 만든다. 사진은 이 설치의 저장소(`files` 버킷)에 있는 해당 사용자의 폴더(`pgpt-pro/<사람 id>/avatar/`)에 새 이름으로 저장되고, 공개 주소가 `users.profile`에 들어간다. 새 사진을 올리거나 사진을 바꾸거나 지우면, 해당 사용자가 전에 올린 사진은 다른 회사의 행에서도 사용하지 않는 경우 저장소에서 지운다. 열 수 없는 파일(사진이 아닌 파일, 브라우저가 읽지 못하는 형식)이거나 30MB보다 큰 파일이면 창에 이유가 한 줄로 보인다(「이 사진은 열 수 없어요. JPG · PNG · WebP 사진을 골라 주세요.」 · 「30MB 보다 큰 사진은 올릴 수 없어요.」).

#### Scenario: 가로로 긴 사진
- **WHEN** 640×400 사진을 올린다
- **THEN** 위 막대 · 설정 · 프로필 화면에 256×256 사진이 보이고, 그 주소는 이 설치 저장소의 `files/pgpt-pro/<내 id>/avatar/` 아래에 있다

#### Scenario: 다시 올리기
- **WHEN** 사진을 올린 뒤 다른 사진을 또 올린다
- **THEN** 새 사진이 보이고, 앞서 올린 사진의 주소는 더 이상 열리지 않는다

### Requirement: 사진 지우기 — 기본 사진으로 되돌리기
시스템은 「사진 지우기」를 누르면 선택한 사진을 지우고 해당 사용자의 기본 사진으로 되돌려야 한다(SHALL). 구글로 로그인한 사용자가 「Google 사진으로」를 누르면 `users.profile`이 구글 사진 주소로 바뀌고, 두 앱 모두 구글 사진을 보여 준다. 그 밖의 사용자는 `users.profile`을 해당 칸의 기본값(새 계정과 같은 값, Process GPT에서는 「사진 없음」)으로 되돌리고, 모든 Lite 화면에서 이름 첫 글자를 보여 준다. 기본 사진은 서버가 인증 기록을 바탕으로 정하며, 화면에서는 주소를 보내지 않는다. 지운 사진이 해당 사용자가 올린 사진이었다면 저장소에서도 지운다. 「지웠다」는 표시는 따로 두지 않는다. 구글로 로그인한 사용자에게 「사진 없음」은 곧 구글 사진을 뜻하기 때문이다.

#### Scenario: 구글 사진으로 되돌리기
- **WHEN** 기본 사진 5번을 선택한 이하준이 「프로필 사진」 창에서 「Google 사진으로」를 누른다
- **THEN** 구글 사진이 보이고 `users.profile`은 구글 사진 주소이며, 다른 팀원의 화면에도 구글 사진이 보인다

#### Scenario: 지우기
- **WHEN** 메일 코드로 로그인하는 김서연(구글 사진 없음)이 자신이 올린 사진을 사용 중인 상태에서 「사진 지우기」를 누른다
- **THEN** 설정 상단과 위 막대에 「김」이 보이고, `users.profile`은 `/images/defaultUser.png`, `GET /api/me`의 `user.picture`는 `null`이며, 올렸던 사진의 주소는 열리지 않는다

### Requirement: 서버는 정해진 사진만 저장하고, 자기 행만 바꾼다
시스템은 `PUT /api/me/picture`의 `{ picture }`로 다음 세 가지만 받아야 한다(SHALL). 그 밖의 값은 400과 이유(`error`)를 반환하며 거절한다.
- Process GPT의 기본 사진 18장 중 하나의 경로를 글자 그대로 전달한 값
- 이 설치 저장소의 `files` 버킷에서 해당 사용자 자신의 폴더(`pgpt-pro/<사람 id>/avatar/`)에 있는 `jpg` · `jpeg` · `webp` · `png` 파일의 공개 주소. 파일 이름에는 영문 · 숫자 · `-` · `_`만 쓸 수 있으며, 쿼리나 조각(`?` · `#`), 하위 폴더, `..`는 붙일 수 없다
- 빈 값(`null` · `""`): 사진 지우기

거절하는 값의 예는 다른 사이트의 주소(추적 픽셀), `//`로 시작하는 주소, `data:` · `javascript:`, 다른 사용자의 폴더나 자신의 다른 폴더(`att/` 등)에 있는 파일, 다른 버킷이나 서명 주소, 18장에 없는 경로, `/images/defaultUser.png`, 문자열이 아닌 값이다. `POST /api/me/picture/upload`는 요청 본문의 앞부분 바이트가 JPEG · WebP · PNG임을 나타낼 때만 받는다(요청에 명시된 형식은 믿지 않는다). 1MB를 넘는 업로드는 413으로, 그림이 아닌 바이트(HTML · SVG · JSON 등)는 400으로 거절한다. 받은 사진은 해당 사용자의 폴더에 새 이름으로 저장한 뒤, 위 규칙에 따라 사진 주소를 저장한다. 두 경로 모두 로그인한 사용자의 해당 회사 행 하나만 바꾸고, 로그인하지 않은 요청에는 401을 반환한다.

구글 사진 주소는 화면에서 보낸 값으로는 받지 않는다(400). 서버는 인증 기록에서 읽은 구글 사진만 사용한다.

화면에 보내는 사진(`user.picture`, `GET /api/people/pictures`)도 검사한다. 이 사이트의 그림(`/images/…` · `/assets/images/…`의 png · jpg · webp · gif), 이 설치 저장소의 공개 그림, 허용된 호스트의 구글 사진만 보낸다. 그 밖의 값(다른 앱이 저장한 다른 사이트의 주소 등)은 `null`로 보내 화면에서 해당 주소를 아예 요청하지 않게 한다. `GET /api/people/pictures`는 해당 회사에서 표시할 사진이 있는 사용자(에이전트 제외)를 `{ 사람 id: 사진 }` 형태로 반환한다.

#### Scenario: 다른 사이트의 주소
- **WHEN** `PUT /api/me/picture`에 `https://tracker.example.com/pixel.gif`를 보낸다
- **THEN** 400을 반환하고, `users.profile`은 그대로다

#### Scenario: 남의 사진
- **WHEN** 김서연이 박도윤의 폴더(`pgpt-pro/<박도윤 id>/avatar/a.webp`) 주소를 보낸다
- **THEN** 400을 반환하고, 박도윤의 행도 김서연의 행도 바뀌지 않는다

#### Scenario: 다른 앱이 저장한 다른 사이트 주소
- **WHEN** 다른 앱이 `users.profile`에 다른 사이트의 주소를 저장한 상태에서 Lite를 연다
- **THEN** `user.picture`는 `null`이고, 동그라미에는 이름 첫 글자가 보이며, 브라우저는 그 주소를 요청하지 않는다

#### Scenario: 그림이 아닌 업로드
- **WHEN** HTML 문서를 `Content-Type: image/png`로 `POST /api/me/picture/upload`에 보낸다
- **THEN** 400을 반환하고, 저장소에도 `users.profile`에도 아무것도 남지 않는다
