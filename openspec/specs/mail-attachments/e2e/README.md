## 화면 시험 (Playwright, `e2e/tests/feature/mail-attachments.spec.js`)

```bash
cd e2e && RT_WORKERS=1 npx playwright test --project=feature tests/feature/mail-attachments.spec.js
# 이음오피스 편집기: lib/officeHost.js 가 빌드된 process-gpt-office-host 를 띄운다(RT_OFFICE_HOST_DIR, 없으면 이웃 ../ieumoffice-web).
# 시트 편집기의 엔진(xlsx-sidecar)은 그 체크아웃의 native/xlsx-engine/target/release 또는 .toolchain/xlsx-target/release 에서 찾는다(XLSX_SIDECAR_PATH 로 줄 수도 있음).
```

- 자기 스택을 띄운다(`lib/localStack.js` — 테넌트 `mailatt-ui`, BFF 8930~ · Vite 5330~). 가짜 Google(8937~, Gmail 원문 · 첨부), 가짜 deepagents(8938~, 받은 첨부를 실제로 열어 exceljs 로 합계를 셈), 가짜 모델(8936~, 채팅 라우터는 늘 DELEGATE)은 이 파일이 띄운다. 실제 모델 · 공용 deepagents(:8888) · completion(:8099) · 허브(:8500)는 부르지 않는다.
- BFF 의 `PGPT_ROOT` 는 임시 폴더다(키가 든 `.env` 는 링크, 에이전트 작업 공간은 비어 있는 임시 폴더). 개발 PC 의 실제 deepagents 작업 공간에 쓰지 않는다.
- 보관함 키링도 이 시험의 것이다(`PRO_VAULT_KEYRING` 을 BFF 와 시험 프로세스가 같이 씀). 한지우의 Gmail 연결은 시험 프로세스가 서버 모듈로 넣는다.
- 메일은 진짜 RFC 822 다(nodemailer): 급여대장(exceljs 로 만든 xlsx), 그림(png), zip.
- 네트워크 확인: 페이지와 그 안의 모든 프레임이 보낸 요청 주소, 그리고 서버의 JSON 응답 전부에 `/storage/v1/object/public/` 이 없는지 본다(F-MA-01 · 02 · 03 · 05 · 07 · 08).
- 끌기는 DataTransfer 끌기 이벤트로 시험한다.
- 사람 · 회사는 지어낸 것이다(한지우 · 서민재, 세무법인 오가람, 하늘테크).

시험하지 않은 것:
- 실제 Gmail 메일함. 가짜 Gmail 의 `format=minimal`(크기) · `format=raw`(원문)를 읽는다. 메일함의 시간 한도(Gmail 60 · 120초, IMAP 연결을 닫음)는 실제로 기다려 보지 않았다(단위 시험은 504 를 흉내 내 기억만 확인). 실제 Gmail 의 원문 크기 한도, 아주 큰 첨부(수십 MB)를 원문 하나로 받는 시간은 재지 않았다(서버는 50MB 를 넘는 첨부를 거절한다). IMAP 메일함도 같은 길(`sourceOf`)이지만 이 시험에는 없다.
- 운영 저장소(Supabase)에서 비공개 버킷이 처음 만들어지는 것(로컬에서는 처음 실행 때 만들어졌다). 운영의 이음오피스 호스트가 저장소의 서명 주소를 받아들이는지는 그 호스트의 허용 출처(`SUPABASE_URL` · `IEUM_ALLOWED_SOURCES`)에 달렸다 — 지금 공개 주소를 받는 출처와 같은 출처다.
- 운영 deepagents(파드)가 서명 주소를 받아 실제로 내려받는 것. 시험의 에이전트는 경로 쪽(같은 기계의 작업 공간)으로 읽고, 서명 주소 쪽은 서버 시험이 실제 저장소로 확인한다.
- 실제 모델이 첨부를 읽고 하는 답의 품질. 영어 화면의 스크린숏. 사람 손의 실제 끌기.
- 동료가 읽기 전용으로 연 문서의 셀 값을 편집기 안에서 읽는 것(편집기가 칸을 그림으로 그림). 그 편집기가 받은 서명 주소의 내용이 첨부 그대로인지를 확인한다.
