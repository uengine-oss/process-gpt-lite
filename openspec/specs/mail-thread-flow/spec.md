# 메일에서 일로 — 메일 칩, 그리고 메일로 인스턴스를 열고 잇기

## Purpose
메일 비서는 새 메일을 읽어 Home에 할 일 카드를 만들고, 채팅에 「모닝 브리프」 요약을 남긴다. 2026-11-24 운영 화면에서는 이 브리프가 요약 말풍선으로만 표시되어, 메일 원문이나 Home에서 작업하던 카드로 이동할 수 없었다. 같은 채팅의 예약 실행 결과에는 해당 예약으로 이동하는 칩이 있었지만, 브리프에는 그런 칩이 없었다. 또한 메일은 회사 프로세스 지도에서 일을 시작하는 사건이지만, 메일로 일이 시작될 때 진행 중인 인스턴스와의 상관관계를 파악하고 인스턴스를 여는 화면 흐름이 없었다. 이 스펙은 두 가지를 정한다. 메일에서 나온 채팅 메시지에는 해당 메일로 이동하는 칩을 붙인다. 메일 시트에서는 해당 메일이 어느 프로세스의 시작인지, 어느 진행 중인 인스턴스에 속한 일인지 묻는다. 사람이 프로세스를 시작하거나 인스턴스에 이으면 메일은 해당 인스턴스의 사건이 된다. 근거는 사용자 요청(「메일 기반으로 처리할 일들이 채팅으로 들어올 때 메일 내용과 연관되었음을 표시 … 스케줄이 칩으로 보여지듯 연관된 쓰레드를 표시」, 「메일은 프로세스 지도의 업무 트리거(이벤트) … 인스턴스화되는 UI 흐름」)과 2026-11-18 결정(인스턴스의 일은 해당 인스턴스 화면에서 처리하고 메인 채팅에 덧붙이지 않는다)이다. 설계는 `docs/mail-thread-flow/design.md`에 있다.

## Requirements

### Requirement: 메일에서 나온 채팅 줄은 그 메일로 가는 칩을 단다
시스템은 메일에서 나온 채팅 메시지 아래에 해당 메일의 Home 카드로 이동하는 칩을 보여 주어야 한다(SHALL). 「모닝 브리프」(오후 · 이브닝 브리프도 동일)의 요약 아래에는 해당 수집에서 만든 카드마다 칩을 하나씩 붙인다. 칩에는 카드의 동사와 글이 표시된다. 메일에서 찾은 요청이나 보낸 답장처럼 메일 한 통에 관한 메시지에는 「메일 · <제목>」 칩을 하나 붙인다. 칩을 누르면 해당 카드의 메일 시트(원문과 답장)가 열린다. Home에서 치운 카드의 시트도 열린다. 칩은 예약 실행의 「… 관리」 칩과 같은 알약 모양이며, 휴대폰 화면 너비를 넘지 않는다. 칩이 가리키는 카드는 `GET /api/mail/card?action=&mail=`로 조회하며, 다른 사람의 카드는 조회할 수 없다(404).

#### Scenario: 모닝 브리프의 칩
- **WHEN** 새 메일에서 「Reply」 카드가 생성되고 채팅에 「모닝 브리프」 요약이 남는다
- **THEN** 요약 아래에 「Reply · <카드 글>」 칩이 표시된다
- **AND** 칩을 누르면 해당 메일의 원문과 답장 초안이 담긴 시트가 열린다

#### Scenario: 휴대폰
- **WHEN** 휴대폰 화면(390×844)의 채팅 탭에서 브리프를 본다
- **THEN** 칩이 화면 안에 표시되고, 누르면 같은 시트가 열린다

---

### Requirement: 시트에서 Home 카드로 돌아간다
시스템은 채팅이나 인스턴스 화면에서 연 메일 시트에 「Home 카드로」를 보여 주어야 한다(SHALL). 이 항목은 카드가 Home에 있을 때만 표시되며, Home에서 연 시트에는 표시되지 않는다. 「Home 카드로」를 누르면 시트가 닫히고 Home으로 이동한다(휴대폰에서는 홈 탭). 해당 카드가 화면 안에 들어오도록 이동하고, 카드의 테두리가 잠깐 빛난다. Home에 카드가 다섯 장 넘게 있어 해당 카드가 목록 밖에 있더라도 이때는 표시한다.

#### Scenario: 채팅에서 연 시트
- **WHEN** 브리프 칩으로 시트를 열고 「Home 카드로」를 누른다
- **THEN** 시트가 닫히고 Home의 해당 카드가 화면 안에 표시되며 테두리가 빛난다

---

### Requirement: 같은 Gmail 스레드의 메일은 그 스레드의 진행 중인 인스턴스에 먼저 잇는다
시스템은 메일 카드에 해당 메일의 Gmail 스레드를 기록해야 한다(SHALL). 새 메일이 들어왔을 때 같은 스레드의 이전 메일이 아직 진행 중인 인스턴스에 이어져 있으면, 모델을 사용하지 않고 해당 인스턴스에 이어야 한다(SHALL). 이때 다음이 함께 일어난다.
- 인스턴스 대화에 「메일 · <제목>」 구분선과 「같은 메일 스레드로 <보낸 사람>님의 새 메일 「<제목>」이 왔어요.」가 남는다.
- Home에 「메일이 이어졌어요 · <인스턴스>」 알림이 오고, 누르면 해당 인스턴스가 열린다.
- 카드와 브리프 칩은 해당 인스턴스를 가리킨다.
- 같은 메일로 지도 프로세스를 새로 시작하지 않는다.

종료된 인스턴스에는 잇지 않는다. 시트를 열었을 때 같은 스레드의 진행 중인 인스턴스가 있으면, 「진행 중인 ‘<인스턴스>’에 잇기」를 「같은 메일 스레드」라는 이유와 함께 가장 먼저 권한다.

#### Scenario: 고객이 같은 스레드로 다시 쓴다
- **WHEN** 견적 인스턴스에 이어진 메일의 스레드로 고객이 새 메일을 보낸다
- **THEN** 새 메일의 카드가 해당 인스턴스에 이어지고, 인스턴스 대화와 Home 알림에 새 메일이 표시된다
- **AND** 해당 메일로 새 건이 시작되지 않는다

#### Scenario: 끝난 인스턴스
- **WHEN** 같은 스레드의 이전 메일이 이어진 인스턴스가 이미 종료되었다
- **THEN** 새 메일은 해당 인스턴스에 이어지지 않는다

---

### Requirement: 시트는 그 메일이 시작하는 프로세스와, 같은 일인 진행 중인 인스턴스를 묻는다
시스템은 인스턴스에 이어지지 않은 메일 카드의 시트에서, 해당 메일이 회사 프로세스 지도의 어느 프로세스의 시작인지와 어느 진행 중인 인스턴스와 같은 일인지를 보여 주어야 한다(SHALL). 조회에는 `GET /api/actions/:id/flow`를 사용한다. 시트를 여는 것만으로는 아무것도 시작하거나 잇지 않는다.

- **지도와 맞는 프로세스**: 지도가 메일을 제안 · 자동 단계 프로세스의 시작으로 판단하면, 「이 메일은 ‘<프로세스>’의 시작으로 보여요 — 진행할까요?」와 함께 시작 일, 단계, 확신을 보여 준다. 관찰 단계 프로세스는 권하지 않는다(MUST NOT). 지도와 대조하는 동안에는 「회사 프로세스 지도와 견주는 중…」이 표시된다. 대조 결과는 카드에 저장하며, 시트를 다시 열 때는 다시 대조하지 않는다. 지도를 읽지 못하면 물음 없이 원문과 답장만 보여 준다.
- **진행 중인 같은 일**: 내가 시작한 진행 중인 건과 내 메일이 이어진 진행 중인 인스턴스가 후보가 된다. 판정 모델은 후보마다 「같은 한 건의 일인가」를 판단하고, 그 확률이 기준값(기본 0.7, 스킬 규칙 `mailFlow.joinMin`) 이상이면 「진행 중인 ‘<인스턴스>’에 잇기 · 같은 일 90%」를 권한다. 한 번 판정한 후보는 다시 판정하지 않는다. 판정은 모델이 수행하며, 낱말 규칙으로 의미를 판단하지 않는다.
- **단추**: 「새로 시작」 · 「진행 중인 ‘…’에 잇기」 · 「이번엔 안 해요」를 보여 준다. 다른 프로세스와도 맞으면 「‘<프로세스>’로 시작」도 보여 준다.
- **카드 한 줄**: Home 카드에도 「‘<프로세스>’의 시작으로 보여요」를 한 줄로 보여 준다.

#### Scenario: 제안 단계 프로세스와 같은 일
- **WHEN** 지도가 메일을 제안 단계 「견적 요청 · 견적서 작성」의 시작으로 판단했고, 판정 모델이 진행 중인 견적 인스턴스와 같은 일일 확률을 90%로 판단한다
- **THEN** 시트에 「이 메일은 ‘견적 요청 · 견적서 작성’의 시작으로 보여요 — 진행할까요?」, 「새로 시작」, 「진행 중인 ‘…’에 잇기 · 같은 일 90%」, 「이번엔 안 해요」가 표시된다
- **AND** 아직 아무것도 시작되거나 이어지지 않은 상태다

#### Scenario: 다른 일
- **WHEN** 판정 모델이 진행 중인 인스턴스와 같은 일일 확률을 기준값보다 낮게 판단한다
- **THEN** 해당 인스턴스는 「잇기」 대상으로 권하지 않는다

#### Scenario: 관찰 단계
- **WHEN** 메일과 맞는 프로세스가 관찰 단계다
- **THEN** 시트는 해당 프로세스를 시작할지 묻지 않는다

---

### Requirement: 시작과 잇기는 사람이 누를 때 한 번만 하고, 메일은 그 인스턴스의 사건이 된다
시스템은 사람이 「새로 시작」이나 「잇기」를 눌렀을 때만 해당 작업을 수행해야 한다(SHALL). 「새로 시작」(`POST /api/actions/:id/flow/start`)은 지도가 이 메일에 해당한다고 판단한 프로세스를 해당 시작 일부터 연다. 건의 요청에는 메일의 제목 · 본문 · 보낸 사람을 사용한다. 지도가 해당한다고 판단하지 않은 프로세스는 받지 않는다(400). 「잇기」(`POST /api/actions/:id/flow/join`)는 내가 볼 수 있고 아직 진행 중인 인스턴스에만 메일을 잇는다(볼 수 없으면 403, 종료되었으면 409). 두 작업 모두 해당 메일에 대해 한 번만 수행할 수 있다. 이미 이어진 메일에 대한 요청이나 동시에 두 번 누른 요청에는 409를 반환한다. 시작에 실패하면 시트에 이유를 보여 준다. 카드는 이어지지 않은 상태로 남으며, 다시 눌러 시도할 수 있다.

시작하거나 이으면 다음이 일어난다.
- 화면이 해당 인스턴스(`/routines/<instId>`)로 이동한다.
- 인스턴스 대화에 「메일 · <제목>」 구분선과 「<보낸 사람>님의 메일 「<제목>」로 ‘<프로세스>’를 시작했어요. 「<시작 일>」부터 해요.」(잇기인 경우 「… 메일 「<제목>」을 이 일에 이었어요.」)가 메일 칩과 함께 남는다. 이 칩을 누르면 해당 메일의 시트가 열린다.
- 메인 채팅에는 아무것도 덧붙이지 않는다(MUST NOT).
- 해당 메일의 Home 카드에는 「루틴 · <인스턴스>」가 표시되며, 누르면 인스턴스가 열린다.
- 브리프와 메일 메시지의 칩도 「루틴 · <인스턴스>」로 바뀌며, 누르면 인스턴스가 열린다.
- 시트에는 「루틴 · <인스턴스> 열기」가 표시된다(해당 인스턴스 화면에서 연 시트에는 표시되지 않는다).

#### Scenario: 진행 중인 인스턴스에 잇는다
- **WHEN** 시트에서 「진행 중인 ‘…’에 잇기」를 누른다
- **THEN** 해당 인스턴스 화면이 열리고, 대화에 메일 구분선과 「… 이 일에 이었어요.」가 표시된다
- **AND** 채팅의 브리프 칩이 「루틴 · <인스턴스>」로 바뀌며, 누르면 해당 인스턴스가 열린다

#### Scenario: 새로 시작한다
- **WHEN** 시트에서 「새로 시작」을 누른다
- **THEN** 해당 프로세스의 건이 시작 일부터 열리고, 화면이 해당 인스턴스로 이동한다
- **AND** 인스턴스 대화의 첫 사건은 해당 메일이다

#### Scenario: 시작할 수 없다
- **WHEN** 지도 엔진에 연결할 수 없어 시작하지 못한다
- **THEN** 시트에 이유가 표시되고, 카드는 이어지지 않은 상태로 남아 다시 누를 수 있다

#### Scenario: 두 번 누른다
- **WHEN** 이미 시작하거나 이은 메일로 다시 시작하거나 잇는다
- **THEN** 409를 받고 새 건은 생성되지 않는다

### Requirement: 「이번엔 안 해요」
시스템은 사람이 「이번엔 안 해요」를 누르면 해당 메일에 대해 더 이상 묻지 않아야 한다(SHALL). 시트에는 「이 메일로는 프로세스를 시작하지 않기로 했어요.」와 「다시 묻기」가 표시되고, Home 카드의 한 줄 안내도 사라진다. 「다시 묻기」를 누르면 다시 묻는다. 이때 지도는 다시 읽지 않고 카드에 저장된 결과를 사용한다. 요청에는 `POST /api/actions/:id/flow/decline {undo?}`를 사용한다.

#### Scenario: 이번엔 안 한다
- **WHEN** 「이번엔 안 해요」를 누른다
- **THEN** 물음이 사라지고 「다시 묻기」가 표시된다

---

### Requirement: 자동 단계 프로세스는 메일로 저절로 시작하고, 그 인스턴스에서 일한다
시스템은 메일을 받을 때 지도가 해당 메일을 자동 단계 프로세스의 확실한 시작으로 판단하면, 사람에게 묻지 않고 시작해야 한다(SHALL). 현재는 문서를 요청하는 메일을 받을 때 지도를 읽는다. 시작하면 다음이 일어난다.
- 메일이 인스턴스 대화의 첫 사건으로 남는다(「…님의 메일 「…」이 와서 ‘…’이 저절로 시작됐어요(자동 단계).」).
- Home에 「메일로 시작 · <인스턴스>」 알림이 온다.
- 해당 메일의 카드와 칩은 인스턴스를 가리킨다.
- 메인 채팅에는 덧붙이지 않는다(MUST NOT).

같은 인스턴스에 대한 Home 알림이 있으면 메일 카드는 Home에 중복으로 표시하지 않는다. 시작 일이 확실하지 않은 자동 단계 프로세스와 제안 단계 프로세스는 시작하지 않는다. 대신 카드에 남겨 시트에서 시작할지 묻는다.

#### Scenario: 자동 단계의 시작
- **WHEN** 지도가 문서를 요청하는 메일을 자동 단계 프로세스의 확실한 시작으로 판단한다
- **THEN** 해당 프로세스가 시작되고, Home 알림을 누르면 메일이 첫 사건으로 기록된 인스턴스가 열린다
- **AND** 메인 채팅에는 묻는 카드도 시작 카드도 없다

#### Scenario: 제안 단계
- **WHEN** 지도가 같은 메일을 제안 단계 프로세스의 시작으로 판단한다
- **THEN** 시작하지 않고, 카드의 시트에서 「진행할까요?」라고 묻는다

---

### Requirement: 인스턴스에 이어진 메일의 답장은 그 인스턴스에 남는다
시스템은 인스턴스에 이어진 메일에 대해 시트에서 답장을 보내면, 보낸 기록을 해당 인스턴스 대화에 메일 칩과 함께 남겨야 한다(SHALL). 메인 채팅에는 남기지 않는다(MUST NOT). 시트에는 「루틴 · <인스턴스>에 기록했어요.」가 표시된다. 인스턴스에 이어지지 않은 메일의 답장은 지금처럼 메인 채팅에 남기되 메일 칩을 붙인다. 「보내기」를 눌러야 보낸다는 규칙(스펙 `mail-reply-review`)은 그대로 유지한다.

#### Scenario: 인스턴스 화면에서 답장한다
- **WHEN** 인스턴스 대화의 메일 칩으로 시트를 열어 초안을 고치고 「보내기」를 누른다
- **THEN** 시트에 「루틴 · <인스턴스>에 기록했어요.」가 표시되고, 인스턴스 대화에 「…에게 보낼 답장 …」이 남는다
- **AND** 메인 채팅에는 남지 않는다
