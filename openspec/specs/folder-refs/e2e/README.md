# 시험과 증거 — 폴더 참조 0단계

참조를 푸는 함수(`server/lib/folders/refs.js` `resolve`)는 단위 시험으로 검증한다. 단위 시험에서는 실제 git과 개발 데이터베이스를 쓰며, 사람 · 자리 종류 · 상태별로 결과를 확인한다. 데이터베이스의 회사 경계(트리거 · RLS)도 같은 파일에서 확인한다. 세 사람이 같은 폴더를 요청하는 HTTP 시험과 화면 시험은 Playwright 파일 하나에서 수행한다. 이 파일은 자체 스택(회사 `folder-refs-web`, BFF 8976 · Vite 5376)과 가짜 모델, 가짜 deepagents를 띄운다. 가짜 deepagents는 채팅 메시지에 담긴 사용자 JWT로 BFF의 실제 폴더 도구(`/mcp/folders`의 `folder_files` · `folder_read`)를 호출하고, 읽은 내용을 답에 옮긴다. 실제 모델과 에이전트는 호출하지 않는다. 사람 · 회사 · 자료는 지어낸 것이다(한서연 · 오지후 · 윤도하, 「영업 자료」 · 「규정집」 · 「제안 준비」).

데이터베이스 변경 파일은 `server/sql/065_folder_refs.sql`이다(추가만 하며 여러 번 실행해도 된다). 개발 공용 데이터베이스에는 적용했다(두 번 실행해 같은 결과를 확인했다).

## 단위 · 통합 시험

```bash
cd server && node --test test/folderRefs.test.js
```

- **RF-U-01 · 02 자리 찾기 · 겹침:** 자리 자체와 그 아래 경로만 자리에 속한다. `폴더10/…`처럼 이름이 같은 글자로 시작하는 다른 경로는 속하지 않는다. 두 경로가 같거나 한쪽이 다른 쪽 안에 있으면 겹친다.
- **RF-U-03 거절:** 잠긴 자리는 403(`ref_locked`), 끊어진 자리는 404(`ref_dangling`)로 거절한다. 정상 자리 · 자리 밖은 거절하지 않는다.
- **RF-U-04 더하기:** 폴더 전체 · 하위 폴더 · 파일 하나 중 어떤 종류인지는 원본을 기준으로 정한다. 파일 자리는 원본의 확장자를 유지한다. 새 참조는 기본으로 main을 따라가며, 기록의 회사는 이 회사다.
- **RF-U-05 resolve:** 원본의 구성원에게는 원본 main의 최신 판과 원본 안의 경로(하위 폴더면 그 아래, 파일이면 자리 자체)를 반환한다. 구성원이 아니면 `{ref, state: 'locked'}`만 반환한다.
- **RF-U-06 잠긴 자리의 모양:** 목록의 잠긴 자리에는 `by · id · label · requested · slot · state`만 있다. 원본의 id · slug · 이름 · 경로 · 판은 없다. 파일 목록 · 에이전트 도구 · 채팅 안내에도 원본의 이름이나 파일이 나오지 않는다.
- **RF-U-07 깊이 1:** 참조된 폴더가 다시 다른 폴더를 참조해도 그 자리는 따라가지 않는다. 자기 자신은 참조할 수 없다.
- **RF-U-08 더하기 거절:** 편집자가 아님(403), 원본의 구성원이 아님(없는 폴더와 같은 404), 스킬 폴더(400), 이 폴더의 파일이 있는 자리 · 겹치는 자리(409 `ref_taken`), 원본에 없는 경로(404), `..` · `.git`이 든 자리(400)를 거절한다.
- **RF-U-09 회사 경계:** 다른 회사의 폴더는 id로도 slug로도 찾지 못한다(404). 회사가 다른 기록은 데이터베이스 트리거가 거절한다(`23514`, 넣기 · 고치기 모두). 트리거를 통과해 들어간 기록이 있어도 끊어진 자리로만 보이고 아무 내용도 반환하지 않는다. RLS가 켜져 있어 `authenticated` 역할로는 행이 보이지 않는다.
- **RF-U-10 구성하는 폴더에서는 읽기만:** 자리의 올리기 · 지우기 · 이음오피스 저장 · 작업실 쓰기는 409(`ref_readonly`)로 거절한다. 자리 밖의 경로에는 그대로 쓸 수 있다. 폴더에 넣기는 자리 이름과 겹치지 않는 다른 이름을 고른다.
- **RF-U-11 실행의 쓰기:** 실행이 변형의 작업 폴더에서 자리 아래에 쓰거나 스테이징한 파일은 커밋에 담지 않는다. 자리 밖의 새 파일은 담는다. 해당 대화에는 「읽기 전용」 칩이 남는다.
- **RF-U-12 끊어짐 · 자리가 우선:** 원본의 파일을 지우면 읽기는 404를 반환하고, 목록에는 「끊어짐」으로 표시된다. 원본 폴더를 지우면 기록은 남고 원본이 비워지며, 원본 정보 없이 「끊어짐」으로 표시된다. main의 작업 트리에서 자리에 쓴 파일은 이 서버의 커밋에 담기지 않는다. 자리는 계속 원본을 읽으며, 그 경로에 올리기는 409로 거절한다.
- **RF-U-13 구성원에서 빠짐:** 원본 구성원에서 빠진 직후 자리가 잠기고, 다시 들어오면 열린다.
- **RF-U-14 접근 요청:** 자리가 잠긴 사람만 요청하며 기록이 남는다. 응답에는 원본 정보가 없다. 하루 안의 두 번째 요청은 기록을 추가하지 않는다. 원본을 읽을 수 있는 사람은 요청하지 않는다.
- **RF-U-15 저장소:** 어느 폴더 저장소에도 gitlink · `.gitmodules`가 없다. 구성하는 폴더의 main과 색인에는 자체 파일만 있다.
- **RF-U-16 함께 지우기:** 구성하는 폴더와 원본을 한 문장으로 함께 지워도 된다(원본이 비워지는 기록이 회사 확인에 걸리지 않는다).
- **RF-U-17 이름에 「tree」 · 「blob」이 든 경로:** 「Family tree」 같은 이름도 비어 있는 자리로 인식해 더할 수 있고, 원본에 없는 「a/Org tree」는 없는 경로(404)로 거절한다. git이 모르는 이름을 종류로 잘못 해석하지 않는다.

- **RF-U-18 ~ RF-U-25 (PR #92 검토 반영)** — 각 시험이 수정 전 코드에서 먼저 실패하는 것을 확인했다(실패 이유는 괄호 안에 적었다).
  - **RF-U-18 이름 없이 더한 자리:** 자리 이름은 「참조 1」 · 「참조 2」가 된다. 원본을 읽지 못하는 동료의 자리 목록 · 에이전트 보기 · 채팅 안내에는 원본 폴더 이름 · 파일 이름 · 하위 폴더 이름이 없다. 파일 자리의 이름에는 형식을 직접 적었거나(「z/메모.txt」) 붙이기를 골랐을 때(「y/innocuous.md」)만 형식이 붙는다. 「x/innocuous」는 그대로 원본 파일을 읽는다(수정 전: 이름이 「규정집 …」이었다).
  - **RF-U-19 경로 끝의 「/」:** 「안내/」 · 「/가격표.xlsx/」의 경로를 정리해 저장하고, 하위 폴더 · 파일로 읽는다(수정 전: 404).
  - **RF-U-20 main의 자리에 놓인 파일:** 다른 올리기 작업이 커밋을 만들어도 그 커밋에 담기지 않고, 지워지지도 않는다(수정 전: 커밋에 함께 담겼다).
  - **RF-U-21 확인하지 못하면 커밋하지 않음:** 자리를 찾는 질의가 실패하면 올리기는 503과 「참조 자리를 확인하지 못해 저장하지 않았어요」를 반환하고 끝난다. 아무것도 커밋하지 않는다(수정 전: 이런 처리 경로가 없었다).
  - **RF-U-22 지우지 않음 · 열린 변형:** 변형의 작업 폴더에 저장하지 않은 「a/notes.md」가 있으면 「a」에 참조를 더하지 않고 해당 변형의 이름을 알린다. 실행이 자리에 쓴 파일은 커밋에서만 빠지고 작업 폴더에는 그대로 남으며, 칩에 「지우지 않았어요」가 표시된다(수정 전: 참조가 더해졌고, 파일이 지워졌다).
  - **RF-U-23 자리가 우선:** 서버의 커밋을 거치지 않은 커밋이 자리 경로에 넣은 파일은 목록에서 가려진다(「가림 1」). 그 경로는 원본을 읽으며, 쓰기는 409로 거절한다(수정 전: 자리가 「이름 겹침」 상태가 되어 우선하지 못했다).
  - **RF-U-24 성능:** 동시에 넷까지 읽으며, 한 원본의 자리 20개를 읽어도 git은 원본마다 두 번(머리 · 종류)만 실행한다. 트리 · 에이전트 목록의 상한과 남은 수를 확인한다. 폴더를 이름으로 찾는 catalog에는 자리 상태가 없다(수정 전: 함수가 없었고, 자리마다 git을 실행했다).
  - **RF-U-25 세부 사항:** 자리로 연 `folder_open` 카드는 읽기 전용이다. 접근 요청을 동시에 세 번 눌러도 기록은 하나만 남는다. 500 응답에는 내부 메시지가 없다. 구성하는 폴더를 지우면 참조 기록도 지워진다. 트리거 함수에 `search_path`가 있다(수정 전: 카드를 편집할 수 있었다).

- **RF-U-26 ~ RF-U-31 (2차 검토 반영)** — 각 시험이 9a23dc1의 코드에서 먼저 실패하는 것을 확인했다(실패 이유는 괄호 안에 적었다).
  - **RF-U-26 자리 위의 링크:** 자리 「p/q」의 부모 「p」가 링크여도 다른 올리기 작업은 커밋되고, 링크 너머에는 아무것도 쓰이지 않는다(수정 전: 모든 커밋이 「beyond a symbolic link」로 실패했다).
  - **RF-U-27 변형 커밋의 거절:** 자리를 확인하지 못하면 `commitVariation`이 `ref_unchecked`(503)로 거절된다. 변형은 「작업 중」으로 남고, 작업 폴더의 파일도 그대로다(수정 전: 거절이 무시되고 「반영 대기」가 되었다).
  - **RF-U-28 보관 자리:** main의 자리에 새로 놓인 파일은 `.slot-leftover/<시각>/`로 옮긴다. 제자리에서 고친 파일은 복사한 뒤 main의 내용으로 되돌려 `git status`를 깨끗하게 유지한다. 자리를 빼기 직전에 놓인 파일도 먼저 옮겨져 다음 커밋에 담기지 않는다(수정 전: main에 변경 사항이 계속 남아 있었다). 편집자 알림은 회사 행이 있는 RF-E-06에서 확인한다.
  - **RF-U-29 가려진 파일:** 채팅 안내 · 폴더에 넣기의 판단 · 회의 자료 후보에 가려진 파일이 나오지 않는다(수정 전: 채팅 안내에 나왔다).
  - **RF-U-30 유니코드:** NFD로 전달한 자리는 NFC로 저장된다. NFD 경로도 NFC 자리와 같은 자리로 인식하며, 쓰기는 409로 거절하고 읽기는 원본에서 한다(수정 전: NFD 그대로 저장했다).
  - **RF-U-31 회사의 날짜:** 접근 요청의 「하루」는 Asia/Seoul의 날짜를 기준으로 한다(수정 전: UTC).
