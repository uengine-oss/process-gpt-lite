# Process GPT Lite 데스크톱 앱 (Electron)

## Purpose
이 스펙은 Lite 서버 하나를 창 하나로 여는 데스크톱 앱(`desktop/`)의 동작을 정한다. 앱은 Lite를 묶어 넣지 않고, 사용자가 고른 서버의 웹 화면을 띄운다. 제목 표시줄은 우리의 다른 데스크톱 앱(Ontological Studio, Robo Architect)처럼 간소화한다. 근거는 2026-11-24 사용자 요청 「라이트 에디션을 일렉트론으로 만들어봐. 타이틀바는 기존 robo-architect 나 studio 처럼 간소화」와 같은 날 정한 제목 영역 모양(하늘 배경이 제목 영역까지 이음매 없이 이어짐 — 권장·기본, 하늘색에 맞춘 단색 띠와 밝음·어두움에 따른 흰색·검정 띠는 대안)이다.

## Requirements

### Requirement: 서버를 한 번 고르고 기억한다
시스템은 처음 켤 때 Lite 서버 주소를 물어야 한다(SHALL). 회사 주소(`https://<회사>.process-gpt.io/lite`)와 이 컴퓨터에 설치한 Lite(`http://localhost:18080`)를 고를 수 있다. 저장하기 전에 `<주소>/api/config`의 응답이 Lite에서 온 것인지 확인해야 하고(SHALL), 연결할 수 없으면 해당 화면에서 알려야 한다. 도메인만 넣으면 `/lite`를 붙여 다시 찾고, 화면 주소(`…/lite/chat`)를 넣으면 앞부분을 쓴다. 고른 주소는 저장하고 메뉴 「서버 바꾸기…」로 바꾼다. 터널처럼 접근 암호(basic auth)가 걸린 주소는 선택 화면에서 아이디와 암호를 받아 해당 서버의 인증 요청에만 응답한다. 암호는 OS 키체인으로 암호화해 저장한다.

#### Scenario: 첫 실행
- **WHEN** 설정이 없는 상태로 앱을 켠다
- **THEN** 서버 선택 화면이 뜬다
- **AND** 연결할 수 없는 주소(`localhost:1`)로 연결을 누르면 「서버에 연결하지 못했어요」가 보이고 아무것도 저장되지 않는다
- **AND** `localhost:<포트>/chat`을 넣으면 `http://localhost:<포트>`가 저장되고 로그인 화면이 열린다

#### Scenario: 서버 바꾸기
- **WHEN** 메뉴 「서버 바꾸기…」를 누른다
- **THEN** 현재 서버 주소가 입력된 선택 화면이 뜨고, 「취소」를 누르면 그 서버의 채팅으로 돌아간다

### Requirement: 로그인은 창 안에서 하고 같은 서버로 돌아온다
시스템은 웹 앱의 로그인(이메일 코드, Google)이 창 안에서 이루어지도록 해야 한다(SHALL). Google 계정 화면과 서버가 알려 준 Supabase 로그인 출처(`/api/config`의 `sso.google`)는 창 안에서 열고, 로그인이 끝나면 같은 서버로 돌아온다. 사용자 에이전트에는 `Electron`을 넣지 않는다.

#### Scenario: 이메일 코드
- **WHEN** 로그인 화면에서 데모 계정 메일과 코드 000000을 넣는다
- **THEN** 채팅 화면이 열린다

#### Scenario: Google
- **WHEN** 「Google로 계속하기」를 누른다
- **THEN** 창 안에서 `accounts.google.com`이 열리고, 시스템 브라우저로 넘어가지 않는다

### Requirement: 제목 표시줄 없이 하늘이 창 맨 위까지 이어진다
시스템은 별도의 제목 띠를 두지 않아야 한다(SHALL). 웹 앱의 하늘 배경은 창 맨 위까지 이어진다. macOS에서는 신호등을 위 메뉴 줄 안((20, 27), 세로 가운데)에 두고, 위 메뉴의 단추가 신호등과 겹치지 않아야 한다(SHALL). 단추는 신호등이 끝나는 곳(x 80)에서 12px 떨어진 곳부터 배치된다. Windows·Linux에서는 오른쪽 위에 투명한 창 단추(`titleBarOverlay`)를 얹고, 웹 앱의 단추는 그 폭(138px)만큼 비켜 간다. 투명하게 표시할 수 없는 환경에서는 설정 `titleBar: "sky"`로 해당 영역에 하늘색 단색을 쓴다. 단추 기호 색과 창 바탕색(불러오는 동안 흰 화면이 번쩍이지 않게)은 웹 앱의 밝음·어두움 설정을 따른다. 창은 위 메뉴 줄의 빈 곳(68px, 위 메뉴가 없는 화면은 40px)을 잡고 끈다. 그 안의 단추·링크·입력·메뉴는 그대로 눌려야 한다(SHALL). 전체 화면에서는 신호등 자리를 비우지 않는다. 휴대폰 폭(760px 이하)의 가로로 스크롤되는 알약 메뉴도 신호등을 비켜 간다. 웹 앱 쪽 변경은 `html.pgl-desktop` 아래에서만 동작하고, 브라우저에서는 아무것도 바뀌지 않아야 한다(SHALL).

#### Scenario: 넓은 폭 (밝음 · 어두움)
- **WHEN** 1280×800 창에서 낮(밝음)과 밤(어두움)의 채팅을 연다
- **THEN** 위 메뉴의 홈 단추가 x 92에서 시작하고 신호등(x 20–80, y 27–41)과 겹치지 않는다
- **AND** 상단 68px이 창을 끌 수 있는 영역이고, 그 안의 단추와 알약 메뉴는 창을 끌 수 있는 영역이 아니며 누르면 동작한다
- **AND** 창 바탕색이 밝음이면 `#4670ad`, 어두움이면 `#0a0f24`이다

#### Scenario: 좁은 폭
- **WHEN** 창을 600px로 줄인다
- **THEN** 휴대폰용 배치로 바뀌고, 알약 메뉴가 x 148부터 시작해 신호등과 검색 단추를 비켜 가며 오른쪽 아바타와도 겹치지 않는다

#### Scenario: 위 메뉴가 없는 화면
- **WHEN** 설정을 연다
- **THEN** 창을 끌 수 있는 영역이 40px이 되고, 설정의 ✕는 그대로 눌린다

#### Scenario: 브라우저
- **WHEN** 같은 웹 앱을 브라우저로 연다
- **THEN** `pgl-desktop` 표시가 없고, 위 메뉴 여백은 16px, 창을 끌 수 있는 영역은 없다

### Requirement: 다른 곳은 창 밖에서 연다
시스템은 선택한 서버의 출처(같은 출처의 ProcessGPT 포함)와 로그인 출처만 창 안에서 열어야 한다(SHALL). 다른 웹 주소와 메일 링크(`mailto:`)는 시스템 브라우저나 메일 앱으로 넘기고, 다른 스킴(`file:` 등)은 차단한다. 같은 서버를 여는 새 창(원본 받기, 문서 링크)은 preload가 없는 일반 창으로 열고, 내려받기만 하는 창은 닫는다. 이 PC에 있는 변형의 작업본은 「폴더 열기」로 파일 관리자(Finder · 탐색기)에서 연다. 「터미널 열기」로는 해당 운영체제의 지정된 터미널(macOS 터미널 · Windows Terminal 또는 명령 프롬프트 · 리눅스의 터미널)에서 연다. 외부 프로그램에는 해당 작업본의 경로 하나만 전달하며, 서버가 보낸 글은 명령으로 실행되지 않는다.

#### Scenario: 바깥 링크
- **WHEN** 채팅 화면에서 `https://example.com`(새 창), `https://example.org`(같은 창), `mailto:` 링크를 누른다
- **THEN** 세 주소 모두 시스템으로 넘어가고, 앱 창은 하나로 유지되고 채팅 화면에 머문다

#### Scenario: 같은 서버의 새 창
- **WHEN** 페이지가 `/api/config`를 새 창으로 연다
- **THEN** 창이 하나 더 열린다

#### Scenario: 작업본을 Finder · 터미널에서
- **WHEN** 작업본이 이 PC에 있는 변형의 작업실에서 「폴더 열기」와 「터미널 열기」를 누른다
- **THEN** 앱 데이터 폴더 아래의 해당 작업 트리가 파일 관리자와 터미널에서 열리고, 페이지는 그 경로를 알지 못한다

### Requirement: 서버가 응답하지 않으면 연결 실패 화면
시스템은 서버에 연결할 수 없거나 서버 앞의 게이트웨이가 5xx로 응답하면 같은 하늘 배경의 연결 실패 화면을 표시해야 한다(SHALL). 화면에는 주소와 이유를 적고, 「다시 시도」와 「서버 바꾸기」를 둔다. 네트워크가 복구되었을 때나 20초마다 백그라운드에서 확인해 서버가 응답하면 연결에 실패했던 화면으로 돌아간다. 접근 암호가 틀린 경우(401)에는 자동으로 다시 시도하지 않는다.

#### Scenario: 서버가 꺼졌다 켜진다
- **WHEN** 서버가 꺼진 상태에서 새로 고침한다
- **THEN** 연결 실패 화면에 서버 주소가 보인다
- **AND** 서버가 다시 켜진 뒤 「다시 시도」를 누르면 채팅으로 돌아온다

### Requirement: 데스크톱 앱다운 기본
시스템은 하나만 실행되어야 한다(SHALL). 두 번째로 켜면 처음 창이 앞으로 오고 두 번째 실행은 종료된다. 창 크기와 위치를 기억하고, 다시 켜면 그 자리에 연다. 단, 해당 위치가 현재 화면 밖이면 기본 위치에 연다. 메뉴는 한국어이고, 웹 앱이 영어면 영어로 바뀐다. 새로 고침(⌘R, 연결 실패 화면에서는 다시 시도), 강제로 새로 고침, 확대·축소, 전체 화면, 뒤로·앞으로를 둔다. 개발자 도구는 개발 실행에서만 메뉴에 있다. 웹 앱의 알림은 시스템 알림으로 표시해야 한다(SHALL). Electron은 서비스 워커 알림을 보여 주지 않고 푸시 서비스도 없으므로, 데스크톱 앱에서는 웹 앱이 `new Notification`으로 띄우고 푸시를 구독하지 않는다. Home 카드 수는 Dock · 작업 표시줄 · 트레이의 숫자로 보인다(「트레이 아이콘과 알림 수」). 알림·마이크·카메라·클립보드 권한은 서버 출처에만 준다. 편집 칸에서 마우스 오른쪽 단추를 누르면 오려두기·복사·붙여넣기 메뉴가, 링크에서는 「링크를 브라우저에서 열기」 메뉴가 뜬다.

#### Scenario: 두 번 켠다
- **WHEN** 앱이 켜진 상태에서 같은 프로필로 한 번 더 켠다
- **THEN** 두 번째 실행은 코드 0으로 끝나고 창은 하나다

#### Scenario: 창 자리
- **WHEN** 창을 (140, 90) 1100×740으로 옮기고 앱을 끈 뒤 다시 켠다
- **THEN** 같은 자리, 같은 크기로 열리고, 로그인한 채로 채팅이 보인다

#### Scenario: 알림과 숫자
- **WHEN** 창이 뒤에 있을 때 새 Home 카드(팀원 메시지)가 온다
- **THEN** `new Notification`으로 「동료」 알림이 뜬다
- **AND** 페이지가 `navigator.setAppBadge(3)`을 부르면 Dock 숫자가 3이 된다

#### Scenario: 메뉴 언어
- **WHEN** 웹 앱을 영어로 바꾼다
- **THEN** 메뉴가 Edit · View · Go · Window · Help가 되고, 한국어로 돌리면 편집 · 보기 · 이동 · 윈도우 · 도움말이 된다

### Requirement: 트레이 아이콘과 알림 수
시스템은 앱이 시작될 때 트레이 아이콘(macOS에서는 메뉴 막대 아이콘)을 하나 표시하고, 웹 앱이 집계한 Home 카드 수를 운영체제의 숫자 표시 영역에 표시해야 한다(SHALL). 근거는 2026-11-25 사용자 요청 「일렉트론 버전의 시스템 트레이에 알람 개수 뱃지 설치」다. 웹 앱(`src/browserNotify.js`의 `setBadge`)은 데스크톱 앱 안에서는 이 수를 preload 브리지(`pglDesktop.setBadge`)로만 보내고, 브라우저에 설치한 웹 앱에서는 기존처럼 `navigator.setAppBadge`를 사용한다. 메인 프로세스는 선택한 서버의 화면이 보낸 수만 받아 0~9999 범위의 정수로 보정한다.

- macOS: Dock의 숫자(`app.setBadgeCount`)와 메뉴 막대 아이콘 옆의 숫자(` 3`, 0이면 비우고 100부터는 ` 99+`)로 표시한다. 알림 수가 0이면 메뉴 막대 아이콘에 앱 아이콘을 바탕으로 만든 템플릿 이미지를 사용하며, 메뉴 막대의 밝기에 맞춰 색이 바뀐다. 알림 수가 1 이상이면 메뉴 막대 아이콘의 오른쪽 위에 빨간 점을 표시하여 새 알림이 있음을 나타내야 한다(SHALL). 근거는 2026-11-26 사용자 요청 「일렉트론 버전에서 맥 같은 경우에 상단 시스템 트레이 말고 상단에 표시되는 부분 … 새 메시지가 오면 새 메시지가 왔다는 표시가 나도록 가능할까 ?」 · 「내가 이야기하는 것은 상단바에 표시되는 카카오톡에 알람이 들어오듯이 저런 것을 이야기하는 거고」다. 템플릿 이미지에는 색을 넣을 수 없으므로, 이때는 템플릿 이미지의 형태를 바탕으로 메뉴 막대의 밝고 어두운 상태(`nativeTheme.shouldUseDarkColors`)에 맞춘 검은색 또는 흰색 아이콘과 빨간 점을 16px · 32px(@2x)로 그리며, 밝고 어두운 상태가 바뀌면 다시 그린다. 숫자는 그대로 아이콘 옆에 표시한다. 창이 전면에 있지 않을 때 알림 수가 늘어나면 Dock 아이콘이 한 번 튀도록 해야 한다(SHALL, `app.dock.bounce('informational')`). 알림 수가 늘어날 때마다 한 번씩 튀도록 하며, 같은 수를 다시 받거나 알림 수가 줄어들 때는 튀지 않도록 한다. 알림 수가 0이고 로컬 에이전트가 실행 중이면 Dock에는 기존처럼 ●를 표시한다.
- Windows: 작업 표시줄 단추에 빨간 배지를 오버레이로 표시하고, 화면 읽기 프로그램에는 「알림 3개」로 알린다. 트레이 아이콘의 오른쪽 위에도 빨간 배지(1~9, 10부터는 9+)를 그린다.
- Linux: 숫자 표시를 지원하는 런처(Unity)에서는 숫자로 표시하고, 트레이 아이콘에는 Windows와 같은 빨간 배지로 표시한다.

트레이 아이콘의 툴팁은 「Process GPT Lite — 알림 3개」(0이면 「Process GPT Lite」)다. 트레이 아이콘을 누르면 메인 창을 표시하고 맨 앞으로 가져와야 한다(SHALL). 메뉴 항목은 「열기」, 「알림 N개 — 열기」, 「종료」다. 「알림 N개 — 열기」를 누르면 채팅으로 이동해 Home을 열고, 수가 0이면 「알림 없음」으로 바뀌어 누를 수 없다. macOS에서는 마우스 오른쪽 단추로 메뉴를 열고, Linux의 앱 표시기는 클릭 이벤트를 전달하지 않으므로 메뉴의 「열기」를 사용한다. 웹 앱이 영어면 트레이의 문구도 영어로 표시한다. 수는 Home 카드를 불러오거나 닫을 때마다 갱신되고, 0이 되면 지워진다. 로그아웃하거나 서버를 바꾸면 0으로 초기화된다. 창을 닫았을 때의 동작은 변경하지 않는다. Windows·Linux에서는 앱이 종료되면서 트레이 아이콘도 사라지고, macOS에서는 Dock과 메뉴 막대에 아이콘이 남으며 트레이 아이콘을 누르면 창이 다시 열린다.

#### Scenario: 페이지가 보낸 수
- **WHEN** 채팅 화면이 `pglDesktop.setBadge(3)`을 호출한다
- **THEN** Dock 숫자가 3이 되고, 메뉴 막대 아이콘 옆에 ` 3`이, 툴팁에 「Process GPT Lite — 알림 3개」가, 메뉴에 「알림 3개 — 열기」가 표시된다
- **AND** 12.7을 보내면 12로, 숫자가 아닌 값을 보내면 0으로 보정한다
- **AND** 0을 보내면 Dock 숫자와 메뉴 막대의 숫자가 지워지고, 메뉴는 「알림 없음」으로 바뀐다

#### Scenario: Home 카드
- **WHEN** Home 카드가 세 장 있는 상태에서 채팅을 연다
- **THEN** 숫자가 3이 된다
- **AND** 카드 하나를 ✕로 닫으면 서버에서 목록을 다시 받지 않아도 숫자가 2가 되고, 모두 닫으면 지워지며, 다시 불러와도 0이다

#### Scenario: 트레이 아이콘을 누른다
- **WHEN** 창을 숨긴 뒤 트레이 아이콘을 누른다
- **THEN** 창이 표시되고 맨 앞으로 온다

#### Scenario: 「알림 N개 — 열기」
- **WHEN** 폴더 화면에서 트레이 메뉴의 「알림 2개 — 열기」를 누른다
- **THEN** 채팅으로 이동하고 Home이 열린다

#### Scenario: 로그아웃
- **WHEN** 숫자가 4인 상태에서 설정의 「로그아웃」을 누른다
- **THEN** 숫자가 0이 된다

#### Scenario: Windows · Linux의 배지 그림
- **WHEN** 수가 3, 12, 0이다
- **THEN** 트레이 아이콘(16px, 32px)의 오른쪽 위에 빨간 원과 흰 숫자 3, 9+가 그려지고, 0이면 원래 아이콘이 그대로 표시된다
- **AND** Windows 작업 표시줄 단추에는 같은 배지만 오버레이로 표시하고, 0이면 제거한다

#### Scenario: macOS 메뉴 막대의 빨간 점
- **WHEN** macOS에서 알림 수가 0에서 3으로 늘어난다
- **THEN** 메뉴 막대 아이콘이 오른쪽 위에 빨간 점이 표시된 이미지(템플릿 이미지가 아님)로 바뀌고, 그 옆에 ` 3`이 표시된다
- **AND** 밝은 메뉴 막대에서는 아이콘을 검은색으로, 어두운 메뉴 막대에서는 흰색으로 그리며, 시스템의 밝고 어두운 상태가 바뀌면 그에 맞춰 다시 그린다
- **AND** 알림 수가 0이 되면 빨간 점이 없는 템플릿 이미지로 돌아간다

#### Scenario: 새 알림이 오면 Dock 아이콘이 한 번 튄다
- **WHEN** macOS에서 창이 전면에 있지 않은 상태로 알림 수가 1에서 3으로 늘어난다
- **THEN** Dock 아이콘이 한 번 튄다(`app.dock.bounce('informational')`)
- **AND** 같은 수를 다시 받거나, 알림 수가 줄어들거나, 창이 전면에 있을 때는 튀지 않는다

### Requirement: 보안
시스템은 창마다 `contextIsolation`과 `sandbox`를 켜고 `nodeIntegration`을 꺼야 한다(SHALL). `<webview>`를 사용하지 않으며 remote 모듈도 없다. preload는 서버 화면에 읽기 전용 정보(`window.pglDesktop`: 앱 · 버전 · 플랫폼)만 제공한다. 로컬 화면(서버 고르기, 연결 실패)에만 해당 화면의 단추를 제공하며(`window.pglLocal`), 메인 프로세스는 요청을 보낸 곳이 앱의 `src/pages/`인지 확인한다. 변형의 작업본(`window.pglDesktop.seats`)은 변형 id만 주고받으며 경로는 주고받지 않는다. 메인 프로세스는 해당 요청이 선택한 서버의 화면에서 왔는지 확인하며, 무엇을 어디에 받을지는 서버가 링크로 정한다. 남은 변경은 시스템 창에서 확인한 뒤에만 버린다.

#### Scenario: 서버 화면이 로컬 단추를 부른다
- **WHEN** 서버 화면에서 `pgl:connect`를 보내려 한다
- **THEN** `window.pglLocal`이 없어서 보낼 수 없고, 보낸다 해도 메인 프로세스가 거절한다

### Requirement: 묶기
시스템은 macOS용(arm64) DMG와 zip을 「Process GPT Lite」라는 이름으로 묶어야 한다(SHALL). 아이콘은 웹 앱의 아이콘(`public/favicon.svg`)을 macOS 아이콘 격자에 맞춰 그린다. Developer ID 서명과 공증은 하지 않고, 묶은 뒤 임시(ad hoc) 서명을 한다. 마이크·카메라 사용 안내 문구를 넣는다. 아무것도 배포하지 않는다.

#### Scenario: 묶은 앱
- **WHEN** `desktop/`에서 `npm run dist`를 실행한다
- **THEN** `release/Process-GPT-Lite-0.1.0-mac-arm64.dmg`와 `.zip`이 생기고, 묶은 앱이 같은 시험(D-01~D-10)을 통과한다
