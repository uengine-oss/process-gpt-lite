# 글을 그리는 한 가지 규칙 — Markdown 은 문서 요소로만

## Purpose
Lite 의 화면에는 사람이 직접 작성하지 않은 글이 많이 표시된다. 에이전트의 답(메일 · 웹 페이지 · 동료의 말을 옮겨 적을 수 있다), 「이미 한 요청」 카드에서 펼쳐 보는 팀원의 지난 답, 스킬 초안의 SKILL.md 와 작업 메모, 회사 프로세스 지도의 스킬 · 일 지시, 인스턴스 화면의 단계 결과, 양식에 다른 사람이 입력한 값, 미션 요약, 프로세스 마이닝 대화, ArtCraft 라이브 답, 공유 폴더의 Markdown 파일이 이에 해당한다.

지금까지 이 글들은 화면마다 조금씩 다른 방식으로 HTML 로 변환되었다. 이 때문에 같은 답이 화면에 따라 다르게 표시되었고(대화의 코드 블록에서 `a < b && c` 가 `a &lt; b &amp;&amp; c` 로 표시되는 등), 링크 · 그림 · 글에 포함된 HTML 을 처리하는 방식도 화면마다 달랐다.

이제 이 글들은 모두 한 곳에서 같은 규칙으로 HTML 로 변환된다. marked 가 Markdown 을 HTML 로 변환하고, 브라우저 자체의 파서가 그 결과를 실행되지 않는 문서로 읽은 다음, 정해진 문서 요소만 남긴다. 이와 함께 앱 페이지와 설치 번들의 nginx 에 콘텐츠 보안 정책(Content-Security-Policy)을 적용한다.

## Requirements

### Requirement: 다른 사람이 쓸 수 있는 Markdown 은 문서 요소로만 그린다
시스템은 위의 글을 HTML 로 렌더링할 때 문서 요소만 남겨야 한다(SHALL).
- 남는 요소: 문단 · 줄바꿈 · 제목(h1~h6) · 굵게 · 기울임 · 지운 줄 · 코드 · 코드 블록 · 목록 · 인용 · 표 · 가로줄 · 링크 · 할 일 목록의 체크 상자(누를 수 없음).
- 남는 속성: 링크의 주소와 설명(`title`), 표 셀의 정렬(left · center · right), 번호 목록의 시작 번호, 체크 상자의 종류와 체크 여부. 그 밖의 속성(`style` · `class` · `id` · `on…` 등)은 남지 않는다.
- 스크립트 · 스타일 · 틀(iframe) · 개체(object · embed) · SVG · MathML · 양식 · 주석은 내부 내용까지 제거한다. 그 밖의 태그는 태그만 제거하고 내부 텍스트는 남긴다.
- 그림 문법(`![설명](주소)`)은 그림을 불러오지 않고 설명 텍스트로 표시한다.
- 링크 주소는 브라우저가 링크를 열 때 사용하는 URL 해석 규칙으로 읽고, http · https · mailto 이거나 이 사이트의 경로일 때만 남긴다. 문자 참조 · 탭 · 앞쪽 공백 · 제어 문자가 포함되어 있어도 해석한 결과를 기준으로 판단한다. 주소가 제거된 링크는 누를 수 없는 텍스트로 표시한다.
- 링크는 새 탭으로 열리며 `rel="noopener noreferrer"` 를 가진다.

#### Scenario: 에이전트의 답에 HTML 이 섞여 있다
- **WHEN** 윤하린의 프로젝트 방에 에이전트가 `<img src=x onerror="…">` · `<iframe srcdoc="…">` · `[자세히 보기](javascript:…)` 가 포함된 보고서 답을 남긴다
- **THEN** HTML 은 작성한 문자 그대로 표시되고, 「자세히 보기」는 누를 수 없는 텍스트로 표시되며, 페이지에서 실행되는 것은 없다
- **AND** 같은 답의 표 · 코드 블록 · 「누리집」 링크(새 탭)는 그대로 표시된다

#### Scenario: 팀원의 지난 답을 펼친다
- **WHEN** 윤하린이 「이미 한 요청」 카드에서 박도윤의 답에 있는 「그 답 보기」를 누르고, 그 답에 같은 HTML 이 포함되어 있다
- **THEN** 대화 화면의 답과 같은 규칙으로 표시된다(HTML 은 문자로 표시되며, 실행되는 것은 없음)

#### Scenario: 스킬 시트와 단계 결과
- **WHEN** 스킬 초안 카드에서 「SKILL.md 전체 보기」를 누르거나 작업 메모를 펼친다. 또는 인스턴스 화면에서 단계가 남긴 긴 텍스트 결과를 연다
- **THEN** 같은 규칙으로 표시된다. 코드 블록의 `grep -c "<tr>" report.html && echo ok` 은 작성한 그대로 표시된다

#### Scenario: 그림 문법
- **WHEN** 답에 `![차트](https://…/pixel.png)` 가 있다
- **THEN** 그림을 불러오지 않고 「차트」라는 텍스트를 표시한다

### Requirement: 보통의 Markdown 은 전과 같이 보인다
시스템은 위의 규칙을 지키면서 일반적인 Markdown 을 이전과 같이 표시해야 한다(SHALL).
- 제목 · 목록 · 표 · 인용 · 지운 줄 · 굵게(한국어 조사 바로 앞의 `**굵게**은` 포함) · 기울임이 그대로 표시된다.
- 「3.」으로 시작하는 번호 목록은 3부터 번호를 매긴다. 표의 열 정렬은 그대로 유지된다.
- 코드와 코드 블록 안의 `<` · `&` 는 작성한 그대로 표시된다.
- `<https://…>` · `<이름@도메인>` 처럼 꺾쇠로 감싼 주소는 링크로 표시된다.
- 대화 화면(에이전트 답 · 팀원 답 · 스킬 · 단계 결과 · 양식 값 · 미션 요약 · 마이닝 대화 · ArtCraft 라이브 답 · 회사 지도의 스킬과 일 지시)에서는 글에 작성한 HTML 태그를 문자 그대로 표시한다(이전과 같다). 문서 화면(공유 폴더의 Markdown 파일)과 내 PC 의 CLI 대화 보기에서는 위의 문서 요소만 렌더링하고 나머지 태그는 제거한다.

#### Scenario: 보고서 형식의 답
- **WHEN** 답에 「# 제목」 · 「3. 셋」 · 정렬된 표 · `` `a < b && c` `` · 할 일 목록 · 인용이 있다
- **THEN** 제목 · 3부터 시작하는 목록 · 왼쪽/가운데/오른쪽으로 정렬된 표 · `a < b && c` · 누를 수 없는 체크 상자 · 인용이 그대로 표시된다

---

### Requirement: 링크와 파일 주소는 웹 주소만 연다
시스템은 다른 사람이 지정할 수 있는 주소를 열 때 웹 주소(http · https, 메일 링크는 mailto)인지 확인해야 한다(SHALL).
- 파일 카드의 「열기」가 앱 내부 보기 화면이 아닌 새 탭으로 파일을 여는 경우, 웹 주소가 아니면 열지 않고 「파일을 열지 못했어요.」라고 알린다.
- 팀 활동(사람 카드 · 시간순 보기)의 산출물 링크는 웹 주소일 때만 링크로 표시하고, 그렇지 않으면 이름만 표시한다.
- 패널 앱의 「열기」(`panel.open`)는 http · https 주소만 연다.
- 서버는 도구의 답에서 파일 카드를 만들 때 http · https 주소만 허용한다.

#### Scenario: 패널 앱이 웹 주소가 아닌 곳을 열려고 한다
- **WHEN** 패널 앱이 `panel.open('javascript:…')` 를 호출한다
- **THEN** 아무것도 열리지 않고 패널은 「http(s) only」 오류를 받는다

---

### Requirement: 페이지와 설치 번들의 콘텐츠 보안 정책
시스템은 앱 페이지에 콘텐츠 보안 정책을 적용해야 한다(SHALL).
- `index.html` 의 meta: `object-src 'none'; base-uri 'self'`. Vite 개발 서버 · 웹 이미지 · 데스크톱 앱이 모두 같은 페이지를 사용하므로 모든 환경에 적용된다. 페이지에 `<object>` · `<embed>` 가 포함되어도 아무것도 불러오지 않고, `<base>` 가 포함되어도 페이지의 상대 주소가 바뀌지 않는다.
- 설치 번들의 nginx(`install/docker/nginx.conf`, 운영의 웹 이미지도 같은 설정)는 앱 페이지에 `frame-ancestors 'self'; object-src 'none'; base-uri 'self'` 헤더를 추가한다. 같은 주소의 페이지만 앱을 틀(iframe) 안에 넣을 수 있다.
- 같은 nginx 는 저장소(`/storage/v1/…`)가 이 주소로 제공하는 HTML · SVG · XML 파일에 `sandbox` 정책(BFF 가 직접 제공하는 파일에 적용하는 것과 같은 정책)을 적용한다. 해당 파일을 별도로 열어도 그림과 글만 표시되고 파일 내부의 스크립트는 실행되지 않는다. 그림 · PDF · 영상 · JSON 과 REST · 로그인 응답에는 적용하지 않는다.
- 작업실의 파일 원본(`GET /api/workroom/:kind/:id/raw`)이 그림 · 소리 · 영상 · PDF · 일반 텍스트(txt · md · csv · json)가 아니면 동일한 `sandbox` 정책을 적용해 전송한다. 확장자가 `.xhtml` · `.xsl`처럼 HTML · XML로 해석되는 파일에도 동일한 정책을 적용한다.
- 스크립트 출처(`script-src`)는 아직 제한하지 않는다. 패널 앱은 sandbox 가 적용된 srcdoc 틀 안에서 자체 인라인 스크립트를 실행하는데, srcdoc 틀은 페이지의 정책을 상속하기 때문이다.

#### Scenario: 저장소의 HTML 파일을 따로 연다
- **WHEN** 설치형 Lite 에서 `/storage/v1/object/public/files/…/보고서.html` 을 브라우저 탭에서 연다
- **THEN** 응답에 `Content-Security-Policy: sandbox; default-src 'none'; …` 가 포함되고, 같은 경로의 `.png` · `.pdf` 응답에는 포함되지 않는다

#### Scenario: 작업실의 XHTML 파일
- **WHEN** 에이전트가 해당 단계의 작업실에 `화면.xhtml`을 남기고, 윤하린이 해당 파일의 원본을 연다
- **THEN** 응답에 `sandbox` 정책이 포함되고, 같은 작업실의 `.png` · `.pdf` · `.md` 응답에는 포함되지 않는다

## 시험
화면: `e2e/tests/feature/safe-html.spec.js`(F-SH-01~07, 자체 스택 — 테넌트 `safehtml-ui`, BFF 8971 · Vite 5371부터). F-SH-01 은 변환 모듈을 브라우저에서 직접 불러와 까다로운 입력 모음과 일반적인 Markdown 을 확인하고, F-SH-02~05 는 대화 · 「이미 한 요청」 · 스킬 시트 · 인스턴스 산출물 화면을 확인하며, F-SH-06 은 meta 정책과 실제 nginx(도커가 있을 때)의 헤더를, F-SH-07 은 작업실 파일 원본의 헤더를 확인한다. 명령과 증거는 `e2e/README.md` 63절과 `openspec/specs/markdown-rendering/e2e/README.md` 에 있다.

### Requirement: API 응답은 해당 주소에서 실행되는 페이지로 열리지 않는다
시스템은 `/api` 아래의 모든 응답에 `X-Content-Type-Options: nosniff`를 추가하고, PDF가 아니면서 경로에 별도 정책이 지정되지 않은 응답에는 스크립트 실행을 허용하지 않는 sandbox 정책(`Content-Security-Policy: sandbox; default-src 'none'; img-src data:; style-src 'unsafe-inline'`)을 적용해야 한다(SHALL). 이에 따라 저장된 XML·SVG·HTML을 링크로 열어도 텍스트만 표시되는 문서로 열린다. 화면에서 데이터를 가져오거나 이미지·동영상을 표시하는 동작은 이 정책의 영향을 받지 않고 그대로 유지된다. 에이전트가 생성한 파일은 해당 회사의 프로세스 단계 결과에 이름이 기록된 실행의 동영상·이미지만 표시하며, 형식은 파일 이름을 기준으로 결정한다.

#### Scenario: 저장된 XML을 링크로 연다
- **WHEN** 사용자가 프로세스 정의의 BPMN 주소를 링크로 연다
- **THEN** 응답에 nosniff와 sandbox 정책이 적용되어 문서 안의 어떤 스크립트도 실행되지 않는다

#### Scenario: PDF와 경로별 정책
- **WHEN** PDF를 열거나, 작업실 원본처럼 경로에 별도 정책이 지정된 응답을 받는다
- **THEN** PDF는 브라우저에서 열리고, 경로에 지정된 정책은 그대로 적용된다
