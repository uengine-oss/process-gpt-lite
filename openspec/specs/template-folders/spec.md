# 템플릿 폴더 — 템플릿에서 프로젝트를 시작하고, 결과물은 그 프로젝트에만, 템플릿의 개선은 고른 파일만 반영 요청으로

## Purpose
2026-11-27 사용자 요청: 「일반 폴더와 템플릿 폴더 종류가 있을거 같은데… 템플릿 폴더는 어떤 프로젝트를 시작할때 참고하는 예를 들어 제안서 템플릿 폴더는 제안에 필요한 정보들이 참조폴더들로 묶여있고 제안관련 스킬들이 포함된 (.claude..) 구조를 갖고있을 수 있다. 이 템플릿 폴더가 선택되어 시작되면 해당 프로젝트에 템플릿 폴더가 참조로 연결된 이 프로젝트 전용 폴더가 생기고 결과물은 전용 폴더내에만 남게 될 것임. 작업 도중 원본 폴더 자체에 뭔가의 개선이필요한 내용은 PR 처럼 요청될 수 있겠지.」 이어서 「일단 variant-based 도 구현하고... 프로젝트 폴더는 별도로 관리될 수 있도록 "폴더" 목록에 나와서는 안되고 해당 프로젝트에서만 보이게하면 될듯.」

공유 폴더의 소유자는 폴더를 「템플릿」으로 지정할 수 있다. 템플릿에서 프로젝트를 시작하면 그 프로젝트만의 작업 공간이 생긴다. 작업 공간은 시작한 순간의 템플릿 main에서 갈라진 변형이고, 프로젝트를 시작한 사람만 볼 수 있다. 프로젝트의 에이전트는 작업 공간에서 일하고, 템플릿의 참조 자리(폴더 참조)는 템플릿을 통해 읽는다. 결과물은 작업 공간에만 남으며 템플릿에 통째로 반영되지 않는다. 템플릿 자체를 고칠 일이 생기면 작업 공간에서 고친 템플릿 파일만 골라 「원본에 반영 요청」으로 보낸다. 요청은 템플릿의 지금 main 위에 새 변형으로 올라가고, 템플릿 주인이 검토해 기존 변형 반영으로 넣는다. 다음 프로젝트는 고친 main에서 시작하며 앞 프로젝트의 작업 공간은 보이지 않는다.

이 스펙은 첫 판(v0, 서버 · 웹)을 다룬다. 새 데이터베이스 변경은 없다(폴더 설정과 변형 기록의 기존 JSON 칸을 쓴다). 작업 공간에 참조 자리의 읽기 전용 사본을 놓는 일, 템플릿의 새 파일(스킬 추가 등)을 요청으로 보내는 일, 요청에 대한 주인의 「수정 요청」 · 「닫기」, 작업 공간 가지를 git 으로 직접 받는 길에서 숨기는 일은 다음 단계에서 다룬다.

## Requirements

### Requirement: 소유자가 폴더를 템플릿으로 지정하고, 템플릿은 표시된다
관리형 공유 폴더의 소유자는 폴더 화면의 「템플릿으로 지정」으로 폴더를 템플릿으로 지정하고 「지정 풀기」로 되돌릴 수 있어야 한다(SHALL). 연결형 · 스킬 · 작업 폴더는 지정할 수 없다. 템플릿 폴더는 폴더 화면 제목 옆과 「폴더」 목록에 「템플릿」 표시가 붙고, 폴더 화면에 「템플릿」 띠를 보여 준다. 띠에는 폴더 맨 위의 `TEMPLATE.md` 머리말 `description`(없으면 본문 첫 줄, 그것도 없으면 「프로젝트를 시작할 때 쓰는 폴더예요」)과, 「프로젝트마다 전용 작업 공간이 생기고, 결과물은 그 프로젝트의 「<결과물 폴더>/」에만 남아요 · 이 폴더는 그대로예요」를 적는다. 결과물 폴더는 `TEMPLATE.md` 머리말 `outputs`이며 없으면 「산출물」이다. `..` · `.git`이 든 값은 무시한다. 지정을 풀어도 이미 시작한 프로젝트의 작업 공간은 그대로다.

#### Scenario: F-TF-01 템플릿으로 지정한다
- **WHEN** 정하윤이 자기 폴더 「제안서 템플릿」 화면에서 「템플릿으로 지정」을 누른다
- **THEN** 제목 옆에 「템플릿」 표시와 「템플릿 · 제안서를 쓸 때 시작하는 템플릿이에요」 띠, 「「산출물/」에만 남아요」 문구, 「템플릿으로 시작」 단추가 보인다
- **AND** 「폴더」 목록의 「제안서 템플릿」 줄에 「템플릿」 표시가 붙고, 다른 폴더에는 붙지 않는다

### Requirement: 템플릿으로 시작하면 그 프로젝트만의 작업 공간이 생긴다
템플릿의 실행 이상 구성원은 템플릿 화면의 「템플릿으로 시작」을 누르고 띠에 나온 칸에 프로젝트 이름을 적어 「시작」을 누르거나, 「새 프로젝트」 화면의 「폴더 고르기」에서 「템플릿」 표시가 붙은 폴더를 골라(칩 「· 템플릿으로 시작」) 프로젝트를 시작할 수 있어야 한다(SHALL). 프로젝트가 만들어지는 순간 템플릿 main의 지금 판에서 갈라진 작업 공간(변형, 가지 `var/t/…`)이 생기고, 작업 공간에는 어느 템플릿의 어느 판에서 시작했는지와 결과물 폴더가 기록된다. 작업 공간은 프로젝트를 시작한 사람의 것이며, 템플릿의 「변형」 목록, 폴더 카드의 변형 수 · 최근 활동, 회의 자료 후보, 「폴더」 목록 어디에도 나오지 않는다. 그 사람이 아닌 사람(템플릿 주인 포함)이 작업 공간의 화면 · 파일 · 차이 · 작업실을 열거나 일괄 반영에 넣으려 하면 없는 변형과 같이 404를 받는다. 프로젝트 화면 위에는 작업 공간 막대가 보인다: 「템플릿」 표시와 템플릿 이름, 「전용 작업 공간 · 바뀐 것 없음」(바뀌면 「전용 작업 공간 · 바뀐 것 N건」), 「원본에 반영 요청」 단추. 막대의 작업 공간을 누르면 작업 공간 화면이 열린다.

#### Scenario: F-TF-02 템플릿 화면에서 시작한다
- **WHEN** 김서연이 「제안서 템플릿」에서 「템플릿으로 시작」을 누르고 띠에 나온 칸에 「에이스정밀 3분기 제안」을 적어 「시작」을 누른다
- **THEN** 그 프로젝트가 열리고 위에 「템플릿 · 제안서 템플릿 · 전용 작업 공간 · 바뀐 것 없음 · 원본에 반영 요청」 막대가 보인다
- **AND** 「제안서 템플릿」의 「변형」 목록에는 정하윤 · 김서연 · 박도윤 누구에게도 이 작업 공간이 없고, 「폴더」 목록에도 프로젝트 폴더가 없다
- **AND** 정하윤이 작업 공간을 주소로 열면 404다

#### Scenario: F-TF-05 「새 프로젝트」에서 템플릿을 고른다
- **WHEN** 박도윤이 「새 프로젝트」에서 「폴더 고르기」를 열어 「템플릿」 표시가 붙은 「제안서 템플릿」을 고르고 첫 말을 보낸다
- **THEN** 칩은 「제안서 템플릿 · 템플릿으로 시작」이고, 만들어진 프로젝트에는 작업 공간 막대가 보인다
- **AND** 작업 공간은 그 순간의 템플릿 main(앞 요청이 반영된 양식)에서 시작했고, 김서연의 결과물은 없으며, 김서연의 작업 공간은 404다

### Requirement: 프로젝트의 에이전트는 작업 공간에서 일하고 결과물은 거기에만 남는다
작업 공간이 있는 프로젝트에서 에이전트에게 일을 맡기면, 에이전트의 작업 폴더에 작업 공간이 꺼내지고 에이전트는 다음 안내를 받아야 한다(SHALL): 템플릿 이름과 작업 공간, 결과물은 결과물 폴더 아래 새 파일로 둘 것, 템플릿의 양식 · 스킬 · `TEMPLATE.md`를 따를 것, 여기서 바꾼 것은 이 프로젝트에만 남고 템플릿 원본은 바뀌지 않는다는 것, 템플릿 파일 자체를 고쳐야 하면 작업 공간의 그 파일을 고치고 사용자가 「원본에 반영 요청」으로 그 파일만 보낼 수 있다는 것, 그리고 템플릿의 참조 자리(자리 이름과 원본, 그 사람에게 잠긴 자리는 「볼 수 없는 참조」)와 그 자리를 폴더 도구(`folder_files` · `folder_read`, 템플릿 이름과 「자리/파일」 경로)로 읽는다는 것. 참조 자리는 그 사람의 원본 권한으로 읽힌다. 턴이 끝나면 바뀐 것은 작업 공간에 커밋되고, 대화에 「이 프로젝트 작업 공간에 담았어요 · <파일> · 템플릿 「<이름>」 원본은 그대로예요」가 남는다. 템플릿 main은 바뀌지 않는다. 작업 공간 화면은 바뀐 파일마다 「결과물」(결과물 폴더 아래이거나 새 파일) 또는 「템플릿 파일」을 표시하고, 「인계하기」 · 「이 변형 반영」 대신 「원본에 반영 요청」과 「이 프로젝트 전용 작업 공간 — 템플릿 「…」의 <판> 에서 시작했어요 …」 안내를 보여 주며, 뒤로 가기는 프로젝트로 간다. 작업 공간의 파일 목록(`tree?ref=<작업 공간>`)에는 템플릿의 참조 자리 파일도 그 사람의 권한대로 나온다.

#### Scenario: F-TF-03 참조 자리를 읽고 초안을 쓰고, 양식도 고친다
- **WHEN** 김서연이 프로젝트에서 「템플릿의 참조 자료를 읽고 에이스정밀 3분기 제안서 초안을 써 줘」, 이어서 「양식의 회사 주소가 옛 주소예요. 새 주소로 고쳐 줘」라고 한다
- **THEN** 에이전트가 받은 안내에 「템플릿 '제안서 템플릿' 에서 시작했어요」, 「'산출물/' 아래에 새 파일로」, 「회사 소개 자료/ — 원본: 「회사 소개 자료」 폴더 전체」가 있고, 에이전트는 「회사 소개 자료」 · 「납품 실적」 자리를 김서연의 권한으로 읽는다
- **AND** 대화에 「이 프로젝트 작업 공간에 담았어요」가 남고 막대는 「전용 작업 공간 · 바뀐 것 N건」이 된다
- **AND** 초안(`산출물/에이스정밀 3분기 제안서 초안.md`)과 고친 양식은 작업 공간에만 있고, 템플릿 main의 양식은 옛 주소 그대로이며 초안이 없다
- **AND** 박도윤이 작업 공간의 파일 목록이나 초안을 열면 404이고, 정하윤이 작업 공간을 일괄 반영하려 하면 404다

### Requirement: 작업 공간은 템플릿에 통째로 반영되지 않는다
작업 공간은 일괄 반영 · 「이 변형 반영」으로 템플릿 main에 들어가지 않아야 한다(SHALL). 그 사람이 반영을 시도하면 409 「템플릿에서 시작한 프로젝트의 작업 공간은 통째로 반영하지 않아요. 고친 템플릿 파일만 「원본에 반영 요청」으로 보내 주세요.」, 다른 사람에게는 404다. 작업 공간은 인계하지 않는다(409).

#### Scenario: 작업 공간을 반영하려 한다
- **WHEN** 작업 공간을 일괄 반영에 넣는다
- **THEN** 그 사람에게는 409와 위 안내, 템플릿 주인에게는 404가 돌아가고 템플릿 main은 그대로다

### Requirement: 원본에 반영 요청은 고른 템플릿 파일만 새 변형으로 보낸다
작업 공간의 사람은 프로젝트 막대나 작업 공간 화면의 「원본에 반영 요청」을 눌러 시트를 열 수 있어야 한다(SHALL). 시트의 「템플릿에서 온 파일 중 이 프로젝트에서 바뀐 것」에는 시작 판에 있던 파일 가운데 결과물 폴더 밖에서 고쳐지거나 지워진 파일만 체크 상자로 나오고(처음엔 모두 체크), 「이 프로젝트에만 남는 결과물 · 보내지 않아요」에는 나머지(결과물 폴더 아래 · 새 파일)가 자물쇠와 함께 나온다. 요청 제목과 템플릿 주인에게 한마디(선택)를 적고 「N개 보내기」를 누르면, 고른 파일만 템플릿의 지금 main 위 한 커밋으로 담긴 보통 변형이 생기고(반영 대기, 보유자 = 보낸 사람, 출처 「<이름> 님이 프로젝트 「…」에서 보낸 반영 요청」), 템플릿의 「변형」 목록에 보인다. 결과물은 따라가지 않는다. 그 사이 템플릿 main에서 같은 파일의 다른 곳이 바뀌었으면 줄 단위로 합쳐 담고, 같은 곳이 바뀌었으면 보내지 않고 409 「템플릿에서도 그 사이 같은 곳이 바뀌었어요: <파일> — 템플릿 주인과 먼저 맞춰 주세요.」를 알린다. 템플릿 파일이 아닌 경로를 보내면 400 「템플릿에서 온 파일만 보낼 수 있어요 — 결과물은 이 프로젝트에만 남아요: …」다. 이미 main과 같으면 409다. 템플릿 소유자에게는 「<이름>님이 템플릿 「<템플릿>」에 반영을 요청했어요」 알림이 가고, 누르면 그 변형이 열린다. 주인은 그 변형을 보고 기존 「이 변형 반영」으로 넣는다. 보낸 쪽에는 「템플릿 「…」 주인에게 반영 요청을 보냈어요 · <파일> · 결과물은 이 프로젝트에만 남아요」가 보이고, 작업 공간에 보낸 요청이 기록된다.

#### Scenario: F-TF-04 양식 고침만 보내고 주인이 반영한다
- **WHEN** 김서연이 「원본에 반영 요청」 시트에서 「제안서 양식.md」(체크됨)와 「보내지 않아요」 아래의 초안을 확인하고, 한마디 「회사 주소가 옛 주소라 새 주소로 바꿨어요」를 적어 「1개 보내기」를 누른다
- **THEN** 시트가 닫히고 「주인에게 반영 요청을 보냈어요」가 보인다
- **AND** 정하윤에게 「김서연님이 템플릿 「제안서 템플릿」에 반영을 요청했어요」 알림이 가고, 그 변형에는 바뀐 파일이 「제안서 양식.md」 하나다
- **AND** 정하윤이 「이 변형 반영」 · 「반영 시작」을 누르면 템플릿 main의 양식이 새 주소가 되고, 템플릿에는 `산출물/`이 없다
- **AND** 초안 경로를 보내려 하면 400이다

#### Scenario: 템플릿도 같은 줄을 고쳤다
- **WHEN** 작업 공간과 템플릿 main이 양식의 같은 줄을 서로 다르게 고친 뒤 그 파일을 보낸다
- **THEN** 409(`tpl_conflict`)로 보내지 않고, 변형은 생기지 않는다

### Requirement: 휴대폰에서도 막대와 시트가 화면 안에 있다
390px 폭에서 작업 공간 막대와 「원본에 반영 요청」 시트는 화면 밖으로 넘치지 않아야 한다(SHALL). 밝은 · 어두운 테마 모두 같다.

#### Scenario: F-TF-06 390px 밝은 · 어두운 테마
- **WHEN** 김서연이 390px 휴대폰에서 프로젝트를 열고 「원본에 반영 요청」을 누른다
- **THEN** 막대와 시트가 화면 안에 있고 옆으로 밀리지 않는다
