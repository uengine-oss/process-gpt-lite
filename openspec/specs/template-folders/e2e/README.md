# 시험과 증거 — 템플릿 폴더 v0

서버의 판단(`server/lib/folders/templates.js` — 템플릿 지정 · 작업 공간 만들기 · 보낼 수 있는 파일 · 반영 요청, `service.js` 의 작업 공간 숨기기, `merge.js` 의 통째 반영 거절, `threadFolders.js` 의 에이전트 안내)은 단위 · 통합 시험으로 검증한다. 실제 git 과 개발 데이터베이스를 쓰고, 사람마다(정하윤 · 김서연 · 박도윤) 무엇이 보이고 무엇이 거절되는지 확인한다. 화면과 HTTP 는 Playwright 파일 하나가 자기 스택(회사 `template-folders-web`, BFF 8981 · Vite 5381)과 가짜 모델 · 가짜 deepagents(59981)를 띄워 확인한다. 가짜 deepagents 는 메시지에 담긴 사용자 JWT 로 BFF 의 실제 폴더 도구(`/mcp/folders` 의 `folder_files` · `folder_read`)를 불러 템플릿과 참조 자리를 읽고, 이 컴퓨터의 deepagents 작업 공간에 있는 프로젝트 작업 폴더에 써서 저장소의 방에 올린다(`lib/roomStore.js` 와 같은 열쇠 — 턴이 끝난 뒤 서버가 바로 가져온다). 실제 모델과 에이전트는 부르지 않는다. 사람 · 회사 · 자료는 지어낸 것이다(「제안서 템플릿」 · 「회사 소개 자료」 · 「납품 실적」, 가나정밀 · 다라테크).

새 데이터베이스 변경은 없다. 템플릿 표시는 `pro_folders.settings.template`, 작업 공간은 `pro_folder_variations.source.template`(템플릿 · 시작 판 · 결과물 폴더) · `source.requests`(보낸 요청), 반영 요청 변형은 `source.request` 에 적는다.

## 단위 · 통합 시험

```bash
cd server && node --test test/templateFolders.test.js
```

- **TF-U-01 TEMPLATE.md:** 머리말 `description` · `outputs`(접힌 여러 줄 포함), 머리말이 없으면 본문 첫 줄과 「산출물」. `../밖` · `.git/x` · 빈 값 · `/` 는 「산출물」, `./out` 은 `out`.
- **TF-U-02 누가 보나:** 작업 공간(`source.template`)은 보유자 한 사람만, 일반 변형은 누구나. 연결형 폴더는 템플릿이 아니다.
- **TF-U-03 준비:** 원본 두 폴더 · 템플릿(양식 · `.claude/skills/proposal-writer/SKILL.md` · `TEMPLATE.md` · 참조 자리 둘) · 김서연 · 박도윤은 템플릿의 실행, 원본 두 폴더의 보기.
- **TF-U-04 지정:** 지정 전에는 `infoOf` 가 null, 지정 뒤 설명 · 결과물 폴더 · 파일 있음. 템플릿이 아닌 폴더에서 시작하면 거절.
- **TF-U-05 시작:** 프로젝트 · 폴더 연결(`project`) · 작업 공간(`var/t/…`, 시작 판 = 그때의 main, 반영 대기, 보유자 김서연). 템플릿의 변형 목록 · 폴더 카드(`live` 0, 최근 활동에 프로젝트 이름 없음) · 폴더 목록에 없음. 김서연은 열고, 정하윤 · 박도윤은 404. 작업실 접근도 김서연만.
- **TF-U-06 프로젝트 턴:** 에이전트 안내에 「템플릿 '제안서 템플릿' 에서 시작했어요」 · 「'산출물/' 아래에 새 파일로」 · 「원본에 반영 요청」 · 참조 자리 둘. 작업 폴더에 쓴 초안 · 양식 고침이 작업 공간에 커밋되고 템플릿 main 은 그대로, 칩 「이 프로젝트 작업 공간에 담았어요」. 참조 자리의 파일은 김서연의 권한으로 읽힌다.
- **TF-U-07 통째 반영 거절:** 정하윤이 작업 공간을 반영하려 하면 404, 김서연이면 409(「통째로 반영하지 않아요」). 템플릿 main 에 `산출물/` 없음.
- **TF-U-08 반영 요청:** 보낼 수 있는 파일은 `M 제안서 양식.md` 하나, 결과물은 따로. 결과물 경로는 400(`tpl_not_template_file`), 다른 사람은 404. 그 사이 정하윤이 같은 양식의 다른 줄(「## 3. …」)을 고쳤는데도 요청 변형의 양식에는 새 주소와 정하윤의 고침이 함께 들어 있다. 요청 변형은 보통 변형(템플릿의 변형 목록에 보임, 반영 대기), 바뀐 파일은 양식 하나, 결과물 없음, 정하윤이 열 수 있다. 정하윤에게 「김서연님이 템플릿 「제안서 템플릿」에 반영을 요청했어요」 알림(주소 = 그 변형). 작업 공간 · 막대에 보낸 요청 1건.
- **TF-U-09 같은 줄:** 작업 공간과 템플릿이 양식의 같은 줄(「제안사」)을 다르게 고치면 409(`tpl_conflict`).
- **TF-U-10 반영 → 다음 프로젝트:** 정하윤이 요청 변형을 반영하면 main 의 양식이 새 주소, 템플릿에 결과물 없음. 박도윤의 「새 프로젝트」(템플릿 고름 — `linkProject`)는 작업 공간이 바로 생기고, 시작 판 = 지금 main, 양식은 새 주소, 결과물 없음, 김서연의 작업 공간은 404, 두 작업 공간 모두 변형 목록에 없음. 참조 자리 안내는 박도윤의 권한대로(「회사 소개 자료/ — 원본: 「회사 소개 자료」 폴더 전체」).

- **TF-U-11 프로젝트 이름:** 프로젝트가 첫 말로 만들어진 뒤 모델이 이름을 지으면 작업 공간의 이름 · 출처 문구도 그 이름이 된다(사람이 바꾼 이름은 그대로). 작업 공간의 턴에는 「반영하면 …」 변경 카드를 만들지 않는다(녹화에서 찾음).

- **TF-U-12 새 변형의 기준:** `baseFor` 는 빈 값 · `main` · 읽을 수 있는 판만 그대로 받는다. 남의 작업 공간 id 는 404, 자기 작업 공간은 409, 가지 이름 · `refs/heads/…` · `:/제안서` · `main~1` · `HEAD` · `…^{commit}` 는 400, 작업 공간에만 있는 판은 남에게도 자기에게도 404(작업 공간에서 새 변형을 만들지 않음). `createVariation` 자체도 작업 공간 id · 가지를 기준으로 받지 않는다(409).
- **TF-U-13 판으로 읽기:** 작업 공간에만 있는 판은 김서연만 읽고 박도윤 · 정하윤은 못 읽는다(`assertRefVisible` 404). main 의 판은 누구나. 없는 판 · 어느 가지에도 없는 판은 아무도.
- **TF-U-14 파일 멘션:** 박도윤이 김서연의 작업 공간 id · 그 판 · 초안의 블롭으로 초안을 멘션하면 404, 양식은 main 의 판으로 바뀐다. 김서연은 자기 작업 공간의 판으로 멘션한다. 작업 공간을 가리키는 멘션 카드는 박도윤에게 「없음」(변형 정보 없음), 김서연에게는 「열기」.
- **TF-U-15 git:** 클러스터 토큰의 `ls-remote` 에 main 은 있고 `var/t/` 가지와 그 판은 없다. 데스크톱 일 토큰은 그 프로젝트의 사람(김서연)의 일일 때만 그 작업 공간 가지 하나가 보이고(`!refs/heads/var/t/…`), 다른 사람의 일 · 다른 폴더에는 보이지 않는다.
- **TF-U-16 프로세스 단계:** `var:<작업 공간 가지>` 를 기준으로 한 deepagents · cli-agent 단계는 변형을 만들지 않는다. 템플릿 프로젝트에서 시작한 인스턴스의 에이전트 단계에는 폴더가 붙지 않는다(`projectStepFolders`).
- **TF-U-17 보내는 파일:** `merge-file` 의 종료 상태(0 깨끗 · 1 이상 충돌 · 그 밖은 실패). 링크(120000)로 바뀐 양식은 400(`tpl_not_plain`). 이름에 줄바꿈이 든 템플릿 파일은 한 파일로 보내지고 요청 변형에 그 파일 하나만 바뀐다.
- **TF-U-18 가지 이름:** 앞 8자가 같은 두 프로젝트의 작업 공간 가지가 다르다(프로젝트 id 전체). 다음 프로젝트의 이름으로 남아 있던 가지는 넘겨받지 않고 `-2` 를 쓰며, 템플릿 main 에서 시작한다.
- **TF-U-19 지정 · 참조 자리:** 작업 폴더 · 연결형은 템플릿으로 지정할 수 없다(400). 김서연의 작업 공간에 있는 경로(`산출물`)에 참조 자리를 더해도 작업 공간을 들여다보거나 프로젝트 이름을 대며 거절하지 않는다.
- **TF-U-20 실행 가지:** 내 PC 에이전트의 실행 가지(`pgpt-agent/local-…`, 변형 행 없음)에만 있는 판과, 그 가지에도 있는 작업 공간의 판은 박도윤 · 정하윤이 sha 로 읽지 못하고(404) 기준으로도 못 쓴다. 그 사람에게도 행 없는 가지에만 있는 판은 아니다. 그 블롭으로 멘션해도 404. `heads/var/t/…` · `var/t/…^0` · 실행 가지 이름은 기준으로 400, `branchExists` 는 정확한 이름만.
- **TF-U-21 비공개 사본:** 작업 공간 · 공유되지 않은 판의 파일은 비공개 저장소의 서명 주소(공개 주소 아님), main 의 파일은 예전처럼 공개 사본.
- **TF-U-22 git:** 클러스터 토큰의 `ls-remote` 에 실행 가지 · 작업 공간 가지 없음, 작업 공간 판으로 `fetch` 실패. 그 판을 가리키는 밀어 넣기(빈 팩)는 거절(`ng … not one this token may read`), 그 판 위에 쌓은 새 판(손으로 만든 팩)은 받은 뒤 되돌려 가지가 남지 않음, 보통 밀어 넣기는 그대로. `hiddenBy` 는 git 의 규칙대로(`!` 로 다시 보이기, 이름 단위), 데스크톱 일 토큰은 자기 실행 가지만.
- **TF-U-23 내 PC 에이전트의 일:** 작업 공간 프로젝트의 일이 밀어 넣은 실행 가지를 `reply` 가 작업 공간에 넣은 뒤 지운다. 변경 카드 없음, 파일 카드는 비공개 서명 주소.
- **TF-U-24 가져오기 · 이름 바꾸기 · 작업실:** 관리형 폴더 가져오기 400. 연결형에서는 `pgpt-agent/ok` 만(`^0` · `var/t/…` · 다른 이름 · `..` · `:/a` · 없는 가지는 안 가져옴). 라벨 없는 작업 공간의 이름 바꾸기는 템플릿 표시를 지우지 않음. 템플릿 꺼낸 곳이 있는 대화 방은 `holdsWorkspace` 참(관리자도 못 엶).
- **TF-U-25 보내는 파일:** 이름에 `:(icase)` · `*` 가 든 템플릿 파일도 그 파일로 보냄(`--literal-pathspecs`). 작업 공간이 실행 권한을 켠 파일은 main 과 합친 결과에도 100755. PATCH 와 `setTemplate` 이 같은 `templateSettings` 규칙(이미 지정된 표시 유지 · 작업 폴더 · 연결형 400).
- **TF-U-26 작업본 자리(#86 과 함께):** 김서연이 작업 공간을 서버 작업실에서 열면 자리는 김서연의 것. 정하윤(소유자)에게 보이는 자리에는 「돌려 달라고 하기」 · 가져오기가 없고(돌려 달라고 한 지 이틀이 지나도), `recall` · `take` 는 404. 템플릿의 「작업실」 목록에 작업 공간 없음. 자리를 잃은 곳에 남은 변경(`leftover`)은 `var/t/…` 가지 · 템플릿 표시 · 김서연 보유로 남아 목록에 없고 정하윤에게 404, 그 판은 박도윤이 못 읽는다. TF-U-05 의 작업실 방은 서버가 만든 방 그대로 김서연만 연다(정하윤 · 박도윤 거절).
- **TF-U-14 에 더함:** 보는 사람이 볼 수 없는 멘션은 `name` · `path` · `state` 만 남는다(폴더 id · 판 · 블롭 · 변형 없음).
- **TF-U-08 에 더함:** 반영 요청 변형의 `source.request` 에는 `note` · `paths` 만 있고 작업 공간 id · 프로젝트 id 가 없다.
