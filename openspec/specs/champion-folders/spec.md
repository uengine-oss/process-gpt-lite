# 챔피언 폴더 — 내 PC의 폴더를 공유 폴더로 올리고, 그 안의 에이전트 자산을 보여 준다

## Purpose
2026-11-26 사용자 요청: 「에이전트를 잘 쓰는 그런 에이전트 챔피언들의 노하우를 공유하기 위한 기능을 좀 만들면 좋을 것 같아요 그래서 이 사람이 폴더를 선택을 하면 그 폴더가 Git의 우리 폴더 서버에 있는 폴더로 동기화 될 수 있는 기능을 만들어주고 이 사람이 가고 있는 스킬이라든지 폴더 안에 .claude … 그 각 플랫폼별 스킬이 포함된 폴더가 있다면 이런 것들이 같이 동반해서」.

「챔피언 폴더」는 에이전트를 잘 쓰는 사람(챔피언)이 자기 컴퓨터에서 쓰던 폴더다. 이 폴더에는 스킬 · 명령 · 지침 · 스펙처럼 작업의 맥락을 담은 자산이 들어 있다. 챔피언은 데스크톱 앱에서 이 폴더를 골라 Lite의 관리형 공유 폴더로 올린다. 이 스펙은 그 첫 단계(0단계)를 정한다. 0단계에서 하는 일은 다음과 같다.
- 폴더를 고른다.
- 무엇이 올라가는지 미리 본다.
- 동의를 받은 뒤 올린다.
- 올린 뒤에는 사람이 「지금 올리기」를 눌러 다시 올린다.
- 폴더 화면의 「에이전트 자산」에서 플랫폼별 자산을 본다.

자동 올리기, 서버의 변경 받기, 회사 공개, 일 넘기기는 다음 단계에서 다룬다. 폴더를 올리는 git 경로와 토큰은 스펙 `folder-git-remote`를 따른다.

## Requirements

### Requirement: 사람은 이 컴퓨터의 폴더를 시스템 창에서 골라 공유 폴더로 올린다
데스크톱 앱은 올릴 폴더를 운영체제의 폴더 선택 창에서만 고를 수 있게 해야 한다(SHALL). 서버가 제공한 화면(페이지)은 경로를 보내지도 받지도 않는다. 페이지는 고른 폴더의 식별표(pick id), 폴더 이름, 미리 보기만 받는다. 서버에는 폴더 이름(이름표)만 전달되고, 경로는 해당 컴퓨터의 앱 설정에만 남는다. 디스크 전체, 홈 폴더, 앱 자체의 데이터 폴더를 포함한 폴더는 고를 수 없다.

「내 PC 폴더 올리기」 단추는 데스크톱 앱의 폴더 목록에만 보인다. 브라우저에서는 단추 대신 「데스크톱 앱에서 내 PC 폴더를 올릴 수 있어요」가 보인다. 올리기를 시작하면 페이지는 새 폴더를 「챔피언 폴더」로 만든다(`POST /api/folders`에 `champion: true`). 이 폴더는 처음에는 파일이 하나도 없으므로, 여기에 올린 스냅숏은 아무것도 지우지 않는다. 만든 사람이 소유자이며, 처음에는 만든 사람만 구성원이다. 올리기가 이루어지지 않으면(창에서 취소했거나 실패했으면) 페이지는 방금 만든 빈 폴더를 지운다(`DELETE /api/folders/:slug`). 서버는 소유자가 요청하고, 해당 폴더가 챔피언 폴더이며, 파일도 변형도 없을 때만 폴더를 지운다(그 밖에는 400 · 403 · 409). 폴더 목록에서 챔피언 폴더에는 「내 PC 에서 올림」과 찾은 자산 수(「스킬 1 · 명령 1 · 지침 2 …」)가 보인다.

올린 뒤에는 「지금 올리기」로 그 시점의 폴더를 다시 올린다. 바뀐 것이 없으면 아무것도 올리지 않는다. 「연결 끊기」는 해당 컴퓨터의 기록과 그림자 저장소만 지우고, 고른 폴더와 서버의 폴더는 그대로 둔다. 다른 사람이 같은 앱에 로그인하거나 로그아웃하면 이전 사람이 연결한 폴더의 올리기는 멈추며, 다른 사람의 이름으로 올라가지 않는다.

#### Scenario: 시스템 창에서 고르고, 페이지는 경로를 모른다
- **WHEN** 박챔피언이 데스크톱 앱의 폴더 목록에서 「내 PC 폴더 올리기」를 누르고 시스템 창에서 「영업 제안 키트」 폴더를 고른다
- **THEN** 올리기 미리 보기 시트에 「영업 제안 키트」와 올라갈 파일 수 · 크기가 보인다
- **AND** 페이지가 받은 값과 서버로 보낸 메시지 어디에도 해당 폴더의 경로가 없다(이름표 「영업 제안 키트」만 있다)

#### Scenario: F-CH-04 브라우저에서는 안내만 보인다
- **WHEN** 박챔피언이 데스크톱 앱이 아닌 브라우저에서 폴더 목록을 연다(넓은 화면, 390px 휴대폰)
- **THEN** 「내 PC 폴더 올리기」 단추는 없고 「데스크톱 앱에서 내 PC 폴더를 올릴 수 있어요」가 보이며, 화면은 옆으로 넘치지 않는다
- **AND** 챔피언 폴더의 줄에는 「내 PC 에서 올림」과 자산 수가 보이고, 해당 폴더 화면에는 「이 PC 의 … 폴더와 연결됨」 줄이 없다

#### Scenario: F-CH-07 이 컴퓨터에서 「아니오」를 고르면 빈 폴더가 남지 않고, 「예」를 고르면 해당 폴더로 이동한다
- **WHEN** 박챔피언이 미리 보기에서 이름을 「취소할 키트」로 적고 「올리기」를 누른 뒤, 시스템 창에서 취소한다
- **THEN** 시트에 「올리지 않았어요 — 폴더도 만들지 않았어요.」가 보이고, 폴더 목록에도 서버에도 「취소할 키트」가 없다
- **AND** 다시 「올린 키트」로 올리고 시스템 창에서 올리기를 고르면, 「올린 키트」 폴더 화면으로 이동하고 「이 PC 의 「영업 제안 키트 PC」 폴더와 연결됨 · 올려 둠」과 「지금 올리기」가 보인다

#### Scenario: 고를 수 없는 폴더
- **WHEN** 사람이 홈 폴더 전체나 디스크의 최상위 폴더를 고른다
- **THEN** 앱은 미리 보기를 만들지 않고 해당 폴더를 고를 수 없다고 알린다

#### Scenario: 다른 사람이 로그인하면 멈춘다
- **WHEN** 박챔피언이 폴더를 연결해 둔 앱에서 로그아웃하고 김동료가 로그인한다
- **THEN** 김동료의 「이 컴퓨터와 연결된 폴더」에는 박챔피언의 폴더가 없고, 해당 폴더는 김동료의 이름으로 올라가지 않는다

#### Scenario: 올리기가 이루어지지 않은 빈 폴더만 지운다
- **WHEN** 페이지가 파일이 이미 올라간 챔피언 폴더, 일반 폴더, 다른 사람이 소유한 빈 챔피언 폴더를 지우려 한다
- **THEN** 서버는 각각 409 · 400 · 403으로 거절하고, 소유자의 빈 챔피언 폴더만 지운다

### Requirement: 올리기 전에 무엇이 올라가는지 보여 주고 시스템 창으로 동의를 받는다
데스크톱 앱은 처음 올리기 전에 미리 보기를 보여 주어야 한다(SHALL). 미리 보기에는 다음이 포함된다.
- 올라갈 파일 수와 크기, 최상위 단계의 묶음(폴더와 파일별 파일 수 · 크기)
- 제외한 항목과 그 이유: 「이 폴더가 빼 둔 것(.gitignore)」(폴더 자체의 `.gitignore`), 「비밀로 보여 뺐어요」, 「내 PC 에만 두는 설정」, 「다시 만들 수 있는 것」, 「큰 파일 — 올리지 않음」(50 MB 초과), 「따로 관리되는 폴더 · 폴더 밖을 가리키는 링크」. 분류별로 개수와 몇 가지 예시가 보인다.
- 확인이 필요한 파일: 파일, 줄, 이유(「길고 무작위인 값」, 「GitHub 토큰」 같은 형태의 이름)만 보이고 값은 보이지 않는다
- 찾은 에이전트 자산: Claude Code의 스킬 · 명령 · 하위 에이전트 · 지침 · 실행 설정, Codex · Cursor · Gemini CLI · GitHub Copilot의 자산, 스펙
- 알림: 폴더가 이미 git 저장소이면 「이 폴더의 git 이력은 올리지 않아요 — 지금 파일만 올라가요」, 한 번에 올릴 수 있는 크기(200 MB)를 넘으면 그 사실

사람은 미리 보기에서 최상위 단계의 폴더 · 파일을 제외하고, 다시 훑은 결과를 본다. 「이 폴더가 빼 둔 것」과 「내 PC 에만 두는 설정」의 파일은 다시 포함할 수 있다. 확인이 필요한 파일은 기본적으로 제외된다. 사람이 「그래도 올리기」를 고른 파일만 올라가며, 확실한 키 형태가 있는 파일은 고를 수 없다(「서버가 받지 않아요」). 비밀로 보여 제외한 파일은 다시 포함할 수 없다. 이 선택은 해당 컴퓨터에만 남는다.

「올리기」를 누르면 페이지가 아니라 운영체제의 창이 「파일 N개(X MB)를 <서버> 의 폴더 '<이름>'(으)로 올립니다」라고 한 번 더 묻는다. 해당 창에서 「올리기」를 골랐을 때만 올라간다. 창에서 「취소」를 고르면 서버에는 아무것도 전달되지 않고, 페이지가 만든 빈 폴더는 지워진다. 미리 보기와 시트는 390px 휴대폰 화면에서도 옆으로 넘치지 않으며, 아래에서 올라오는 시트로 보인다.

#### Scenario: F-CH-01 미리 보기에 제외한 항목과 확인이 필요한 파일이 보인다
- **WHEN** 박챔피언이 `.env` · `.claude/settings.local.json` · `node_modules/` · 키 형태의 글이 든 `config/app.txt` · 스킬 · `CLAUDE.md`가 있는 폴더를 고른다
- **THEN** 미리 보기의 제외한 항목에 「비밀로 보여 뺐어요」(`.env`), 「내 PC 에만 두는 설정」(`.claude/settings.local.json`), 「다시 만들 수 있는 것」(`node_modules/`)이 보인다
- **AND** 확인이 필요한 파일에 `config/app.txt`와 해당 줄 번호 · 이유(예: GitHub 토큰 형태)가 보이고, 그 값은 화면에 없다
- **AND** 찾은 에이전트 자산에 해당 폴더의 Claude Code 스킬과 `CLAUDE.md`가 보인다

#### Scenario: F-CH-07 제외 항목과 확인할 파일이 올리기에 그대로 반영된다
- **WHEN** 박챔피언이 미리 보기에서 「녹화」 폴더의 선택을 해제하고, 확인이 필요한 `견적/메모.md`는 그대로 둔 채 올린다
- **THEN** 파일 수가 「녹화」를 제외한 수(214개 → 193개)로 바뀐다
- **AND** 앱에 전달한 「뺄 것」에는 `녹화`와 `견적/메모.md`가 들어 있고, 「비밀로 보여 뺐어요」의 파일에는 「넣기」가 없다

#### Scenario: 시스템 창에서 취소하면 아무것도 올라가지 않는다
- **WHEN** 박챔피언이 미리 보기에서 「올리기」를 누르고 시스템 창에서 「취소」를 고른다
- **THEN** 서버에 해당 컴퓨터의 원본이 생기지 않고, 폴더 목록에 새 폴더가 남지 않는다

### Requirement: 비밀 · 개인 설정 · 큰 파일은 올라가지 않는다
데스크톱 앱은 이름과 경로에 관한 규칙에 따라 다음 파일을 올리지 않아야 한다(SHALL). 이 규칙에 사용하는 목록은 서버와 같다.
- 비밀: `.env` · `.env.*`(`.env.example` 같은 예시는 올림), `*.pem` 같은 키 파일, `id_rsa` 같은 개인 키(공개 키 `*.pub`는 올림), `.npmrc` · `.netrc`, `.aws/` · `.ssh/`, CLI의 로그인 정보(`.claude/.credentials.json` · `.codex/auth.json`)
- 개인 설정과 기록: `.claude/settings.local.json` · `.claude/projects/` · `.codex/sessions/` · `.vscode/` …
- 다시 만들 수 있는 것: `node_modules/` · `.venv/` …
- 50 MB를 넘는 파일, 내부에 있는 다른 git 저장소, 폴더 밖을 가리키는 링크

폴더의 `.gitignore`가 해당 파일을 다시 포함하도록 지정하더라도(`!.env`) 앱의 제외 규칙이 우선한다. 남은 1 MB 이하 텍스트 파일에서는 알려진 키 형태를 검사한다. 검사 대상은 개인 키의 시작 부분, 제공자별로 정해진 토큰 형식, 길고 고르게 섞인 `이름=값`이다. 탐지된 파일은 사람이 포함하지 않는 한 올리지 않는다. 이는 파일 이름과 토큰 형식을 검사하는 것이며, 글의 뜻을 읽는 것은 아니다. 탐지된 값은 화면, 로그, 서버 어디에도 보내지 않는다. 파일 이름, 줄 번호, 이유만 보낸다.

서버도 동기화로 들어온 항목을 같은 목록으로 한 번 더 검사한다. 비밀에 해당하는 이름이거나 확실한 키 형태(개인 키, 제공자 토큰)가 든 파일이 있으면, 서버는 해당 올리기를 main에 반영하지 않는다. 해당 컴퓨터의 가지는 올리기 직후에 직전 머리로 되돌린다. 그리고 해당 컴퓨터에 「비밀」이라는 이유와 파일 · 줄 · 이유의 목록을 알린다. 이 검사는 한 번의 올리기에 포함된 모든 커밋에 대해 수행한다(중간에 넣었다가 지운 키도 탐지된다). 탐지된 값은 서버의 기록에도 남지 않는다. 데스크톱의 해당 폴더에는 「멈춤 · 비밀로 보이는 파일이 있어 서버가 받지 않았어요」와 파일 · 줄 · 이유가 보인다. 해당 파일을 제외하고 다시 올리면 반영된다.

#### Scenario: F-CH-03 `.env`와 `settings.local.json`은 서버에 없다
- **WHEN** 박챔피언이 `.env`와 `.claude/settings.local.json`이 든 폴더를 올린다
- **THEN** 해당 공유 폴더의 파일 목록과 git의 main 어디에도 `.env` · `.claude/settings.local.json`이 없다
- **AND** `.env.example` · `.claude/settings.json`은 올라가 있다

#### Scenario: 폴더의 .gitignore가 비밀을 다시 포함해도 제외된다
- **WHEN** 폴더의 `.gitignore`에 `!.env`가 있다
- **THEN** 미리 보기에서 `.env`는 「비밀로 보여 뺐어요」에 있고, 올린 뒤 서버에 없다

#### Scenario: 개인 키 형태가 있는 파일이 포함된 올리기는 서버가 받지 않는다
- **WHEN** 박챔피언의 컴퓨터가 `deploy/서버 열쇠.txt`(둘째 줄에 개인 키)가 든 스냅숏을 자기 가지로 올리고 「올렸어요」라고 알린다
- **THEN** 서버는 「비밀」이라는 이유와 `deploy/서버 열쇠.txt` · 2째 줄 · 개인 키(PEM)를 돌려주고, 해당 가지는 직전 머리에 있으며, 폴더의 main과 파일 목록은 그대로다
- **AND** 해당 키의 값은 응답에도 서버의 기록에도 없다
- **AND** 해당 파일을 제외하고 다시 올리면 main이 해당 스냅숏으로 이동한다

---

### Requirement: 고른 폴더는 읽기만 한다
데스크톱 앱은 고른 폴더에 아무것도 만들거나 바꾸지 않아야 한다(SHALL). `.git`도, 설정 파일도, 그 밖의 어떤 파일도 만들지 않는다. 동기화의 색인과 기록은 앱 데이터 폴더의 그림자 저장소에 둔다. 고른 폴더가 이미 git 저장소여도 사용자의 `.git`(이력 · 원격 · 가지 · 설정)은 열지도 바꾸지도 않는다. 기존 이력은 올라가지 않고, 현재 파일의 스냅숏만 올라간다. 올리기에는 작업 트리를 되돌리거나 정리하거나 바꾸는 git 명령(`reset` · `clean` · `checkout`)을 쓰지 않는다. 서버에서 바뀐 내용은 이 단계에서 고른 폴더에 들어오지 않는다.

#### Scenario: 올린 뒤에도 고른 폴더는 그대로다
- **WHEN** 박챔피언이 자기 git 저장소인 폴더를 올리고, 웹에서 누군가 해당 공유 폴더의 파일을 고친 뒤 「지금 올리기」를 누른다
- **THEN** 고른 폴더의 모든 파일 · 폴더의 내용과 시각, 사용자의 `.git`이 올리기 전과 바이트 단위까지 같고, 새 파일이 없다
- **AND** 서버 main의 첫 스냅숏은 커밋 하나이고(사용자의 기존 커밋은 없다), 작성자는 박챔피언, 메시지는 「동기화 · <기기 이름>」이다
- **AND** 웹에서 고친 파일은 서버의 main에 남고(병합), 고른 폴더에는 생기지 않는다

---

### Requirement: 올린 스냅숏은 폴더의 main이 되고, 충돌하면 main은 그대로다
서버는 컴퓨터가 자기 가지에 올렸다고 알린 머리를 해당 폴더의 직렬 잠금 안에서 main으로 반영해야 한다(SHALL). 순서는 다음과 같다.
1. 웹에서 main에 고쳐 둔 내용이 있으면 먼저 커밋한다.
2. main을 해당 머리로 앞감기한다.
3. 앞감기가 안 되면 병합한다.
4. 양쪽에서 같은 파일을 고쳐 충돌하면 main은 그대로 두고, 해당 컴퓨터에 「서버 쪽에도 바뀐 것이 있어요」를 알린다.

main이 이동하면 폴더의 파일 목록과 에이전트 자산이 곧바로 갱신되고, 문서 카드는 잠시 뒤에 만들어진다. 알린 머리가 해당 가지의 끝이 아니면 받지 않는다. 해당 컴퓨터는 폴더 화면에서 「이 폴더를 올리는 PC」로 보인다. 해당 컴퓨터에서의 폴더 이름, 사람, 기기 이름, 상태, 마지막으로 올린 시각, 파일 수 · 크기가 보이며, 경로는 보이지 않는다. 해당 사용자나 폴더 소유자는 해당 컴퓨터에 대해 「멈추기」 · 「다시 켜기」 · 「연결 빼기」를 할 수 있다. 다른 사람은 403을 받는다. 멈추거나 연결을 빼면 연결된 컴퓨터에 곧바로 그 사실이 전달된다. 그 뒤 해당 컴퓨터의 토큰과 토큰 요청은 거절된다. 해당 컴퓨터는 다시 연결할 수 있다. 데스크톱 앱 안에서 해당 폴더를 열면 상단에 「이 PC 의 「<이름>」 폴더와 연결됨」, 상태, 「지금 올리기」 · 「폴더 열기」가 보인다.

#### Scenario: 첫 스냅숏이 main이 된다
- **WHEN** 박챔피언의 컴퓨터가 새 챔피언 폴더에 스킬 · 명령 · `CLAUDE.md` · `AGENTS.md` · Cursor 규칙 · OpenSpec 스펙 · 문서 8개를 올리고 알린다
- **THEN** main은 해당 머리로 앞감기되고, 폴더의 파일 목록에 8개가 모두 있으며, 「에이전트 자산」에 6개가 있다
- **AND** 「이 폴더를 올리는 PC」에 「영업 제안 키트 · 박챔피언 · 박챔피언의 맥 · 올려 둠」이 보이고 경로는 없다

#### Scenario: 웹의 편집과 합쳐지고, 충돌하면 main은 그대로다
- **WHEN** 웹에서 `웹에서.md`를 추가한 뒤 컴퓨터가 `CLAUDE.md`를 고친 스냅숏을 올린다
- **THEN** main에는 두 변경이 모두 있다
- **AND** 그 뒤 웹과 컴퓨터가 `CLAUDE.md`의 같은 줄을 다르게 고치면 main은 웹의 버전 그대로이고, 컴퓨터에는 「서버 쪽에도 바뀐 것이 있어요」가 전달된다

#### Scenario: 웹에서 멈추거나 연결을 빼면 해당 컴퓨터에 곧바로 전달된다
- **WHEN** 폴더 소유자가 「이 폴더를 올리는 PC」에서 박챔피언의 맥에 대해 「멈추기」를 했다가 「다시 켜기」를 하고, 그 뒤 「연결 빼기」를 한다
- **THEN** 멈춘 동안 해당 컴퓨터에는 「멈춤」이 전달되고 토큰은 거절되며, 다시 켜면 토큰을 다시 사용할 수 있다
- **AND** 연결을 빼면 해당 컴퓨터에 「웹에서 연결을 뺐어요」가 전달되고, 해당 토큰과 토큰 요청은 거절되며, 컴퓨터는 목록에서 사라진다
- **AND** 김동료(해당 컴퓨터의 사용자도 소유자도 아님)가 연결을 빼려 하면 403을 받는다

### Requirement: 폴더 안의 에이전트 자산을 찾아 보여 준다
시스템은 폴더의 main이 이동할 때마다 main에 있는 파일의 **위치(경로)**만으로 에이전트 자산을 찾아야 한다(SHALL). 파일에 적힌 글의 뜻은 읽지 않는다. 위치 목록은 데스크톱 앱의 미리 보기와 같은 데이터를 사용하며, 플랫폼이 늘면 해당 목록만 고친다.

| 플랫폼 | 위치 | 종류 |
|---|---|---|
| Claude Code | `.claude/skills/<이름>/SKILL.md` · `.claude/commands/**/*.md` · `.claude/agents/*.md` · `CLAUDE.md`(하위 폴더 포함) · `.claude/settings.json` · `.mcp.json` | 스킬 · 명령 · 하위 에이전트 · 지침 · 실행 설정 · MCP 서버 |
| Codex | `AGENTS.md`(하위 폴더 포함) · `.codex/skills/<이름>/SKILL.md` · `.agents/skills/<이름>/SKILL.md` · `.codex/prompts/*.md` · `.codex/config.toml` | 지침 · 스킬 · 프롬프트 · 실행 설정 |
| Cursor | `.cursor/rules/**/*.mdc` · `.cursorrules` | 규칙 |
| Gemini CLI | `GEMINI.md` · `.gemini/commands/**/*.toml` | 지침 · 명령 |
| GitHub Copilot | `.github/copilot-instructions.md` · `.github/instructions/*.instructions.md` · `.github/prompts/*.prompt.md` | 지침 · 프롬프트 |
| 스펙 | `openspec/specs/*/spec.md` · `openspec/changes/*/proposal.md` · `specs/*/spec.md` · `.kiro/specs/*/requirements.md` · `aidlc-docs/**/*.md` | 스펙 · 진행 중인 변경 |

각 자산의 이름과 설명은 다음과 같이 정한다.
- 이름: 파일의 YAML 머리말(`name`)에서 가져온다. 머리말에 이름이 없으면 위치에 따라 정한다. 스킬은 해당 폴더 이름, 명령은 Claude Code에서 부르는 이름(`.claude/commands/opsx/apply.md` → `opsx:apply`), 그 밖의 자산은 파일 이름을 쓴다.
- 설명: 머리말의 `description`에서 가져온다(한 줄, 따옴표, 여러 줄 `>` · `|`, CRLF 모두). 머리말이 없는 지침 · 규칙 · 스펙은 첫 제목을 설명으로 쓴다.
- 실행 설정(`.claude/settings.json` · `.mcp.json` 등): 훅, 허용 목록, MCP 서버처럼 실행되는 항목이 들어 있을 때만 「실행되는 설정」으로 표시한다.
- 파일이 바뀌지 않았으면 다시 읽지 않고, main에서 사라진 자산은 목록에서도 제외한다.

`GET /api/folders/:slug/kit`은 보기 이상의 권한이 있는 사람에게 `[{platform, type, path, name, description, runs}]`를 제공한다. 챔피언 폴더이거나 자산이 하나라도 있으면 폴더 화면에 「에이전트 자산」 탭(자산 수)이 생긴다. 탭에는 다음이 보인다.
- 플랫폼별 묶음과 각 묶음 상단의 한 줄 안내(「이 폴더에서 일하면 Claude Code 가 저절로 읽어요」), 종류별 수
- 항목별 종류 · 이름 · 설명 · 경로. 누르면 해당 파일이 폴더의 다른 파일처럼 열린다.
- 실행되는 설정이 있으면 맨 위에 「이 폴더에는 실행되는 설정이 있어요: <파일> — …」

탭은 밝은 테마와 어두운 테마 모두에서 읽을 수 있고, 390px 휴대폰에서 옆으로 넘치지 않으며, 묶음은 접을 수 있다.

#### Scenario: F-CH-02 올린 뒤 폴더에 파일과 「에이전트 자산」 탭이 있다
- **WHEN** 박챔피언이 스킬 · 명령 · `CLAUDE.md` · `AGENTS.md`가 든 폴더를 데스크톱 앱에서 올린다
- **THEN** 폴더 화면의 파일 목록에 해당 파일들이 있다
- **AND** 「에이전트 자산」 탭에 Claude Code 스킬(이름 · 설명) · 명령 · 지침, Codex 지침이 플랫폼별로 보인다

#### Scenario: F-CH-05 390px 휴대폰의 「에이전트 자산」 — 밝은 · 어두운 테마
- **WHEN** 박챔피언이 main에 `.claude/skills/x/SKILL.md` · `.claude/commands/opsx/apply.md` · `.claude/settings.json`(훅) · `CLAUDE.md` · `AGENTS.md` · `.cursor/rules/a.mdc` · `openspec/specs/y/spec.md`가 있는 챔피언 폴더를 390px 휴대폰에서 열고 「에이전트 자산」을 누른다
- **THEN** Claude Code · Codex · Cursor · 스펙 네 묶음에 7개가 보이고, 「실행되는 설정이 있어요: .claude/settings.json」이 보인다
- **AND** 밝은 테마와 어두운 테마 모두에서 항목이 화면 너비 안에 있고, 화면은 옆으로 넘치지 않는다

#### Scenario: F-CH-06 넓은 화면의 「에이전트 자산」
- **WHEN** 박챔피언이 같은 폴더를 넓은 화면에서 열고 「에이전트 자산 7」 탭을 누른다
- **THEN** 스킬에는 머리말의 이름 「견적 규칙」과 설명 「견적서를 만들 때 지킬 것 — 할인율 · 납기 · 서명」이, 명령에는 `opsx:apply`가, `.claude/settings.json`에는 「실행되는 설정」이 보인다
- **AND** 「견적 규칙」을 누르면 `SKILL.md`가 열린다

#### Scenario: 자산이 바뀌면 표가 갱신된다
- **WHEN** main에서 스킬의 머리말 이름을 바꾸고 `AGENTS.md`를 지운다
- **THEN** 탭의 스킬 이름이 바뀌고 Codex 묶음이 사라진다
