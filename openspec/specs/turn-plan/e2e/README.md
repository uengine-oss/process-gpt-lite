# 시험과 증거 — 계획 카드와 진행 상황

규칙(앞단 계획 읽기, 앞단 모델과 빠른 모델의 경주, 언어 지시, 처리 방법 판단의 시간 한도, 중간 글 나누기, 할 일 목록 읽기, 진행 상태 경로, 작업 카드 한 줄)은 OpenAI 형식을 모방한 가짜 서버로 단위 시험한다. 화면 동작은 Playwright로 실제 화면에서 확인한다. 새 SQL은 없다.

## 단위 시험 (실제 모델 없이)

```bash
cd server && node --test test/turnPlan.test.js
```

- `turnPlan.test.js`(22 — TP-U 10, 아래 검토 항목의 TP-R 12):
  - TP-U-01: 앞단 계획 JSON을 읽는다. 울타리(```` ```json ````)로 감싸져 있어도 읽고, 단계는 4개까지만 받으며, `think:false` · `max_tokens` 400으로 묻는다. 계획이 아닌 답은 버린다.
  - TP-U-02: 4초 안에 답이 없으면 null을 반환한다(4.0~4.8초). 카드에는 「요청을 받았어요. 바로 살펴볼게요.」가 표시되고, 에이전트에게는 계획 블록이 전달되지 않는다.
  - TP-U-03: 앞단 모델과 빠른 모델의 경주를 확인한다.
    - 앞단 모델에서 오류가 발생하면 곧바로 빠른 모델에 묻는다.
    - 앞단 모델이 2.5초 동안 답하지 않으면 빠른 모델에도 묻고, 빠른 모델이 먼저 답한다.
    - 앞단 모델이 빠른 모델보다 먼저 답하면 앞단 모델의 답을 사용한다.
    - 같은 모델이면 응답이 느릴 때는 두 번 묻지 않고, 오류가 발생했을 때만 한 번 더 묻는다.
    - 둘 다 실패하면 null을 반환한다.
  - TP-U-04: 언어를 확인한다.
    - 앞단 호출: 한국어 화면에서는 「메시지의 언어, 말이 없으면 한국어 해요체」로, 영어 화면에서는 영어로 쓰도록 지시하고 `LANGUAGE: English`를 붙인다.
    - 에이전트 지시: 한국어 화면에서는 `[Instruction] 언어: 한국어 …`를, 영어 화면에서는 `LANGUAGE: English`를 붙인다.
    - 계획 블록: `[계획]` · `[Plan]` 블록을 붙인다.
  - TP-U-05: 처리 방법 판단을 확인한다.
    - 6초가 지나면 null을 반환한다(→ 에이전트).
    - 500 오류가 발생하거나 인자가 JSON이 아니어도 null을 반환한다.
    - DELEGATE는 `call` 없이 반환하고, 도구는 그대로 반환한다.
    - 「멈추기」 신호가 오면 즉시 null을 반환한다.
    - 생각(thinking)은 끄지 않는다. 아래 「측정」을 참고한다.
  - TP-U-06: 중간 글을 나눈다.
    - 짧은 글 뒤에 도구가 오면 해당 글은 메모가 되고, 답에는 포함되지 않는다.
    - 200자를 넘으면 한 번 답으로 올리고, 이어지는 글은 그대로 흘려보낸다.
    - 그 뒤에 도구가 오면 retract하고 메모로 옮긴다.
    - 마지막 조각을 답으로 삼는다. 마지막 조각이 없으면 마지막으로 닫힌 조각을 답으로 삼는다.
    - 스킬 작성 중에는 흘려보내지 않는다.
  - TP-U-07: `plan_todos`를 할 일 목록으로 바꾼다.
  - TP-U-08: `GET /api/threads/:id/turn`은 계획 · 처리 주체 · 단계 · 할 일 · 한 일 · 메모를 반환한다. 다른 사람이 호출하면 404를 반환한다. 턴이 끝나면 비워지고, 답에는 `content.plan` · `content.notes`가 남는다.
  - TP-U-09: 최근 작업 카드 한 줄을 확인한다.
    - NotebookLM 카드는 `browser task · waiting · NotebookLM에서 노트북 만들기 · https://medium.com/… · skill notebooklm`으로 작성한다.
    - 내 PC 작업 카드도 한 줄로 작성한다. 한 줄은 160자까지이며, 상태는 다섯 가지로 변환한다.
    - 「이제 아까 만들기로 한 노트북 만들자」를 보내면 처리 방법 판단 프롬프트와 앞단 프롬프트에 그 한 줄이 포함된다.
  - TP-U-10: 「멈추기」는 앞 단계(처리 방법 판단 전)의 턴에 전달된다. 대기 중인 턴은 waiting 상태로 남는다.
- 변경된 기대값: `lang.test.js`의 「outside any request the language is ko」는 이제 한국어 화면에서도 `[Instruction] 언어: 한국어`를 기대한다(설계 §1.5).

- 시험이 자체 스택을 띄운다(`lib/localStack.js` — 회사 `turnplan-ui`, BFF 8945 · Vite 5345부터 빈 포트 사용, `PRO_BACKGROUND=0`).
- 가짜 모델(8946)과 가짜 deepagents(8947)는 시험 파일이 띄운다.
  - 가짜 모델: 앞단 계획은 프롬프트에서 영어를 요청할 때만 영어로 답한다. 처리 방법 판단에는 DELEGATE로 답한다. 링크에 `router-500` · `slow-router` · `stop-router` · `slow-front`가 있으면 각각 오류를 반환하거나 8초 · 10초 · 6.5초 뒤에 답한다.
  - 가짜 deepagents: `plan_todos` → 짧은 문장 「먼저 링크의 글을 열어 볼게요.」 → `plan_tools` · `tool_start` · `tool_end` → `plan_todos`(첫 항목 완료) → 16초 대기 → 답 → `plan_todos`(모두 완료) → `done` 순서로 보낸다. 링크에 `quick`이 있으면 대기 시간이 짧고, `short`가 있으면 3초다.
- 맥락 라우터 · completion · 판단 서버는 연결 대상이 없는 주소를 사용한다. 실제 모델 · 에이전트는 호출하지 않는다.
- 서버를 새로 띄우면 첫 채팅 턴이 늦게 시작하므로, 그 턴을 측정하지 않도록 먼저 한 턴을 보낸다(아래 「알려진 것」).

## 측정

- 카드가 표시되기까지 걸린 시간(가짜 모델, 이 PC): F-TP-01에서 Enter를 누른 뒤 이해한 문장이 표시되기까지 307 · 815 · 843 · 846 · 1346 · 1357 ms가 걸렸다(여러 번 실행, 마지막 실행 307 ms). 서버 로그 기준으로 앞단 호출은 253~260 ms가 걸렸다. 안내 문장은 4149 · 4196 · 4687 ms에 표시됐다(F-TP-02).
- 처리 방법 판단의 시간 한도: 오류가 발생했을 때는 Enter를 누른 뒤 에이전트에 전달되기까지 362 · 390 ms, 8초 걸리는 판단에서는 6082 · 6489 ms가 걸렸다(F-TP-03).
- 실제 사내 모델(frentis, 2026-11-25, 이 PC): 앞단 계획은 361~641 ms가 걸렸다. 링크만 보낸 메시지에는 「링크된 Medium 글을 읽고 요약해 드릴게요.」, 단계 3개, tier light가 반환됐다.
- 처리 방법 판단에서 생각(thinking)을 끄면 frentis가 잘못 선택한다. 같은 프롬프트로 생각을 끄면(`think:false`) 링크만 보낸 메시지와 「소개 페이지와 메모, 마인드맵을 만들어 줘」를 browser_task로, 「주간 보고를 마크다운으로 써 줘」를 process로 보냈다(3번 모두). 생각을 켜면 세 가지 모두 DELEGATE였다. 예약 · 브라우저 · 알림은 두 경우 모두 올바르게 선택했다. 생각을 켠 판단은 0.9~3.7초 걸렸다. 따라서 처리 방법 판단에서는 생각을 끄지 않고 6초 한도와 토큰 상한(1500)만 둔다. 앞단 계획에서는 생각을 끈다.

## 알려진 것 · 확인하지 못한 것

- 새로 띄운 서버의 첫 턴에서 카드가 표시되기까지 4초 넘게 걸린 적이 한 번 있었다(이해한 문장이 나오지 않은 채 「요청을 읽는 중」만 표시됐다). 따라서 시험에서는 먼저 한 턴을 보낸 뒤에 측정한다. 운영 서버는 늘 실행 중이므로 해당하지 않을 것으로 보지만, 확인하지는 않았다.
- 전체 실행 중 한 번은 F-TP-10의 턴이 `done` 뒤 25초 넘게 끝나지 않았다. 같은 시점에 서버 로그에 `[local-agents] claim canceling statement due to statement timeout`(공용 DB 지연)이 기록됐다. 같은 시험을 따로 실행했을 때와 전체를 다시 실행했을 때는 통과했다.
- 실제 deepagents가 `done.content`에 마지막 답만 담는지는 코드 검토(출력 정리 함수)로만 확인했다. 운영 턴에서는 확인하지 않았다.
- 운영 모델(`PRO_LLM_FRONT_MODEL=claude-sonnet-5-5`)의 앞단 계획 시간과 문장은 측정하지 않았다. 이 PC의 모델 게이트웨이에는 frentis만 연결된다.
- 영어 화면에서 답 아래의 「어떻게 했나요 · 1단계 · 조회한 곳 …」 줄은 번역되지 않는다. 이 변경 전부터 있던 현상이다(사전의 `어떻게 했나요 · {0}단계{1}`가 `{1}` 앞의 공백 때문에 일치하지 않음).
