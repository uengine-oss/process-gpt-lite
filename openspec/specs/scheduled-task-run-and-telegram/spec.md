# 예약 작업 바로 실행 · 텔레그램 알림 · 작업 흔적

## Purpose
사용자는 채팅으로 예약 작업(1시간마다 주가 보기 같은 일)을 만들고, 만든 작업을 바로 시험해 보고, 결과를 텔레그램으로도 받고 싶어 한다. 이 스펙은 이미 있는 예약 작업을 지금 한 번 실행하는 방법, 결과를 사용자의 텔레그램 봇으로 보내는 방법, 답을 만들 때 어디서 무엇을 읽었는지 보여 주는 방법, 주가 같은 시세를 읽을 때 지켜야 할 사항을 정한다. 근거는 2026-11-21 휴대폰 검토 녹화(결정 D-1121-03~06)다.
## Requirements
### Requirement: 이미 있는 예약 작업을 지금 한 번 실행한다
사용자가 대화에서 방금 만들었거나 실행한 예약 작업 또는 이름을 지정한 예약 작업을 「지금 · 곧바로 · 바로 · 테스트로 … 실행해 봐」처럼 지금 실행해 달라고 하면, 시스템은 새 예약을 만들지 않아야 한다(SHALL NOT). 대신 그 작업을 바로 한 번 실행해야 한다(SHALL). 응답에는 실행할 작업을 설명하는 한 줄과 「지금 실행 · <작업 이름>」 표시를 남겨야 한다(SHALL). 실행 결과는 요청한 대화에 그 작업의 구분선 아래에 올려야 하며(SHALL), 조건(예: 5% 급등락)에 해당하는 결과가 없어도 확인한 값과 판단을 보여 주어야 한다(SHALL). 실행 기록에는 trigger를 `manual`로 남겨야 한다(SHALL).
「10분 뒤에」「내일 9시에」처럼 실행 시각이나 실행을 미루는 표현이 있으면 지금 실행이 아니다(SHALL NOT). 작업 이름도 없고 바로 앞 대화에서 다룬 작업도 없으면 이 규칙을 적용하지 않고(SHALL NOT), 다른 요청(예: 프로세스 시작)으로 처리한다. 프로세스·스크립트·스킬처럼 다른 실행 대상을 말한 경우도 같다(SHALL NOT). 예약된 작업 화면의 「지금 실행」 단추는 이 시험 실행이 아니며, 그 작업의 알림 규칙(바뀐 게 있을 때만 등)을 그대로 따라야 한다(SHALL).

#### Scenario: 방금 만든 작업을 바로 시험한다
- **GIVEN** 대화에 「예약됨 · 주가 5일 누적 급등락 감시」가 있다
- **WHEN** 「곧바로 하나 정도 한번 실행해 봐」라고 보낸다
- **THEN** 예약 작업 수는 그대로다
- **AND** 「지금 실행 · 주가 5일 누적 급등락 감시」 표시가 생기고, 실행 기록에 `manual` 실행이 하나 생긴다
- **AND** 실행이 끝나면 결과가 그 작업 이름의 구분선 아래에 올라온다

#### Scenario: 시각이 있으면 새 예약이다
- **WHEN** 「10분 뒤에 한 번 실행해 줘」라고 보낸다
- **THEN** 지금 실행하지 않고, 한 번만 실행되는 새 예약으로 처리한다

---

### Requirement: 같은 분에 시작하는 예약 실행도 모두 돈다
시스템은 같은 사람의 예약 실행 여러 개가 같은 분에 시작해도 모두 실행해야 한다(SHALL). 예약 실행은 로그인 링크로 그 사람의 세션을 만든다. 같은 사람의 링크를 새로 만들면 이전 링크가 무효가 되므로 한 사람의 세션은 차례로 만든다. 각 실행은 자기 세션을 받는다(갱신 토큰을 공유하지 않는다). 그사이 다른 서버가 링크를 썼으면 링크를 한 번 더 만든다.

#### Scenario: 같은 분에 둘
- **WHEN** 한 사람의 예약 작업 둘이 같은 분에 시작한다
- **THEN** 둘 다 실행되고, 「session mint failed … otp_expired」로 실패하지 않는다

### Requirement: 예약 작업의 결과를 텔레그램으로도 보낸다
사용자가 「급등락이 감지되면 내 텔레그램 봇으로 알려줘」처럼 말하면, 시스템은 그 대화에서 다룬 예약 작업(또는 이름을 말한 작업)의 전달 대상에 텔레그램을 추가해야 한다(SHALL). 봇이 연결되어 있지 않으면 대화에 텔레그램 연결 카드를 띄우고(SHALL), 연결되면 다음 결과부터 텔레그램으로도 보내야 한다(SHALL). 「텔레그램 알림 꺼 줘」라고 하면 그 작업의 텔레그램 전달을 꺼야 한다(SHALL).
작업 실행 결과가 대화에 올라왔다면(조건을 충족했거나, 매번 알리는 작업이거나, 지금 실행한 경우) 같은 내용을 사용자의 텔레그램 봇으로 보내야 한다(SHALL). 보낸 결과는 실행 기록에 `telegram: "sent"`로 남겨야 한다(SHALL). 보내지 못하면 대화에 사유를 한 줄 남기고 실행 기록에 그 사유 코드를 남겨야 한다(SHALL). 봇이 아직 연결되지 않아 못 보낸 경우의 안내 줄은 작업마다 한 번만 남겨야 하며(SHALL), 매 실행마다 쌓지 않아야 한다(SHALL NOT). 어느 작업인지 알 수 없으면 작업 이름을 물어야 하고(SHALL), 다른 작업에 임의로 켜거나 방금 답을 대신 보내지 않아야 한다(SHALL NOT). 텔레그램을 쓰는 방법을 묻는 질문이나 텔레그램 채널을 다루는 새 예약 요청은 이 규칙의 대상이 아니다(SHALL NOT). 예약된 작업 화면의 「텔레그램으로도」 스위치로도 켜고 끌 수 있어야 하며(SHALL), 다른 사람의 작업은 바꿀 수 없어야 한다(SHALL NOT, 404).

#### Scenario: 봇이 없을 때 알려 달라고 한다
- **GIVEN** 대화에 예약 작업이 있고 텔레그램 봇이 연결되어 있지 않다
- **WHEN** 「급등락이 감지되면 내 텔레그램 봇으로 알려줘」라고 보낸다
- **THEN** 그 작업의 전달 대상에 텔레그램이 들어간다
- **AND** 대화에 텔레그램 연결 카드가 하나 생긴다

#### Scenario: 연결한 뒤 실행 결과
- **GIVEN** 그 작업에 텔레그램 전달이 켜져 있고 봇이 연결되어 있다
- **WHEN** 작업을 지금 실행한다
- **THEN** 결과가 대화에 올라오고, 같은 내용이 텔레그램 봇 대화로 간다
- **AND** 그 실행 기록에 `telegram: "sent"`가 남는다

#### Scenario: 다른 사람의 작업
- **WHEN** 다른 사람이 `POST /api/missions/<id>/channels`로 그 작업의 텔레그램을 켜려 한다
- **THEN** 404를 받는다

### Requirement: 텔레그램 봇 연결
시스템은 사용자가 자신의 텔레그램 봇을 연결할 수 있게 해야 한다(SHALL). 순서는 다음과 같다.
1. BotFather에서 받은 토큰을 붙여 넣으면 봇을 확인하고(getMe), 그 봇을 여는 링크를 보여 준다.
2. 사용자가 카드의 「봇 열기」 링크로 봇을 열어 시작(Start)을 누르면 그 대화를 알림을 받을 곳으로 저장한다. 봇 이름은 누구나 알 수 있으므로, 이 링크로 연 대화(`/start <연결 표식>`)만 저장해야 하며(SHALL), 이름으로 찾아 누른 시작은 저장하지 않고 링크로 열라고 안내해야 한다(SHALL).
3. 연결이 끝나면 시험 메시지를 보낼 수 있고, 연결을 끊을 수 있다.

토큰은 사용자의 암호화된 보관함에만 저장해야 하며(SHALL), 어떤 응답·기록·화면에도 나오지 않아야 한다(SHALL NOT). 잘못된 토큰이면 저장하지 않고 사유를 보여 주어야 한다(SHALL). 4096자를 넘는 결과는 나누어 보내야 하며(SHALL), 마크다운 표시는 평문으로 바꾸어 보내야 한다(SHALL). API: `GET /api/telegram`, `POST /api/telegram/connect {token}`, `POST /api/telegram/link`, `POST /api/telegram/test`, `DELETE /api/telegram`.

서버가 텔레그램 Bot API에 연결하지 못하면 503으로 응답하고, 그 이유(오류 코드와 호스트)를 응답과 서버 기록에 남겨야 한다(SHALL). 502는 사용하지 않는다 — 운영 환경에서는 앞단의 Cloudflare가 502를 자체 HTML 오류 페이지로 바꿔 오류 이유가 사라진다. 화면은 API 대신 HTML 페이지를 받아도 마크업을 보여 주지 않고, 상태 코드와 함께 다시 시도하라는 문장을 표시해야 한다(SHALL).

#### Scenario: 연결부터 시험 메시지까지
- **WHEN** 토큰을 넣고 「연결」을 누른다
- **THEN** 「@<봇> 봇을 찾았어요」와 「봇 열기」가 보인다
- **WHEN** 봇에서 시작을 누른다
- **THEN** 몇 초 안에 「연결됐어요 · <이름>」이 보인다
- **AND** `GET /api/telegram` 응답에는 토큰이 없다

#### Scenario: 잘못된 토큰
- **WHEN** 봇을 찾을 수 없는 토큰으로 연결한다
- **THEN** 「이 토큰으로는 봇을 찾지 못했어요」 사유가 보이고, 저장된 연결은 바뀌지 않는다

#### Scenario: 서버가 텔레그램에 닿지 못할 때
- **WHEN** 서버가 텔레그램에 연결할 수 없는 상태에서 토큰을 입력하고 「연결」을 누른다
- **THEN** 응답은 503이고 `code`는 `telegram_unreachable`이며, `detail`에는 오류 코드와 호스트만 포함된다(토큰 없음)
- **AND** 카드에 「이 서버에서 텔레그램에 연결하지 못했어요 (<이유>)」가 표시되고, 토큰을 다시 보낼 수 있다

#### Scenario: 앞단이 HTML 오류 페이지를 돌려줄 때
- **WHEN** 「연결」의 응답이 Cloudflare의 502 HTML 페이지다
- **THEN** 카드에는 「서버가 응답하지 못했어요 (502). 잠시 후 다시 시도해 주세요.」가 표시되고, HTML 마크업은 보이지 않는다

### Requirement: 답을 만들 때 어디서 무엇을 읽었는지 보여 준다
에이전트의 답(예약 실행 결과 포함) 아래에는 그 답을 만드는 데 거친 단계를 접힌 상태의 한 줄로 보여 주어야 한다(SHALL). 한 줄의 형식은 「어떻게 했나요 · N단계 · 조회한 곳 <사이트>」이다. 펼치면 각 단계에서 한 일과 읽은 사이트(호스트 이름), 검색어, 파일 이름을 보여 주어야 한다(SHALL). 명령줄, 주소 전체, 쿼리 문자열, 키·토큰은 보이지 않아야 한다(SHALL NOT). 사내·로컬 주소도 보이지 않아야 한다(SHALL NOT).

#### Scenario: 주가 조회 결과
- **WHEN** 에이전트가 공개 시세 주소를 명령으로 읽어 답한다
- **THEN** 답 아래 「어떻게 했나요 · N단계 · 조회한 곳 ac.stock.naver.com, api.stock.naver.com」이 보인다
- **AND** 펼쳐도 명령줄이나 키 값은 보이지 않는다

### Requirement: 시세는 공개 출처에서 읽고, 종목은 지어내지 않는다
주가·지수 요청을 처리하는 에이전트에게 시스템은 공개 시세를 읽을 곳과 종목을 찾는 방법을 함께 알려야 한다(SHALL). 종목을 찾을 때는 이름의 띄어쓰기를 달리하거나 영문·약칭·티커로 바꿔 국내와 해외를 모두 찾아야 한다. 결과에는 선택한 종목(이름·시장·코드), 기준 날짜, 출처를 밝혀야 한다(SHALL). 찾지 못한 종목의 코드를 지어내서는 안 되며(SHALL NOT), 후보를 함께 보여 주어야 한다. 예약 작업을 만들 때도 사용자가 말하지 않은 종목 코드를 작업 지시에 넣지 않아야 한다(SHALL NOT).

#### Scenario: 「ast 모바일」
- **GIVEN** 예약 작업 지시가 「코스피·코스닥·테슬라·ast 모바일 주가를 보고 5일 누적 5% 급등락이면 알려줘」다
- **WHEN** 작업이 실행된다
- **THEN** 작업 지시에는 사용자가 말하지 않은 코드(예: 「AST모바일(031440)」)가 없다
- **AND** 결과는 선택한 종목(예: AST 스페이스모바일 · NASDAQ · ASTS)과 기준 날짜, 「출처: 네이버 증권」을 밝힌다

---

### Requirement: 한국어 조사 앞의 굵은 글씨
에이전트 답의 `**굵게**` 바로 뒤에 한국어 조사가 붙어도(예: `**AST모바일(096540)**은`) 시스템은 별표 없이 굵은 글씨로 보여 주어야 한다(SHALL). 코드 안의 별표와 양쪽에 빈칸이 있는 별표는 그대로 두어야 한다(SHALL).

#### Scenario: 괄호 뒤 조사
- **WHEN** 답에 `**AST모바일(096540)**은 조회 데이터에서`가 있다
- **THEN** 「AST모바일(096540)」이 굵게 보이고 별표는 보이지 않는다
