# 공유 폴더 파일 찾기와 열기 — 붙이지 않아도 찾고, 채팅에서 바로 연다

## Purpose
공유 폴더의 문서는 채팅에서 에이전트가 찾아 읽고, 사용자가 열어 달라고 하면 그 자리에서 열어야 한다. 2026-11-23 운영 화면에서 사용자가 「장진영 이력서를 열어줘」라고 하자 에이전트는 "연결된 Google Drive와 공유 폴더에 해당 파일이 없습니다"라고 답했다. 사용자가 「이력서」 폴더를 참고로 붙이고 「여기서 찾아봐」라고 하자 그제야 `장진영_프로필.docx`를 찾았지만, "공유 폴더의 DOCX는 바이너리 파일로만 제공되어 내용을 바로 열어 읽을 수는 없습니다"라고 답했다. 원인은 세 가지였다. 폴더를 찾을 때 검색어 전체를 한 덩어리로 찾았다. 운영 서버 이미지에 압축 해제 도구가 없어 워드·한글·파워포인트·엑셀 본문을 한 번도 읽지 못했다. 에이전트에게는 파일을 화면에서 여는 도구가 없었다. 이 스펙은 사용자 지적(「현재 내가 접근할 수 있는 폴더내에 요청 사항에 대한 파일이 있음에도 그것을 첨부해야만 찾을 수 있는 상태임. 그리고 파일을 바로 열어보이지 않는 문제도 있음(이음오피스로 바로 열어줬어야)」)과 결정 D-1123-05에 따라 파일을 찾고 읽고 여는 방식을 정한다.

## Requirements

### Requirement: 폴더를 붙이지 않아도 사용자가 구성원인 모든 폴더에서 찾는다
시스템은 에이전트가 사내 문서를 찾을 때 채팅에 폴더가 붙어 있지 않아도 사용자가 구성원인 모든 공유 폴더에서 찾아야 한다(SHALL). 검색어를 낱말로 나누어 각각 찾는다. 낱말은 폴더 이름, 파일 경로, 문서 요약, 키워드에서 찾고, 전문 색인이 켜진 폴더에서는 본문에서도 찾는다. 파일은 검색어와 일치하는 낱말이 많은 순서로 돌려준다. 일치하는 낱말 수(`matched`)도 함께 준다. 두 글자 이상인 낱말이 있으면 한 글자 낱말은 쓰지 않는다. 구성원이 아닌 폴더는 결과에 나오지 않는다.

#### Scenario: 이름과 폴더에 나뉘어 있는 낱말
- **WHEN** 사용자가 구성원인 「이력서」 폴더에 `장진영_프로필.docx`와 `김민수_프로필.docx`가 있고, 에이전트가 「장진영 이력서」로 찾는다
- **THEN** 결과의 첫 폴더는 「이력서」이고 첫 파일은 `장진영_프로필.docx`다
- **AND** `장진영_프로필.docx`에서 검색어와 일치하는 낱말 수가 `김민수_프로필.docx`보다 크다

#### Scenario: 어떤 이름에도 없는 낱말
- **WHEN** 에이전트가 폴더 이름, 파일 이름, 요약 어디에도 없는 낱말로 찾는다(이력서가 "프로필"이라는 이름으로 저장된 경우)
- **THEN** "맞는 것이 없다"고만 답하지 않고, 사용할 수 있는 모든 폴더를 파일 이름·요약과 함께 돌려준다
- **AND** 에이전트는 그 이름과 요약을 보고 맞는 파일을 고른다

---

### Requirement: 문서 본문을 읽는다
시스템은 공유 폴더의 워드(docx), 파워포인트(pptx), 엑셀(xlsx), 한글(hwpx), PDF 문서에서 본문을 읽어야 한다(SHALL). 읽은 본문으로 문서 카드(요약·키워드)를 만들고, 에이전트가 파일 내용을 읽을 때 그 본문을 돌려준다. 색인에 본문이 없으면 읽을 때 바로 추출한다(전문 색인은 큰 폴더에서만 켜진다). 본문을 읽을 수 없는 문서(손상된 파일, 스캔 PDF)는 오류를 내지 않고 본문이 비어 있는 것으로 처리한다. 이전에 본문을 읽지 못해 카드가 없는 문서는 서버가 시작될 때 한 번 다시 읽는다. 다시 읽어도 본문이 없으면 모델에 보내지 않는다.

#### Scenario: 워드 파일을 읽는다
- **WHEN** 에이전트가 `장진영_프로필.docx`의 내용을 읽는다
- **THEN** 문서 본문이 텍스트로 돌아오고, 파일이 바이너리라서 읽을 수 없다는 표시는 나오지 않는다

#### Scenario: 예전에 읽지 못한 문서
- **WHEN** 문서 카드가 "본문을 읽지 못했어요"로 남아 있고 파일은 그대로인 채 서버가 다시 시작된다
- **THEN** 서버는 그 문서를 다시 읽어 카드를 만든다

---

### Requirement: 열어 달라는 파일은 채팅에서 바로 연다
시스템은 사용자가 공유 폴더의 파일을 열어 달라고 하면 그 파일을 채팅의 파일 카드로 붙이고, 메시지를 보낸 화면에서 바로 열어야 한다(SHALL). 워드·한글·엑셀·파워포인트·PDF는 이음오피스 편집기로 연다. 그림·소리·영상은 카드에서 바로 보거나 재생한다. 같은 사용자의 다른 기기에는 카드만 나타나고 편집기는 자동으로 열리지 않는다. 에이전트가 열지 않고 내용만 참고한 파일은 카드로 붙이지 않는다. 사용자가 구성원이 아닌 폴더의 파일은 열 수 없다. 앱 안에서 열 수 없는 형식이면 링크를 알려 준다. 편집기에서 고친 내용은 폴더 원본을 바꾸지 않는다. 폴더 원본에는 지금처럼 변형을 만들고 사람이 검토한 뒤 반영한다.

#### Scenario: 열어 달라고 한 화면
- **WHEN** 사용자가 채팅에서 「장진영 이력서를 열어줘」라고 보내고, 에이전트가 「이력서」 폴더의 `장진영_프로필.docx`를 연다
- **THEN** 채팅에 `장진영_프로필.docx` 카드가 나타난다
- **AND** 그 화면에서 이음오피스 편집기가 바로 열린다

#### Scenario: 같은 사람의 다른 기기
- **WHEN** 사용자가 다른 기기에서 메시지를 보냈고, 이 화면에서는 그 대화를 보고만 있다
- **THEN** 이 화면에는 카드만 나타나고 편집기는 열리지 않는다

#### Scenario: 만들어 준 문서
- **WHEN** 에이전트가 새로 만든 문서 카드가 온다(열어 달라는 요청이 아님)
- **THEN** 편집기는 자동으로 열리지 않고, 사용자가 카드를 눌러야 열린다

#### Scenario: 구성원이 아닌 폴더
- **WHEN** 구성원이 아닌 사용자의 요청으로 에이전트가 「이력서」 폴더의 파일을 열려고 한다
- **THEN** 폴더를 찾지 못했다는 답이 돌아오고 파일 카드는 나타나지 않는다
