# 기존 저장소를 폴더로 연결하기

## Purpose
이 스펙은 서버 디스크에 이미 있는 git 저장소를 공유 폴더로 등록하는 「저장소 연결」의 사용 환경과 권한을 정한다. 저장소를 연결하면 서버가 해당 저장소를 읽으므로, 이 기능은 한 회사만 사용하는 설치형 서버에서 해당 회사 관리자만 사용할 수 있다. 개인 PC의 폴더를 회사 폴더로 올리는 작업은 데스크톱 앱이 담당하며, 이 스펙의 범위에 포함하지 않는다.

## Requirements

### Requirement: 저장소 연결은 한 회사만 사용하는 설치형 서버에서 관리자만 사용할 수 있다
시스템은 여러 회사가 사용하는 서버(ProcessGPT 게이트웨이 뒤에 있거나, 주소별로 회사를 구분하는 `PRO_TENANT_HOSTS` 환경)에서는 저장소 연결을 허용하지 않아야 한다(SHALL). 이 환경에서는 요청자와 관계없이 `403`을 반환하고, 새 폴더를 만들어 파일을 올리도록 안내한다. 한 회사만 사용하는 설치형 서버에서는 해당 회사의 관리자(`users.is_admin` 또는 회사 소유자)만 저장소를 연결할 수 있어야 한다(SHALL). 관리자가 아니면 `403`을 반환한다. 설치형 서버에서도 `PRO_FOLDERS_LINK=0`이면 이 기능을 비활성화한다.

#### Scenario: 관리자가 아닌 사용자
- **WHEN** 설치형 서버에서 관리자가 아닌 사용자가 경로를 지정해 저장소를 연결하려 한다
- **THEN** `403`과 「저장소 연결은 관리자만 할 수 있어요.」를 반환하고, 폴더를 생성하지 않는다

#### Scenario: 여러 회사가 사용하는 서버
- **WHEN** 게이트웨이 뒤의 운영 서버에서 관리자가 저장소를 연결하려 한다
- **THEN** `403`을 반환하고, 폴더 화면에 「저장소 연결」 단추를 표시하지 않는다

### Requirement: 이미 폴더로 관리되는 경로와 git 저장소가 아닌 경로는 연결하지 않는다
시스템은 서버의 공유 폴더 저장 위치(`PRO_FOLDERS_ROOT`, 기본값은 홈 디렉터리 아래의 `pgpt-folders`) 내부 경로를 연결하지 않아야 한다(SHALL). 공유 폴더마다 구성원이 정해져 있으므로, 같은 경로를 다른 폴더로 다시 등록해 기존 구성원이 아닌 사용자에게 읽기 권한을 부여하지 않는다. 심볼릭 링크를 거치는 경로도 실제 위치를 기준으로 판단한다. git 저장소가 아닌 경로도 `400`을 반환해 연결을 거부한다.

#### Scenario: 다른 폴더의 저장소 경로
- **WHEN** 관리자가 다른 사람이 만든 공유 폴더의 저장소 경로를 지정해 연결하려 한다
- **THEN** `400`과 「이미 폴더로 관리되는 곳이에요. …」를 반환하고, 해당 관리자가 그 폴더에 접근하면 계속 `403`을 반환한다

#### Scenario: git 저장소가 아닌 경로
- **WHEN** 관리자가 `/tmp`처럼 git 저장소가 아닌 경로를 지정한다
- **THEN** `400`과 「git 저장소가 아니에요.」를 반환한다

### Requirement: 단추는 연결할 수 있는 사용자에게만 표시한다
시스템은 `GET /api/folders/caps`의 응답이 `{ link: true }`인 사용자에게만 폴더 화면의 「저장소 연결」 단추를 표시해야 한다(SHALL). 그 외 사용자에게는 「새 폴더」만 표시한다.

#### Scenario: 관리자가 아닌 사용자의 폴더 화면
- **WHEN** 관리자가 아닌 사용자가 폴더 화면을 연다
- **THEN** 「새 폴더」만 표시하고 「저장소 연결」은 표시하지 않는다
