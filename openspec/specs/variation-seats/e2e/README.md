# 시험과 증거 — 변형의 자리 0단계(작업본은 한 곳에)

자리의 규칙(열기 · PC의 자리 · 넘기기 마무리 · 돌려놓기 · 가져오기 · 돌려 달라 · 기한)은 순수 함수의 단위 시험으로 확인하고, 데이터베이스와 실제 git을 사용하는 흐름(동시에 열기 · 다른 곳의 자리 거절 · 있는 그대로 커밋 · 인계 · 반영 · 버리기 · 회차 · 채팅의 「내 PC」 실행 · 회사 나눔 · 기한 쓸기)은 통합 시험으로 확인한다. 세 사람의 HTTP 흐름과 화면은 Playwright로 확인한다. 모델은 호출하지 않는다.

SQL은 `server/sql/063_variation_seats.sql`이다(추가만 하며 여러 번 실행해도 된다. RLS는 켜져 있고 정책은 없다). 개발 공용 데이터베이스에는 적용했다. 운영 환경에서는 이 파일을 그대로 실행한다. 이 SQL이 없는 서버는 자리 없이 예전처럼 동작하고, 로그로 한 번 알린다.

## 단위 · 통합 시험

```bash
cd server && node --test test/variationSeats.test.js
```

- **WL-U-01 열기:** 보관 중이면 「넘기는 중」 → 자리로 전환되고, 회차가 오른다. 같은 사람이 같은 곳에서 열면 그대로다. 남의 작업실 · 서버 에이전트 · PC · 넘기는 중에는 거절한다. 지난 회차의 마무리는 거절한다.
- **WL-U-02 같은 사람의 작업실 → 서버 에이전트 턴:** 먼저 커밋한 뒤 옮긴다. 반대 방향의 턴에서는 작업실로 옮기기를 거절한다.
- **WL-U-03 PC의 자리(채팅의 「내 PC」 실행):** 내 작업실에서는 옮기고, 서버 에이전트 · 다른 사람 · 다른 실행은 거절한다. 같은 실행은 그대로이며, 같은 실행이 다른 PC로 가면 자리가 따라간다.
- **WL-U-04 돌려놓기:** 자리를 가진 사람만 할 수 있으며, 지난 회차는 거절한다. 서버 자리는 먼저 커밋한 뒤 「돌려놓는 중」으로 전환되고, PC 자리는 그 PC에서만 돌려놓을 수 있다(실행이 끝날 때).
- **WL-U-05 가져오기:** 본인은 언제나 가져올 수 있고, 소유자는 돌려 달라고 한 뒤 24시간이 지나고 PC가 꺼져 있을 때만 가져올 수 있다.
- **WL-U-06 돌려 달라:** 남의 자리에만 요청할 수 있으며, 서버 에이전트 실행에는 요청할 수 없다. 회차는 그대로다.
- **WL-U-07 서 있지 않은 자리:** 기한이 지난 넘기기와 체크아웃이 없는 서버 자리는 없는 것으로 본다. PC 자리는 서버 체크아웃 없이도 유지된다.
- **WL-U-08 누가 여나:** 사람의 변형은 그 사람만 열 수 있고, 에이전트의 변형은 실행할 수 있는 사람이라면 누구나 열 수 있다.
- **WL-I-01 동시에 열기:** 세 사람이 한꺼번에 열면 하나만 열리고, 나머지 둘은 409와 자리 정보를 받는다(경로 · 기기 id 없음). 열 개를 한꺼번에 잡아도 행은 하나다(행 잠금).
- **WL-I-02 다른 곳의 자리 거절:** 남의 변형 · 남의 작업실 · 서버 에이전트 · PC의 자리는 거절한다(PC는 기기 이름만 표시). 그 밖의 사람의 작업실은 가지에서 읽는 읽기 전용 방이다(쓰기 · 셸 409, `.git` · 바깥 경로 400).
- **WL-I-03 있는 그대로 커밋:** 작업실 → 서버 에이전트 턴에서는 저장하지 않은 파일이 가지에 있고, 이전 작업 트리는 없다. 기록은 open · held · move · held다. 다른 곳의 체크아웃을 치우는 `S.checkout`도 먼저 커밋한다.
- **WL-I-04 인계:** 저장하지 않은 것까지 커밋해 넘기고, 받은 사람만 연다. 남이 작업실에 있으면 409를 반환한다.
- **WL-I-05 지난 회차:** 옮기기 전의 터미널 표와 지난 회차의 돌려놓기는 거절한다. 데스크톱 작업본 토큰(다음 단계)은 요청마다 기기 · 자리 · 회차 · 폴더를 확인하며, 가져온 뒤에는 멈춘다.
- **WL-I-06 반영 · 버리기:** 남이 반영하면 409를 반환하고, 본인이 반영하면 저장하지 않은 것까지 main에 반영한다. 버린 변형의 가지에도 저장하지 않은 것이 남는다.
- **WL-I-07 돌려 달라 · 소유자의 가져오기:** 알림에는 그 변형의 주소와 까닭을 담는다. 하루가 지나기 전에는 거절하고, 하루가 지난 뒤에는 가져온다(저장하지 않은 것까지 커밋).
- **WL-I-08 채팅의 「내 PC」 실행:** 프로젝트 변형의 자리를 PC가 가지며(작업실은 커밋 뒤 닫힘), 그동안 작업실 · 서버 에이전트 턴 · 다른 실행은 거절한다. 턴의 결과는 가지로 올리고(「방금 올림」), 가져온 뒤 올라온 결과는 「… — 사무실 PC에 남아 있던 변경」이라는 새 변형으로 만든다. 실행이 끝나면 보관 중으로 전환된다.
- **WL-I-09 회사 나눔 · 기한:** 다른 회사에서는 자리가 보이지 않는다. 끝나지 않은 넘기기는 기한이 지나면 보관 중으로 전환된다(회차 +1, 기록 expire).

## 검토 반영 시험(PR #86 검토, 각 항목은 수정 전에 실패)

```bash
cd server && node --test test/variationSeats.review.test.js
```

- **R-01 재시작한 서버의 쓸기:** 이 서버 밖에서 실행 중인 단계와 채팅 변경의 자리는 유지하고, 3분 동안 실행 중임을 알리지 않은 턴만 커밋해 보관한다. 작업본 없이 끝난 단계는 작업본을 다시 펼친 뒤 결과를 반영한다.
- **R-02 커밋 실패:** git이 읽지 못하는 파일이 있으면 409 `unsaved`를 반환하고, 자리 · 폴더는 그대로 유지한다. .gitignore 대상 파일과 내부 저장소는 폴더 옆(`.kept-…`)으로 옮겨 둔다. 다른 곳의 체크아웃을 정리하는 `S.checkout`도 커밋이 실패하면 아무것도 옮기지 않는다.
- **R-03 실행 종료:** 드롭은 해당 실행의 회차에서만 가능하며, 사람은 서버 에이전트의 자리를 돌려놓을 수 없다. 자리를 잃은 턴의 결과는 새 변형이 되고, 그사이에 생긴 사람의 작업실은 그대로 유지한다.
- **R-04 인스턴스 줄:** 작업실에서 열면 409 `line`을 반환한다.
- **R-05 반영 중:** 서버 에이전트 · PC의 자리에도 409 `integrating`을 반환한다. 반영한 커밋보다 앞서간 변형은 「반영 대기」로 남는다.
- **R-06 잠금:** 다른 곳에서 넘기는 중(변형의 잠금이 잡힌 상태)이면 쓸기는 기한이 지나도 치우지 않는다.
- **R-07 늦은 쓰기:** 옮기기 전에 읽은 작업실에 쓰기를 시도하면 409를 반환하고, 치운 폴더는 다시 생기지 않는다.
- **R-08 자리 없는 체크아웃:** 해당 사람의 「돌려놓기」나 쓸기(10분)를 통해 현재 상태 그대로 커밋해 보관한다.
- **R-09 돌려 달라:** 소유자의 하루는 첫 요청부터 계산하고, 같은 사람의 요청은 4시간에 한 번만 알린다.
- **R-10 회사:** 다른 회사에서는 작업실을 찾을 수 없다.
- **R-12 목록 · 질의:** 읽기 전용 목록은 한 번에 조회하고(2만 개 파일, 1초 이내), 작업실 하나를 여는 질의는 7개 이하로 제한한다.
- **R-13 설정 실패:** 씨앗 올리기에 실패한 실행은 자리를 돌려주고 작업본을 치운다.

- **R8 확인 반영(같은 PR):** `server/test/variationSeats.review8.test.js` — Y-01 다른 파일 시스템으로 복사하는 동안 원본이 바뀌면(같은 크기로 다시 쓰이거나 사라지면) 원본을 지우지 않고 나중에 다시 시도한다(새로 쓴 내용을 잃지 않는다). Y-02 두 쓸기가 같은 멈춘 사본을 함께 찾으면 하나만 남기고, 실패와 기록도 각각 하나만 남긴다. 진행 중인 다른 서버의 표지는 그대로 두고, 멈춘 서버의 표지는 이어받는다. Y-03 다른 파일 시스템으로 옮기는 사본에 FIFO가 있어도 멈추지 않고 건너뛰며, 그 내역을 기록에 적는다.
