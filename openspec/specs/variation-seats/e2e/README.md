# 시험과 증거 — 변형의 자리 0단계 · 1단계(작업본은 한 곳에)

자리의 규칙(열기 · PC의 자리 · 넘기기 마무리 · 돌려놓기 · 가져오기 · 돌려 달라 · 기한)은 순수 함수의 단위 시험으로 확인하고, 데이터베이스와 실제 git을 사용하는 흐름(동시에 열기 · 다른 곳의 자리 거절 · 있는 그대로 커밋 · 인계 · 반영 · 버리기 · 회차 · 채팅의 「내 PC」 실행 · 회사 나눔 · 기한 쓸기)은 통합 시험으로 확인한다. 세 사람의 HTTP 흐름과 화면은 Playwright로 확인한다. 모델은 호출하지 않는다.

SQL은 `server/sql/063_variation_seats.sql`이다(추가만 하며 여러 번 실행해도 된다. RLS는 켜져 있고 정책은 없다). 개발 공용 데이터베이스에는 적용했다. 운영 환경에서는 이 파일을 그대로 실행한다. 이 SQL이 없는 서버는 자리 없이 예전처럼 동작하고, 로그로 한 번 알린다.

## 단위 · 통합 시험

```bash
cd server && node --test test/variationSeats.test.js
```

- **WL-U-01 열기:** 보관 중이면 「넘기는 중」 → 자리로 전환되고, 회차가 오른다. 같은 사람이 같은 곳에서 열면 그대로다. 남의 작업실 · 서버 에이전트 · PC · 넘기는 중에는 거절한다. 지난 회차의 마무리는 거절한다.
- **WL-U-02 같은 사람의 작업실 → 서버 에이전트 턴:** 먼저 커밋한 뒤 옮긴다. 반대 방향의 턴에서는 작업실로 옮기기를 거절한다.
- **WL-U-03 PC의 자리(채팅의 「내 PC」 실행):** 내 작업실에서는 옮기고, 서버 에이전트 · 다른 사람 · 다른 실행은 거절한다. 같은 실행은 그대로이며, 같은 실행이 다른 PC로 가면 자리가 따라간다.
- **WL-U-04 돌려놓기:** 자리를 가진 사람만 할 수 있으며, 지난 회차는 거절한다. 서버 자리는 먼저 커밋한 뒤 「돌려놓는 중」으로 전환되고, PC 자리는 그 PC에서만 돌려놓을 수 있다(실행이 끝날 때).
- **WL-U-05 가져오기:** 본인은 언제나 가져올 수 있고, 소유자는 돌려 달라고 한 뒤 24시간이 지나고 PC가 꺼져 있을 때만 가져올 수 있다.
- **WL-U-06 돌려 달라:** 남의 자리에만 요청할 수 있으며, 서버 에이전트 실행에는 요청할 수 없다. 회차는 그대로다.
- **WL-U-07 서 있지 않은 자리:** 기한이 지난 넘기기와 체크아웃이 없는 서버 자리는 없는 것으로 본다. PC 자리는 서버 체크아웃 없이도 유지된다.
- **WL-U-08 누가 여나:** 사람의 변형은 그 사람만 열 수 있고, 에이전트의 변형은 실행할 수 있는 사람이라면 누구나 열 수 있다.
- **WL-I-01 동시에 열기:** 세 사람이 한꺼번에 열면 하나만 열리고, 나머지 둘은 409와 자리 정보를 받는다(경로 · 기기 id 없음). 열 개를 한꺼번에 잡아도 행은 하나다(행 잠금).
- **WL-I-02 다른 곳의 자리 거절:** 남의 변형 · 남의 작업실 · 서버 에이전트 · PC의 자리는 거절한다(PC는 기기 이름만 표시). 그 밖의 사람의 작업실은 가지에서 읽는 읽기 전용 방이다(쓰기 · 셸 409, `.git` · 바깥 경로 400).
- **WL-I-03 있는 그대로 커밋:** 작업실 → 서버 에이전트 턴에서는 저장하지 않은 파일이 가지에 있고, 이전 작업 트리는 없다. 기록은 open · held · move · held다. 다른 곳의 체크아웃을 치우는 `S.checkout`도 먼저 커밋한다.
- **WL-I-04 인계:** 저장하지 않은 것까지 커밋해 넘기고, 받은 사람만 연다. 남이 작업실에 있으면 409를 반환한다.
- **WL-I-05 지난 회차:** 옮기기 전의 터미널 표와 지난 회차의 돌려놓기는 거절한다. 데스크톱 작업본 토큰(다음 단계)은 요청마다 기기 · 자리 · 회차 · 폴더를 확인하며, 가져온 뒤에는 멈춘다.
- **WL-I-06 반영 · 버리기:** 남이 반영하면 409를 반환하고, 본인이 반영하면 저장하지 않은 것까지 main에 반영한다. 버린 변형의 가지에도 저장하지 않은 것이 남는다.
- **WL-I-07 돌려 달라 · 소유자의 가져오기:** 알림에는 그 변형의 주소와 까닭을 담는다. 하루가 지나기 전에는 거절하고, 하루가 지난 뒤에는 가져온다(저장하지 않은 것까지 커밋).
- **WL-I-08 채팅의 「내 PC」 실행:** 프로젝트 변형의 자리를 PC가 가지며(작업실은 커밋 뒤 닫힘), 그동안 작업실 · 서버 에이전트 턴 · 다른 실행은 거절한다. 턴의 결과는 가지로 올리고(「방금 올림」), 가져온 뒤 올라온 결과는 「… — 사무실 PC에 남아 있던 변경」이라는 새 변형으로 만든다. 실행이 끝나면 보관 중으로 전환된다.
- **WL-I-09 회사 나눔 · 기한:** 다른 회사에서는 자리가 보이지 않는다. 끝나지 않은 넘기기는 기한이 지나면 보관 중으로 전환된다(회차 +1, 기록 expire).

## 1단계 — 내 PC 에서 작업(데스크톱 앱 0.2.6)

SQL 은 더하지 않았다(063 의 `dirty` · `ahead` · `auto_save` · `head` · `pushed_at` 을 쓴다). 서버는 링크 메시지 `seat:*`(`server/lib/folders/seatLink.js`)와 공개 git 경로의 범위 `seat` · `left`(`gitHttp.js`, `devices.js` 의 `seatAccess` · `leftAccess`)를 더했고, 데스크톱은 작업본 엔진(`desktop/src/runner/seats.js`)과 챔피언 폴더와 함께 쓰는 올리기 엔진(`desktop/src/runner/upload.js` — `sync.js` 에서 꺼냄)을 더했다.

```bash
cd server && node --test test/seatsPc.test.js                 # 범위 seat · left, 링크 메시지의 자리 전이
cd server && node test/seats-pc.e2e.mjs                       # 가짜 데스크톱 + 실제 링크 · git (BFF 8972, SEAT_PORT 로 바꿈)
cd desktop && node --test test/seats.test.js                  # 작업본 엔진(실제 git 서버 · 가짜 링크)
cd e2e && npx playwright test --project=desktop tests/desktop/seats.spec.js   # Electron + 브라우저 (BFF 8972 · Vite 5372)
```

- **WL-P-01 ~ 08(서버 단위 · 통합):** 회차 가지 · 남은 변경 가지의 이름과 한 번짜리 토큰, 넘기는 중의 토큰은 읽기만, 지난 회차 · 다른 PC 의 ready 거절, 앞으로만 옮김(갈라진 머리 · 열쇠 생김새는 거절하고 가지를 되돌림, main · 남의 가지는 못 올림), 토큰은 요청마다 다시 봄(기기 끊김 · 자리가 옮겨 감 · 역할이 runner 아래로 — 살아 있는 토큰도 그 순간 멈춤), 데스크톱의 가지는 다른 토큰(일 · 동기화 · 다른 변형의 작업본 · 클러스터)에 보이지 않음(받기 전의 자리도 미리 숨김), 돌려놓기(회차 가지 지움), 남은 변경(그 사람만 · 한 번만 · 다른 회사는 닿지 않음), 기기 연결을 끊으면 작업본 자리는 보관 중.
- **SP-E-01 ~ 06(HTTP e2e, 가짜 데스크톱):** 「이 PC 에서 작업」 → `seat:prepare` → 받기 → `seat:ready` → 쥠(옛 앱 · 꺼진 PC · 남의 PC · 남의 변형은 거절), 저장 지점 → 변형이 앞으로 · 수가 웹에 · 「지금 올리기」 · 스위치가 PC 로, 돌려놓기 → 서버 작업실이 PC 의 내용으로 열림, 꺼진 사이 웹에서 가져옴 → 다시 켜지면 옛 토큰의 push 403 → 「… — 한소유의 맥북에 남아 있던 변경」, PC 가 켜져 있으면 가져오기는 PC 가 돌려놓게 함 · 남의 링크 · 다른 회사에는 닿지 않음.
- **데스크톱 단위(seats.test.js):** 올리기 엔진(묻고 답 받기 · 시간 초과 · 오프라인 · 하나씩 · 토큰은 기록에 없음), 앱 데이터 아래에만 저장소와 작업 트리(링크는 평범한 파일 · 사람의 폴더는 그대로 · 같은 변형은 한 자리), 있는 그대로 커밋(새 · 고친 · 지운 파일은 올라가고 .env · 열쇠 생김새 · 링크 · .gitmodules · 안의 저장소는 빠져 디스크에 그대로), reset · clean · checkout 같은 명령은 부르지 않고 부르려 해도 거절, 다른 가지면 올리지 않음, 저장 지점의 때(조용해진 뒤 한 번 · Claude Code 의 end_turn · Codex 의 task_complete · 스위치를 끄면 저절로는 안 올림), 돌려놓기(서버가 받은 뒤에만 치움 · git 이 싣지 않는 파일은 앱 휴지통), 지난 회차는 이 PC 에서도 거절, 자리를 잃은 PC(새 변형 · 새 것이 없으면 그냥 치움 · 못 올리면 「남은 변경」), git 이 답하지 못하면 작업본을 치우지 않음, 이어질 때 맞추기.
- **검토 반영(11-26, 데스크톱 단위 `검토 1 ~ 12` · 서버 `WL-P-01 · 07 · 09 · 10` — 모두 수정 전 실패):** `.git`이 없어진 작업본에서 git이 상위 경로의 바깥 저장소(홈의 설정 저장소)를 찾아 커밋하던 동작을 차단했다. 작업본 밖에서는 저장소를 찾지 않고, 작업본이 앱의 저장소에 속하는지 확인한다. 집계에 쓰는 git이 응답하지 못하면 작업본을 남긴다(검토자의 재현 `gitless.js` 통과). 정리할 때는 작업본을 통째로 휴지통으로 옮긴다. 자리를 잃은 작업본은 CLI의 턴이 끝난 뒤에 정리한다. 자리는 변형 id 전체로 구분한다(남겨진 폴더는 휴지통으로 이동 · 앞 8자리가 같은 두 변형은 별도로 구분). 받는 동안 넘기기 기한을 늘리고(`seat:preparing`), 서버 목록은 잠금 안에서 다시 확인한다. 받다가 멈춘 작업본은 다시 받고, 돌려받은 뒤 정리하지 못하면 「남은 변경」으로 남긴다. 거절은 그 말에 대한 답일 때만 처리한다(`re`). CLI 기록은 끝에서부터 읽고, Codex는 앞 64KB를 읽으며, 하나의 스캐너를 사용한다. 휴지통 알림 · 열기 · 크기 한도를 적용한다. 남은 변경의 토큰 사용 기록은 데이터베이스에 남긴다. 사용자의 전역 git 설정 · 리다이렉트 · 태그를 따르지 않고, 가지 이름에는 변형 id 전체를 사용하며, 서버 git 환경에서 `GIT_PROTOCOL`을 제거한다. 받기 전에 자동으로 실행되는 설정 파일을 알린다(F-WL-15).
