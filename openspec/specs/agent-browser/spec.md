# 에이전트가 턴 도중에 내장 브라우저를 호출한다

## Purpose
2026-11-28 운영 환경의 프로젝트 방에서 사람이 티스토리 링크를 주며 NotebookLM에 넣고 슬라이드와 오디오 오버뷰를 만들어 달라고 했다. 앞단 계획에도 같은 내용을 적었다(① NotebookLM에 새 노트북 만들기 ② 링크를 소스로 추가하기 ③ 슬라이드 자료 생성하기 ④ 오디오 오버뷰 생성 후 파일 받기). 턴은 에이전트(deepagents)로 넘어갔지만, 에이전트에게는 브라우저가 없었다. 에이전트는 페이지를 직접 받아 reportlab으로 PDF를 만들기 시작했고, 계획 지킴이(`turn-plan` 「요청이나 계획에서 벗어나면 멈추고 사람에게 묻는다」)가 턴을 멈췄다. 사용자: 「랭체인 디베이전트가 일을 하는 도중에 이 브라우저 유즈 기존의 브라우저 유즈가 또 불려질 수 있는 그런 상황이어야 되고 그게 화면상에 곧바로 나타나면서 진행사항이 나타나면서 서로 커뮤니케이션 하면서 왔다갔다 일이 되어야」.

이 스펙은 에이전트가 턴 도중에 Lite의 내장 브라우저(스펙 `browser-handoff`의 작업 카드 · 질문 · 넘기기)를 호출하는 방식을 정한다. 작업은 사람의 채팅에 곧바로 나타나고, 사람은 카드에서 답한다. 에이전트는 결과를 받아 계획을 이어 간다.

- 도구 서버: `pgpt-browser`(`/mcp/browser`, `server/mcp/connectors/browser.js`) — 기본 도구 목록(`server/mcp/toolServers.js`, 스펙 `agent-tools`)에 포함된다. 도구는 `browser_task` · `browser_task_wait` · `browser_task_say`의 세 가지다.
- 판단과 진행 상황 확인은 `server/lib/agentBrowser.js`가 담당한다. 브라우저 작업 자체는 `server/lib/browser.js`가 담당한다.
- 운영 공통 MCP 목록의 항목은 사람의 토큰과 함께 에이전트의 대화를 전달한다: `"X-Conversation-Id": "{{conversation_id}}"`(`pgpt-mail`과 같다).

## Requirements

### Requirement: 에이전트는 턴 도중에 내장 브라우저로 웹사이트에서 작업한다
시스템은 모든 회사의 에이전트에게 내장 브라우저 도구 서버 `pgpt-browser`를 기본 도구로 제공해야 한다(SHALL). `browser_task`는 사람의 계정으로 웹사이트에서 만들기 · 올리기 · 생성하기 · 받기를 수행한다. 도구 설명은 언제 사용해야 하는지를 데이터로 알린다. API 도구가 없는 사이트(예: NotebookLM)이거나 사람이 해당 사이트를 언급했을 때 사용하며, 결과를 스스로 다시 만들지 않는다. 도구 설명에는 이 서버의 브라우저 스킬(`metadata.runs_in: browser`)을 이름 · 이름표 · 설명과 함께 싣는다. `skill`은 그 이름 중 하나다. 어떤 요청이 브라우저 작업인지 정규식이나 낱말로 구분해서는 안 된다(MUST NOT). 이를 선택하는 주체는 에이전트다.

작업은 에이전트의 대화가 있는 방에 곧바로 작업 카드로 나타나야 한다(SHALL). 카드는 실시간 화면 · 단계 · 질문을 `browser-handoff`와 같은 방식으로 보여 준다. 에이전트의 턴이 진행되는 동안 해당 턴의 계획 카드는 처리하는 곳을 「에이전트 · 브라우저 · <스킬 이름표>」로 표시한다. 실시간 줄에는 브라우저가 현재 하는 일이나 사람에게 질문 중이라는 상태가 표시된다. 에이전트의 답은 작업 카드 뒤에 온다. 브라우저 작업이 끝나도 에이전트의 턴이 진행 중이면 방은 「일하는 중」 상태를 유지한다.

#### Scenario: NotebookLM 같은 사이트에서 하는 작업
- **GIVEN** 사람이 채팅에서 사이트에 무언가를 만들고 받아 달라고 요청했고, 턴이 에이전트로 넘어갔다
- **WHEN** 에이전트가 해당 사이트의 스킬과 함께 `browser_task`를 호출한다
- **THEN** 몇 초 안에 해당 방에 작업 카드가 나타나고 실시간 화면이 보인다. 에이전트의 계획 카드는 계속 표시되며, 처리하는 곳은 「에이전트 · 브라우저 · <이름표>」다
- **AND** 에이전트의 답은 작업 카드 뒤에 오고, 답에 남은 계획에도 「에이전트 · 브라우저 · <이름표>」가 표시된다

#### Scenario: 휴대폰
- **WHEN** 폭 390인 휴대폰의 밝은 화면과 어두운 화면에서 같은 작업을 요청한다
- **THEN** 작업 중에 계획 카드와 작업 카드가 화면 폭 안에 표시되고, 화면이 옆으로 밀리지 않는다

### Requirement: 사람이 있을 때만 그 사람의 작업으로 실행한다
시스템은 에이전트의 호출이 어느 방에 속하는지 해당 대화(`X-Conversation-Id`)로 찾아야 한다(SHALL). 검색 범위는 토큰에 해당하는 사용자의 항목으로 제한한다. 그 사람의 진행 중인 에이전트 턴, 해당 대화가 있는 그 사람의 방, 그 사람의 프로젝트 주제를 확인한다. 다른 사람의 대화라면 거절하고 어느 방에도 카드를 표시하지 않아야 한다(MUST). 대화가 없거나 알 수 없는 대화라면 예전처럼 해당 사용자의 작업 중인 방을 사용하고, 그런 방도 없으면 메인 채팅을 사용한다.

그 대화에 사람이 글로 쓴 메시지에 답하는 진행 중인 턴이 있으면(루틴 · 예약 실행 · 서버가 지은 턴 · 멈춘 턴이 아니고, 파일이나 참조만 보낸 메시지도 아님) 작업은 그 사람의 것으로 돈다(SHALL). 무엇을 해도 되는지의 근거는 그 턴에서 사람이 쓴 말이다. 에이전트가 쓴 목표나 에이전트가 작업에 전한 말은 근거가 되지 않는다. 프로젝트의 계획과 사람에게 보여 준 계획 단계는 배경으로만 간다. 결제는 `browser-handoff` 의 규칙대로, 보내기 · 지우기 · 게시 같은 동작은 아래 「에이전트가 시작한 작업의 보내기 · 지우기 · 게시는 사람의 승인 카드를 거친다」대로 카드에서 사람의 승인을 기다린다.

그 밖의 호출(사람이 없는 실행)은 공개 페이지를 읽기만 한다. 이 작업은 저장된 쿠키와 로그인이 없는 임시 브라우저에서 실행하고, 작업이 끝나면 그 브라우저를 지운다(MUST). 그 사람의 브라우저(저장된 로그인이 있는 서버의 프로필, 그 사람의 PC 브라우저)는 쓰지 않는다. 저장된 로그인으로 접속하지 않으며(`PRO_BROWSER_TOOL_LOGINS=unattended`일 때만 예외), 무엇도 만들거나 보내거나 지우거나 바꾸지 않는다(MUST NOT). 임시 브라우저를 열 수 없으면 작업을 시작하지 않고 그 이유를 결과에 적는다.

에이전트가 시작한 작업은 사람이 있든 없든, 사람의 PC 브라우저에서 실행되더라도 해당 PC의 내부망 주소를 열지 않는다(MUST NOT). 시작 주소는 공개 웹 주소이거나 회사가 허락한 주소여야 한다. 끝에 점이 붙은 이름도 같은 이름으로 보며, 내부 서비스 이름과 한 단어로 된 이름은 받지 않는다. 한 사람당 동시에 진행할 수 있는 에이전트 작업 수는 몇 개(기본 2)로 제한하며, 이후 호출은 이유와 함께 거절한다.

#### Scenario: 사람의 메시지에 답하는 턴
- **GIVEN** 사람의 메시지에 답하는 에이전트 턴이 진행 중이다
- **WHEN** 에이전트가 해당 대화에서 `browser_task`를 호출한다
- **THEN** 작업 카드는 그 사람의 방에 나타나고, 목표 끝에 「읽기만」이 붙지 않는다. 구매 여부는 사람의 말을 읽고 판단한다

#### Scenario: 사람이 없는 실행
- **WHEN** 예약 실행 · 루틴 · 서버가 만든 턴(팀원의 말 · 홈 카드 · 이어 하기)에서 호출하거나, 턴이 끝난 뒤 같은 대화에서 호출한다
- **THEN** 작업은 공개 페이지를 읽기만 하며, 에이전트가 받는 결과에 「아무도 보지 않아 읽기만 했다」가 적힌다
- **AND** 로그인 칸을 만나도 저장된 로그인을 입력하지 않고, 메모에 「사람이 없는 작업이라 저장된 로그인을 쓰지 않음」을 남긴다. 무언가를 만드는 단추는 누르지 않고, 메모에 「읽기만 함」을 남긴다
- **AND** 그 사람의 브라우저에 저장된 쿠키는 이 작업이 여는 페이지에서 보이지 않으며, 작업 카드에는 「이 작업은 공개 페이지를 읽기만 해요」가 표시된다

#### Scenario: 파일만 보낸 메시지
- **WHEN** 사람이 글 없이 파일이나 참조만 보낸 메시지에 답하는 턴에서 에이전트가 `browser_task`를 호출한다
- **THEN** 사람의 말이 없으므로 작업은 읽기만 한다

#### Scenario: 다른 사람의 대화
- **WHEN** 한 사람의 토큰으로 다른 사람의 대화 id를 전달해 호출한다
- **THEN** 「이 대화를 이 계정에서 찾지 못해 브라우저 작업을 시작하지 않았어요.」라는 메시지로 거절되며, 어느 방에도 작업 카드가 표시되지 않는다

### Requirement: 브라우저는 웹 주소(http · https)로만 이동한다
모든 브라우저 작업은 사람이 채팅에서 시킨 것이든 에이전트가 시작한 것이든 웹 주소(http · https)로만 이동한다(MUST). 그 밖의 주소(빈 페이지 `about:blank` 제외)로는 이동하지 않고, 브라우저의 모델에게 「웹 주소만 열 수 있다」고 알린다. 시작 주소에도 같은 기준을 적용한다. 에이전트가 시작한 작업에서는 웹 주소를 열 때도 아래 판정을 거친다. 주소를 여는 것만으로 동작이 실행되는 페이지가 있기 때문이다(구독 해지 · 초대 수락 같은 링크).

#### Scenario: 웹 주소가 아닌 곳으로 이동
- **WHEN** 사람이 채팅에서 시킨 작업이나 에이전트가 시작한 작업이 웹 주소(http · https)가 아닌 곳으로 이동하려 한다
- **THEN** 이동하지 않고 현재 페이지에 그대로 머문다

#### Scenario: 열면 동작이 실행되는 주소
- **GIVEN** 사람이 구독 해지를 요청하지 않았다
- **WHEN** 에이전트가 시작한 작업이 구독을 해지하는 주소를 열려 한다
- **THEN** 「「<주소>」 주소를 열까요? 에이전트가 시작한 작업이라 …」 승인 카드가 표시되고, 「취소」를 누르면 그 주소는 열리지 않는다

### Requirement: 에이전트가 시작한 작업에서 무언가를 만들거나 바꿀 수 있는 곳은 사람이 말한 사이트뿐이다
사람이 있는 에이전트 작업이 시작될 때, 시스템은 그 턴에서 사람이 쓴 말을 모델에게 한 번 읽게 하여 사람이 일을 맡긴 사이트를 호스트 이름으로 정해야 한다(SHALL, 최대 셋). 이 서버의 브라우저 스킬(이름 · 이름표 · 시작 주소)도 판단 자료로 함께 제공한다(예: 「노트북엘엠」 → NotebookLM 스킬의 시작 주소). 정한 사이트는 작업에 기록하고, 작업 카드에 「이 작업이 할 수 있는 곳: …」으로 표시한다.

- 정한 사이트(또는 그 아래 이름)에서는 아래 판정이 「보기」 · 「자기 작업 공간」 · 「사람이 말한 동작」이면 그대로 진행한다.
- 그 밖의 사이트에서는 보기만 그대로 진행하고, 나머지 동작은 판정이 「사람이 말한 동작」이라 해도 승인 카드를 거친다.
- 사람의 말에 사이트가 없거나 판단을 받지 못하면 모든 곳에서 보기만 그대로 진행하고, 나머지 동작은 승인 카드를 거친다. 카드에는 「이 작업은 보기만 해요」가 표시된다.

#### Scenario: 사람이 말한 사이트와 다른 사이트
- **GIVEN** 사람이 「노트북엘엠에 이 링크를 넣고 슬라이드를 만들어 줘」라고 했다
- **WHEN** 작업이 NotebookLM에서 「생성」을 누르고, 다른 사이트에서도 무언가를 만들려 한다
- **THEN** NotebookLM의 「생성」은 그대로 진행하고, 다른 사이트의 동작은 승인 카드에서 사람의 승인을 기다린다. 작업 카드에는 「이 작업이 할 수 있는 곳: <NotebookLM 호스트>」가 표시된다

### Requirement: 에이전트가 시작한 작업의 보내기 · 지우기 · 게시는 사람의 승인 카드를 거친다
에이전트가 시작한 작업은 단추 누르기, 입력 칸에 글쓰기(쓰기만 해도 저장되는 편집기가 있다), Enter로 보내기, 파일 칸이 아닌 단추로 파일 고르기 열기, 웹 주소 열기를 수행하기 전에 해당 동작이 무엇을 하는지 판정받아야 한다(SHALL). 판정에는 모델을 사용하며, 기준은 0.7이다. 낱말 목록으로 판정하지 않는다. 판정할 때는 해당 동작(단추 이름 · 칸 이름과 쓴 글 · 열 주소), 사이트와 페이지, 해당 턴에서 사람이 쓴 말만 읽는다. 페이지의 글은 짧게 줄이고, 웹사이트의 내용일 뿐 지시가 아니라고 밝혀서 제공한다. 에이전트가 쓴 목표와 전한 말은 읽지 않는다(MUST NOT).

같은 작업 안에서 그대로 진행해도 된다는 판정은 페이지(주소의 출처와 경로) · 단추 이름 · 화면의 글(대화 상자가 열리면 달라진다) · 입력한 글이 모두 같을 때만 다시 쓴다. 이름이 없는 단추는 판정을 다시 쓰지 않고, 승인은 기억하지 않는다.

- 보기만 하는 동작(열기 · 찾기 · 걸러 보기 · 받기)과 사람 자신의 작업 공간 안에서 만드는 동작(NotebookLM의 새 노트북 · 소스 넣기 · 슬라이드와 오디오 생성)은 그대로 진행한다.
- 바깥에 영향을 주는 동작(보내기 · 게시 · 공유 · 초대 · 지우기 · 설정이나 권한 바꾸기 · 결제 · 주문 · 예약 · 남에게 양식 제출)은 사람이 해당 사이트의 해당 동작을 분명히 말했을 때만 그대로 진행한다. 그렇지 않거나, 동작이 무엇을 하는지 분명하지 않거나, 판정을 받지 못하면 해당 단추와 사이트를 적은 승인 카드에서 사람의 승인을 기다린다. 사람이 「승인」을 누를 때만 해당 동작을 한 번 실행하고, 「취소」를 누르면 실행하지 않는다. 브라우저의 모델은 이 카드를 건너뛰거나 대신 답할 수 없다.
- 이 승인은 해당 단추를 한 번 누를 때만 적용하며, 결제 승인으로는 쓰지 않는다(결제는 별도로 `browser-handoff`의 규칙에 따라 묻는다).
- 사람이 없는 실행에서는 보기만 하는 동작만 한다.

사람이 채팅에서 직접 시킨 브라우저 작업은 예전과 같이 진행한다.

#### Scenario: 사람이 말하지 않은 지우기
- **GIVEN** 사람이 「노트북 사이트의 목록을 보기 좋게 정리해 줘」라고 했고, 에이전트가 시작한 작업이 노트북의 「delete 삭제」 메뉴를 누르려 한다
- **WHEN** 판정 결과가 「바깥에 영향이 있고, 사람이 말하지 않은 동작」이다
- **THEN** 작업 카드는 `need: approve`로 멈추고, 채팅에 「<사이트>에서 「delete 삭제」을(를) 누를까요? 에이전트가 시작한 작업이라 …」 승인 카드(「취소」 · 「승인」)가 표시된다(PC · 휴대폰 390)
- **AND** 「취소」를 누르면 해당 메뉴를 누르지 않고 작업이 끝나며, 목록은 그대로 유지된다

#### Scenario: 자기 작업 공간에서 만들기
- **WHEN** 에이전트가 시작한 작업이 사람이 부탁한 대로 자기 작업 공간에서 「생성」을 누른다
- **THEN** 승인 카드 없이 그대로 진행한다

### Requirement: 멈추기는 에이전트가 시작한 작업도 멈춘다
사람이 에이전트의 답을 멈추면(멈추기, 계획 지킴이의 멈춤, 바로잡는 말로 전환) 해당 턴에서 에이전트가 시작한 브라우저 작업도 멈춰야 한다(SHALL). 작업 카드는 「에이전트의 답을 멈춰서 이 작업도 멈췄어요.」로 끝나며, 멈춘 작업은 이어서 진행하지 않는다.

#### Scenario: 오래 걸리는 작업 도중에 멈추기
- **GIVEN** 에이전트가 시작한 작업이 아직 진행 중이다
- **WHEN** 사람이 해당 답을 멈춘다
- **THEN** 작업 카드가 멈춤 상태로 끝나고, 같은 대화에서 이어서 진행하는 턴은 시작되지 않는다

### Requirement: 오래 걸리는 작업의 진행 상황을 확인하고, 사람에게는 카드로 질문하며, 에이전트의 말도 전할 수 있다
`browser_task`는 에이전트의 MCP 읽기 한도(5분)를 넘지 않도록 4분 안에 반환해야 한다(SHALL). 그 안에 작업이 끝나면 결과를, 끝나지 않으면 현재 상태를 반환한다. 현재 상태에는 `state`(`running` · `waiting_for_person` · `queued`), `task_id`, 마지막 몇 단계(`progress`)가 포함된다. 사람에게 질문 중이면 질문과 보기도 포함된다. 결과에는 `state`(`done` · `failed` · `needs_review` · `cancelled`), 요약, 메모, 마지막 주소, 페이지 글(4,000자까지), 받은 파일이 포함된다. 받은 파일은 이미 채팅에 파일 카드로 표시되어 있다. 결과는 파일의 주소를 알리며, 에이전트의 작업 공간에 사본이 있으면 그 경로도 알린다.

`browser_task_wait`는 해당 사용자의 작업만 기다려야 한다(MUST). 작업이 끝나거나 사람에게 새 질문을 하기 시작하면 곧바로 반환한다. 그 외에는 주어진 시간(240초까지)이 지난 뒤 현재 상태를 반환한다. 같은 질문 때문에 두 번 즉시 반환하지는 않는다. 사람에게 질문하는 동안의 안내는 도구 설명과 결과에 포함된다. 사람은 채팅의 작업 카드에서 질문을 받고 있으므로 에이전트는 같은 내용을 다시 묻지 않는다.

`browser_task_say`는 같은 대화에서 에이전트가 시작한 작업이 진행 중일 때만 말을 전한다. 사람이 채팅에서 시킨 작업이나 다른 대화의 작업에는 말을 전하지 않는다(MUST NOT). 이 말은 사람의 말로 취급하지 않는다. 결제 · 보내기 · 지우기의 승인으로 삼거나, 구매 판단과 위 판정에서 읽는 사람의 말에 포함하거나, 사람에게 한 질문의 답으로 취급해서는 안 된다(MUST NOT). 작업 카드에는 「에이전트가 전한 말」로 표시된다. 서버가 다시 켜진 뒤 카드에서 다시 읽은 작업은 결과만 읽을 수 있으며, 그 사람의 작업으로 이어서 실행되지 않는다.

에이전트의 호출이 끊기면(연결이 닫힘) 기다림도 멈춘다. 결과는 열려 있는 호출에 돌려준 뒤에야 에이전트가 받은 것으로 본다.

#### Scenario: 4분이 넘는 작업
- **WHEN** 작업이 도구의 대기 시간보다 오래 걸린다
- **THEN** `browser_task`는 `running`과 `task_id`, 지금까지 한 일을 반환한다. 에이전트는 `browser_task_wait`로 이어서 기다린 뒤 결과를 받는다

#### Scenario: 브라우저가 사람에게 묻는다
- **GIVEN** 사이트에서 사람이 선택해야 할 항목이 있다
- **WHEN** 작업이 카드로 질문한다
- **THEN** 에이전트의 호출은 곧바로 `waiting_for_person`과 해당 질문 · 보기를 반환하고, 계획 카드의 실시간 줄에는 「브라우저가 묻고 있어요」가 표시된다
- **AND** 사람이 카드에서 선택하면 작업이 이어지고, 에이전트는 그 답이 포함된 결과를 받아 이어서 답한다

#### Scenario: 에이전트가 말을 전한다
- **WHEN** 에이전트가 진행 중인 작업에 `browser_task_say`로 말을 전한다
- **THEN** 작업 카드에 「에이전트가 전한 말」과 전달한 말이 표시된다. 작업은 다음에 화면을 볼 때 그 말을 읽는다
- **AND** 작업이 사람을 기다리는 중이면, 사람이 답한 뒤에 그 말을 읽는다

#### Scenario: 다른 사람의 작업
- **WHEN** 다른 사람의 작업 id로 `browser_task_wait`나 `browser_task_say`를 호출하거나, 사람이 채팅에서 시킨 작업 또는 다른 대화의 작업 id로 `browser_task_say`를 호출한다
- **THEN** 「그 task_id 를 찾지 못했어요」라는 메시지로 거절된다

### Requirement: 에이전트의 턴이 먼저 끝나면 결과가 에이전트에게 돌아간다
사람의 작업으로 실행한 브라우저 작업이 에이전트의 턴보다 늦게 끝나고 에이전트가 결과를 받지 못했다면, 시스템은 작업 카드에 결과를 남긴 뒤 같은 대화에서 이어서 진행하는 턴을 한 번 시작해야 한다(SHALL). 해당 턴의 메시지에는 어느 작업(task_id)이 어떤 상태로 끝났는지와 처음 계획만 담는다. 웹사이트에서 온 글(요약 · 메모 · 페이지 글)은 넣지 않는다(MUST NOT). 에이전트는 `browser_task_wait`로 결과를 도구의 답으로 읽고 계획의 남은 단계를 수행한다. 채팅에는 「브라우저 작업이 끝났어요. 에이전트가 결과를 읽고 남은 일을 이어서 해요.」와 「Lite 가 보냄 · 브라우저 작업이 끝나 에이전트가 이어서 해요」가 표시된다. 이어서 진행하는 턴은 서버가 만든 턴이다. 사람의 말이 아니므로 구매를 허용하지 않으며, 사람은 멈추기로 턴을 중단할 수 있다. 해당 턴에서 시작한 브라우저 작업은 읽기만 하며, 작업이 끝나도 다시 이어서 진행하는 턴을 시작하지 않는다.

이어 하지 않는 경우: 그 턴의 사람 메시지 뒤에 사람이 그 방에 쓴 메시지가 하나라도 있다(턴이 도는 동안 쓴 것도), 그 방에 다른 턴이 돈다, 사람이나 계획 지킴이가 그 턴을 멈췄다, 에이전트가 결과를 이미 받았다, 같은 작업을 이미 이어 했다, `PRO_BROWSER_HANDBACK=0` 이다.

#### Scenario: 에이전트가 먼저 답을 끝냈다
- **GIVEN** 에이전트가 오래 걸리는 작업을 시작하고 「끝나면 이어서 할게요」라는 말로 답을 끝냈다
- **WHEN** 작업이 끝난다
- **THEN** 같은 대화에서 이어서 진행하는 턴이 한 번 시작되며, 해당 메시지에는 작업 id와 상태만 담긴다. 에이전트는 `browser_task_wait`로 결과(요약 · 받은 파일)를 읽고 이어서 답한다
- **AND** 두 번째 이어 하기는 없다

#### Scenario: 사람이 그사이에 다른 말을 했다
- **WHEN** 해당 턴이 진행 중이거나 끝난 뒤에 사람이 해당 턴의 메시지에 이어 같은 방에 새 메시지를 쓰고, 그다음에 작업이 끝난다
- **THEN** 이어 하는 턴은 시작되지 않는다. 결과는 작업 카드에 남는다
