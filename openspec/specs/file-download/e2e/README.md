# 시험과 증거

이름과 주소에 관한 규칙(어떤 이름으로 내려받는지, 어떤 주소를 어떻게 가져오는지, 가져오지 못할 때 어떻게 처리하는지)은 화면 없이 단위 시험으로 확인한다. 데스크톱 앱의 파일 저장 위치도 단위 시험으로 확인한다. 동작은 Playwright를 사용해 실제 화면과 실제 이음오피스 편집기에서 확인하고, 내려받은 파일의 이름과 바이트(문서는 내부의 글)를 직접 읽어 비교한다. 서버 경로와 SQL은 새로 만들지 않았다. 내려받기에는 화면에 이미 있는 주소나 단추를 누를 때 권한을 다시 확인해 받은 기존 경로(폴더 raw · 메일 첨부 서명 경로 · `POST /api/messages/:id/open-file`)를 그대로 사용한다.

## 단위 시험 (화면 없이)

```bash
cd server && node --test test/download.test.js
cd desktop && node --test test/downloads.test.js
```

- `download.test.js`(14): 화면에 보이는 이름 그대로 내려받는다(한글 · 띄어쓰기 · 괄호 · `#`, NFC). 사용할 수 없는 문자만 `_`로 바꾼다. 이름이 비어 있으면 주소의 이름을 사용한다. 확장자가 없으면 주소의 확장자를, 주소에도 없으면 MIME의 확장자를 붙인다. 주소가 다른 종류의 파일을 가리키면 해당 종류의 확장자를 사용한다(jpg · jpeg처럼 표기만 다르면 이름의 표기를 유지하고, 저장소 키의 `.bin`은 무시한다). 긴 이름은 확장자를 유지하면서 120자로 줄인다. 저장소 주소는 로그인 정보 없이 그대로 가져오고, 대체 경로에는 `?download=<이름>`을 사용한다(서명 토큰 유지). 이 서버의 경로는 동일 출처에서 서명과 토큰을 그대로 사용하고, 폴더 raw에는 `download=1`을 붙인다. 빈 주소와 다른 scheme의 주소는 허용하지 않는다. 결과 알림 문구와 거절 문구도 확인한다. 가짜 브라우저에서는 blob과 `<a download=이름>`, 거절(401 · 404) 시 저장하지 않는 동작, 가져오기 실패 시 새 탭을 여는 동작(차단되면 누를 수 있는 링크 제공), 300MB가 넘는 파일을 메모리에 담지 않는 동작을 확인한다.
- `downloads.test.js`(3): 「다운로드」 폴더에 페이지가 지정한 이름으로 저장하고, 같은 이름이 있으면 「 (1)」 · 「 (2)」를 붙이며, 폴더 밖에는 저장하지 않는다.

## 화면 시험 (Playwright)

```bash
cd e2e && RT_WORKERS=1 npx playwright test --project=feature tests/feature/file-download.spec.js
cd e2e && RT_WORKERS=1 RT_API_FROM=8967 RT_WEB_FROM=5367 RT_OFFICE_FROM=5402 npx playwright test --project=feature tests/feature/mail-attachments.spec.js -g "F-FD-07|F-MA-09"
```

`file-download.spec.js`는 자체 스택(`lib/localStack.js`의 회사 `download-ui`, BFF는 8967 · Vite는 5367부터 사용 가능한 포트)과 실제 이음오피스 편집기(`lib/officeHost.js`, 5402부터)를 실행한다. 모델 · deepagents · completion은 호출하지 않는다. CADCraft는 시험용 셸(`PRO_CRAFT_WEB_ROOT`)을 사용한다. 사람과 파일은 가상의 시험 데이터다(도하은, 「견적서 초안 (최종).docx」 · 「2026년 11월 매출 집계.xlsx」 · 「서비스 이용 계약서.pdf」 · 「현장 사진 1.png」 · 「팩스 수신 11월 26일.tif」 · 「2층 배치도.dxf」, 「인사 자료」 폴더의 「한소율_프로필.docx」).

| 시험 | 확인하는 것 |

## 확인하지 못한 것
- 실제 엑셀 편집기에서의 내려받기: 이 개발 PC의 office-host(ieumoffice-web 11-26 빌드와 11-25 빌드 모두)에서는 엑셀 편집기 페이지가 열리는 동안 멈춘다(페이지 스크립트가 답하지 않음. origin/main 화면과 편집기 페이지를 따로 열어도 같다). 그래서 F-FD-01의 xlsx는 시험용 편집기 껍데기(`ready`를 보내고 `#root`를 채움)로 열어 단추와 받는 길(편집기 밖의 문서 패널)만 확인한다. `RT_REAL_SHEETS=1`이면 실제 편집기로 연다.
- iOS Safari · Android Chrome 실기기: blob `<a download>`가 iOS 13 이상에서 「파일 › 다운로드」에, Android에서 「다운로드」에 저장되는지 여부(시험은 Chromium 모바일 에뮬레이션으로만 확인).
- 데스크톱 앱(Electron)에서 실제로 「다운로드」 폴더에 저장되는지 여부와 Dock 알림(경로 규칙만 단위 시험으로 확인).
- 300MB가 넘는 실제 파일, 실제 CORS 거절 · 팝업 차단(가짜 브라우저로만 확인).
- 영어 화면의 문구(사전 항목은 추가함).
