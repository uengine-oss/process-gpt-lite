# 파일이 열리는 모든 곳에 동일한 「내려받기」

## Purpose
2026-11-26 사용자는 다음과 같이 말했다. 「파일을 열면 바로 열리는 건 좋은데 다운로드 받을 방법이 없네. 지금 다운로드 받을 방법을 파일이 열린 상태에서 다운로드 버튼이 어딘가 있든지 뭔가 공통적으로 뭔가 작업이 돼야 될 것 같아가지고 이홈오피스가 됐든 각 툴들의 그 헤더 부분에 다운로드 받는 버튼이 있든 뭔가 조치가 있어야 될 것 같네.」(이홈오피스는 이음오피스를 뜻한다.)

당시에는 파일을 누르면 앱 안의 편집기나 보기 화면이 바로 열렸다. 그러나 이음오피스 문서 패널, ArtCraft 앱, 그림 · 소리 · 영상 보기 화면에는 파일을 내려받는 단추가 없었다. 공유 폴더 미리보기의 「원본 받기」와 작업실의 「원본」은 새 탭을 여는 링크였다. 팩스(TIFF) 보기 화면의 「내려받기」는 하단에 따로 있었지만, 저장소 주소의 출처가 달라 브라우저가 `download` 속성을 무시했다. 그 결과 파일은 저장소 키 이름(`…/att/<uuid>.tif`)으로 저장되거나 현재 화면에서 열렸다.

이 명세는 파일이 열리는 모든 곳의 헤더에 동일한 모양의 「내려받기」 단추(`src/components/DownloadButton.vue`)를 동일한 위치에 배치하고, 해당 단추로 무엇을 어떤 이름으로 내려받는지 정의한다. 이름과 주소에 관한 판단은 `src/downloadPlan.js`가, 브라우저에서 파일을 내려받는 작업은 `src/download.js`가 담당한다. 데스크톱 앱의 파일 저장 위치는 `desktop/src/downloads.js`가 결정한다.

## Requirements

### Requirement: 파일이 열리는 모든 곳의 헤더에 동일한 「내려받기」가 있다
시스템은 파일이 열리는 모든 곳의 헤더에 동일한 「내려받기」 단추를 표시해야 한다(SHALL). 단추는 아래쪽 화살표 아이콘과 「내려받기」라는 글자로 구성하며, 인접한 단추와 동일한 모양을 사용한다.
- 대상: 이음오피스 문서 패널(채팅 · 메신저 · 회의 · 단계 산출물 · Drive 산출물 · 메일 첨부 · 패널 앱의 시트), ArtCraft 앱(CADCraft · VectorCraft · PhotoCraft · SoundCraft · FilmCraft), 그림 · 소리 · 영상 · 팩스 보기 화면, 공유 폴더 파일 미리보기, 작업실에서 연 파일, 프로세스 지도에서 연 문서, 회의 무대의 폴더 문서와 편집기가 없는 파일.
- 위치: 공유 단추가 있는 헤더에서는 「공유」 바로 앞에, 공유 단추가 없는 헤더에서는 크기 · 닫기 단추 앞에 배치한다. 보기 화면에서는 ✕ 바로 앞에 배치한다.
- 한 화면에는 「내려받기」 단추를 하나만 표시한다. 공유 폴더 미리보기 · 작업실 · 회의 무대처럼 별도의 헤더가 있는 곳에서는 내부 편집기 막대에 단추를 배치하지 않는다. 문서에서 추출해 PhotoCraft로 수정하는 그림처럼 별도로 보관할 파일이 아닌 경우에도 배치하지 않는다.
- 헤더가 좁은 곳(편집기 막대가 640px 이하, 화면이 520px 이하인 휴대폰)에서는 글자를 숨기고 화살표만 표시한다. 이때도 단추의 이름(`aria-label` · `title`)은 「내려받기」로 유지한다.
- 밝은 테마와 어두운 테마 모두에서 인접한 단추와 동일한 색을 사용한다. 영어 화면에서는 「Download」로 표시한다.

#### Scenario: 이음오피스 문서 패널
- **WHEN** 도하은이 채팅의 「견적서 초안 (최종).docx」 카드를 누른다
- **THEN** 이음오피스 막대의 이음오피스 표시 바로 뒤이자 「공유」 앞에 「내려받기」가 표시된다

#### Scenario: 그림 보기 화면
- **WHEN** 도하은이 「현장 사진 1.png」 카드를 눌러 보기 화면을 연다
- **THEN** 헤더에는 「내려받기」와 ✕만 표시되며, 「내려받기」는 ✕ 앞에 있다

#### Scenario: 공유 폴더 미리보기에는 하나만
- **WHEN** 도하은이 「인사 자료」 폴더의 「한소율_프로필.docx」를 연다
- **THEN** 미리보기 헤더의 「원본 받기」 위치에 「내려받기」가 표시된다
- **AND** 내부 이음오피스 막대에는 「내려받기」가 표시되지 않는다

#### Scenario: 휴대폰
- **WHEN** 390px 휴대폰에서 문서 · 그림 · 폴더 파일을 연다
- **THEN** 「내려받기」는 화살표만 표시되며 화면 안에 있고, 닫기 단추도 화면 안에 있다
- **AND** 화살표를 누르면 파일을 내려받는다

---

### Requirement: 화면에 표시된 이름으로 내려받는다
시스템은 파일을 해당 화면에 표시된 이름으로 내려받아야 한다(SHALL). 저장소 키 이름(`<uuid>.docx`)이나 주소의 마지막 부분을 파일 이름으로 사용하지 않는다.
- 한글 · 띄어쓰기 · 괄호 · `#`는 그대로 유지한다. 맥에서 분해된 형태로 저장된 한글은 조합된 형태로 정규화한다(NFC).
- 파일 이름에 사용할 수 없는 문자(`/ \ : * ? " < > |`)는 `_`로 바꾸고, 제어 문자와 맨 앞의 점은 제거한다. 보이지 않는 서식 문자(`\p{Cf}`: 오른쪽에서 왼쪽으로 쓰기 지정 문자, 폭 없는 공백 · 결합자, BOM)도 제거한다. `청구서` + U+202E + `gnp.exe`라는 이름이 「청구서exe.png」처럼 보이지 않게 하기 위해서다.
- 이름에 확장자가 없으면 주소의 확장자를 붙이고, 주소에도 확장자가 없으면 저장된 형식(MIME)에 맞는 확장자를 붙인다(이름 없이 받은 `download`와 `audio/mp4` → `download.m4a`).
- 이름의 확장자가 알려진 파일 종류이고 주소가 가리키는 파일 종류와 다르면 실제 바이트의 종류를 따른다(「견적서.hwp」 카드의 편집본이 `.hwpx`이면 「견적서.hwpx」). 같은 종류의 다른 표기(jpg · jpeg, tif · tiff, htm · html)는 이름에 사용된 표기를 유지한다. 알려진 파일 종류가 아닌 점 뒤의 글자는 이름의 일부로 보고 확장자를 덧붙인다(「Q3.final」 → 「Q3.final.docx」).
- 이름이 길면 확장자를 포함해 UTF-8 240바이트 이하로 줄인다(ext4 등 대부분의 파일 시스템 한도는 255바이트이고, 한글 한 글자는 3바이트다). 확장자는 유지하고, 글자 하나(서로게이트 쌍, 피부색이 붙은 이모지 · 결합 문자 같은 자소 묶음)를 쪼개지 않는다.
- 주소의 %-이스케이프가 깨져 있어도(「%zz」, 「50%.pdf」) 내려받기는 실패하지 않는다.

#### Scenario: 저장소의 채팅 파일
- **WHEN** 저장소 주소가 `…/att/<uuid>.docx`인 「견적서 초안 (최종).docx」를 내려받는다
- **THEN** 브라우저는 「견적서 초안 (최종).docx」라는 이름으로 저장하며, 바이트는 업로드한 파일과 동일하다

#### Scenario: 팩스
- **WHEN** 보기 화면에서 「팩스 수신 11월 26일.tif」를 내려받는다
- **THEN** 키 이름이 아닌 「팩스 수신 11월 26일.tif」로 저장된다

### Requirement: 이미 보유한 주소로만 내려받고, 공개 주소를 새로 만들지 않는다
시스템은 해당 화면이 이미 보유한 주소나 단추를 누를 때 권한을 다시 확인해 받은 주소로만 파일을 가져와야 한다(SHALL). 내려받기를 위해 파일을 공개하거나 공개 주소를 만들지 않는다.
- 페이지가 파일을 가져와 메모리에 담은 뒤 해당 이름으로 저장한다(blob과 `<a download>`). 출처가 다른 저장소 주소에서는 브라우저가 `download` 속성을 무시하고, 휴대폰에서는 PDF가 앱 대신 현재 화면에서 열리기 때문이다.
- 저장소 주소(공개 · 서명)는 그대로 사용해 파일을 가져오며(CORS), 로그인 정보는 보내지 않는다. 이 서버의 경로(폴더 · 작업실의 raw, 메일 첨부 · 메신저 공유의 서명 주소)는 주소에 포함된 서명이나 토큰을 그대로 사용한다. 폴더 raw에는 `download=1`을 붙인다.
- 비공개 카드(메일 첨부와 그 편집본)는 문서를 열 때 받은 10분짜리 서명 주소나 편집기가 저장한 주소를 사용하지 않는다. 단추를 누를 때 새로 받은 주소를 사용한다. 폴더에 정리된 첨부는 폴더 main의 그 파일(`/api/folders/:slug/raw`)을, 편집본이 있는 카드는 해당 카드의 새 서명 주소(`POST /api/messages/:id/open-file`)를, 그 밖의 첨부는 메일 첨부의 서명 경로(`POST /api/mail/attachments/:card/:n/open {download: true}`)를 사용한다.
- 이 서버가 요청을 거절하면 서버가 보낸 문장을 그대로 표시한다. 다른 출처(저장소)가 보낸 문장(「InvalidJWT」 같은)은 표시하지 않는다. 문장이 없거나 다른 출처이면 401은 「주소가 만료됐어요. 다시 열어 주세요.」, 403은 「이 파일을 내려받을 권한이 없어요.」, 404는 「파일을 찾지 못했어요.」로 알린다.
- 페이지가 파일을 가져오지 못하면(네트워크 · CORS 거절) 새 탭에서 연다. 300MB보다 큰 파일은 메모리에 담지 않는다. 서버가 크기를 알리면 받기 전에, 알리지 않으면(chunked · 압축) 받은 바이트를 세다가 넘는 순간 멈춘다. 이 서버의 경로는 해당 주소의 `<a download>`로 내려받고, 저장소 주소는 `?download=<이름>`을 붙여 새 탭에서 연다. 브라우저가 새 탭을 차단하면 「브라우저가 새 창을 막았어요 · 눌러서 여세요」와 함께 누를 수 있는 「열기」를 표시한다.

#### Scenario: 메일 첨부 문서
- **WHEN** 한지우가 메일 첨부 「하늘테크 용역 계약서 (수정본).docx」를 이음오피스로 열고 「내려받기」를 누른다
- **THEN** 파일이 동일한 이름으로 저장되며, 바이트는 메일 첨부 파일과 동일하다
- **AND** 페이지의 요청 중 `/storage/v1/object/public/` 주소는 하나도 없다

#### Scenario: 만료된 주소
- **WHEN** 서버가 401과 「주소가 만료됐어요. 다시 열어 주세요.」로 응답한다
- **THEN** 단추 아래에 「내려받지 못했어요 · 주소가 만료됐어요. 다시 열어 주세요.」가 표시되고, 아무것도 저장되지 않는다

### Requirement: 수정한 내용이 있으면 먼저 저장하고, 어떤 버전인지 알린다
시스템은 이음오피스 문서에 아직 저장하지 않은 수정 사항(직접 수정한 내용이나 에이전트가 작성한 내용)이 있으면, 편집기의 저장 단추를 먼저 누르고 해당 버전을 내려받아야 한다(SHALL). 보기 전용 문서는 열린 버전을 그대로 내려받는다.
- 채팅 문서에서는 편집기에서 저장하면 원본 옆에 편집본(`edited-…`)이 생성되고 카드가 해당 편집본을 가리킨다. 이 편집본을 내려받는다.
- 공유 폴더 문서에서는 남은 수정 사항을 폴더에 저장하고(이력 한 줄), 해당 버전을 폴더에서 내려받는다. 다른 사람이 먼저 수정해 내 수정 내용이 「…(이름 수정본)」으로 별도 저장된 경우에는 해당 파일을 내려받고 그 사실을 알린다.
- 작업실에서 연 텍스트 파일에 저장하지 않은 수정 사항이 있으면 먼저 저장한 뒤 내려받는다.
- 저장하는 동안 단추 아래에 「내려받기 전에 저장하는 중…」을 표시한다. 내려받은 뒤에는 「방금 저장한 판을 내려받았어요 · <이름>」이라고 알린다. 저장할 내용이 없으면 「내려받았어요 · <이름>」이라고 알린다.
- 편집기의 업로드가 끝나도 그 저장이 카드가 가리키는 곳(공유 폴더 문서는 폴더 main의 커밋, 메일 첨부는 내 채팅의 비공개 카드)에 닿지 않았으면 저장에 실패한 것으로 본다. 한 번 다시 시도하고, 그래도 실패하면 「방금 저장한 판」이라고 하지 않는다. 고칠 내용이 없을 때도 앞선 저장이 닿지 않았으면 같다. 채팅에서 연 공유 폴더 문서는 폴더 main의 그 파일(`/api/folders/:slug/raw`)을 내려받는다. 저장이 닿으면 main이 그 커밋으로 바뀌고, 닿지 않으면 그대로이므로 그것이 마지막으로 저장된 버전이다.
- 저장에 실패하면(편집기가 실패를 알리거나 25초 안에 응답하지 않거나 위처럼 저장이 카드에 닿지 않으면) 내려받지 않는다. 대신 「저장하지 못했어요 (<이유>). 마지막으로 저장된 판을 내려받을까요? 방금 고친 내용은 들어 있지 않아요.」와 함께 「마지막 저장본 받기」 · 「취소」를 표시한다. 「마지막 저장본 받기」를 누르면 마지막으로 저장된 버전을 내려받고 「마지막으로 저장된 판을 내려받았어요 — 방금 고친 내용은 들어 있지 않아요 · <이름>」이라고 알린다.
- ArtCraft 앱에 저장하지 않은 변경 사항이 있으면(「저장 안 됨」) 앱마다 저장 방법이 다르므로 대신 저장하지 않는다. 「앱에서 고친 내용이 아직 저장되지 않았어요(<저장 방법>). 마지막으로 저장된 판을 내려받을까요?」라고 묻는다. 앱에서 저장한 직후에는 카드가 아직 그 저장본으로 옮겨 가지 않았어도(채팅은 서버 호출이 끝난 뒤, 회의 무대는 옮기지 않음) 방금 저장한 파일을 내려받는다.
- 알려진 한계: 편집기 안의 변경은 키 입력 · 붙여넣기 · 끌어 놓기 · 입력기 · 슬라이드의 도형 끌기와 에이전트의 편집으로 알아본다. 리본의 단추만 눌러 바꾼 서식(굵게, 색 등)은 알아보지 못해, 그것만 바꾸고 바로 누르면 마지막으로 저장된 버전을 받는다(편집기마다 「변경됨」을 알리는 방법이 달라 아직 읽지 않는다).

#### Scenario: 수정 직후 내려받기
- **WHEN** 도하은이 채팅에서 연 docx에 「내려받기전저장」을 입력하고 곧바로 「내려받기」를 누른다
- **THEN** 편집기가 저장한 편집본이 내려받아지고, 해당 파일에 「내려받기전저장」이 포함되어 있다
- **AND** 단추 아래에 「방금 저장한 판을 내려받았어요 · 견적서 초안 (최종).docx」가 표시되고, 카드는 편집본을 가리킨다

#### Scenario: 저장에 실패했을 때
- **WHEN** 도하은이 「저장안된두번째」를 추가로 입력하고 「내려받기」를 눌렀으나 편집기가 저장 실패를 알린다
- **THEN** 아무것도 내려받지 않고 「마지막 저장본 받기」 · 「취소」 중 하나를 선택하도록 묻는다
- **AND** 「마지막 저장본 받기」를 누르면 「내려받기전저장」은 포함되고 「저장안된두번째」는 포함되지 않은 버전이 내려받아진다

#### Scenario: 공유 폴더 문서
- **WHEN** 도하은이 폴더 미리보기에서 문서에 「폴더저장후받기」를 입력하고 곧바로 「내려받기」를 누른다
- **THEN** 수정 사항이 먼저 폴더 main에 저장되고(「폴더에 저장했어요」), 해당 버전이 내려받아진다

#### Scenario: 폴더 커밋이 실패했을 때
- **WHEN** 채팅에서 연 공유 폴더 문서에 글을 쓰고 「내려받기」를 눌렀는데, 편집기의 업로드는 끝났지만 폴더 커밋이 실패한다
- **THEN** 「방금 저장한 판」이라고 하지 않고 「마지막 저장본 받기」를 묻는다
- **AND** 「마지막 저장본 받기」를 누르면 폴더 main의 이전 버전이 내려받아진다

#### Scenario: 메일 첨부의 편집본이 내 카드가 되지 못했을 때
- **WHEN** 메일 첨부 문서에 글을 쓰고 「내려받기」를 눌렀는데, 편집기의 업로드는 끝났지만 내 채팅의 비공개 카드로 저장되지 못한다
- **THEN** 「마지막 저장본 받기」를 묻고, 누르면 메일의 첨부가 그대로 내려받아진다

#### Scenario: 저장되지 않은 ArtCraft
- **WHEN** CADCraft가 「저장 안 됨」을 표시한 상태에서 「내려받기」를 누른다
- **THEN** 앱에서 수정한 내용이 아직 저장되지 않았다고 알리고 「마지막 저장본 받기」를 선택할지 묻는다

### Requirement: 결과는 단추 아래에서 알린다
시스템은 내려받기 결과를 단추 바로 아래의 작은 말풍선으로 알려야 한다(SHALL). 휴대폰 브라우저에서는 내려받기 완료 여부가 잘 드러나지 않기 때문이다.
- 성공 알림은 몇 초 뒤 사라진다. 실패 알림은 9초 동안 표시된다. 「마지막 저장본 받기」 질문은 항목을 선택하거나 바깥을 누르거나 Esc를 누를 때까지 유지된다.
- 질문은 `role="alertdialog"`로 표시하고 첫 번째 단추에 초점을 둔다. 실패 알림은 `role="alert"`, 그 밖의 알림은 `role="status"`로 표시한다.
- 말풍선은 화면 안에 표시한다(390px 휴대폰에서도 가로로 넘치지 않음). 밝은 테마와 어두운 테마에서 동일한 어두운 말풍선(성공은 초록, 실패는 빨강)을 사용한다.
- 내려받기가 진행되는 동안 단추는 「받는 중…」을 표시하며, 다시 누를 수 없다.
- 문서 패널이나 ArtCraft 앱이 전체 화면이면 말풍선과 질문을 그 전체 화면 요소 안에 그린다(전체 화면에서는 그 요소만 보이므로).
- 파일 칩(뷰어가 없는 단계 산출물 · 양식의 파일)과 그릴 수 없는 팩스의 「내려받기」도 같은 단추다. 서버가 거절하면 그 까닭을 알리고 새 탭을 열지 않으며, 브라우저가 새 탭을 막으면 누를 수 있는 「열기」를 보여 준다.

#### Scenario: 휴대폰의 말풍선
- **WHEN** 390px 휴대폰에서 문서를 내려받는다
- **THEN** 화살표 아래에 「내려받았어요 · <이름>」이 화면 안에 표시된다

#### Scenario: 전체 화면
- **WHEN** 문서 패널을 전체 화면으로 하고 「내려받기」를 누른다
- **THEN** 알림과 「마지막 저장본 받기」 질문이 전체 화면 안에 보이고 누를 수 있다

### Requirement: 데스크톱 앱은 「다운로드」 폴더에 바로 저장한다
시스템은 데스크톱 앱에서 이 앱이 내려받는 파일(선택한 서버의 페이지가 만든 blob, 그 서버의 경로)을 저장 대화상자 없이 시스템의 「다운로드」 폴더에 페이지가 전달한 이름으로 저장해야 한다(SHALL). 다른 페이지나 프레임(편집기, 다른 사이트)이 시작한 내려받기는 Electron의 저장 대화상자를 그대로 쓴다. 같은 이름의 파일이 있으면 확장자 앞에 「 (1)」 · 「 (2)」 …를 붙인다. 맥에서는 내려받기가 완료되면 Dock의 다운로드 스택이 이를 알린다.
- 이름에서 경로 구분자 · 제어 문자 · 맨 앞의 점을 제거하므로 「다운로드」 폴더 밖에 저장되지 않는다.
- 서버의 에이전트가 이 PC에서 사용하는 브라우저(별도 세션)의 내려받기는 이 규칙을 따르지 않는다.

#### Scenario: 같은 이름이 이미 있을 때
- **WHEN** 「다운로드」에 「급여대장.xlsx」 · 「급여대장 (1).xlsx」가 있는 상태에서 「급여대장.xlsx」를 내려받는다
- **THEN** 「급여대장 (2).xlsx」로 저장된다
