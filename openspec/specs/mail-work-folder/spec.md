# 일 하나에 작업 폴더 하나 — 메일과 단계 결과를 한곳에, 들어올 때 지도와 견주기

## Purpose
메일로 일(프로세스 인스턴스)이 시작되거나 진행 중인 일에 메일이 이어지면, 그 일을 수행하는 에이전트와 사람에게 「이 일의 폴더」가 하나 생긴다. 2026-11-24 사용자 결정은 세 가지다. ① 일 하나에 작업 폴더 하나: 첫 메일부터 그 폴더에 담고, 산출물을 쌓으며, 다음 단계의 에이전트가 그 맥락을 참고한다. 이어진 메일도 이 폴더를 통해 엔진 단계의 입력으로 전달한다. ② 메일 카드가 생기는 모든 메일에서 프로세스를 찾으면 해당 프로세스의 단계에 따라 처리한다. 자동은 저절로 시작해 첫 작업까지 수행하고, 제안은 사용자에게 묻고, 관찰은 시작하지 않는다. ③ 프로세스 지도를 쓰는 회사는 메일이 들어올 때 프로세스를 찾는 데 드는 모델 비용을 받아들인다. 따라서 지도와 견주는 작업은 시트를 처음 열 때가 아니라 카드가 생길 때 수행한다. 이는 2026-11-18 결정(인스턴스의 일은 해당 인스턴스 화면에서 처리하고 메인 채팅에 덧붙이지 않는다)과 `mail-thread-flow` 스펙(메일 칩 · 시트 · 시작 · 잇기)을 잇는다. 설계는 `docs/mail-work-folder/design.md`에 있다.

## Requirements

### Requirement: 메일이 들어온 일에는 작업 폴더가 하나 있다
시스템은 메일로 인스턴스를 시작하거나(자동 시작 · 시트의 「새로 시작」 · 마이닝으로 등록한 흐름), 작업 폴더가 없는 진행 중인 인스턴스에 메일을 이을 때(「잇기」 · 같은 Gmail 스레드) 해당 인스턴스의 작업 폴더를 하나 만들어야 한다(SHALL). 작업 폴더는 공유 폴더이며, 다음 규칙을 따른다.
- 주인은 해당 메일의 주인(시작하거나 이은 사람, 자동 시작이면 메일함 주인)이다.
- 이름은 인스턴스 이름과 같다. 같은 이름의 폴더가 있으면 「 (2)」처럼 번호를 붙인다.
- 폴더에는 메일함 주인의 원문 메일이 들어가므로 기본적으로 다른 사람과 공유하지 않는다. 회사가 프로세스 찾기 스킬의 `mailWork.shareWithRoles`를 켜면 해당 건의 역할을 맡은 다른 사람(에이전트 제외)이 보기 권한을 가진 구성원으로 추가된다. 주인은 폴더 화면에서 직접 구성원을 추가할 수 있다.
- 같은 인스턴스(같은 건을 옮겨 생긴 다음 인스턴스 포함)에는 폴더가 하나만 있다. 두 번 이어도 폴더가 두 개 생기지 않는다.
- 폴더를 만들지 못해도 메일과 인스턴스는 연결된다.

#### Scenario: 새로 시작
- **WHEN** 시트에서 「새로 시작」을 눌러 「견적 요청 · 견적서 작성 · 한빛상사」 인스턴스가 시작된다
- **THEN** 이름이 「견적 요청 · 견적서 작성 · 한빛상사」인 작업 폴더가 생기고, 버튼을 누른 사람이 주인이 된다
- **AND** 해당 건의 「검토자」 역할을 맡은 동료는 그 폴더를 볼 수 있다

#### Scenario: 폴더 없던 일에 메일을 잇는다
- **WHEN** 메일로 시작하지 않은 진행 중인 인스턴스에 「잇기」로 메일을 잇는다
- **THEN** 해당 인스턴스의 작업 폴더가 생기고, 이은 메일이 첫 메일이 된다

---

### Requirement: 메일은 원문 · 읽는 판 · 첨부로, 번호 순서대로 들어간다
시스템은 작업 폴더에 메일을 `메일/NN_<YYYY-MM-DD>_<제목>.eml`(메일 원문)과 `.md`(머리글과 본문)로 저장하고, 첨부 파일을 `메일/NN_첨부/<파일>`에 넣어야 한다(SHALL).
- `NN`은 01부터 시작하며, 이 폴더에 들어온 순서를 나타낸다. 날짜는 메일의 날짜(한국 시간)다. 제목과 파일 이름에서 경로와 사용할 수 없는 문자는 제거한다.
- `.eml`은 메일함에 있는 원문을 그대로 사용한다(Gmail · IMAP). 원문이 없는 데모 메일함에서는 보낸 사람 · 받는 사람 · 제목 · 날짜 · 본문으로 메일 프로그램에서 열 수 있는 메시지를 만든다.
- `.md`는 제목, 보낸 사람 · 받는 사람 · 참조 · 날짜 · 첨부(경로) 목록, 구분선, 본문으로 구성한다. 본문의 줄바꿈은 그대로 표시한다.
- 메일 한 통은 메일을 넣은 사람(시작 · 잇기를 한 사람, 자동이면 메일함 주인)의 커밋 하나로 기록한다. 커밋 메시지는 「메일 NN · <제목>」이다.
- 같은 메일은 두 번 넣지 않는다.
- 다음 메일이 이어지면(「잇기」 · 같은 Gmail 스레드) 같은 폴더에 다음 번호로 넣는다.

#### Scenario: 첫 메일
- **WHEN** 「세미나 견적 부탁드립니다」 메일로 일이 시작된다
- **THEN** 작업 폴더에 `메일/01_<오늘>_세미나 견적 부탁드립니다.eml`과 `.md`가 있다
- **AND** 이력에 「메일 01 · 세미나 견적 부탁드립니다」가 해당 사람의 이름으로 남는다

#### Scenario: 같은 스레드의 첨부 있는 메일
- **WHEN** 첨부 두 개가 있는 Gmail 메일로 일이 시작되고, 고객이 같은 스레드로 다시 메일을 보낸다
- **THEN** 첫 메일의 원문(.eml)은 메일함의 원문과 같고, 첨부는 `메일/01_첨부/`에 있다
- **AND** 다음 메일은 `메일/02_…`로 들어가고, 새 건은 시작되지 않는다

---

### Requirement: 끝난 단계의 결과는 인스턴스 라인에 쌓인다
시스템은 인스턴스의 단계가 끝나면(끝남 · 제출됨, 취소 아님) 그 결과를 작업 폴더의 인스턴스 라인 `inst/<인스턴스>`에 있는 `산출물/NN_<단계>/`에 넣어야 한다(SHALL).
- 해당 단계에서 만든 파일(이 서버에 있는 것)은 내용을 그대로 넣고, 다른 곳의 링크는 이름과 주소만 넣는다. 값은 `결과.md`(수행한 사람 · 완료 시각 · 파일 · 값)에 기록한다.
- 단계 하나는 커밋 하나로 기록한다. 에이전트 단계의 작성자는 「업무 에이전트」이며, 사람이 제출한 단계의 작성자는 해당 사람이다. 한 단계는 한 번만 넣는다.
- 「요청 접수」 단계는 첫 메일과 같으므로 넣지 않는다.
- main에는 사람이 인스턴스 라인을 반영할 때까지 메일만 저장된다. 인스턴스 라인은 폴더의 변형(「<인스턴스> — 인스턴스 라인」, 반영 대기)으로 표시된다.
- 인스턴스 라인이 생긴 뒤에 들어온 메일은 인스턴스 라인에도 넣는다. 다른 엔진의 단계가 결과를 남길 때 인스턴스 라인이 그사이에 변경되었다면, 이전 상태로 되돌리지 않고 합친다.

#### Scenario: 견적서 작성 단계가 끝난다
- **WHEN** 에이전트의 「견적서 작성」 단계가 「한빛상사 견적서.xlsx」와 결과 글을 생성하고 끝난다
- **THEN** 인스턴스 라인에 `산출물/01_견적서 작성/한빛상사 견적서.xlsx`와 `결과.md`가 생기고, 작성자는 「업무 에이전트」다
- **AND** main에는 아직 `산출물/`이 없다

#### Scenario: 첫 단계 뒤에 메일이 온다
- **WHEN** 첫 단계가 끝난 뒤 고객의 「Re: …」 메일을 잇는다
- **THEN** 해당 메일이 main과 인스턴스 라인에 모두 있다

---

### Requirement: 에이전트 단계는 작업 폴더의 메일과 앞 단계 결과를 읽는다
시스템은 작업 폴더가 있는 인스턴스의 에이전트 단계에 해당 폴더의 메일(먼저 온 순서로 날짜 · 보낸 사람 · 제목 · 첨부 이름 · 본문)과 앞 단계 결과(경로와 결과 글)를 제공해야 한다(SHALL). 단계가 시작될 때 이미 완료된 앞 단계의 결과를 먼저 폴더에 넣는다. 길이 제한은 스킬 규칙 `mailWork`(한 통 · 모두 · 결과)로 정하고, 본문이 잘리면 폴더 경로에서 전문을 찾을 수 있다고 안내한다.
- 회사 지도의 단계(글로 만드는 단계 · 양식 채우기 · 스킬 · 에이전트 위임)와 마이닝으로 등록한 흐름의 단계에 제공한다. 무엇을 어떻게 읽어야 하는지는 스킬(`process-discovery`의 `work-folder` · `draft-step` 프롬프트)에 명시한다.
- 다른 엔진(deepagents · cli-agent)의 에이전트 단계에는 해당 폴더를 인스턴스 라인에서 시작하는 변형으로 제공한다.
- 인스턴스 대화에서 질문에 답할 때는 해당 폴더를 참고 자료로 읽는다. 그 대화에서 수정을 요청하더라도 폴더 이름을 언급하지 않으면 이 폴더에 대한 변경 요청으로 처리하지 않는다.

#### Scenario: 회신 메일 단계
- **WHEN** 메일 두 통(「세미나 견적 부탁드립니다」, 「Re: … 인원이 40명으로 늘었습니다」)과 견적서 작성 결과가 있는 일에서 회신 메일 단계가 실행된다
- **THEN** 해당 단계의 입력에 두 메일이 순서대로 포함되고, 견적서 작성의 `결과.md`도 함께 포함된다

---

### Requirement: 카드가 생긴 메일은 들어올 때 지도와 견주고, 프로세스의 단계대로 한다
시스템은 프로세스 지도를 쓰는 회사에서 새 메일로 Home 카드가 생기면, 즉시 해당 메일을 회사 프로세스 지도와 견주어야 한다(SHALL). 대상은 문서를 요청하는 메일뿐 아니라 카드가 생긴 모든 메일이다. 견준 결과는 카드에 저장하고, 시트에서는 그 결과를 사용한다(지도를 다시 읽지 않는다).
- **자동** 단계 프로세스의 시작으로 확실히 판단되면 해당 프로세스를 자동으로 시작하고, 작업 폴더를 만들어 메일을 넣으며, 엔진이 첫 단계를 바로 수행한다. 알림은 인스턴스 대화와 Home 알림으로만 전달하고 메인 채팅에는 덧붙이지 않는다.
- **제안** 단계 프로세스면 시작하지 않고, 카드와 시트에서 시작 여부를 묻는다.
- **관찰** 단계 프로세스는 읽지 않으며, 시작하지도 묻지도 않는다. 진행 중인 같은 일이면 시트에서 「잇기」만 권한다.
- 같은 Gmail 스레드로 이미 진행 중인 인스턴스에 이어진 메일은 해당 인스턴스로 전달한다. 지도와 다시 견주지 않으며, 두 번째 건을 시작하지 않는다(MUST NOT).
- 스레드가 없는 메일이 자동 프로세스의 시작으로 판단되더라도, 판정 모델이 진행 중인 같은 일로 판단하면(시트와 같은 기준값) 자동으로 시작하지 않고 카드에서 「잇기」를 묻는다.
- 자동으로 시작하더라도 사람 단계는 초안 모드로 진행하고, 회사 밖으로 나가는 단계는 사람을 기다리며, 메일은 「보내기」를 눌러야 발송된다.
- 데모 메일함의 견본 메일과 카드가 없는 메일은 들어올 때 지도와 견주지 않는다.

#### Scenario: 자동
- **WHEN** 지도가 문서를 요청하지 않는 메일을 자동 단계 「견적 요청」의 확실한 시작으로 판단한다
- **THEN** 해당 프로세스가 자동으로 시작되고, 카드는 해당 인스턴스를 가리키며, 작업 폴더에 메일 01이 있다
- **AND** Home에 「메일로 시작 · …」 알림이 오고, 메인 채팅에는 아무것도 추가되지 않는다

#### Scenario: 제안
- **WHEN** 지도가 메일을 제안 단계 프로세스의 시작으로 판단한다
- **THEN** 아무것도 시작하지 않고, 카드에 해당 프로세스가 남는다
- **AND** 시트를 열면 지도를 다시 읽지 않고 「진행할까요?」를 묻는다

#### Scenario: 관찰
- **WHEN** 메일이 관찰 단계 프로세스의 일에만 해당한다
- **THEN** 아무것도 시작하지 않고 묻지도 않는다

#### Scenario: 고객이 다시 썼지만 스레드가 없다
- **WHEN** 진행 중인 견적 일이 있는 상태에서 같은 고객이 새 메일을 보내고, 지도가 이를 자동 프로세스의 시작으로 판단하며, 판정 모델이 진행 중인 견적 일과 같은 일일 확률을 92%로 판단한다
- **THEN** 새 건을 시작하지 않고, 시트에서 「진행 중인 ‘…’에 잇기 · 같은 일 92%」를 권한다

### Requirement: 인스턴스 화면 · 폴더 · 메일 시트에서 작업 폴더로 오간다
시스템은 작업 폴더를 볼 수 있는 사람에게 다음 이동 경로를 보여 주어야 한다(SHALL).
- **인스턴스 화면**: 제목 아래에 「작업 폴더 · <폴더>」와 「메일 N통 · 단계 결과 N개」를 표시한다. 단계 결과가 있으면 「단계 결과 보기」(인스턴스 라인 변형)를 표시한다. 폴더를 볼 수 없는 사람에게는 표시하지 않는다.
- **인스턴스 대화**: 메일을 넣을 때마다 「작업 폴더 ‘…’를 만들고 메일 01 「…」를 넣었어요」 · 「작업 폴더 ‘…’에 메일 02 「…」를 넣었어요」 칩을 표시한다. 칩을 누르면 폴더가 열린다.
- **폴더 화면**: 이름 옆에 「작업 폴더」를 표시하고, 그 아래에 「루틴 · <인스턴스>」를 표시한다(누르면 인스턴스 화면으로 이동). 폴더 목록에도 「작업 폴더」를 표시한다.
- **메일 시트**: 인스턴스에 이어진 메일이면 「작업 폴더 · <폴더>」를 표시한다.
- 휴대폰 화면(390×844)에서 가로로 넘치지 않아야 한다.

#### Scenario: 인스턴스에서 폴더로, 폴더에서 인스턴스로
- **WHEN** 메일을 이은 인스턴스 화면에서 「작업 폴더」를 누른다
- **THEN** 해당 폴더가 열리고 `메일/01_…` 파일이 보이며, 「루틴 · <인스턴스>」를 누르면 인스턴스 화면으로 돌아온다

#### Scenario: 휴대폰
- **WHEN** 휴대폰에서 인스턴스 화면과 작업 폴더를 연다
- **THEN** 「작업 폴더」와 폴더 화면이 화면 너비 안에 표시된다

### Requirement: 다른 파드에서 도는 에이전트도 폴더 체크아웃을 받고 돌려준다
시스템은 deepagents가 공유 폴더의 변형에서 작업할 때(엔진 단계 · 변형 인계 · 충돌 해결), deepagents가 방을 복원하는 저장소 위치에 체크아웃을 올려야 한다. 작업이 끝나면 에이전트가 그곳에서 수정 · 생성 · 삭제한 내용을 커밋 전에 받아 와야 한다(SHALL). 이는 채팅 턴에서 이미 사용하는 방식과 같다. 그동안 이 서버의 디스크는 변경되지 않아도 된다.

#### Scenario: 다른 파드의 에이전트가 고친 파일
- **WHEN** deepagents 엔진 단계의 체크아웃이 저장소에 올라가고, 에이전트가 그곳에서 `a.md`를 수정하고 `c.md`를 만들고 `자료/b.md`를 삭제한다
- **THEN** 단계가 끝난 뒤 해당 변형의 커밋에 세 변경이 모두 포함된다
