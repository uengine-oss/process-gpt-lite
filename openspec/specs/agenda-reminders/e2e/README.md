# 시험과 증거 — 약속 알림: 메일과 대화방에서 정한 약속을 그때 알린다

새 테이블은 넷이다(`server/sql/067_agenda.sql`): 약속(`pro_agenda_items`), 사람별 알림(`pro_agenda_reminders`), 대화방별 읽은 위치(`pro_agenda_rooms`), 「이건 아니에요」 피드백(`pro_agenda_feedback`). 여기에 사람별 설정(`pro_profile.agenda`)을 더했다. 공유 개발 DB에 두 번 적용해 두 번째 실행도 오류 없이 끝남을 확인했다.

시험은 네 단계로 나뉜다. 시간 계산과 모델 응답 검증은 모델 · DB 없이 단위 시험으로 확인한다. 모델의 읽기는 사례 22건으로 확인하되, 기본은 가짜 모델로 결정적으로 실행하고, 원하면 실제 모델로 정확도를 잰다. 저장 · 알림 · 열람자 규칙은 개발 DB에서 시험 전용 회사(`agenda-it`)로 통합 시험한다. 이때 판정과 읽기는 대본으로 대신한다. 화면 · 알림 · 푸시는 Playwright가 자체 스택(회사 `agenda-ui`, BFF 8983 · Vite 5383부터 빈 포트, `PRO_BACKGROUND=0`)에서 실제 Chromium으로 확인한다. 이 스택의 모델은 시험 파일의 가짜 모델(OpenAI 호환 — 판정의 첫 글자 확률 · 메일 비서 · 약속 읽기), 푸시 서비스는 가짜(`server/test/fixtures/fakePush.mjs`), 시계는 시험 전용 경로(`PRO_AGENDA_TEST_CLOCK=1`, 이 컴퓨터의 요청만, `POST /api/agenda/test/tick {now}`)다. 실제 메일 · 실제 기기 · 실제 모델로는 아무것도 보내지 않는다.

```bash
cd server && node --test test/agenda.test.js                                                   # 단위 18 (AG-U-01~18)
cd server && node --test test/agenda-read.test.js                                              # 사례 22 + 1 (가짜 모델)
cd server && AGENDA_EVAL=1 node --test test/agenda-read.test.js                                # 실제 모델(.env 의 게이트웨이) → results/model-eval.json
cd server && node --test --test-concurrency=1 test/agenda.integration.test.js                  # 통합 12 (AG-I-01~12, 개발 DB)
cd e2e && RT_WORKERS=1 npx playwright test --project=feature tests/feature/agenda-reminders.spec.js   # F-AG-01~08
```

## 재검토(PR #95) 반영

재검토에서 진행을 막을 문제는 없었고, 앞의 열 가지는 모두 확인됐다. 남은 문제를 고쳤으며, 이번에도 시험을 먼저 쓰고 수정 전 코드에서 실패를 확인했다(단위 6건 · 통합 3건 모두 실패). 수정 후에는 모두 통과한다.

```bash
cd server && node --test test/agenda-review2.test.js                                    # R2-U-01~06 (모델 · DB 없음)

```

| 재검토 | 고친 내용 | 시험 | 수정 전 |
|---|---|---|---|
| #1 카드가 링크를 준 사람을 잘못 표시함 | 약속을 만들 때와 링크를 바꿀 때마다 그 메일의 보낸 사람을 `source.linkFrom`에 기록하고, 카드에 그 사람을 보여 준다 | R2-U-01 · R2-I-01 | 같은 스레드의 박 과장이 바꾼 링크 옆에 김 대리(처음 정한 사람)가 표시됨 |
| #2 여러 사람이 함께 쓰는 발신 주소 | 메일 머리(List-Id · List-Unsubscribe · Precedence: bulk · list · junk · 「no」가 아닌 Auto-Submitted · 보낸 사람과 다른 X-Original-Sender)로 판단하고, 그런 메일과 그런 주소에서 처음 정한 약속은 같은 스레드에서만 연결한다. Gmail · IMAP에서 메일을 가져올 때 이 머리도 가져온다. 주소의 낱말은 보지 않는다 | R2-U-02 · 03 · R2-I-02 | `sharedSender` · `headerFields` 없음, 리스트 주소의 다른 스레드 메일도 약속을 봄 |
| #3 메일 약속의 글 속 주소가 푸시에 실림 | 메일 약속의 제목 · 장소 · 챙길 것 · 메모 속 주소는 알림 글에서 「(링크: 도메인)」으로 바꾼다. 카드에는 그대로 보여 준다 | R2-U-04 | 제목에 `https://evil.example/t?x=1` |

검토 당시 RV-U-03(「새 메시지는 마지막 15개만」)은 재검토 #4에 맞게 바꿨다. 새 메시지 40개를 모두 넣고, 메시지마다 112자 이하, 합계는 15 × 300자 이하인지 확인한다. 수정 후 다시 실행한 시험: `agenda` 단위 18 · 사례 23 · 검토 4 · 재검토 6, 통합 12 · 검토 11 · 재검토 3, `mailCard` 8 · 11, `mailSelf` 7 · 1, `mailPollRace` 2, `mailFlow` 12, `roomStore` 6, `i18n-dictionary` 3, Playwright F-AG-01~08(8/8) — 모두 통과.

## 시험하지 않은 것

- 실제 Android · iPhone 기기의 푸시(가짜 푸시 서비스가 받은 본문만 확인), 실제 Gmail · IMAP 메일함(데모 메일함으로만 확인), 실제 Google 캘린더에 넣기.
- 열어 둔 대화방은 약속이 생긴 뒤 다시 열어야 메시지 아래 표시가 보인다(실시간으로 붙이지 않음).
- Process GPT 화면에서 쓴 메시지를 방 피드로 읽는 경로(`PRO_BACKGROUND` 서버의 LISTEN)는 화면 시험에서 쓰지 않았다. 피드가 호출하는 함수는 Lite 메신저가 호출하는 함수와 같다.
- 하루 단위의 실제 시간 흐름(실제 시계에 따라 알림 발송)은 시험 시계로만 확인했다. 운영 서버의 1분 주기 발송(`startAgendaTicker`)은 화면 시험에 쓰지 않았다.
