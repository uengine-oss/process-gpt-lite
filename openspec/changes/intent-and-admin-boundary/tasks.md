## 1. 현재 동작을 고정하는 시험

- [ ] 1.1 결정된 추천이 있는 상태에서 사례가 겹치는 다른 묶음이 들어오는 경우를 시험으로 적는다. 지금 코드에서는 근거 업무가 덮어써지는 것을 확인해 둔다 ("이미 있는 추천인지 가리기")
- [x] 1.2 한 사람에게 서로 다른 문서를 공유하는 경우를 시험으로 적는다. 지금 코드에서는 역할로 같은 이름이 붙는 것을 확인해 둔다 ("검토 단계의 이름")

## 2. 업무 범주

- [x] 2.1 사례 기록에 업무 범주를 담을 자리를 더한다
- [x] 2.2 업무가 끝날 때 범주를 한 번 정해 저장한다. 이미 있으면 다시 판단하지 않는다 ("업무 범주 판단과 저장")
- [x] 2.3 관리자가 고른 범주가 판단을 덮고, 그 뒤로 다시 판단하지 않는다 ("업무 범주 판단과 저장" 두 시나리오)

## 3. 마이닝 서비스와 주고받기

- [x] 3.1 반복 업무 찾기가 `POST /patterns` 를 쓰고, 사례별 범주와 결정된 경계를 넘긴다 ("반복 업무 찾기 주기와 수동 실행")
- [x] 3.2 결정된 추천은 키가 같을 때만 근거 업무를 바꾸고, 모양은 다시 그리지 않는다 ("이미 있는 추천인지 가리기")
- [x] 3.3 아직 결정되지 않은 추천의 판정은 지금 그대로 둔다

## 4. 확인 필요 목록

## 7. 확인 중 나온 수정

- [x] 7.1 끝나지 않은 업무까지 확인 필요로 물었다. 끝난 업무만 묻게 고쳤다 ("범주를 가리지 못한 업무를 관리자에게 묻는다")
- [x] 7.2 범주를 한 건씩 판단하니 행사 이름마다 쪼개졌다(워크숍 견적·송별회 견적·시상식 견적 …). 한 번에 묶어 판단하고, 일의 종류로 정하도록 고쳤다
- [x] 7.3 결정된 추천의 옛 근거가 남아 한 사례가 두 추천에 함께 보였다. 결정된 추천의 근거는 마이닝 서비스가 그 묶음에 넣은 사례와 같게 했다 ("이미 있는 추천인지 가리기")
- [x] 7.4 옛 기준이 만든 미결정 추천이 남의 사례를 근거로 들고 있었다. 근거를 잃은 제안은 거두게 했다 ("제안이 거두어진다")
- [x] 7.5 연습 메일 두 가지를 더해(새봄교육 교육 일정표·온보딩 안내서) 지금 테넌트에서 확인했다. 등록 프로세스의 가로채기 낱말·형식에 걸리지 않는 업무라 새 사례가 열린다
- [x] 7.6 범주를 정하는 기준이 추천을 만드는 기준과 달랐다. 고객 회신만 끝으로 보아, 회신 없이 멈춘 업무는 범주가 영영 붙지 않았다. 둘을 같은 기준으로 맞췄다 ("업무 범주 판단과 저장")
