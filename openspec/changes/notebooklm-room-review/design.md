## Context

운영 Lite(`<회사>.process-gpt.io/lite`)는 서버 한 대가 여러 회사를 받는다. 에이전트 서비스(deepagents)는 다른 파드에 있다. 운영에는 context-router·판정 서버가 없다. 서버 브라우저(Playwright Chromium, headless)는 사람마다 프로필 하나를 쓴다. 이번 변경은 2026-11-21 휴대폰 녹화의 지적을 고친다. 11-04 에 만들고 병합하지 않은 방 규칙·NotebookLM 안내·작업 독·직접 제어 고침을 main 으로 옮긴다.

## Goals / Non-Goals

**Goals**
- 녹화의 순서(규칙 → 링크 → NotebookLM)가 운영에서 사람의 구글 로그인 한 번으로 이어지게 한다.
- 멈추면 무엇이 필요한지와 할 일을 사람이 바로 알게 한다.
- 운영 DB·매니페스트를 바꾸지 않고 서버 이미지만으로 낸다.

**Non-Goals**
- 구글이 서버 브라우저 로그인을 막는 경우의 우회. 막히면 알리기만 한다.
- deepagents 의 멈추기 권한(Lite 대화의 방 소유 확인)을 고치는 것.
- 메일 연동(운영 Google OAuth 값·회사별 콜백).

## Decisions

1. **방 규칙은 그 방의 안내 메시지에 둔다.** 11-04 에는 테이블(`pro_room_rules`)을 두었다. 그대로 내면 운영 DB 에 SQL 을 먼저 돌려야 한다. 규칙을 받아 적은 안내 메시지의 내용(`roomRule: {said, action, runs, off}`)에 두면 SQL 없이 나가고, 방을 지우면 함께 사라진다. 대가는 하나다. 방마다 마지막 규칙 하나만 쓰고, 다른 사람의 규칙을 막는 일은 방 주인 확인(스레드의 사용자)으로 한다.
2. **규칙 판정은 판정기(서버가 없으면 LLM)로 한다.** 11-04 판은 첫 토큰 확률(logprob)을 썼는데, 그 기능은 병합하지 않은 브랜치에 있다. 운영에는 판정 서버가 없어 LLM 이 대신 고르고 확신도를 말한다. 기준은 0.7 그대로다. 모델에 묻기 전 낱말 걸러내기를 넓혀, 녹화의 문장(「이 방에서 내가 주는 url이 있으면」)이 걸리게 했다.
3. **바로잡는 말은 앞 작업을 대신한다.** 프로젝트 방은 대화가 하나다. 그래서 그 방의 새 사이트 작업이 늘 앞 턴을 대신한다. 메인 채팅은 여러 일이 나란히 돌아, 짧고 자기 링크가 없는 말일 때만 판정한다(0.7). 멈추기는 기존 「멈추기」 경로(deepagents `/chat/stop` → 안 되면 스트림 끊기)를 쓴다.
4. **로그인 벽은 규칙으로 알아보고 모델 턴을 쓰지 않는다.** 녹화에서는 모델이 로그인 화면에서 몇 분 동안 헛돌았다. 벽의 모양은 흔하고 분명하다(구글 로그인 주소, NotebookLM 첫 화면). 그래서 규칙이 더 빠르고 정확하다.
5. **자동화 탐지를 피하지 않는다.** 구글이 서버 브라우저 로그인을 거절하면 사실대로 알리고, 사람이 직접 만든 파일을 올리는 길을 안내한다.
6. **프로필은 `/data/browser-profiles`.** 운영 PVC 가 `/data` 에 붙는다. 이미지 안 경로는 배포 때마다 지워졌다. 파드가 바뀔 때 남는 잠금 파일은 띄우기 전에 정리한다.
7. **휴대폰 문서 보기는 Lite 쪽에서만 바꾼다.** 편집기 iframe 은 같은 출처라 스타일·클래스를 넣어 바꿀 수 있다. 편집기 이미지(office-host ecea940)는 그대로 둔다. 선택자가 편집기 클래스에 기대므로, 편집기 이미지를 올릴 때 `office-mobile` 시험을 다시 돌린다.

## Risks / Trade-offs

- **구글이 서버 브라우저 로그인을 막을 수 있다.** headless 브라우저이기 때문이다. 확인하지 못했다. 막히면 카드가 그렇다고 말한다.
- **deepagents 가 Lite 대화의 `/chat/stop` 을 403 으로 거절한다.** SDK 가 `chat_rooms` 로 방 소유를 확인하는데, Lite 대화는 거기 없다. 화면에서는 앞 작업이 멈춘 것으로 끝나지만, 에이전트 서비스의 턴은 끝까지 돌 수 있다. 그 턴이 만든 파일 카드는 대화에 붙지 않는다. SDK 고침이 따로 필요하다.
- **PVC 10Gi 를 함께 쓴다.** HTTP 캐시는 50MB 로 묶었지만, Service Worker·코드 캐시는 자랄 수 있다.
- **방 규칙 저장 방식이 바뀌었다.** 로컬 공용 DB 에 남은 `pro_room_rules` 테이블은 더 읽지 않는다. 운영에는 그 테이블이 없다.
